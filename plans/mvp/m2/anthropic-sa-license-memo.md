## 1. 事實（已實查，非本備忘新查）

| 項目 | 內容 |
| --- | --- |
| 對象 | `anthropics/skills` 的 **4 個 Skill**：`docx`、`pdf`、`pptx`、`xlsx`；pin commit `f6656c12` |
| 授權檔 | `skills/<name>/LICENSE.txt`：「© 2025 Anthropic, PBC. All rights reserved.」＋ 使用受 Consumer／Commercial Terms 管轄 |
| 禁止條款一 | 「distributing, sublicensing, or transferring these materials to any third party」 |
| 禁止條款二 | 「extracting, copying, creating derivative works, or reproducing the materials **outside the Services**」 |
| 同 repo 的例外 | `brand-guidelines`、`internal-comms` 為 **Apache-2.0**（`skills/<name>/LICENSE.txt` 實查），**不受本備忘影響** |
| 平台現況 | 4 筆皆為 `documents` 類**已索引**層（非精選）；已保存內容快照與雜湊、已產生 LLM 增強摘要與向量、詳情頁可看全文與檔案樹、已在 M2 基準試跑中實跑過、**Download Artifact 已封鎖** |

**條款二是本案的全部難點。** PDM-002 當初的統一政策（「索引與平台內試跑照常，一律不產出 Download Artifact」）只回應了條款一——「在平台上執行不等於再散布」對條款一成立，對條款二不成立，因為條款二管的不是散布，是**在 Anthropic 服務之外的複製與衍生**。

## 2. 四種平台行為的逐項風險評估

風險等級是**條款字面涵蓋程度**的評估，不是被主張的機率評估（後者需要法務）。

### 2.1 索引（保存內容快照、雜湊、FTS 與向量）

| | |
| --- | --- |
| 平台實際做了什麼 | 把套件位元組存進物件儲存與資料庫，保存內容雜湊（`SKILL-001`／INGEST-004），建立 FTS 與 pgvector 索引 |
| 條款涵蓋 | **條款二直接命中字面**：「copying / reproducing the materials outside the Services」——一份存在 Skill Hub 資料庫裡的副本，就是 Anthropic 服務之外的一份副本 |
| 對平台的緩解論據 | 這是**內部技術性重製**、不對外提供原始位元組；索引本身是搜尋引擎的必要動作，與快取／爬取的既有實務同型 |
| **風險** | **中高**。字面涵蓋最直接，但也是所有其他功能的前提——它一旦不成立，這 4 筆只能停在「外部結果」層 |
| 拿掉的代價 | `documents` 已索引由 10 → **6**，跌破 `CONTENT-001` 每類 8–12 的下限；`docx` 是 golden query **D01 的 gold primary 且為現行 Top-1**，該題失去判定基準 |

### 2.2 展示（詳情頁摘要、進階模式的 `SKILL.md` 全文與檔案樹）

| | |
| --- | --- |
| 平台實際做了什麼 | 一般模式顯示白話摘要、限制、依賴；**進階模式顯示 `SKILL.md` 全文與套件檔案樹**（`DISC-003`／`03` DISC-007），且公開搜尋不要求登入（`DISC-010`） |
| 條款涵蓋 | **最接近條款一**：對任何未登入訪客逐字呈現全文，實質等於把 materials 提供給第三方。條款二的 "reproducing" 亦同時涵蓋 |
| 對平台的緩解論據 | 內容在原 repo 本來就公開可讀；平台標明來源與授權、連回原始位置 |
| **風險** | **高**（四項中最高），**但也是緩解成本最低的一項**——關掉這 4 筆的全文與檔案樹，只留摘要與來源連結，不影響任何其他功能 |

### 2.3 沙箱試跑

| | |
| --- | --- |
| 平台實際做了什麼 | 把套件解到隔離沙箱、由 Agent 讀取並執行任務、產出 Artifact 與 Trace（M2 基準試跑已對這 4 筆執行過） |
| 條款涵蓋 | 執行本身是**使用**不是散布，條款一不涵蓋；但「解到沙箱」是又一次 copying，而 Run 產物可能被視為 derivative works——**條款二部分涵蓋** |
| 對平台的緩解論據 | 使用者自己的 Run、產物只回到該使用者的 Workspace、不對外散布；`CONTENT-004` 已明訂 source-available 不產 Download Artifact |
| **風險** | **中**。且**目前實務上尚未對外發生**——`SEC-009`／`SBX-010` 未通過前，依 ADR-015 定案紀錄本來就不得開放外部使用者提交 Skill 執行 |

### 2.4 打包下載

| | |
| --- | --- |
| 平台實際做了什麼 | **不做**。`CONTENT-004` 與 ADR-012 已封鎖，UI 顯示「可在平台試跑，不提供下載」 |
| **風險** | **低（現況合規）**。唯一要做的是**維持**，並確保未來的 `PACK-001` 實作不會因為「已人工確認」而誤放行——`02:CONTENT-002` 已明文「已人工確認不等於可再散布」 |

### 2.5 橫切項：LLM 增強摘要與向量（容易被漏掉的一項）

摘要、任務範例句與 tags 是**對 materials 的加工產出**，字面上可被讀為 derivative works；向量是不可還原的數值投影，風險較低。實務上摘要是事實性轉述而非替代原文（`02` §4.7 的 v4／v5 約束正是在壓「不得加碼」），但**若法務認定條款二涵蓋衍生產出，受影響的不只是展示，還包括這 4 筆的增強欄位與搜尋召回**。此項在 §5.2 的原告警中未被點出，本備忘補上。

## 3. 處置提案

### 方案 A：全面下架至「外部結果」層

只留 URL 與 metadata，不存內容、不展示全文、不試跑。**風險最低，代價已知且明確**：`documents` 已索引 10 → 6 跌破下限，須自備援池補 2–6 個 OSI 候選（`w95` 的 39 個自製 skill、`danielrosehill` 13 個與 `YuYY2004` 2 個未複查 Skill）；D01 失去 gold primary。

### 方案 B：維持現況 ＋ 下載前顯著標示授權

代價是字面風險最高的兩項（保存快照、公開全文展示）都沒有變動，而「下載」本來就已封鎖——**標示解決的是一個並不存在的風險**。不建議。

### 方案 C（**建議**）：分層收斂，把最像散布的行為先拿掉

| 行為 | 處置 | 理由 |
| --- | --- | --- |
| 打包下載 | **維持封鎖** | 已合規，零成本 |
| 展示 | **關閉這 4 筆的進階模式全文與檔案樹**，改為摘要 ＋ 限制 ＋ 來源連結（「原文請至來源 repo 檢視」） | 風險最高、成本最低的一刀；把「向第三方逐字提供 materials」這個行為移除 |
| 沙箱試跑 | **終判前不對外部使用者開放** | 不需額外動作——`SEC-009` 未過本來就不得開放；只需在終判前**不解除** |
| 索引 | **維持**，但保存範圍限於檢索必要，並確保可一鍵下架 | 它是其他一切的前提；風險以「可快速撤回」而非「事前移除」控制 |
| 增強摘要與向量 | 維持，於終判時一併裁定（§2.5） | 若判定涵蓋衍生產出，處置與索引同進退 |

**方案 C 有一個隱含前置必須點名**：「可一鍵下架」目前**做不到**——`INGEST-010`（下架流程）與 `SEC-011`（operator 角色）皆未實作，現行唯一的下架手段是直接改資料庫。**在這兩項落地之前，方案 C 的風險控制手段只是紙上的。** 這一點應與終判一併考慮。

### 並行建議（成本最低，可能直接消滅整個問題）

**直接向上游詢問書面澄清或許可。** 條款二的 "outside the Services" 顯然不是為了規範「第三方目錄索引一個公開 repo 裡的 Skill」而寫的，而詢問的成本是一封信。若取得書面同意，本備忘的四項風險同時歸零，且 `documents` 的補位工作可以取消。建議與方案 C 並行，不互斥。

## 4. 交給終判者的三個問題

1. **保存內容快照是否構成 "reproducing … outside the Services"？**（§2.1；這一題決定 4 筆能不能留在「已索引」層）
2. **若構成，衍生產出（LLM 摘要、任務範例句、向量）是否一併受涵蓋？**（§2.5；決定的是「連摘要都要撤」還是「只撤原文」）
3. **公開展示 `SKILL.md` 全文，與條款一的 "transferring to any third party" 的距離為何？**（§2.2；若答案是「太近」，方案 C 的那一刀應立即執行，不必等前兩題）

### 6.2 執行內容

機制是 migration **`0023`** 的 `skills.access_restriction`（NULL ＝ 無限制；非 NULL ＝ 原因碼，本案為 `license-review`）。設計理由寫在該檔頂端，摘要三點：

1. **不重用 `takedown_at`**。下架是 410 Gone ＋ 移出索引 ＋ 不可 Fork；方案 C 要保留的正是這些。同一個欄位表達兩個相反的意圖，遲早有人只讀了其中一半。
2. **放在 `skills` 不是 `skill_versions`**。授權涵蓋來源，因此涵蓋每一個版本（含尚未匯入的）；而且旗標必須可解除，`skill_versions` 是不可變的（鐵律 4）。
3. **隨 Fork 傳播**。Fork 是同一批素材的另一份副本；旗標在 Fork 當下複製（同 `WS-001` 對 License 關係的要求）。不傳播的話，「Fork 一次」就是繞過的手段。

逐筆處理（`tools/content/restrict-anthropic-sa-display.sql`，可重跑）：**4 筆目錄項 ＋ M2 基準試跑留下的 4 個存活 Fork**，共 8 列。已軟刪除的 Fork 未處理——它們對所有讀取路徑都已不存在。

### 6.3 行為對照

| 路徑 | 裁定前 | 裁定後 |
| --- | --- | --- |

### 6.4 這次沒有解決的事（必須交接）

- **§3 點名的「可一鍵下架做不到」仍然做不到。** 設定與解除受限旗標目前**只能由審查者直接跑 SQL**，沒有端點、沒有 audit event——`SEC-011`（operator 角色）與 `CORE-008` 都未實作。本次把「受限」變成一個有定義、有測試、fail-closed 的**狀態**，但操作它的**流程**仍是紙上的。
