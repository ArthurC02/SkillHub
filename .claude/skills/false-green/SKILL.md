# 假綠燈：四種「看起來過了」

**通過 ＝ 你看到成功那一行。沒看到 ＝ 不知道，不是通過。**

## 1. 先指名成功字串，再確認它出現

說出這個工具成功時會印什麼，然後在輸出裡找到它。不要從「沒有紅字」反推。

- `go test ./...` → 每個套件一行 `ok  <pkg>`；`no test files` 不是通過
- `pytest` → `N passed`
- `eslint` → 通過時**不印任何東西**，所以這一項只能靠 exit code

輸出會被 pipe、`head`、工具包裝或代理層截斷與吞掉。看不到成功行，就當作沒跑。

## 2. 看跳過幾條，不只看通過幾條

`312 passed, 148 skipped` 和 `460 passed` 是兩件事。整組整合測試因為某個環境變數沒設而被跳過時，套件照樣印綠、exit code 照樣 0。

每次把 skipped／filtered／deselected 的數字唸出來，並跟上一次比。**通過數掉了或跳過數漲了，就是有東西不再跑了。**

## 3. 本機綠不等於 CI 綠

CI 的平台才是事實來源。差異最常出在：檔名大小寫（本機 case-insensitive、CI 不是）、路徑解析與行尾、工具版本、只在 CI 設的環境變數、formatter 的預設值。

本機綠的意思只是「值得推上去看」，不是「過了」。

## 4. 懷疑輸出被過濾，就導到檔案再讀

    <command> > out.txt 2>&1; echo "exit=$?"

然後讀 `out.txt`，並看那個 exit code。exit 0 但輸出是空的，跟 exit 0 且成功行在裡面，不是同一件事——前者通常代表指令根本沒執行到你以為的東西。

## 回報格式

`<command> → exit <n>，<成功字串>，skipped <n>（上次 <n>）`

任何一欄缺了，就寫「未確認」，不要寫「過了」。
