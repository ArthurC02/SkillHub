# 沙箱節點維護與撤下提案

現有手冊先移除舊 Provider，再等節點跑完；控制平面重啟後會失去既有 attempt 的輪詢與拆除路由。`docker ps` 未列出執行中容器，也不能證明停止容器、建立中的 attempt 與金鑰／授權已清理。本包修正這些操作文字，提出獨立的 maintenance 行為，甲-5 保持未結案。

## 領域事實與最小方案

已審查的 Run owner 擁有派送、輪詢與清理。P1 會保留現場且不得降級；容量 halt 可自動恢復。提議保存獨立、持久的 per-Provider maintenance 意圖，阻擋新 attempt 並保留舊端點；operator 查到完整且同世代的清理、庫存與記錄證據後，才可安排人工撤下。既有失聯重派上限、attempt 冪等與等待時計算保持原義；資源清理後的延後查費不要求舊節點繼續服役。

不新增 Run Aggregate 或雲端編排框架。尚未審查 maintenance、節點世代與庫存的 owner，以及多 Worker 派送與維護宣告的競爭語義；不能把 Operations 的名稱當作雲端生命週期的所有權。這些問題與新增 operator API 須由 developer 審查後再實作。雲端建機／刪機、排程與費用授權留在後續明確範圍，不在本包執行。

## 證明與反證

六項義務均為 planned，沒有已跑或通過宣稱。後續以可控制的 Provider 替身、真實 PostgreSQL 與兩個 Worker 驗證宣告前後派送競爭、既有工作收尾、P1／容量／maintenance 的狀態組合、等待時計算、空與未知的庫存、停止容器、費用待補報、權限與世代錯誤、重送及重啟。每項保護都要移除一次，確認焦點測試變紅後精確還原；免費替身不替代真節點驗收。

## 審查與限制

此包沒有 reviewer 同意、Registry 異動、正式契約、遷移或雲端副作用。7 天與事件觸發的換新仍未自動化；真節點准入、記錄送達、預算及不可逆的撤機授權須另行完成。事故仍依 P1 程序保留現場，不因節點超齡而逕行清除。
