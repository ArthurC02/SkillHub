# Runtime 映像准入提案

掃描已過期的 digest 目前仍可接新 Run。此提案沿用既有 Provider 建立協作，在建立任何工作資源之前驗證映像的 SBOM、掃描、身分與有效期限；拒絕使用既有 503 回應，已執行的 Run 照常管理。

## 已審查事實與缺口

Run Context 擁有生命週期、派送、跟隨與清理；其重試與 attempt 冪等規則維持。Registry 沒有可當作已審查事實的映像准入規則或獨立 Sandbox Context。本包將供應鏈政策視為現行規範的輸入，提交 developer 確認 Provider 上的判定邊界，不新增 Context、事件或資料表。

## 實作交接

相同 attempt 的重送先回原資源，同鍵異內容回 409。新 attempt 才進准入：驗證材料綁定指定 OCI digest，核對 30 天期限、可修 Critical／High 與已核准不可修豁免；最後建立容器前複查時效，使用同一映像的不可變 ID。若最後才拒絕，撤回暫留名額與紀錄，不回 201、不傳入 Skill／資料或啟動 Trace。輪詢、取消、清理與既有 Run 收養不被新驗證阻擋。

不新增戰術模式或驗證服務。只在節點啟動時檢查會漏過後續到期；unsigned PASS 收據、tag／label 與告警都不能代替驗證；停止現有 Run 違反既定不中斷規則。

## 測試義務

七項義務對應 requirement 的七條可觀察結果，目前全為 planned，沒有執行或通過宣稱。實作須用固定時鐘測到期前、到期瞬間、剛過期、未來時間與等待中到期；用決策表涵蓋簽章／來源／digest／漏洞／豁免讀不到的分支；用狀態轉移證明重送、衝突、取消、收養與清理。必須斷言實際容器、名額、輸入搬運及平台重試次數，不能只看 HTTP 狀態碼。每次驗證皆有可造成失敗的反證並還原原碼。

## 契約與未決事項

提案沿用 Sandbox Provider 契約的 503 `RunError`，回 `provision`／`retryable: true`，平台仍決定重試上限。正式 OpenAPI、程式與節點供應尚未改動。驗證材料的刷新／取得、節點驗證器、派送時間預算、503 相容行為及核准豁免來源須由 developer 確認；不從簽署這份提案推導產品負責人的漏洞豁免。

只有 `agent:codex` 提出方案，沒有代簽 reviewer、提升 Registry 事實或放寬門檻。真實節點驗收、通知送達、跨 Run 網路隔離與節點重建仍是各自的未結案工作。
