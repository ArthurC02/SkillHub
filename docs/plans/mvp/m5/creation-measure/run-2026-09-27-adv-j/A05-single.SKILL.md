# 競爭對手價格追蹤

此技能用於**整理與執行價格監控流程**：先確認要追蹤的三家競爭對手、對應商品頁或價格頁、比對規則與通知方式，再建立可重複的監控紀錄。若環境沒有可用的自動化、排程或網路存取工具，則只能協助設計監控方案與通知格式，不能直接完成即時抓取或推播。

## 先確認的資訊

在開始前，先向使用者確認以下內容：

1. 三家競爭對手的名稱與官網網址
2. 每一家要追蹤的具體頁面
   - 商品頁
   - 分類頁
   - 價格頁
   - 活動頁
3. 要比對的欄位
   - 售價
   - 原價
   - 折扣
   - 運費
   - 庫存狀態
   - 規格/容量
4. 變動判定規則
   - 任一欄位變動就通知
   - 只在價格變動時通知
   - 變動超過某個百分比才通知
5. 通知方式
   - 電子郵件
   - 即時訊息
   - 其他可用管道
6. 監控頻率
   - 每小時
   - 每天
   - 每週
7. 是否需要保留歷史紀錄與變動摘要

## 執行流程

### 1. 建立監控清單

把每個目標整理成一筆紀錄，至少包含：

- 競爭對手名稱
- 頁面名稱
- URL
- 需要擷取的價格欄位
- 比對規則
- 上次已知價格
- 上次檢查時間

若使用者尚未提供完整清單，先回覆缺少哪些資訊，不要自行猜測。

### 2. 取得基準值

對每個頁面先建立初始基準：

- 開啟頁面並確認價格是否可直接讀取
- 若價格由 JavaScript 動態載入，需等待內容完成後再讀取
- 若頁面有多種幣別、會員價或地區價，先依使用者指定的版本記錄
- 將基準值與擷取時間保存為第一筆紀錄

### 3. 進行比對

每次檢查時，將新讀到的值與上次紀錄比較：

- 若完全相同，標記為「無變動」
- 若任一指定欄位不同，標記為「有變動」
- 若使用者設定百分比門檻，先計算變動幅度再判定是否通知

比對時要注意：

- 數字格式差異，例如 `1,299` 與 `1299`
- 幣別符號差異，例如 `$`、`NT$`
- 空白、換行與大小寫差異
- 同頁面不同規格造成的價格切換

### 4. 產出變動摘要

若偵測到變動，整理成簡短摘要，至少包含：

- 競爭對手名稱
- 頁面名稱或商品名稱
- 舊價格
- 新價格
- 變動幅度
- 檢查時間
- 頁面連結

若有多個欄位變動，逐項列出。

### 5. 通知使用者

依使用者指定的通知方式送出摘要。通知內容應簡潔，優先讓使用者快速判斷是否需要進一步查看。

若無法直接發送通知，則準備可直接貼上的通知文字，並明確標示：

- 哪一家變動
- 變動前後數值
- 需要使用者採取的下一步

### 6. 保留紀錄

每次檢查後更新歷史紀錄，至少保存：

- 檢查時間
- 讀到的價格
- 是否變動
- 變動前後內容
- 備註（例如頁面無法讀取、價格被登入遮蔽）

## 異常處理

遇到以下情況時，不要硬猜價格：

- 頁面無法開啟
- 價格被登入、地區或年齡限制遮蔽
- 頁面顯示「請稍後再試」或反爬驗證
- 同一頁面出現多個價格且無法判定哪個是目標價格

此時應回報：

- 無法讀取的原因
- 目前可見的頁面狀態
- 需要使用者補充的資訊

## 建議的輸出格式

當有變動時，使用以下格式整理：

- 競爭對手：
- 頁面：
- 舊價格：
- 新價格：
- 變動：
- 時間：
- 連結：
- 備註：

當無變動時，簡短回報：

- 競爭對手名稱
- 本次檢查結果：無變動
- 檢查時間

## 重要限制

- 這個任務需要持續監控與可能的網路存取；若目前環境沒有可用工具或排程能力，只能協助你建立監控規格、比對規則與通知模板。
- 不要自行推測未提供的價格、網址或通知管道。
- 不要把未確認的頁面內容當成有效價格。
