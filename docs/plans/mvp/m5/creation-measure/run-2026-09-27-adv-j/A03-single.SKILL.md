# 目的
將客服信箱「上週」收到的客訴信整理成分類統計表，並附上可追溯的分類依據。

# 適用範圍
- 只處理已提供給你的郵件內容、匯出檔或對話紀錄。
- 若沒有郵件資料、無法辨識日期範圍，或無法存取信箱內容，先說明缺少哪些資料，再請求補充。
- 這個技能不負責登入信箱、抓取郵件或做任何需要額外權限的動作；只能整理已提供的內容。

# 作業步驟
1. **確認資料範圍**
   - 找出「上週」的定義是否已在資料中明確標示。
   - 若資料跨多週，只保留上週收到的客訴信。
   - 若日期格式不一致，先統一成同一時區與同一日期格式，再篩選。

2. **辨識客訴信**
   - 只納入明確表達不滿、申訴、要求補償、要求改善、退費、延誤、瑕疵、服務態度等內容的信件。
   - 若一封信同時包含詢問與抱怨，以主要目的判定是否為客訴。
   - 若無法判定，標記為「待確認」，不要硬分到某一類。

3. **建立分類規則**
   - 先從信件內容歸納出穩定的主分類，再統計數量。
   - 建議使用以下常見分類；若資料顯示其他明顯主題，可新增分類：
     - 商品瑕疵 / 損壞
     - 出貨延遲 / 未收到貨
     - 退貨 / 退款
     - 服務態度 / 客服回應
     - 訂單錯誤 / 缺件 / 寄錯
     - 帳務 / 付款問題
     - 網站 / 系統問題
     - 其他
     - 待確認
   - 每封信只指定一個「主要分類」；若需要，可另外加註次要分類或備註。

4. **逐封標註**
   - 讀取每封客訴信的主旨、內文、日期、寄件者（若有）。
   - 為每封信標註：
     - 郵件日期
     - 主旨
     - 主要分類
     - 簡短判定理由
   - 若同一客戶多封重複抱怨，仍逐封計數；但可在備註中註明重複案件。

5. **統計數量**
   - 計算每個分類的信件數。
   - 若資料足夠，也可加上占比（分類數 / 客訴總數）。
   - 同時列出總客訴封數與待確認封數。

6. **輸出分類統計表**
   - 先給總覽，再給明細。
   - 總覽表至少包含：分類、數量、占比、備註。
   - 明細表至少包含：日期、主旨、分類、理由。
   - 若有待確認案件，獨立列出，避免混入正式統計。

# 建議輸出格式
## 一、摘要
- 上週客訴總數：X
- 已分類：X
- 待確認：X
- 主要客訴類型：前 3 名

# 品質要求
- 分類名稱要一致，避免同義詞分散統計。
- 不要把推測當事實；理由要引用信件中的明確訊息。
- 若資料量很大，先完成分類規則，再批次整理，最後再統計。
- 若郵件內容不足以分類，寧可列為待確認。
