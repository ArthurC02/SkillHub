## 目的
將使用者提供的履歷改寫為「資料分析職缺」導向的一頁內版本，優先凸顯分析能力、工具經驗、商業影響與可量化成果。

## 使用時機
在使用者要求：
- 把履歷改成資料分析／數據分析／BI／商業分析職缺版本
- 壓縮成一頁內
- 強調與職缺相關的技能、專案與成果

## 工作原則
1. 只根據使用者提供的履歷內容改寫，不捏造學歷、工作經歷、工具或數字。
2. 若資訊不足以支撐資料分析定位，先提出需要補充的關鍵資訊，再進行改寫。
3. 內容必須精簡、具體、可掃讀，目標是一頁內。
4. 優先保留與資料分析相關的內容，刪除與目標職缺關聯低的細節。
5. 用成果導向語氣，盡量把職責改寫成「做了什麼、用什麼方法、帶來什麼影響」。

## 改寫流程
### 1. 先盤點原始履歷
整理出以下資訊：
- 個人摘要／自我介紹
- 工作經歷與每段職務的主要成果
- 專案經驗
- 技能與工具
- 學歷與證照

### 2. 對齊資料分析職缺重點
將內容重新排序，優先保留：
- SQL、Python、R、Excel、Tableau、Power BI、Looker、A/B testing、統計分析、資料清理、資料視覺化
- 商業分析、營運分析、產品分析、行銷分析、報表自動化、儀表板建置
- 可量化成果：提升效率、降低成本、增加轉換率、改善決策速度、縮短報表時間

### 3. 改寫每段經歷
每個條目盡量使用以下結構：
- 動作 + 方法/工具 + 產出 + 影響

例如改寫方向：
- 「負責報表製作」→「使用 SQL 與 Excel 自動化週報流程，將報表產出時間縮短 40%」
- 「分析銷售數據」→「整合銷售與會員資料，建立分群分析，協助團隊找出高價值客群」

### 4. 控制篇幅
輸出內容應符合一頁內，建議結構如下：
- 標題區：姓名、聯絡方式、LinkedIn/作品集（若有）
- 專業摘要：2–3 行
- 核心技能：一行或短條列
- 工作經歷：每段 2–4 個條列
- 專案／作品集：1–2 個條列（若有且相關）
- 學歷與證照：精簡列出

### 5. 調整語氣與用字
- 使用資料分析職缺常見詞彙：分析、洞察、指標、報表、自動化、視覺化、預測、分群、優化、監控
- 避免空泛形容詞，例如「認真、負責、熱情」若沒有具體成果支撐就不要保留
- 避免過度技術堆疊；只保留與經歷相符且能證明能力的工具

## 若資訊不足
如果使用者沒有提供足夠內容，先詢問以下最少必要資訊：
- 原始履歷全文或主要段落
- 想投遞的資料分析職缺類型（例如產品分析、商業分析、BI）
- 是否有可量化成果、工具經驗、作品集連結

## 輸出要求
- 直接輸出改寫後的履歷內容
- 保持一頁內的精簡風格
- 不要加入與履歷無關的說明
- 不要捏造內容
- 若需要補充資訊，先列出缺少的項目，再暫停改寫
