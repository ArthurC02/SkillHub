# 目的
將「上週收到的客訴信」整理成可讀的分類統計表，並保留可追溯的分類依據。

# 適用情境
- 需要把客服信箱中的客訴郵件做分類統計。
- 需要輸出每一類的件數、占比，以及必要的代表性摘要。
- 若沒有郵件內容、信箱存取權限或時間範圍資訊，先補齊資料再整理。

# 作業步驟
1. **確認資料範圍**
   - 以「上週」為準，先確認時間區間的定義。
   - 若系統沒有明確週起訖，採用最近完整的 7 天，並在結果中註明實際區間。
   - 只納入客訴信；若信件標題或內容不明確，先列入待判定清單。

2. **收集信件清單**
   - 逐封讀取上週收到的相關信件。
   - 為每封信記錄至少以下欄位：
     - 收件日期
     - 寄件者
     - 主旨
     - 主要問題描述
     - 是否為客訴
     - 初步分類
   - 若同一事件有多封往來信，視情況合併為同一案件，避免重複計數。

3. **建立分類規則**
   - 先從信件內容歸納出主要客訴類別。
   - 類別應以內容為準，不以寄件者或部門名稱為準。
   - 若類別過細，合併成可管理的上層分類；若類別過粗，拆分成能反映主要問題的子類。
   - 常見分類可包含但不限於：
     - 商品瑕疵
     - 配送延誤
     - 退款／退貨
     - 服務態度
     - 訂單／帳務問題
     - 系統／網站問題
     - 其他

4. **逐封標註分類**
   - 依每封信的主要訴求指定一個主分類。
   - 若一封信同時涉及多個問題，選擇最主要、最直接的客訴原因作為主分類，並可加註次要分類。
   - 對於無法判定的信件，標記為「待確認」並列出原因。

5. **統計彙總**
   - 計算每個分類的件數。
   - 計算各分類占全部客訴信的比例。
   - 如有需要，補充：
     - 最高頻分類
     - 重複出現的關鍵字或問題模式
     - 需要優先處理的案件

6. **輸出分類統計表**
   - 以表格呈現，至少包含以下欄位：
     - 分類
     - 件數
     - 占比
     - 代表性問題摘要
     - 備註
   - 若有待確認信件，另附一個「待確認」區塊，列出信件主旨與待判定原因。

7. **品質檢查**
   - 確認所有納入統計的信件都已分類。
   - 確認總件數與各分類加總一致。
   - 若有合併案件，說明合併原則，避免重複計數。

# 注意事項
- 不要把非客訴信混入統計。
- 不要因為主旨相似就直接歸類，必須以內容判定。
- 若資料不足以可靠分類，明確標示不確定性，不要硬分。
