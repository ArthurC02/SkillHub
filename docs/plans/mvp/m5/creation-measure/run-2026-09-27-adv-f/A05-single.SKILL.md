# 目的
監控三個競爭對手官網上的價格頁面，將目前價格與上次記錄比對；只要有變動，就整理可直接通知使用者的摘要。

# 先確認的資訊
在開始前，先確認並記錄以下內容：
1. 三家競爭對手的網站名稱與價格頁面網址。
2. 要追蹤的商品或方案名稱。
3. 價格欄位的定義：是否含稅、是否含運費、是否有會員價/促銷價/原價。
4. 比對規則：
   - 只比對標價，還是要比對折扣後價格。
   - 幣別是否一致，若不一致是否需要換算。
   - 是否忽略短期促銷標示，只看最終售價。
5. 通知方式與格式：例如簡訊、Email、聊天訊息，或僅輸出摘要供人工轉送。

如果缺少任一項，先提出需要補充的資訊，不要自行猜測。

# 執行流程
## 1. 建立基準
- 逐一打開三家官網的價格頁面。
- 找出每一家對應商品或方案的當前價格。
- 記錄以下欄位：
  - 來源網站
  - 商品/方案名稱
  - 價格數值
  - 幣別
  - 價格類型（原價、促銷價、會員價等）
  - 擷取時間
  - 頁面網址
- 若同一頁面有多個價格，依先前確認的比對規則選定唯一一個作為基準。

## 2. 比對歷史
- 讀取上次保存的價格記錄。
- 對每一家網站逐一比對：
  - 價格是否改變
  - 幣別是否改變
  - 價格類型是否改變
  - 商品/方案是否已下架或改版
- 若頁面結構改變導致無法可靠擷取，標記為「需人工確認」，不要硬判定為價格變動。

## 3. 判定變動
- 只要符合以下任一情況，就視為有變動：
  - 價格數值不同
  - 幣別不同且未設定自動換算
  - 原本追蹤的價格類型消失或被替換
  - 商品/方案下架或頁面無法找到對應項目
- 若只是文案、排序、版面改變，但價格未變，不算變動。

## 4. 產出通知內容
當有變動時，輸出一則可直接通知使用者的摘要，包含：
- 哪一家網站變動
- 變動前價格
- 變動後價格
- 變動幅度（若可計算）
- 變動時間
- 對應頁面連結
- 是否需要人工確認

範例格式：
- A 官網：原價 1,200 元 → 1,350 元（+150，+12.5%）
- B 官網：促銷價 899 元 → 799 元（-100，-11.1%）
- C 官網：頁面結構變更，無法確認價格，需人工確認

## 5. 無變動時
- 若三家都沒有變動，輸出簡短狀態：
  - 三家價格皆無變動
  - 最近檢查時間
  - 若有，附上上次記錄時間

# 記錄方式
- 為每一家網站保留一筆最新價格記錄與歷史變動紀錄。
- 每次檢查後更新記錄，保留足夠資訊以便下次比對。
- 若無法持久保存，至少在本次回覆中列出需要人工保存的欄位。

# 注意事項
- 不要把促銷倒數、庫存、運費提示誤判為價格變動。
- 不要在未確認規則前自行換算幣別或推測折扣後價格。
- 若網站需要登入、驗證碼、付費或其他無法由代理直接完成的步驟，明確說明無法自動完成，並請使用者提供可存取的公開頁面或授權資料。
- 若網站內容是動態載入，先嘗試從頁面可見內容或結構化資料中擷取；若仍不可靠，標記為需人工確認。
