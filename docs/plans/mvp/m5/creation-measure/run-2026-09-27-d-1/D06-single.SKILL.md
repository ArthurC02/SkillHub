# Daily 餐廳營業額結算 Skill

## 適用範圍
此 Skill 用來協助完成「每日餐廳日結」的工作流程：
1. 取得當日營業額資料。
2. 核對現金與信用卡明細是否一致。
3. 產出結算結果。
4. 在晚上 10 點前準備好要送到老闆 LINE 群組的內容。

## 重要限制
- 這個 Skill **不能自行登入任何系統、不能排程、不能直接發送 LINE 訊息**，除非執行環境另外提供了可用工具與授權。
- 若沒有可用的登入憑證、POS 後台存取權、或 LINE 發送管道，先停止並向使用者索取必要資訊。
- 若需要實際操作網站或系統，必須遵守該系統的使用規範與權限限制。

## 執行流程

### 1. 確認日結範圍
先確認以下資訊：
- 要結算的日期（通常是今天，依門店打烊時間判定）。
- POS 後台名稱與登入方式。
- 需要核對的欄位：
  - 總營業額
  - 現金金額
  - 信用卡金額
  - 其他付款方式（若有）
  - 退款或作廢金額（若有）
- LINE 群組的發送方式是否已建立好。

若日期跨日，依門店規則決定是以「營業日」還是「自然日」結算。

### 2. 取得 POS 日結資料
依 POS 後台提供的報表或頁面，擷取當日資料。優先順序如下：
1. 使用官方報表匯出功能。
2. 若無匯出功能，從日結頁面讀取數值。
3. 若資料分散在多頁，逐一收集後彙整。

至少要記錄：
- 日期
- 總營業額
- 現金收款
- 信用卡收款
- 其他收款
- 退款/折讓
- 應結金額或實收金額（若系統有提供）

### 3. 核對現金與信用卡明細
將 POS 資料與實際明細比對：
- 現金：
  - 應收現金 vs. 實際現金
  - 是否有找零、短溢收
- 信用卡：
  - POS 顯示金額 vs. 刷卡機或金流明細
  - 是否有未入帳、失敗交易、退款
- 其他付款方式：
  - 若有第三方支付、電子票券、外送平台，需分別核對

核對時遵循以下規則：
- 若金額一致，標記為「一致」。
- 若有差異，記錄差額與可能原因。
- 若無法判定原因，標記為「待人工確認」。

### 4. 產出結算結果
整理成簡潔、可直接傳送到 LINE 群組的格式，至少包含：
- 日期
- 總營業額
- 現金結算結果
- 信用卡結算結果
- 是否有差異
- 差異金額
- 備註或待確認事項

建議格式：
- 標題：`[日結] YYYY-MM-DD`
- 內容分行列出各項金額與核對結果
- 若有異常，先寫明異常，再寫建議處理方式

### 5. 發送前檢查
在準備送出前，先確認：
- 日期正確
- 金額格式一致（同一幣別、同一小數位規則）
- 沒有遺漏退款、作廢或其他付款方式
- 若有差異，已清楚標示

若資料不完整或有明顯錯誤，不要直接發送成正式結算；先要求補資料或人工確認。

### 6. 送到 LINE 群組
若執行環境有可用的 LINE 發送工具或已授權的整合：
- 使用既有管道發送結算結果。
- 只發送已核對完成的內容。
- 若發送失敗，記錄失敗原因並回報。

若沒有可用的發送工具：
- 產出一份可直接貼到 LINE 的最終訊息。
- 明確告知使用者需要人工貼送。

## 異常處理
遇到以下情況時，停止自動結算並回報：
- 無法登入 POS 後台
- 找不到當日報表
- 現金或信用卡明細缺失
- 金額差異過大且無法解釋
- LINE 發送權限不足或管道不可用

回報內容應包含：
- 發生問題的步驟
- 已取得的資料
- 缺少的資料
- 建議下一步

## 輸出標準
最終輸出應包含兩部分：
1. **核對摘要**：供內部確認。
2. **LINE 訊息草稿**：供直接發送給老闆群組。

若資料不足，輸出應改為「需要補充的資訊清單」，不要自行猜測金額。
