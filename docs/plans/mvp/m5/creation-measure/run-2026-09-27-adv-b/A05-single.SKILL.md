# 目的
監控三家競爭對手官網的公開價格資訊，偵測價格變動，並在有變動時產出可通知使用者的摘要。

# 適用範圍
- 只處理公開可存取的網頁內容。
- 不處理需要登入、驗證碼、付費牆、購買流程或其他需要即時人工操作的情況。
- 若價格資訊是動態載入、圖片化、或無法穩定抓取，先說明限制，並改以可行的人工檢查清單與比對欄位設計。

# 執行步驟
1. **確認監控對象**
   - 收集三家競爭對手的官網網址。
   - 對每一家確認要監控的具體價格頁面或商品頁面。
   - 若同一網站有多個價格欄位，明確指定要比對的欄位，例如：售價、原價、折扣價、方案月費、年費、運費。

2. **定義比對規則**
   - 記錄每個價格欄位的名稱、幣別、單位與顯示格式。
   - 決定是否要把稅金、運費、促銷碼、會員價納入比對。
   - 若頁面同時顯示多種方案，固定比對同一方案，避免誤判。

3. **建立基準值**
   - 先擷取每個目標頁面的當前價格作為基準。
   - 保存以下資訊：
     - 網站名稱
     - 頁面網址
     - 擷取時間
     - 價格欄位名稱
     - 原始顯示文字
     - 正規化後的價格值
   - 若頁面有多個商品或方案，逐一建立對應基準。

4. **後續比對**
   - 每次重新檢查時，擷取相同頁面與相同欄位。
   - 將新值與基準值或上一次記錄值比對。
   - 判定變動時，至少包含以下情況：
     - 價格上升
     - 價格下降
     - 幣別改變
     - 方案內容改變導致價格不可直接比較
   - 若頁面結構改版導致無法定位價格，標記為「需人工確認」，不要硬判定為價格變動。

5. **整理變動通知**
   - 若有任一網站價格變動，輸出清楚摘要：
     - 哪一家網站變動
     - 哪個頁面變動
     - 舊價格與新價格
     - 變動幅度與方向
     - 擷取時間
   - 若多家同時變動，分網站列出。
   - 若沒有變動，回報「本次未發現價格變動」。

6. **處理例外情況**
   - 若頁面無法存取、回傳錯誤、或內容疑似被反爬限制，記錄失敗原因。
   - 若價格以 JavaScript 動態載入且無法直接取得，改為記錄可見文字或請求使用者提供可監控的替代頁面。
   - 若價格顯示為區間、起價、或依地區/登入狀態不同，先確認要監控的固定條件。

# 通知內容格式
建議使用以下格式輸出：

- 監控時間：YYYY-MM-DD HH:MM
- 變動網站：網站名稱
- 頁面：URL
- 欄位：價格欄位名稱
- 舊值：...
- 新值：...
- 變動：上升 / 下降 / 幣別變更 / 方案變更
- 備註：如有必要，說明是否需人工確認

# 注意事項
- 只比對可公開取得的資訊，不推測未顯示的價格。
- 不要把促銷標語、刪除線文字、或非價格資訊誤判為正式售價，除非使用者明確要求。
- 若使用者未提供三家網站與目標頁面，先要求補齊這些資訊，再開始監控。
