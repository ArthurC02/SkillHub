# 目的
將「客服信箱上週收到的客訴信」整理成可讀的分類統計表，並保留可追溯的分類依據。

# 適用範圍
- 只處理已提供給你的郵件內容、匯出檔或郵件清單。
- 不假設可直接登入信箱、抓取郵件或存取外部系統；若缺少原始郵件資料，先請使用者提供。

# 作業步驟
1. **確認資料範圍**
   - 只納入「上週」收到的客訴信。
   - 若時間範圍不明，先向使用者確認上週的定義（例如依系統時區或自然週）。
   - 若資料中混有非客訴信，先排除。

2. **建立分類規則**
   - 先閱讀全部郵件，找出重複出現的主題。
   - 建議至少建立以下分類：
     - 商品/服務品質
     - 出貨/物流
     - 退款/退貨
     - 帳務/付款
     - 客服態度/溝通
     - 系統/網站/App 問題
     - 其他/未明確
   - 若郵件內容顯示更適合的分類，優先使用資料中的實際主題。
   - 一封信可只歸入一個主分類；若需要，也可加註次分類，但統計時以主分類為準。

3. **逐封標記**
   - 為每封信記錄：
     - 郵件編號或主旨
     - 收件日期
     - 客訴主題分類
     - 嚴重度（低/中/高，依內容判斷）
     - 是否已處理（若資料中有此資訊）
     - 備註（例如關鍵字、特殊情況）
   - 若內容不足以判斷分類，標記為「未明確」，並在備註說明原因。

4. **統計彙總**
   - 計算每個分類的：
     - 件數
     - 佔總數比例
     - 高嚴重度件數
     - 已處理件數（若可得）
   - 若資料足夠，可再加上：
     - 依日期分布
     - 依嚴重度分布
     - 常見關鍵字

5. **輸出分類統計表**
   - 先輸出總覽，再輸出明細。
   - 總覽表建議欄位：
     - 分類
     - 件數
     - 佔比
     - 高嚴重度
     - 已處理
   - 明細表建議欄位：
     - 編號/主旨
     - 日期
     - 分類
     - 嚴重度
     - 備註

6. **檢查一致性**
   - 確認所有上週客訴信都已被分類。
   - 確認總件數與明細筆數一致。
   - 若有重複信件、轉寄信或同一事件多封信，依使用者需求決定是否合併；若未指定，先保留為獨立信件並註明可能重複。

# 輸出格式
使用清楚的表格呈現，並在表格前加上一段簡短摘要，例如：
- 上週共收到 X 封客訴信
- 主要集中在 Y 類與 Z 類
- 高嚴重度案件共有 N 件

# 注意事項
- 不要臆測郵件內容；只能根據提供的資料分類。
- 若資料來源不完整，先列出缺少哪些欄位，再進行可行的統計。
- 若使用者希望匯出成 CSV、Excel 或其他格式，先確認可用的輸出方式，再依同樣欄位整理。
