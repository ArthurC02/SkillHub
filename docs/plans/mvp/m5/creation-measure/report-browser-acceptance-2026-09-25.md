# 互動創作：架構師代理瀏覽器驗收

## 證據範圍

使用者授權代理以架構師角度回答規則問題。這是本機真實模型、真實 API 與瀏覽器的功能驗證，不是獨立真人答問、易用性或採用率量測。沒有解除生成入口曝光與正式隔離部署的邊界。

環境為 Windows 淨測試模式、PGlite、記憶體物件儲存、無隔離 Provider；模型呼叫經既有 LiteLLM 閘道。只放行逐字審查的純文字 CSV Skill 版本，沒有 Script、附件或要求外連的內容。前端另建到 scratchpad，透過 9190 的 preview 代理 9090 API，避免重建覆寫仍在執行的 API 所快取之資產。

會話：`950ab85b-ecfa-4f6a-9385-92aa791223fd`。Skill：`7c90c706-2349-42d9-8843-33fc4b3f978f`。這些識別碼屬於一次性測試環境，不是部署後可回訪的永久證據網址。

## 架構師決定

- 缺值保留並標示，不補零、不納入總額與排名。
- 同名品項有效金額先加總；並列最高全部列出。
- 固定繁體中文條列：總列數、有效列數、缺值列數、受影響品項、總額、最高品項及金額。
- 全缺值時有效列數是 `0（無有效數字）`，總額與最高品項是「無法計算」。計數的零與捏造金額的零不是同一概念。
- 引文無法回驗不等於業務規則失敗，不為了得到綠燈放寬規則或覆寫原始評估。

## 創作迴圈與內容審查

瀏覽器走過答問、需求差異確認、草稿、候選、權限確認、Run、評估與帶回會話。時間線正確呈現第一輪的部分達成、完整定向問題、代理回答與模型建議；第二輪結果另起一個「達成」回合，沒有挪用第一輪的回答。

最終以瀏覽器確認保存；API 回讀為 revision 48、`saved`，16 步，會話花費 299 點、保留額 0、`usage_unknown=false`。保存的候選仍連結第二輪 Run 與同一版本，正文 hash 為 `9d2f39d6845854fef6555565a09268fff38c04519dd10407d9960cdf28f6a418`，通過後未再改稿。會話點數不包含另列的 Run／Judge 費用。

模型產出仍有內容品質限制：曾漏掉總額驗收條件、把確認句放進 sample_input、在已按確認後再次要求確認，以及宣稱修改完成但正文仍保留矛盾欄位。代理逐次要求修訂並核對實際結構與正文；最後實測的版本已去除重複欄位及零值歧義。這不是無人介入的一輪成功率證據，也不能證明其他資料情境普遍正確。

## 實測抓到並修正的程式缺陷

API 的無附件草稿回傳 `files: null`，前端直接 `.map` 導致整頁崩潰。修正 `5d3837b41396bcda45a05d2c589cd64ba554c8ca` 讓目前與上一份草稿均可顯示空附件；同一場會話無需重建即可恢復。

兩個參數案例分別將目前／上一份草稿設為 null，確認兩份正文與另一份有效附件仍顯示。去掉 optional chaining 時兩案都以 null `.map` 失敗；還原後創作區 128 項、全前端 671 項通過，均無跳過。Typecheck、Prettier、comment-lint、生成一致性與 automation-check 通過；lint exit 0，仍有既有警告，並非零警告。此次未修上游序列化契約。

本機 doctor 的 Node 版本不符仍存在；本機成功不替代遠端 CI。遠端狀態須以完整 SHA 查詢所有 workflow run，不以此報告推定綠燈。
