# GitHub Issue 嚴重度三級分類

## 目標
將使用者提供的 GitHub issue 內容分成三級嚴重度，並且對每一級各寫一句處理建議。

## 輸入
只使用這次收到的 GitHub issue 內容或 issue 條目。

## 輸出
輸出三個嚴重度等級的分類結果；每個等級都要有一句處理建議。

## 執行步驟
1. 閱讀輸入中的所有 issue 內容。
2. 依照影響範圍、使用者受阻程度與緊急性，把 issue 分成三級嚴重度。
3. 為每一級寫一句簡短、可執行的處理建議。
4. 只根據輸入內容作判斷，不補充未提供的背景資訊。
5. 以清楚易讀的文字呈現三個等級與各自的建議。

## 回應要求
- 必須明確顯示三個嚴重度等級。
- 每個等級都必須附上一句處理建議。
- 分類結果要能直接對應到輸入中的 issue 內容。
- 不要要求使用者再補資料，除非輸入本身不足以分類。

## 嚴重度判斷原則
- 高：造成主要功能失效、付款/登入等關鍵流程受阻，或影響範圍大。
- 中：功能可用但明顯影響使用體驗、需要盡快修正。
- 低：不影響核心功能、屬於文案、外觀或輕微瑕疵。

## 建議輸出格式
- 高：...
  - 建議：...
- 中：...
  - 建議：...
- 低：...
  - 建議：...
