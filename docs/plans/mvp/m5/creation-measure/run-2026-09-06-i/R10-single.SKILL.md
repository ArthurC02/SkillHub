## 目的
每週從三個 Slack 頻道中找出「尚未回覆的問題」，整理成可直接貼出的清單，並附上每則訊息的連結。

## 適用時機
- 使用者要你做每週 Slack 問題盤點
- 需要從三個頻道中找出沒人回覆的提問
- 需要輸出成清單並保留原始訊息連結

## 先確認的資訊
如果輸入沒有明確提供，先向使用者確認：
1. 三個 Slack 頻道名稱或連結
2. 統計的週期範圍，例如「上週一到週日」或「最近 7 天」
3. 什麼算「問題」：
   - 只有問號的訊息
   - 以提問語氣開頭的訊息
   - 含有求助、請問、how/what/why 等字樣的訊息
4. 什麼算「未回覆」：
   - 完全沒有回應
   - 只有表情符號不算回覆
   - 作者自己的補充訊息不算回覆

## 判定規則
1. 只看指定的三個頻道與指定週期內的訊息。
2. 找出看起來是在提問、求助或請求確認的訊息。
3. 對每則問題檢查後續串列：
   - 若沒有任何其他人的文字回覆，視為未回覆。
   - 若只有 emoji、反應、或作者自己續貼，仍視為未回覆。
   - 若有人用文字回應，視為已回覆，不列入。
4. 若同一則問題被多次轉貼或引用，只保留原始提問那一則。
5. 若訊息內容不明確是否為問題，保守處理：只有在明顯是提問時才列入。

## 整理步驟
1. 逐一檢視三個頻道在指定週期內的訊息。
2. 標記所有疑似問題訊息。
3. 逐則查看 thread 或後續回應，判斷是否有人回覆。
4. 篩出未回覆者。
5. 依頻道分組，或依時間由新到舊排序；若使用者未指定，預設依時間由新到舊。
6. 每則都附上可點擊的 Slack 訊息連結。

## 輸出格式
使用以下格式輸出，保持簡潔一致：

### #頻道名稱
- [訊息摘要](連結) — 發言者，日期時間
- [訊息摘要](連結) — 發言者，日期時間

### #另一個頻道名稱
- [訊息摘要](連結) — 發言者，日期時間

## 訊息摘要寫法
- 以一句話概括問題內容，不要長篇複製原文。
- 保留關鍵詞，讓人一眼知道在問什麼。
- 若原文很短，可直接用原文作摘要。

## 注意事項
- 不要把已經有人回覆的問題列進去。
- 不要把純公告、閒聊、感謝、表情反應當成問題。
- 如果無法取得某則訊息的連結或 thread 資訊，先列出可確認的部分，並註明缺少連結資訊。
- 若資料不足以判斷是否未回覆，應明確標示「待確認」，不要自行猜測。
