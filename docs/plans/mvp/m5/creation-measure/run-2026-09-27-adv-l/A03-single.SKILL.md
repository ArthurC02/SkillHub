# 目的
將「上週收到的客訴信」整理成可讀的分類統計表，並保留可追溯的分類依據。

# 適用情境
- 需要把客服信箱中的客訴郵件做分類統計。
- 需要輸出每一類的件數、占比、代表案例或摘要。
- 需要先從郵件內容中抽取資訊，再彙整成表格。

# 作業流程

## 1. 確認資料範圍
- 只處理「上週」收到的信件。
- 若「上週」的定義不明，先依目前日期往前推 7 天到 13 天前的完整自然週，並在結果中註明採用的日期區間。
- 只納入「客訴」相關信件；若信件內容無法判定是否為客訴，先列入「待確認」類別，不要自行忽略。

## 2. 收集每封信的基本欄位
對每封符合範圍的信件，至少記錄：
- 收件日期
- 寄件者
- 主旨
- 主要抱怨內容
- 涉及產品／服務／流程
- 是否重複來信
- 是否已處理／是否需要跟進

## 3. 建立分類規則
先依內容建立一致的分類標準。若沒有既定分類，使用以下常見類別作為起點，並依實際信件內容調整：
- 產品瑕疵／故障
- 配送延誤／物流問題
- 退款／退貨問題
- 服務態度／客服回應
- 訂單錯誤／出貨錯誤
- 帳務／付款問題
- 系統／網站／App 問題
- 其他
- 待確認

分類時遵守：
- 一封信只歸入一個主類別；若內容明顯跨類別，選最主要的抱怨點，並在備註中標示次要類別。
- 同一封信若包含多個問題，優先以造成客訴的直接原因分類。
- 若內容不足以判斷，歸入「待確認」。

## 4. 逐封判定與標記
- 逐封閱讀信件內容，依分類規則標記主類別。
- 對每封信寫下 1 句簡短分類理由，方便日後回查。
- 若有重複主題的多封信，保留可辨識的共同特徵，但不要合併成單一案件，除非使用者明確要求合併。

## 5. 統計彙總
完成標記後，計算每個類別：
- 件數
- 占全部客訴信的比例
- 代表性摘要（1 句）

如有需要，也可加上：
- 最高頻主題
- 重複來信件數
- 待確認件數
- 需要優先處理的類別

## 6. 輸出表格
輸出一份清楚的分類統計表，建議欄位如下：
- 類別
- 件數
- 占比
- 代表性問題摘要
- 備註／處理建議

若需要更完整，可再附一張明細表：
- 日期
- 寄件者
- 主旨
- 類別
- 分類理由
- 是否需跟進

## 7. 品質檢查
在交付前檢查：
- 是否只包含上週信件
- 是否每封客訴信都有歸類
- 件數加總是否等於總客訴數
- 占比是否以同一總數計算
- 「待確認」是否已單獨列出

# 輸出格式建議
先給摘要，再給表格。

範例結構：
1. 統計摘要
2. 分類統計表
3. 明細表（如需要）
4. 備註與待確認事項

# 注意事項
- 不要憑空補寫信件內容；只能根據實際郵件內容分類。
- 若資料來源不完整，明確標示限制。
- 若無法存取客服信箱或郵件內容，應先請使用者提供匯出的郵件清單或原始信件內容，再進行整理。
