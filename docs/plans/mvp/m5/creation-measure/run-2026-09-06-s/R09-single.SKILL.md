## 目的
將使用者提供的履歷內容重寫為「資料分析職缺」導向的版本，並控制在一頁以內。重點是保留真實經歷，重新排序與改寫成更符合資料分析職務的表述。

## 使用時機
在使用者要求：
- 把履歷改成資料分析、數據分析、商業分析、BI、產品分析等職缺版本
- 壓縮成一頁內
- 強調分析能力、工具能力、專案成果、商業影響

## 工作流程
1. **先確認輸入是否足夠**
   - 需要至少有原始履歷內容。
   - 若缺少關鍵資訊，先向使用者索取：
     - 原始履歷全文
     - 目標職缺名稱或職缺描述（若有）
     - 希望使用的語言（中文、英文或雙語）
     - 是否要保留特定經歷或刪除某些內容

2. **抽取可轉換成資料分析語言的內容**
   - 找出與以下主題相關的經歷：
     - 數據整理、報表、儀表板、分析、A/B test、SQL、Python、Excel、Tableau、Power BI、統計、預測、資料清理、流程優化、商業決策支援
   - 將一般職務描述轉成分析導向表述，例如：
     - 「整理資料」→「清理並整合多來源資料，提升報表一致性」
     - 「協助主管」→「提供數據洞察以支援決策」
     - 「製作報表」→「建立週/月報表並追蹤核心指標變化」
   - 保留真實成果，優先量化：
     - 百分比、金額、時間節省、錯誤率下降、效率提升、轉換率改善、覆蓋規模

3. **重寫履歷結構**
   依下列順序輸出，讓內容更像資料分析職缺履歷：
   - 姓名與聯絡資訊
   - 專業摘要（2–3 行）
   - 核心技能
   - 工作經歷
   - 專案經歷或作品集（若原履歷有）
   - 學歷
   - 證照／其他（若與職缺相關）

4. **專業摘要寫法**
   - 用 2–3 行概括：
     - 年資或背景
     - 主要分析工具與方法
     - 能帶來的商業價值
   - 例如方向：
     - 「具 X 年資料分析／營運分析經驗，熟悉 SQL、Python 與資料視覺化，能將複雜資料轉化為可執行洞察，支援產品與營運決策。」
   - 若使用者沒有明確工具經驗，不要硬加；改寫成其實際具備的能力。

5. **核心技能整理**
   - 只列與資料分析職缺高度相關的技能。
   - 建議分類：
     - 資料處理：SQL、Excel、Python、R
     - 視覺化：Tableau、Power BI、Looker
     - 分析方法：統計分析、A/B test、回歸、分群
     - 商業能力：需求分析、指標設計、報表自動化、跨部門溝通
   - 若原履歷沒有明確證據，不要新增不存在的技能。

6. **工作經歷改寫原則**
   - 每段經歷用 3–5 個條列。
   - 每個條列盡量採用「動詞 + 方法 + 結果」格式。
   - 優先呈現：
     - 分析了什麼
     - 用了什麼工具或方法
     - 產生什麼影響
   - 若原文偏行政、營運、業務、行銷，也要轉成分析角度，但不得捏造。
   - 若缺少數字，可保留質化成果，但避免空泛形容詞。

7. **一頁內控制**
   - 內容要精簡，避免冗長敘述。
   - 刪除與資料分析無關或弱相關內容。
   - 優先保留：
     - 最近且最相關的經歷
     - 可量化成果
     - 與職缺關鍵字一致的技能
   - 若原履歷過長，主動濃縮而不是完整重排。

8. **輸出格式**
   - 直接輸出改寫後的履歷內容。
   - 不要加解釋、不要評論改寫策略、不要列出修改前後對照。
   - 使用清楚的標題與條列。
   - 若使用者要求中文履歷，請以繁體中文輸出。

## 品質檢查
在輸出前確認：
- 是否聚焦資料分析職缺
- 是否保留真實資訊，沒有憑空新增技能或經歷
- 是否盡量量化成果
- 是否足夠精簡，適合一頁內
- 是否語氣專業、簡潔、可直接投遞

## 若資訊不足
如果使用者只說要改寫，但沒有提供履歷內容，請先請他貼上履歷全文；若有職缺描述，也一併請他提供，以便更精準對齊關鍵字。
