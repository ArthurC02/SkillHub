## 目的

每週從三個 Slack 頻道中找出「未回覆的問題」，整理成一份可直接追蹤的清單，並附上每則訊息的連結。

## 適用範圍

- 只處理使用者指定的三個 Slack 頻道。
- 只列出看起來是「問題／請求／需要協助」且尚未出現回覆的訊息。
- 若無法確認是否已回覆，應標記為「待確認」，不要自行假設。

## 作業步驟

1. 先確認本週的時間範圍。
   - 以最近 7 天為預設週期，除非使用者另有指定。
   - 若需要更精準的週報區間，依使用者提供的週起訖日處理。

2. 取得三個目標頻道的訊息。
   - 逐一檢視每個頻道在時間範圍內的貼文。
   - 優先找出包含問句、求助、請求確認、請求決策、請求操作的訊息。

3. 判斷哪些是「未回覆的問題」。
   - 視為已回覆：同一串討論中出現明確回應、解答、指示、確認或處理結果。
   - 視為未回覆：原始提問後沒有任何實質回應。
   - 若只有表情符號、已讀、或無關短句，仍視為未回覆，除非內容明確表示已處理。
   - 若串內回覆內容不清楚，標記為「待確認」。

4. 去重與整理。
   - 同一問題若被轉貼到多個頻道，只保留最早或最完整的一則，並在備註中說明重複來源。
   - 若同一人連續發出多則相近問題，分開列出，除非明顯是同一件事的延續。

5. 為每則項目附上連結。
   - 使用該訊息的可點擊連結。
   - 若只能取得頻道與時間資訊，至少保留頻道名稱與訊息時間，並註明連結不可取得。

## 輸出格式

輸出一份清單，依頻道分組或依時間排序皆可，但必須清楚易掃描。每筆至少包含：

- 頻道名稱
- 發問者
- 發問內容摘要
- 發問時間
- 狀態：未回覆 / 待確認
- 連結

### 建議格式

- `#channel-name｜@user｜問題摘要｜2026-09-06 10:23｜未回覆｜link`

## 注意事項

- 不要把一般公告、閒聊、純資訊分享列入。
- 不要把已經有明確答案的串列入。
- 不要編造回覆內容或連結。
- 若三個頻道都沒有符合條件的問題，輸出「本週無未回覆問題」。
- 若資料不足以判斷，明確寫出缺少哪些資訊。
