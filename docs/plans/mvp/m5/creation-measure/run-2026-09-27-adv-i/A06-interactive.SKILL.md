# Self-Introduction Writing Skill

## What this skill does
Turn the facts the user provides into a ready-to-use self-introduction. Use it when the user asks for an introduction for an interview, application, networking, class, video, profile, or other stated situation.

## How to work
1. Read the user’s request and the facts they provide.
2. Identify the target situation, language, tone, style, and length if any are given.
3. Write the self-introduction directly from the provided facts.
4. Keep the user’s facts intact and do not add invented details.
5. If the user gives more than one relevant fact, integrate all of the explicit facts that fit the request.
6. Deliver the finished self-introduction itself in the output.

## Required rules
- when the input makes two requirements impossible to meet together (a length limit and 'keep everything'), keep the hard limit and say in one line what you left out — never drop it silently;
- never invent a fact the input does not give — no name, date, figure or event — and write 'not given' only for such a missing fact;
- when a setting the work needs is missing (a working-day length, a tone, a format), use the common default, say which one you used, and finish the work rather than stopping;
- you cannot send, post, schedule, monitor or fetch anything, so when the request asks for that, deliver the content ready to use and say plainly that sending or scheduling is left to the person;
- deliver the finished artifact itself in the output — never a description of the rules, a plan, or a request for access.

## Output behavior
- Match the requested language if one is given.
- Match the requested tone or style if one is given.
- Match the requested length as closely as possible if one is given.
- If the user asks for a self-introduction for a specific situation, make that situation clear in the opening or framing sentence.
- If the user provides a title, role, or target job, align the wording to that target.
- If the user provides no usable facts at all, say that the needed facts are not given and ask for them once.

## What to avoid
- Do not add achievements, employers, schools, dates, titles, or skills that the user did not provide.
- Do not explain your process unless the user asks for an explanation.
- Do not return a template with blanks when enough facts are available to write the introduction.
- Do not invent context beyond the user’s request.
