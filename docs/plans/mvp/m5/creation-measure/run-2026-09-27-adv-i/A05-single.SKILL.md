# 目的
建立一個可重複執行的競品價格追蹤流程：先確認三家競爭對手、對應商品頁與基準價格，再定期比對最新價格；一旦發現變動，就輸出可直接通知的摘要。

# 先決條件
- 你必須先取得三家競爭對手的官網商品頁網址。
- 你必須先取得每個商品要追蹤的識別方式：商品名稱、規格、幣別、是否含稅/運費。
- 若沒有可用的網頁存取工具、排程工具或通知工具，這個技能只能協助你整理監測規格與通知內容，不能自行完成即時監測或發送通知。

# 流程
## 1. 建立追蹤清單
對每一家競爭對手，記錄以下欄位：
- 競爭對手名稱
- 商品名稱
- 商品頁 URL
- 追蹤規格/型號
- 幣別
- 基準價格
- 基準日期時間
- 價格來源位置（例如頁面主價格、促銷價、會員價）
- 備註（例如是否需登入、是否顯示稅金、是否有多規格切換）

## 2. 定義比對規則
在開始監測前，先固定以下規則：
- 只比對同一商品頁、同一規格、同一幣別。
- 若頁面同時顯示多種價格，優先使用你事先指定的價格來源位置。
- 若頁面無法直接讀取價格，記錄為「無法判定」，不要猜測。
- 若價格格式包含千分位、折扣、區間價或促銷標示，先轉成可比較的數值，再比對。

## 3. 定期檢查
每次檢查時，對每個商品頁執行：
1. 開啟商品頁。
2. 找到與基準一致的規格與價格來源。
3. 擷取目前價格與時間戳。
4. 與基準價格比較。
5. 記錄結果：
   - 無變動
   - 漲價
   - 降價
   - 無法判定

## 4. 判定是否需要通知
只要符合以下任一條件，就視為需要通知：
- 目前價格與基準價格不同。
- 同一商品頁出現新的促銷價、會員價或折扣後價格，且你事先定義它應納入比對。
- 商品頁無法讀取價格，且這種狀況是新發生的。

若只是頁面文案、排序、圖片或非價格資訊變動，不通知。

## 5. 產出通知內容
當有變動時，整理成以下格式：
- 競爭對手：
- 商品：
- 規格：
- 舊價格：
- 新價格：
- 變動幅度：
- 變動方向：
- 檢查時間：
- 商品頁：
- 備註：

若同一輪有多筆變動，合併成一則摘要，依價格變動幅度由大到小排序。

## 6. 保留歷史紀錄
每次檢查都要保存：
- 檢查時間
- 目前價格
- 與前次價格的差異
- 是否通知
- 備註

歷史紀錄可用來判斷是否為短暫促銷、是否反覆波動，以及是否需要調整基準價格。

# 異常處理
- 若頁面需要登入、驗證碼、地區限制或其他無法由目前工具處理的限制，停止自動判定，改為回報「需要人工確認」。
- 若價格顯示為區間、起價或依規格變動，必須先確認追蹤的是哪一個具體規格。
- 若同一商品頁有多個幣別或地區版本，必須固定單一版本後再追蹤。

# 建議的執行節奏
- 若價格波動頻繁：每天檢查一次。
- 若價格波動較少：每週檢查一次。
- 若有促銷檔期：提高檢查頻率。

# 你可以直接輸出的結果
當你完成一次檢查後，輸出其中一種結果：
- 「無變動」：三家皆與基準一致。
- 「有變動」：列出所有變動項目與通知摘要。
- 「需要人工確認」：遇到無法自動判定的限制。
