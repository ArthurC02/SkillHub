# Daily 餐廳營業額結算

## 適用情境
當任務是「每天打烊後結算當日營業額、核對現金與信用卡明細、並在指定時間通知老闆」時使用。

## 先決條件
- 必須已經有合法授權可登入 POS 後台。
- 必須已經有可用的營業額報表來源、現金明細、信用卡明細。
- 若要在晚上 10 點自動發送，必須有可用的排程環境與 LINE 群組發送權限。
- 若上述任一條件不存在，不能假裝完成；只能整理出需要人工執行的步驟、需要的資料，以及可直接貼上的通知內容。

## 執行流程

### 1. 取得當日結算資料
1. 以授權帳號登入 POS 後台。
2. 進入當日營業額或日結報表頁面。
3. 擷取以下資料：
   - 日期
   - 總營業額
   - 現金收入
   - 信用卡收入
   - 其他付款方式（若有）
   - 退款、折讓、作廢金額（若有）
4. 若系統可匯出報表，優先使用匯出結果；若只能畫面查看，則逐項抄錄。

### 2. 核對現金與信用卡明細
1. 取得當日現金實收金額。
2. 取得當日信用卡請款或刷卡明細。
3. 依下列邏輯核對：
   - 現金明細是否等於報表中的現金收入。
   - 信用卡明細是否等於報表中的信用卡收入。
   - 若有其他付款方式，也逐項核對。
4. 若有差異，記錄：
   - 差異項目
   - 差異金額
   - 可能原因（例如找零、退款未入帳、刷卡未結帳、人工輸入錯誤）
5. 若無法判定原因，標記為「待人工確認」。

### 3. 產出結算結果
結算結果至少包含：
- 日期
- 總營業額
- 現金金額
- 信用卡金額
- 其他付款金額（如有）
- 核對結果：一致 / 不一致
- 差異明細（如有）
- 備註

### 4. 準備 LINE 群組通知內容
1. 將結算結果整理成簡短、清楚、可直接貼到 LINE 的格式。
2. 若核對一致，訊息應明確寫出「已核對完成」與金額摘要。
3. 若核對不一致，訊息應明確寫出差異與待確認事項。
4. 不要在訊息中加入未核實的推測。

### 5. 晚上 10 點發送
- 若環境支援排程與 LINE 發送：
  1. 設定在晚上 10 點執行通知。
  2. 執行前再次確認當日資料已完成核對。
  3. 發送到指定老闆 LINE 群組。
- 若環境不支援自動發送：
  1. 在晚上 10 點前準備好訊息。
  2. 提醒使用者手動貼到 LINE 群組。

## 異常處理
- 無法登入 POS：停止，回報登入失敗原因，請求有效帳號或權限。
- 報表缺失：停止，列出缺少的報表名稱與日期。
- 金額不一致：不要自動修正，先列出差異並標記待確認。
- 無法發送 LINE：保留完整通知內容，改為人工發送。

## 建議輸出格式
```text
日期：YYYY-MM-DD
總營業額：
現金：
信用卡：
其他：
核對結果：一致 / 不一致
差異：
備註：
```

## 建議 LINE 訊息格式
```text
[日結完成] YYYY-MM-DD
總營業額：
現金：
信用卡：
其他：
核對結果：一致 / 不一致
差異：
```

## 注意事項
- 只使用已取得授權的系統與資料。
- 不要編造金額。
- 不要在未核對完成前發送「已完成」訊息。
- 若流程需要登入、排程或外部傳送權限而目前不可用，應明確說明限制並提供人工替代步驟。
