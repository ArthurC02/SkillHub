## 目的

從 Slack 的三個指定頻道中，找出「未回覆的問題」，整理成一份可直接分享的清單，並附上每則訊息的連結。

## 適用情境

- 每週例行整理待跟進事項
- 需要從三個 Slack 頻道中篩出尚未被回覆的提問
- 需要把結果交給團隊做後續處理

## 作業步驟

1. **確認範圍**
   - 先確認這次要檢查的三個 Slack 頻道名稱。
   - 如果頻道名稱未提供，先向使用者索取，不能自行猜測。
   - 確認時間範圍是「最近一週」或使用者指定的週期；若未指定，預設以最近 7 天為準。

2. **收集訊息**
   - 逐一查看三個頻道在時間範圍內的訊息。
   - 只保留看起來是「問題」或「需要回覆」的訊息，例如：
     - 含有疑問句
     - 明確請求協助、確認、決策、排程、修正
     - 以「有人知道…」「請問…」「可以幫忙…」等方式提出
   - 排除以下內容：
     - 已經明顯得到回覆的串
     - 純公告、閒聊、轉貼、無需回覆的訊息
     - 自問自答且已完成處理的訊息

3. **判定是否未回覆**
   - 對每則候選問題檢查串內回覆。
   - 若串中有任何實質回應，通常不列入「未回覆」；除非回覆只是表情、確認收到、或未解決問題。
   - 若原訊息後面有人接續回答了問題，視為已回覆，不列入。
   - 若只有提問者自己補充但沒有真正答案，仍視為未回覆。
   - 若無法判定是否已回覆，優先保守處理：先列入「待確認」，不要直接當成已回覆。

4. **整理清單**
   - 每筆結果至少包含：
     - 頻道名稱
     - 發問者
     - 訊息摘要
     - 訊息連結
     - 狀態標記（例如：未回覆 / 待確認）
   - 摘要要短，保留問題核心，不要長篇複製原文。
   - 連結必須指向原始 Slack 訊息。

5. **排序原則**
   - 先依頻道分組，或依時間由新到舊排序；若使用者沒有指定，採用「時間由新到舊」。
   - 同一頻道內，較新的問題排前面。

6. **輸出格式**
   - 用條列清單輸出。
   - 每筆一行，格式建議如下：
     - `- [頻道名] 發問者：問題摘要｜未回覆｜連結`
   - 若有待確認項目，標示為 `待確認`，不要混寫成已確認未回覆。
   - 若結果很多，可先列出最重要或最早需要處理的項目。

## 品質檢查

- 確認每一筆都真的來自指定的三個頻道。
- 確認每一筆都在指定時間範圍內。
- 確認每一筆都附有可點擊的原始訊息連結。
- 確認沒有把已回覆的問題誤列為未回覆。

## 注意事項

- 這個技能只負責整理與篩選，不負責實際回覆 Slack 訊息。
- 如果沒有 Slack 存取權、沒有頻道名稱、或沒有可用的訊息資料，應明確說明無法完成，並列出還需要哪些資訊。
