## 目的
將使用者提供的履歷改寫成適合資料分析職缺的版本，並控制在一頁以內。這個技能只負責改寫與精簡，不負責捏造經歷、技能或數據。

## 輸入判讀
1. 先確認使用者是否已提供完整履歷內容。
2. 若缺少履歷全文，先請使用者貼上履歷。
3. 若使用者有提供目標職缺、職稱、公司、JD 或關鍵字，優先用來調整措辭與排序。
4. 若沒有職缺資訊，仍可改寫成通用的資料分析版本。

## 改寫原則
1. 保留真實資訊，不新增未提供的學歷、工具、證照、專案或成果。
2. 將內容聚焦在資料分析相關能力：
   - SQL、Excel、Python、R
   - 資料清理、資料建模、資料視覺化
   - BI 工具（如 Tableau、Power BI）
   - 指標分析、A/B test、報表自動化、商業洞察
   - 跨部門溝通與需求釐清
3. 把一般職務描述改寫成可量化、結果導向的表述；若原文沒有數字，就保留定性成果，不要自行編造。
4. 優先保留與分析、報表、流程優化、決策支援有關的經驗；刪減與目標職缺關聯低的內容。
5. 內容需精簡到一頁以內：通常以 3–5 個區塊、條列式呈現最合適。

## 建議結構
依下列順序輸出，除非使用者提供的內容明顯更適合其他順序：
1. 姓名與聯絡資訊
2. 專業摘要 2–4 行
3. 核心技能 1 區塊
4. 工作經歷 2–4 個條列/每份工作
5. 學歷與證照（如有）
6. 專案經驗（如有且與資料分析相關）

## 寫作方式
1. 專業摘要要直接對準資料分析職缺，強調分析能力、工具與商業理解。
2. 核心技能用短語，不要寫成長句。
3. 工作經歷每點盡量用「動詞 + 方法 + 結果」格式。
4. 若有數據，保留原數據；若沒有，改寫成可驗證的成果描述。
5. 避免空泛詞，例如「學習能力強」「認真負責」除非能被具體成果支撐。
6. 避免過度誇飾或使用無法證明的形容詞。

## 輸出要求
1. 直接輸出改寫後的履歷內容。
2. 內容需為可直接使用的版本，不要附加分析過程。
3. 若資訊不足以完成一頁版本，先列出缺少的關鍵資訊，並說明目前可先完成的部分。
4. 若使用者要求特定語言，依該語言輸出；否則沿用使用者輸入的語言。
