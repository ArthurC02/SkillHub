# 民宿訂房取消退款試算

依使用者提供的訂房資料，逐筆計算取消距入住的日曆天數及退款金額；不查網路，也不套用未提供的退款規則。

## 步驟

1. 讀取使用者訊息中的每筆訂房資料。保留識別碼、日期、金額及方案的原始內容；資料可為表格、文字或其他清楚可辨的格式。多筆資料分開處理，不把不同訂房的欄位混在一起。
2. 每筆資料需要入住日期、取消日期、房費總額及方案。方案只接受「標準方案」或「不可退款方案」。識別碼是選填資料，不因缺少識別碼而停止試算。
3. 若同一筆資料對同一欄位有互相矛盾的值（包括後文改動前文數值），不要自行選一個；標明衝突的欄位和值，請提出請求的人確認。只略過依賴該欄位的計算，其餘不受影響的資料仍繼續處理。不要就未衝突的內容追問。
4. 將資料整理成 `records.json`，內容為 JSON 陣列；每筆使用 `id`、`check_in`、`cancellation`、`amount`、`plan` 欄位。照錄已提供的事實，不要補造值。缺少的欄位留空字串 `""`；識別碼未提供時可省略。確保 JSON 字串中的引號與特殊字元已正確逸出。
5. 從本 SKILL.md 所在目錄執行：

   `python scripts/refund.py --input records.json`

6. 逐筆呈現腳本結果中的識別碼、方案、日曆天數及退款金額。將缺少的值標為「未提供」；若某項結果因必要資料缺少而無法求得，也明確標為「未提供」，並附上可直接補填的欄位模板。有效資料的結果照常列出，不因另一筆資料有缺漏或錯誤而隱去。
7. 腳本回報無法使用的值時，原樣指出每個值及其欄位，請提出請求的人確認；不要用該值計算，也不要提供依賴該值的結果。無效日期、無法解析或負數房費、及不支援的方案都屬此類。除明確有衝突或無效值外，不提出問題。
8. 依結果列出可直接使用的試算內容。沒有提供識別碼、標籤或其他非必要資料，不得阻止計算或輸出。

## 計算規則

- 日曆天數＝入住日期減取消日期，以兩日期間的日曆日計算。
- 「不可退款方案」一律退款 0，優先於天數規則。
- 「標準方案」：日曆天數至少 7 天，全額退款；3 至 6 天退款 50%；至多 2 天退款 0。
- 50% 金額若有小數，以四捨五入至小數點後兩位；金額沿用輸入單位。不推定其他費用或規則。
- 欄位缺漏時，將可由其他已知欄位獨立決定的結果照常算出；不得將未提供欄位當成已知值。完整輸入格式及輸出欄位見 `scripts/refund.py` 的使用方式與結果。
