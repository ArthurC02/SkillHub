# 每週業績自動寄送與 Slack 公告

## 適用情境
當需求是「每週固定時間把本週業績數字發給整個部門，並同步在 Slack 公告」時使用。

## 先確認這件事能不能直接執行
這類任務通常需要：
- 可存取的業績來源（例如試算表、資料庫、BI 報表、CRM 匯出檔）
- 可發信的郵件系統權限
- 可發 Slack 訊息的工作區權限
- 排程能力（例如 cron、工作流程平台、雲端排程器）

如果目前沒有這些存取權限或登入資訊，不能直接完成自動化；改為先整理需求與所需資訊，並請使用者提供權限或指定可用工具。

## 執行步驟
1. **確認報表定義**
   - 釐清「本週」的時間範圍：通常是週一 00:00 到週五 23:59，或依公司時區定義。
   - 釐清要寄出的業績數字：例如營收、訂單數、成交數、達成率、與上週比較、與目標比較。
   - 釐清收件人範圍：全部門的郵件群組、Slack 頻道名稱、是否需要抄送主管。

2. **確認資料來源與計算方式**
   - 找出唯一可信來源。
   - 確認是否需要手動匯出、API 讀取，或從固定檔案讀取。
   - 明確定義計算規則：
     - 是否排除退款、取消單、測試資料
     - 是否以建立時間、成交時間或入帳時間計算
     - 是否需要四捨五入與幣別格式

3. **定義輸出內容**
   - 郵件主旨建議包含週期與主題，例如：`[每週業績] 2026-09-21 至 2026-09-25`
   - 郵件內文至少包含：
     - 本週總結
     - 主要指標
     - 與上週或目標的比較
     - 必要的備註或異常說明
   - Slack 公告內容應簡潔，保留最重要的數字與連結。

4. **建立排程邏輯**
   - 設定每週五下午執行。
   - 若公司有固定時區，使用該時區排程。
   - 若執行時間遇到假日或非工作日，先確認是否仍要照常發送。

5. **建立發送流程**
   - 先產生報表內容，再分別送出郵件與 Slack。
   - 兩個通道都應使用同一份數據，避免數字不一致。
   - 若其中一個通道失敗，記錄失敗原因並保留另一個通道的結果。

6. **加入驗證與防呆**
   - 發送前檢查數字是否缺漏、格式是否正確、收件人是否存在。
   - 若本週資料為空或異常，先停止自動發送並通知負責人。
   - 避免重複發送：加入執行紀錄或鎖定機制。

7. **測試**
   - 先用測試資料或測試頻道驗證內容。
   - 確認郵件與 Slack 顯示格式一致。
   - 確認排程只會在指定時間觸發一次。

8. **上線後監控**
   - 保留每次執行紀錄：時間、資料期間、發送結果、錯誤訊息。
   - 若連續失敗，通知維運或負責人。

## 如果目前無法直接自動化
請先向使用者收集以下資訊：
- 業績資料來源與存取方式
- 郵件系統與收件群組
- Slack 工作區與頻道名稱
- 排程時區與確切發送時間
- 報表欄位與計算規則
- 是否需要附檔、圖表或歷史比較

在取得這些資訊前，只能完成流程設計與需求整理，不能實際替代登入、發信或發 Slack。
