# 客訴信分類統計

此技能用於把「客服信箱上週收到的客訴信」整理成可讀的分類統計表。它不會自動存取信箱；如果你沒有提供郵件內容、匯出檔或可讀取的郵件清單，先請使用者提供資料。

## 先確認資料範圍
1. 確認「上週」的定義：以使用者所在地時區的最近完整 7 天，或明確的日期區間。
2. 確認資料來源格式：
   - 郵件全文
   - 郵件標題與摘要
   - 匯出的 CSV / Excel / JSON
   - 已整理的郵件清單
3. 若資料不足以分類，先請使用者補充至少以下欄位之一：
   - 寄件時間
   - 主旨
   - 內文摘要或全文
   - 客訴對象 / 產品 / 服務
   - 處理狀態（若要統計處理進度）

## 整理步驟
1. 逐封讀取郵件，為每封信建立一筆紀錄。
2. 擷取可用欄位：
   - 收件日期
   - 寄件者（若需要去識別化，可只保留網域或匿名編號）
   - 主旨
   - 客訴內容摘要
   - 客訴分類
   - 嚴重度
   - 是否重複案件
   - 處理狀態
3. 依內容將每封信歸類到最主要的一個分類；若一封信涉及多個問題，選擇最核心的主分類，並可加註次分類。
4. 若分類不明確，先建立「其他／待確認」類別，不要硬猜。
5. 統計每個分類的件數與占比。
6. 若有處理狀態資料，再統計各狀態件數，例如：
   - 未處理
   - 已回覆
   - 處理中
   - 已結案
7. 若有嚴重度資料，再統計各嚴重度件數，例如：
   - 高
   - 中
   - 低
8. 檢查是否有重複信件、同一事件多封來信，必要時分開列出「原始件數」與「去重後件數」。

## 分類原則
- 以客訴主題為優先，不以寄件者或部門名稱作為主分類。
- 常見分類可包含：
  - 產品瑕疵
  - 配送延誤
  - 退款／退貨
  - 帳務／扣款問題
  - 服務態度
  - 系統／網站問題
  - 訂單異常
  - 其他
- 若使用者已有既定分類規則，優先採用使用者規則。
- 同一封信若同時反映多個問題，主分類以造成主要不滿的問題為準。

## 輸出格式
輸出一份清楚的分類統計表，至少包含：

### 1. 總覽
- 統計期間
- 總信件數
- 已分類件數
- 未分類件數
- 去重後件數（若適用）

### 2. 分類統計表
建議欄位：
- 分類
- 件數
- 占比
- 代表性主旨或摘要
- 備註

### 3. 狀態統計表（若有）
- 狀態
- 件數
- 占比

### 4. 嚴重度統計表（若有）
- 嚴重度
- 件數
- 占比

### 5. 重點觀察
簡短列出：
- 件數最多的前三類
- 是否有集中爆發的問題
- 是否有需要優先處理的高嚴重度案件

## 品質檢查
- 確認所有郵件都被納入統計，或明確標示排除原因。
- 確認分類名稱一致，不要同義詞混用造成重複統計。
- 若資料來源是非結構化文字，先做摘要再分類，避免直接憑單句判斷。
- 若無法判定某封信的分類，標記為「待確認」，不要自行補完事實。

## 若資料未提供
如果使用者只說要整理，但沒有提供郵件內容或匯出檔，回覆時請明確說明：
- 目前無法直接完成統計
- 需要提供上週客訴信的內容或匯出檔
- 建議提供的最小欄位清單

## 建議回覆模板
- 先給一段簡短總結
- 再附表格
- 最後列出需要補充或待確認的項目
