# 目的
協助建立與執行「三家競爭對手官網價格追蹤」流程：蒐集網址、定義比對規則、記錄基準價格、定期檢查、偵測變動、整理通知。

## 先確認的資訊
在開始前，先向使用者確認或收集以下內容：
1. 三家競爭對手的商品頁或價格頁網址。
2. 要追蹤的商品名稱、規格或 SKU。
3. 價格欄位的判定方式：
   - 售價
   - 原價/特價
   - 含稅/未稅
   - 幣別
4. 檢查頻率：每天、每週或手動觸發。
5. 通知方式與收件對象：例如電子郵件、聊天訊息、工單摘要。
6. 是否要追蹤其他欄位：庫存、促銷標籤、運費、會員價。

如果缺少網址或商品識別資訊，先停止比對，改為請使用者補齊。

## 執行流程
### 1. 建立基準
1. 逐一開啟三家官網頁面。
2. 找出每個目標商品的價格欄位。
3. 記錄以下基準資料：
   - 競爭對手名稱
   - 頁面網址
   - 商品名稱
   - 價格數值
   - 幣別
   - 抓取時間
   - 任何影響比對的備註（例如會員登入後才顯示、需選規格）
4. 若頁面有多個價格，優先採用使用者指定的欄位；若未指定，採用頁面上最明顯的現售價格，並在備註中說明。

### 2. 定期檢查
1. 依照設定頻率重新開啟相同頁面。
2. 以相同規則擷取價格。
3. 與基準或上次紀錄比對。
4. 若頁面結構改變，先嘗試以可見文字、標籤或結構相近區塊重新定位價格；若仍無法判定，標記為「無法確認」，不要猜測。

### 3. 判定變動
只要符合以下任一情況，就視為變動：
- 價格數值改變。
- 幣別改變。
- 原價/特價結構改變，且會影響實際售價判讀。
- 商品頁改版導致價格無法可靠比對。

若價格相同但促銷標籤、庫存或規格選項改變，只有在使用者要求追蹤這些欄位時才納入通知。

### 4. 產出通知
當偵測到變動時，整理成簡短、可直接轉發的通知內容，包含：
- 競爭對手名稱
- 商品名稱
- 舊價格 → 新價格
- 變動幅度（若可計算）
- 抓取時間
- 頁面網址
- 備註（例如頁面結構變更、需人工確認）

通知內容應清楚區分：
- 已確認的價格變動
- 無法確認但需要人工檢查的情況

### 5. 記錄歷史
每次檢查都保留一筆紀錄，至少包含：
- 時間戳
- 來源網址
- 擷取價格
- 比對結果（無變動 / 有變動 / 無法確認）
- 備註

這樣可用來追蹤趨勢與回溯異常。

## 品質與注意事項
- 不要憑頁面標題或促銷文案猜價格，必須以明確價格欄位為準。
- 若頁面需要登入、地區限制、驗證碼或其他無法自動取得的條件，明確告知使用者目前無法可靠監測，並請其提供可存取版本或替代來源。
- 若三家網站的價格定義不同，先統一比對口徑，再開始監測。
- 若使用者未提供通知管道，先輸出結構化變動摘要，等待後續轉發。
