# 目的
把會議逐字稿轉成結構化待辦清單，每一條都要包含：
- 任務內容
- 負責人
- 期限

# 使用原則
- 只根據逐字稿中明確提到的內容整理，不要自行補寫不存在的任務、負責人或日期。
- 若逐字稿中的資訊不足，先標記為「待確認」，並列出需要補問的問題。
- 保留原意，避免過度改寫導致責任或期限失真。
- 若同一任務被多次提及，合併成一條，並保留最完整的資訊。

# 處理步驟
1. **通讀逐字稿**
   - 找出所有表示行動、決策、跟進、交付、確認、修正、提供資料的句子。
   - 排除純討論、背景說明、意見交換、與任務無關的內容。

2. **辨識待辦事項**
   - 將每個明確的行動項目拆成一條待辦。
   - 若一句話包含多個動作，拆成多條，前提是它們可獨立執行。
   - 若是依賴前置條件的任務，保留依賴關係在備註中。

3. **找出負責人**
   - 優先使用逐字稿中明示的姓名、職稱、部門或代稱。
   - 若只有「我」「你」「我們」等代詞，依上下文判斷；若仍無法確定，標記為「待確認」。
   - 若任務是多人共同負責，寫成「A、B」或「團隊名稱」。

4. **找出期限**
   - 擷取明確日期、時間、週期、相對期限（例如「本週五前」「下次會議前」「兩天內」）。
   - 若只有事件型期限，保留原文，例如「下次會議前」。
   - 若完全沒有期限，標記為「待確認」。

5. **整理成清單**
   - 以條列或表格輸出。
   - 每條至少包含：
     - 待辦事項
     - 負責人
     - 期限
   - 可加上「來源片段」或「備註」欄，方便回查。

# 輸出格式建議
## 待辦清單
| 待辦事項 | 負責人 | 期限 | 備註 |
|---|---|---|---|
| ... | ... | ... | ... |

# 資訊不足時的處理
- 若負責人不明：填「待確認」
- 若期限不明：填「待確認」
- 若任務本身不夠清楚：先寫成較中性的描述，並在備註中註明原句
- 若整段逐字稿幾乎沒有可執行事項：回覆「未找到明確待辦事項」，並列出可疑句子供人工確認

# 品質檢查
在完成前檢查：
- 每條待辦是否真的可執行
- 是否每條都有負責人與期限
- 是否有重複項目
- 是否把討論內容誤當成待辦
- 是否保留了需要人工確認的缺口
