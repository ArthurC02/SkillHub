# 目的
把會議逐字稿轉成結構化待辦清單，並確保每一條都包含：
- 待辦事項
- 負責人
- 期限

# 適用範圍
使用者提供的是會議錄音逐字稿、會議紀錄文字、或類似的對話內容，且希望整理成可追蹤的工作清單。

# 處理原則
1. 只根據逐字稿內容整理，不要自行補充未提到的工作。
2. 優先抓取明確的行動句，例如：
   - 「請 A 負責…」
   - 「B 需要在週五前…」
   - 「我們下週完成…」
3. 若同一事項有多個步驟，拆成多條可執行待辦。
4. 若逐字稿中沒有明確負責人或期限，先嘗試從上下文推定；若仍無法確定，標示為「未指派」或「未提及」，不要捏造。
5. 若期限是相對時間，保留原文並在必要時轉寫成較清楚的格式，例如「本週五」、「下次會議前」。
6. 若有衝突資訊，以較明確、較晚出現的指示為準，並在必要時保留備註。

# 工作步驟
1. 通讀逐字稿，標記所有可能的行動項目。
2. 排除純討論、背景說明、意見交換、已完成事項。
3. 將每個行動項目整理成一句清楚的待辦描述。
4. 為每條待辦補上負責人：
   - 直接從逐字稿中的指派語句擷取。
   - 若只有角色沒有姓名，保留角色名稱。
   - 若完全沒有，寫「未指派」。
5. 為每條待辦補上期限：
   - 直接擷取明確日期、時間、週期或相對期限。
   - 若沒有，寫「未提及」。
6. 檢查每條是否都能獨立執行、可驗收。
7. 輸出成條列或表格，保持一致格式。

# 建議輸出格式
使用下列欄位：
- 待辦事項
- 負責人
- 期限
- 備註（可選，僅在需要保留原文語氣或不確定性時使用）

範例格式：

| 待辦事項 | 負責人 | 期限 | 備註 |
|---|---|---|---|
| 整理新版提案並寄給客戶 | 王小明 | 週五下班前 | 原文提到需先確認數字 |
| 與設計確認首頁視覺稿 | 設計部 | 下次會議前 |  |

# 品質檢查
在輸出前確認：
- 每條待辦都有負責人
- 每條待辦都有期限
- 沒有把討論內容誤寫成待辦
- 沒有加入逐字稿以外的新資訊
- 用詞簡潔、可執行、可追蹤
