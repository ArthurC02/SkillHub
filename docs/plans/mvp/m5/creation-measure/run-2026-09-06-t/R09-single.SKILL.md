## 目的
將使用者提供的履歷改寫成適合資料分析職缺的版本，並控制在一頁以內。輸出應優先凸顯資料處理、分析、報表、自動化、商業洞察與跨部門溝通能力。

## 工作流程
1. 先讀取使用者提供的履歷內容；如果內容不足以完成改寫，先列出缺少的關鍵資訊，再請使用者補充。
2. 辨識與資料分析最相關的經歷、技能與成果，包括但不限於：
   - SQL、Python、R、Excel、Tableau、Power BI、Looker
   - 資料清理、ETL、資料驗證、報表自動化
   - A/B test、指標設計、漏斗分析、留存分析、分群分析
   - 商業分析、營運分析、產品分析、行銷分析
   - 與利害關係人合作、需求釐清、簡報與洞察傳達
3. 將內容重寫成「資料分析職缺導向」的敘述：
   - 用成果導向語句，優先寫可量化結果。
   - 把一般職務描述改寫成分析貢獻，例如把「整理資料」改成「建立自動化報表並縮短每週彙整時間」。
   - 若原文沒有數字，保留可驗證的成果描述，但不要捏造數據。
4. 刪除與資料分析無關或弱相關的內容，除非它能支持分析職能，例如流程改善、跨部門協作、問題解決。
5. 若內容過長，進行壓縮與合併，確保最終版本適合一頁以內。
6. 若使用者未提供某些資訊，不要自行編造；可用較中性的寫法保留原意。

## 改寫原則
- 標題與摘要要直接對準資料分析職缺。
- 技能區塊要把分析工具與方法放前面。
- 經歷條列每點盡量以「動作 + 工具/方法 + 成果」呈現。
- 優先使用動詞：分析、建立、優化、自動化、監控、驗證、整合、視覺化、預測、追蹤。
- 避免空泛形容詞與與職缺無關的敘述。
- 保持專業、精簡、可掃讀。

## 輸出格式
- 直接輸出改寫後的履歷內容。
- 不要加解釋、不要評論改寫過程、不要列出修改建議。
- 內容應可直接貼入履歷文件。
- 若資訊不足以完成一頁版本，先提出需要補充的項目，而不是硬寫。
