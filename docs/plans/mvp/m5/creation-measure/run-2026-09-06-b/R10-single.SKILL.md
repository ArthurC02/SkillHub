## 目的

從 Slack 的三個頻道中找出「問題但尚未被回覆」的訊息，整理成可直接追蹤的清單，並附上每則訊息的連結。

## 適用情境

- 需要每週做一次 Slack 問題盤點
- 只關心三個指定頻道中的未回覆問題
- 產出給團隊跟進用的清單，而不是直接回覆訊息

## 執行步驟

1. **確認三個頻道名稱**
   - 先取得要檢查的三個 Slack 頻道名稱或連結。
   - 如果未提供，先向使用者確認，因為沒有頻道清單就無法開始。

2. **收集本週訊息**
   - 逐一查看三個頻道中本週的訊息。
   - 只保留看起來是「問題」的訊息，例如：
     - 明確提問
     - 請求協助
     - 需要確認、排查、決策的內容
   - 排除純公告、閒聊、已完成事項。

3. **判斷是否已回覆**
   - 對每則問題訊息，檢查其下方串接回覆與後續對話。
   - 若已有明確回覆、解答、指派處理者或已完成跟進，則不列入。
   - 若只有表情符號、簡短確認但沒有實質回答，仍視為未回覆。
   - 若問題已在同一串中被解決，但原訊息沒有明確答案，也不要列入。

4. **整理未回覆問題**
   - 對每則未回覆問題，記錄以下資訊：
     - 頻道名稱
     - 發問者
     - 發問時間
     - 問題摘要
     - 原始訊息連結
   - 摘要要短，保留問題核心，不要改寫成答案。

5. **去重與排序**
   - 若同一問題被重複貼在不同頻道或同頻道多次出現，保留最早且最完整的一則，其他可註記為重複。
   - 依時間由舊到新排序，方便先處理最早遺留的問題。

6. **輸出清單**
   - 以條列或表格輸出。
   - 每筆至少包含：
     - 頻道
     - 問題摘要
     - 連結
   - 若有多筆，保持一致格式，方便直接貼給團隊。

## 輸出範例格式

- #channel-name｜問題摘要｜https://...
- #channel-name｜問題摘要｜https://...

## 注意事項

- 這個任務需要能查看 Slack 訊息與訊息連結；如果沒有 Slack 存取權限或無法取得頻道內容，就只能先請使用者提供匯出內容或截圖。
- 不要臆測訊息是否已回覆；看不到回覆串就標記為「需確認」，不要直接當作未回覆。
- 不要把非問題訊息混進清單。
