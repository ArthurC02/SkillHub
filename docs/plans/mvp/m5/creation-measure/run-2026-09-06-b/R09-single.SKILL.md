## 目的
將使用者提供的履歷內容，改寫成更適合資料分析職缺的一頁版履歷，優先凸顯可量化成果、資料處理能力、分析工具與商業影響。

## 先確認的資訊
如果使用者沒有提供以下內容，先詢問缺少的部分，再開始改寫：
- 原始履歷全文
- 目標職缺名稱或職缺描述（若有）
- 希望保留的經歷、專案或技能
- 語言偏好（繁中、英文，或雙語）

## 改寫原則
1. 以資料分析職缺為導向重寫，不只是潤飾文字。
2. 保留真實經歷，不新增未提供的技能、工具、學歷或成果。
3. 優先呈現以下內容：
   - 資料清理、整理、分析、視覺化
   - SQL、Python、R、Excel、Tableau、Power BI、Looker 等工具
   - 指標設計、報表、自動化、A/B test、統計分析
   - 對營收、效率、轉換率、成本、決策的影響
4. 將一般職務描述改寫成分析導向語句，例如把「協助整理資料」改成「整理並分析跨部門資料，建立可追蹤的報表流程」。
5. 每段經歷盡量使用動詞開頭，並加入可量化成果；若原文沒有數字，保留定性成果但不要捏造數字。
6. 全文控制在一頁以內：內容精簡、去除重複、刪除與資料分析無關的細節。

## 改寫步驟
1. 讀取原始履歷，找出與資料分析最相關的經歷、專案、技能與成果。
2. 依資料分析職缺常見結構重排內容：
   - 標題與聯絡資訊
   - 個人簡介／摘要
   - 核心技能
   - 工作經歷
   - 專案經歷（若有且相關）
   - 學歷與證照（精簡）
3. 為每段經歷提煉 2–4 個重點，聚焦在：
   - 問題是什麼
   - 你做了什麼分析或處理
   - 使用了什麼工具或方法
   - 產生了什麼結果
4. 若原履歷偏向其他職能，將內容轉譯成資料分析語言，但不得誇大或虛構。
5. 若有多個版本可行，優先選擇最能對應資料分析職缺的版本，而不是保留所有內容。

## 輸出格式
- 直接輸出改寫後的履歷內容。
- 使用清楚的履歷標題與條列式格式。
- 不要附加解釋、改寫說明或評語。
- 不要超過一頁的篇幅。

## 品質檢查
在輸出前確認：
- 是否明確強調資料分析相關技能與成果
- 是否刪除了與目標職缺無關的冗長內容
- 是否沒有捏造經歷、工具或數字
- 是否整體長度可控制在一頁內
