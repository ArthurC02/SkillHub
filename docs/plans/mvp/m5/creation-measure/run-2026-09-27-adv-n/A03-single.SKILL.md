# 客訴信分類統計

## 適用情境
當你已經拿到客服信箱中「上週收到的客訴信」內容，並需要把它整理成分類統計表時，使用此技能。

## 先決條件
- 你必須已經取得信件內容或匯出的郵件資料。
- 這個技能**不能**直接登入信箱、抓取郵件或存取外部系統；若尚未提供信件內容，先請使用者提供匯出檔、貼上內容，或提供可讀取的郵件清單。

## 作業流程
1. **確認資料範圍**
   - 只處理「上週」收到的客訴信。
   - 若資料中混有其他日期，先排除不屬於上週的信件。
   - 若「上週」定義不明，先依使用者所在時區與最近完整七天處理，並在結果中註明採用的期間。

2. **逐封信判定是否為客訴**
   - 只納入明確表達不滿、申訴、退貨/退款爭議、服務失誤、產品瑕疵、配送問題、帳務爭議等內容的信件。
   - 若一封信同時包含多個問題，允許多重分類。
   - 若內容不足以判定，標記為「待確認」並在備註列出原因。

3. **建立分類規則**
   - 先從信件內容歸納主題，再統一到固定分類名稱。
   - 建議使用以下分類，必要時可依實際內容增減，但要保持一致：
     - 產品品質/瑕疵
     - 配送延誤/物流問題
     - 退款/退貨
     - 帳務/付款問題
     - 服務態度/客服回應
     - 網站/系統問題
     - 訂單錯誤/缺件
     - 其他
     - 待確認
   - 若同類問題有不同說法，應合併為同一分類。

4. **統計數量**
   - 計算每個分類的信件數。
   - 若一封信可歸入多類，請同時：
     - 計入各分類的類別數
     - 另外提供「信件總數」與「分類命中總數」
   - 若需要避免重複計數，請明確區分：
     - 「主分類統計」：每封信只算一次
     - 「多標籤統計」：每封信可算多次
   - 預設輸出主分類統計，並在備註說明多標籤情況。

5. **整理成表格**
   - 表格至少包含以下欄位：
     - 分類
     - 信件數
     - 占比
     - 代表性內容摘要
     - 備註
   - 占比以客訴信總數為分母，四捨五入到小數點後一位。
   - 代表性內容摘要要簡短，概括該類常見問題，不要暴露不必要的個資。

6. **檢查一致性**
   - 確認各分類加總與總數一致。
   - 若有未能分類的信件，單獨列出數量與原因。
   - 若資料有缺漏、重複或日期不完整，先在結果前說明限制。

## 輸出格式
請輸出以下內容：

1. **摘要**
   - 上週客訴信總數
   - 主要客訴類型
   - 是否存在待確認信件

2. **分類統計表**
   - 以 Markdown 表格呈現

3. **補充說明**
   - 分類原則
   - 是否採用主分類或多標籤統計
   - 任何資料限制或異常

## 範例表格欄位
| 分類 | 信件數 | 占比 | 代表性內容摘要 | 備註 |
|---|---:|---:|---|---|
| 配送延誤/物流問題 | 12 | 40.0% | 包含延遲到貨、追蹤資訊異常、包裹未送達 | 主分類 |
| 退款/退貨 | 8 | 26.7% | 退款進度慢、退貨流程不清楚 | 主分類 |
| 產品品質/瑕疵 | 6 | 20.0% | 商品破損、功能異常、與描述不符 | 主分類 |
| 待確認 | 2 | 6.7% | 內容不足以判定具體問題 | 需人工確認 |

## 注意事項
- 不要編造信件內容或數字。
- 不要輸出可識別個資；若摘要需要引用內容，請去識別化。
- 若使用者只提供部分信件，請明確標示這是「部分統計」。
- 若資料來源是截圖或掃描文字，先確認文字可讀性；不可讀時請要求提供可複製文字。
