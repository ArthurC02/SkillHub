# 每週五下午業績公告流程

這個技能的目標是：在每週五下午，把「本週業績數字」整理成一致的訊息，並同時發送給全部門的電子郵件與 Slack 公告。

## 先確認這件事是否可直接執行

如果你沒有以下任一項，這個任務不能完整自動完成：
- 可發信的郵件系統存取權限
- 可發 Slack 訊息的工作區存取權限
- 本週業績數字的來源或可查詢位置
- 部門收件人清單或 Slack 頻道名稱

若缺少其中任何一項，先向使用者索取，或請使用者提供可讀取的資料來源與發送目標。不要自行猜測收件人、頻道或數字。

## 執行步驟

1. **確認週期與時點**
   - 以使用者所在時區的「每週五下午」為準。
   - 若系統有排程能力，設定在每週五下午固定執行。
   - 若沒有排程能力，則在每週五下午由人工觸發此流程。

2. **取得本週業績數字**
   - 從指定來源讀取本週業績。
   - 優先使用可追溯的來源，例如報表、儀表板匯出、CRM 統計或資料表。
   - 若來源有多個指標，整理成簡短且一致的格式，例如：
     - 本週總業績
     - 與上週比較
     - 重要補充說明
   - 若數字不完整、來源衝突或無法驗證，先停止發送並回報問題。

3. **整理公告內容**
   - 內容要同時適合 email 與 Slack。
   - 保持簡潔、明確、可直接轉貼。
   - 建議包含：
     - 主旨或標題
     - 本週業績數字
     - 與上週或目標的比較（若有）
     - 必要的備註或下一步
   - 避免加入未經確認的推測。

4. **確認收件對象**
   - Email：使用全部門的正式收件清單。
   - Slack：使用指定的部門頻道或公告頻道。
   - 若收件清單或頻道名稱不明確，先詢問，不要自行選擇。

5. **發送 Email**
   - 使用部門公告信箱或群組寄送。
   - 主旨應清楚標示週次與內容，例如「本週業績公告」或「週五業績更新」。
   - 內文使用與 Slack 相同的核心資訊，必要時可稍微補充細節。
   - 發送前再次檢查收件人是否正確。

6. **發布 Slack 公告**
   - 在指定頻道發送相同核心內容。
   - 若公司慣例允許，可使用簡短格式與條列。
   - 若需要標註頻道或提及全員，先確認是否符合團隊規範，避免誤觸通知。

7. **發送後檢查**
   - 確認 email 已成功送出。
   - 確認 Slack 訊息已成功發布。
   - 若任一管道失敗，記錄失敗原因並只重試該管道；不要重複發送已成功的管道。

8. **保留紀錄**
   - 記錄發送時間、使用的數字版本、收件對象與 Slack 頻道。
   - 若有附件或來源連結，也一併記錄。

## 建議訊息格式

### Email 主旨
- 本週業績公告｜YYYY/MM/DD
- 週五業績更新｜YYYY/MM/DD

### 內文 / Slack 範例
- 各位同仁好，
- 以下為本週業績數字：
  - 總業績：XXX
  - 與上週相比：+/- XXX
  - 備註：XXX
- 謝謝大家。

## 例外處理

- **數字尚未產出**：延後發送，並通知使用者目前缺少資料。
- **收件名單不完整**：先補齊名單，不要只寄給部分人。
- **Slack 或 Email 權限不足**：回報無法完成，並指出缺少哪個權限。
- **內容需審核**：若組織要求先審核，先產出草稿再等待確認，不要直接送出。
