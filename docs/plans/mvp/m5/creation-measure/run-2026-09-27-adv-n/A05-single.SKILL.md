# 目的
監測三家競爭對手官網上的價格是否變動，並在有變動時整理可通知的摘要。

# 先確認的資訊
在開始前，先向使用者確認或整理以下內容：
1. 三家競爭對手的官網網址。
2. 要追蹤的商品或價格頁面。
3. 每個商品要比對的價格欄位：售價、原價、折扣價、運費、會員價或其他。
4. 比對頻率：每天、每週、每小時或手動執行。
5. 通知方式：電子郵件、聊天訊息、報表摘要或僅輸出結果。
6. 是否要忽略小幅波動，例如幣別換算、稅金、運費變動。
7. 是否需要保留歷史紀錄與變動時間。

# 執行原則
- 只做可由代理完成的部分：蒐集、比對、整理與輸出通知內容。
- 不假設可直接登入、購買或繞過網站限制。
- 若網站需要登入、驗證碼、付費牆或其他無法由代理完成的步驟，明確告知使用者需要提供可存取的公開頁面、匯出資料，或授權後再進行。
- 若網站內容無法穩定讀取，優先請使用者提供可機器讀取的頁面、API、RSS、站內匯出檔，或固定格式的截圖/HTML。

# 監測流程
1. 逐一打開三家官網的目標頁面。
2. 找出每個商品的價格資訊，記錄：
   - 網站名稱
   - 商品名稱或識別碼
   - 目前價格
   - 幣別
   - 抓取時間
   - 頁面網址
3. 若有歷史基準，與上次紀錄比對。
4. 判斷是否有變動：
   - 價格上升
   - 價格下降
   - 折扣或原價改變
   - 運費或附加費改變
5. 若沒有歷史基準，先建立初始基準，不宣稱有變動。
6. 若有變動，整理成清楚摘要，包含：
   - 哪一家網站變動
   - 哪個商品變動
   - 舊價格與新價格
   - 變動幅度與百分比（若可計算）
   - 變動時間
   - 可能影響（例如最低價被超越）

# 比對規則
- 以同一商品、同一幣別、同一價格類型為比對單位。
- 若頁面同時顯示多種價格，先依使用者指定的欄位比對；未指定時以主要售價為準。
- 若價格格式不同，先標準化為數字再比對。
- 若網站顯示區間價、起價、會員價或促銷價，需在摘要中明確標示，不可混為同一種價格。
- 若無法確定是否為同一商品，先標記為「需人工確認」，不要自行合併。

# 通知內容格式
當有變動時，輸出以下格式的摘要：
- 監測時間：
- 變動網站：
- 商品：
- 舊價格：
- 新價格：
- 差額：
- 變動百分比：
- 頁面：
- 備註：

若沒有變動，輸出簡短狀態：
- 本次檢查未發現價格變動。
- 已更新基準，或已與上次紀錄一致。

# 建議的紀錄方式
若環境允許保存檔案，為每次檢查保留一筆結構化紀錄，至少包含：
- timestamp
- site
- product
- price
- currency
- url
- notes

# 異常處理
- 若頁面無法載入，記錄失敗原因與網址。
- 若價格欄位缺失或格式不明，標記為「無法判讀」。
- 若同一頁面出現多個價格，列出所有候選值並請使用者指定。
- 若網站內容疑似動態載入但無法取得，請使用者提供可讀取來源或截圖。

# 交付標準
完成後，至少提供：
1. 三家網站各自的目前價格紀錄。
2. 與上次基準的差異判定。
3. 若有變動，提供可直接轉發的通知摘要。
4. 若無法完成比對，說明缺少的資訊或技術限制。
