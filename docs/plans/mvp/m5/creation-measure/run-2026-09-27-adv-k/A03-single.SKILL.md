# 目的
將客服信箱中「上週」收到的客訴信整理成分類統計表，並保留可追溯的分類依據。

# 適用範圍
- 只處理已提供給你的郵件內容、匯出檔或對話紀錄。
- 不主動登入信箱、不抓取線上郵件、不執行任何需要帳號權限或即時網路存取的動作。
- 若沒有提供郵件資料，先請使用者提供可讀取的郵件清單或匯出內容。

# 作業步驟
1. **確認資料範圍**
   - 只納入「上週」收到的客訴信。
   - 若資料中沒有明確日期，先用信件日期欄位判定是否落在上週。
   - 若「上週」定義不明，請先向使用者確認採用的週期標準（例如：最近完整自然週）。

2. **讀取每封信的基本資訊**
   - 至少擷取：寄件者、日期、主旨、內文摘要、附件是否存在。
   - 若同一封信有多個問題，記錄主要客訴與次要客訴。

3. **建立分類規則**
   - 先依內容歸納出可重複使用的客訴類別。
   - 類別名稱要簡短、可理解、彼此盡量不重疊。
   - 若資料量不大，優先使用內容自然形成的類別；若資料量較大，將相近問題合併成較高層級類別。
   - 常見可用類別示例：
     - 商品瑕疵
     - 出貨延遲
     - 配送問題
     - 退款/退貨
     - 帳務/收費
     - 服務態度
     - 系統/網站問題
     - 其他

4. **逐封分類**
   - 為每封信指定一個主要類別。
   - 如有需要，可加上次要類別，但統計時以主要類別為主。
   - 對於無法判定的內容，歸入「其他」並註明原因。

5. **統計數量**
   - 計算每個類別的信件數。
   - 若可行，另外統計：
     - 含附件的信件數
     - 重複來信數
     - 高優先級或需立即處理的信件數
   - 若資料中可辨識客戶名稱或案件編號，可在備註中保留。

6. **輸出分類統計表**
   - 以表格呈現，至少包含以下欄位：
     - 類別
     - 信件數
     - 代表性主旨或案例
     - 備註
   - 若有次要統計，也一併列出。

7. **補充摘要**
   - 在表格前或後加上一段簡短摘要，說明：
     - 總共整理了幾封信
     - 哪些類別最多
     - 是否有明顯異常或集中爆量的問題

# 輸出格式建議
使用繁體中文，表格可採 Markdown 格式：

| 類別 | 信件數 | 代表性主旨或案例 | 備註 |
|---|---:|---|---|
| 出貨延遲 | 5 | 「訂單遲未出貨」 | 其中 2 封附有訂單編號 |

# 品質要求
- 分類標準前後一致。
- 不要把同一類問題拆得過細，除非資料量足夠且確實需要。
- 不要臆測信件內容；看不清楚或資訊不足時，明確標示「無法判定」。
- 若郵件內容涉及個資，輸出時只保留必要資訊，避免揭露完整敏感資料。
