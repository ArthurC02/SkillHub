# 每週業績自動寄送與 Slack 公告

## 先確認這件事能不能直接做
這個任務通常**不能只靠文字本身完成**，因為它需要：
- 可存取業績數字來源（例如 CRM、報表系統、資料庫、試算表）
- 可寄信的郵件系統權限
- 可發 Slack 訊息的工作區權限
- 排程能力（例如每週五下午觸發）

如果目前沒有這些存取權限，請先蒐集資訊與權限，再進行設定；本技能只能協助你整理需求、確認內容、設計流程與產出設定規格。

## 目標
在每週五下午，自動完成兩件事：
1. 將「本週業績數字」寄給全部門
2. 同步在 Slack 公告相同或精簡版內容

## 執行流程

### 1) 確認報表定義
先釐清以下項目，避免自動化後寄錯內容：
- 「本週」的定義：週一到週五？還是最近 7 天？
- 「業績數字」包含哪些欄位：營收、訂單數、成交數、轉換率、達標率等
- 是否要與上週比較、與目標比較、或只顯示本週總數
- 是否要分部門、分產品、分地區
- 是否要附上明細檔或只寄摘要

### 2) 確認收件與公告對象
- 部門收件人清單：使用群組信箱、通訊錄群組，或固定名單
- Slack 發布位置：指定頻道名稱或頻道 ID
- 是否需要 @channel、@here，或只發一般訊息
- 是否需要主管抄送或密件副本

### 3) 確認資料來源與產出格式
選定一個穩定來源：
- 試算表
- BI 報表
- CRM 匯出
- 資料庫查詢

定義輸出格式：
- 郵件主旨格式，例如：`[每週業績] 2026-09-25`
- 郵件內容：
  - 本週總結
  - 關鍵數字
  - 與上週/目標比較
  - 附件或連結
- Slack 內容：
  - 簡短摘要
  - 連結到完整報表

### 4) 設計自動化步驟
建立一個固定流程：
1. 取得本週業績數字
2. 驗證數據是否完整
3. 生成郵件內容與 Slack 訊息
4. 寄送郵件給全部門
5. 發布 Slack 公告
6. 記錄成功/失敗結果

### 5) 加入失敗處理
若資料缺失或來源不可用：
- 不要寄出空白或錯誤報表
- 改為發送失敗通知給負責人
- 在 Slack 或郵件中標示「資料尚未完成」
- 記錄錯誤原因與時間

### 6) 驗證排程
在正式啟用前，先做一次測試：
- 用測試資料跑完整流程
- 確認郵件收件人正確
- 確認 Slack 頻道正確
- 確認時間是每週五下午的正確時區
- 確認內容格式可讀

### 7) 上線後的例行檢查
每週確認：
- 是否準時送出
- 數字是否與來源一致
- Slack 與郵件內容是否一致
- 是否有退信或 Slack 發送失敗

## 你需要準備的資訊
若要真正落地，請先提供或確認：
- 業績資料來源
- 本週的計算規則
- 部門收件名單
- Slack 頻道名稱或 ID
- 寄送時間與時區
- 郵件主旨與內容格式
- 是否需要附件、圖表或連結

## 不能直接完成的部分
如果沒有系統權限或外部工具連線，這個技能**不能直接替你寄信或發 Slack**。它只能幫你把需求整理成可執行的自動化規格，並列出需要設定的項目。
