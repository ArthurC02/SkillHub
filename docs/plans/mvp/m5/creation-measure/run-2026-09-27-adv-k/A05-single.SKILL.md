# 目的
建立一個可重複執行的價格追蹤流程，用來比較三家競爭對手官網的價格，並在價格有變動時產出通知摘要。

# 適用範圍
- 只處理可公開存取的官網價格頁面。
- 不負責登入後頁面、付費牆、CAPTCHA、或需要即時網路操作才能完成的通知送出。
- 若無法直接取得頁面內容，先記錄原因與缺口，再請使用者提供可存取的網址、截圖或匯出資料。

# 執行步驟
1. **確認追蹤對象**
   - 收集三家競爭對手的名稱、價格頁網址、要追蹤的商品或方案名稱。
   - 若同一網站有多個價格方案，明確指定要比對的項目，避免誤判。

2. **建立基準資料**
   - 為每一家網站記錄：
     - 網站名稱
     - 價格頁網址
     - 商品/方案名稱
     - 幣別
     - 顯示價格
     - 折扣、促銷、稅金、運費是否包含
     - 擷取日期時間
   - 若頁面有多種價格呈現方式，優先記錄官方主要顯示價格，並附註條件。

3. **比對規則**
   - 每次檢查時，將新價格與上次記錄的價格逐一比對。
   - 判定「有變動」的情況包括：
     - 價格數字改變
     - 幣別改變
     - 原價/特價結構改變
     - 促銷標示改變且影響實際成交價
   - 若只是版面改版但價格未變，標記為「無價格變動」。

4. **處理變動**
   - 若任一網站價格有變動，整理以下內容：
     - 哪一家網站變動
     - 變動前價格
     - 變動後價格
     - 差額與漲跌幅
     - 變動時間
     - 相關頁面連結
     - 可能影響的商品/方案
   - 若三家都未變動，記錄「本次無變動」。

5. **通知內容格式**
   - 使用簡潔摘要：
     - 標題：`價格變動通知`
     - 內文：列出有變動的網站與價格差異
     - 若無變動：`三家競爭對手價格本次未變動`
   - 若需要轉交給其他系統發送通知，輸出可直接貼上的純文字摘要。

6. **維護歷史紀錄**
   - 每次檢查都保留一筆紀錄，避免只看最新結果。
   - 歷史紀錄至少包含：日期時間、網站、價格、備註。
   - 若價格頁結構改變導致無法比對，先標記為「需人工確認」，不要直接視為價格變動。

# 異常處理
- **頁面無法開啟**：記錄錯誤與時間，保留上次有效價格。
- **價格未明確顯示**：記錄頁面位置與截圖需求，請使用者補充。
- **多幣別或地區定價**：先固定同一地區與同一幣別再比較。
- **促銷倒數或動態價格**：以頁面最終顯示的可購買價格為準，並註明條件。

# 輸出要求
每次執行後輸出以下其中一種結果：
- `有變動`：列出變動明細與通知摘要
- `無變動`：列出三家網站皆未變動
- `需人工確認`：列出無法判定的原因與需要補充的資訊
