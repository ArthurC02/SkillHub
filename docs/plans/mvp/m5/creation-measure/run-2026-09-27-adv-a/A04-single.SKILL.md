# 每週業績自動寄送與 Slack 公告

## 先確認這件事能不能真的自動化
這個任務通常需要：
- 可讀取本週業績數字的資料來源
- 可寄信的郵件系統或寄信 API
- 可發 Slack 訊息的工作區權限或 Slack API
- 可排程的工具或工作流程平台

如果目前沒有這些存取權限，這個 Skill 不能直接替你完成實際寄送；你仍然可以用它來整理需求、準備內容、確認收件名單與排程規則。

## 執行步驟

### 1. 確認報告規格
先釐清以下資訊：
- 「本週」的定義：週一到週五、或最近 7 天
- 「業績數字」包含哪些指標：營收、訂單數、轉換率、達成率等
- 是否要附上比較值：上週、上月、目標值
- 收件對象：全部門的名單來源
- Slack 發布位置：指定頻道、私訊群組，或兩者都要
- 發送時間：每週五下午的確切時間與時區

### 2. 取得資料
從正式資料來源擷取本週業績數字，並確認：
- 數字已更新到週五下午的截止時間
- 與報表口徑一致
- 沒有重複計算或缺漏

若資料來源不明，先向負責人確認唯一可信來源，不要自行拼湊。

### 3. 整理成一致的訊息內容
建立兩個版本，但內容保持一致：
- Email 版：較完整，可含摘要、重點、表格、附件或連結
- Slack 版：較精簡，先給結論與重點，再附連結

建議內容結構：
1. 主旨/標題：本週業績更新（YYYY/MM/DD）
2. 一句摘要：本週整體表現如何
3. 關鍵數字：列出主要指標
4. 與目標或上週比較：如有需要
5. 備註：異常原因、補充說明、下一步

### 4. 檢查收件名單與頻道
在發送前確認：
- Email 收件人是否為全部門最新名單
- 是否需要 CC / BCC
- Slack 頻道名稱是否正確
- 是否需要 @channel、@here，或避免打擾式通知

若名單來自群組或自動同步，先確認群組成員是否已更新。

### 5. 排程發送
若你有排程工具，設定為：
- 觸發時間：每週五下午
- 觸發條件：資料已完成更新後再發送
- 動作 1：寄出 Email
- 動作 2：在 Slack 公告
- 失敗處理：任一動作失敗時記錄錯誤並通知負責人

若沒有排程工具，這個 Skill 只能協助你準備可直接貼上的內容與流程清單，不能自行在背景執行。

### 6. 發送前最後檢查
在送出前確認：
- 數字與來源一致
- 日期正確
- 收件人與 Slack 頻道正確
- 沒有敏感資訊外洩
- 語氣符合公司內部公告風格

### 7. 發送後記錄
保留以下紀錄：
- 發送時間
- Email 主旨與收件範圍
- Slack 頻道與訊息連結
- 使用的資料版本或報表連結

這樣可方便下次追蹤是否有漏發或內容不一致。

## 建議的公告格式
### Email
主旨：本週業績更新｜YYYY/MM/DD

內文：
- 本週總結：
- 主要數字：
- 與上週/目標比較：
- 備註：

### Slack
本週業績更新已整理完成：
- 總結：
- 主要數字：
- 詳細內容請見 Email / 報表連結

## 如果資訊不足
若缺少以下任一項，先不要發送：
- 正確的業績資料來源
- 全部門收件名單
- Slack 頻道或權限
- 排程方式

先向負責人確認，再繼續。
