# 目的
建立一個可重複執行的價格追蹤流程，用來比對三家競爭對手官網的商品價格，並在價格有變動時產出通知摘要。

# 先確認的資訊
在開始前，先向使用者確認或整理以下內容：
1. 三家競爭對手的官網網址。
2. 要追蹤的商品或價格頁面連結。
3. 每個網站要比對的價格欄位是什麼（例如售價、促銷價、會員價、含稅/未稅）。
4. 是否要追蹤幣別、運費、折扣、庫存或促銷標籤。
5. 比對頻率與通知門檻（例如任何變動都通知，或只在漲跌超過某百分比時通知）。
6. 通知格式偏好（簡短摘要、表格、逐站詳列）。

# 執行流程
1. 為每一家網站建立一份基準紀錄，至少包含：
   - 網站名稱
   - 頁面網址
   - 商品名稱或識別資訊
   - 擷取到的價格文字
   - 幣別
   - 擷取時間
2. 每次執行時，重新讀取三個頁面，擷取相同欄位。
3. 將新資料與上一版基準紀錄逐一比對。
4. 判斷是否有變動：
   - 價格數值變動
   - 幣別變動
   - 原本的價格欄位消失或新增
   - 顯示方式改變導致無法直接比對
5. 若有變動，整理通知內容，至少包含：
   - 哪一家網站變動
   - 變動前價格
   - 變動後價格
   - 變動幅度與方向
   - 變動時間
   - 來源頁面連結
6. 若沒有變動，記錄「無變動」並保留最新擷取結果作為下一次比對基準。

# 比對原則
- 以網站實際顯示的價格為準，不自行推算未顯示的折扣。
- 若同頁有多個價格，優先使用使用者指定的欄位；若未指定，選擇最接近主要購買按鈕旁的價格。
- 若網站使用動態載入，先確認頁面是否已完整載入價格再比對。
- 若價格文字包含範圍、起價、會員限定或條件式價格，需在通知中明確標示。
- 若無法可靠擷取，標記為「無法判定」，不要猜測。

# 通知摘要格式
當有變動時，輸出一份可直接轉送的摘要，建議格式如下：
- 站點名稱
- 商品/頁面
- 舊價格 → 新價格
- 差額
- 變動方向（上漲/下跌/不變）
- 擷取時間
- 頁面連結
- 備註（例如促銷、會員價、無法直接比對）

# 注意事項
- 這個任務需要能夠存取目標網站內容；若目前環境無法連線或無法讀取網站，先明確告知無法完成即時監測，並改為提供可執行的比對清單與通知模板。
- 不要假設網站內容固定不變；每次都以最新頁面為準。
- 若網站有反爬、登入、地區限制或驗證碼，先記錄限制並請使用者提供可存取的公開頁面或授權方式。
