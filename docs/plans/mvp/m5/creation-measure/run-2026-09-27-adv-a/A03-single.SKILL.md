# 客訴信分類統計表整理

## 目的
將客服信箱中「上週收到的客訴信」整理成分類統計表，輸出可直接用於報告或後續分析的結果。

## 適用時機
當使用者提供：
- 客訴信全文、郵件匯出檔、郵件清單，或
- 已整理的信件內容片段

且要求你做分類、統計、彙整、表格化時使用。

## 先確認資料是否足夠
1. 檢查是否有可用的信件內容。
2. 若只有一句需求、沒有任何郵件內容或匯出資料，先回覆：
   - 目前沒有足夠資料可統計。
   - 請提供上週客訴信內容、郵件匯出檔，或至少每封信的主旨與內文。
3. 若資料不完整但仍可部分處理，先說明可統計的範圍與缺漏。

## 處理步驟
1. **逐封讀取信件**
   - 以每封信為單位辨識主旨、寄件時間、寄件者、內文。
   - 若同一封信有多個問題，記錄所有相關類別。

2. **建立分類規則**
   - 依內容將客訴歸入明確類別。
   - 若使用者未指定分類，先從內容中歸納常見類別，例如：
     - 商品瑕疵
     - 出貨延遲
     - 配送問題
     - 退款/退貨
     - 帳務/付款
     - 服務態度
     - 網站/系統問題
     - 其他
   - 若使用者已有指定分類，優先採用使用者分類。

3. **標記每封信的分類**
   - 每封信至少標一個主分類。
   - 若內容涉及多項問題，可加上次分類或多標籤。
   - 對於無法判定者，歸入「其他/待確認」。

4. **統計數量**
   - 計算每個分類的信件數。
   - 若同一封信可歸多類，需先說明統計口徑：
     - **主分類統計**：每封信只算一次，依最主要問題分類。
     - **多標籤統計**：同一封信可同時計入多個分類。
   - 若未特別要求，預設使用「主分類統計」。

5. **整理成表格**
   - 至少輸出以下欄位：
     - 分類
     - 信件數
     - 占比
     - 代表性內容摘要
   - 若資料允許，可再加：
     - 相關信件主旨
     - 備註

6. **檢查一致性**
   - 確認總數是否等於已處理信件數。
   - 若有未分類信件，單獨列出。
   - 若有重複信件，去重後再統計，並註明已去重。

## 輸出格式
先給一段簡短摘要，再給統計表。

### 建議輸出範例結構
- 本週共收到 X 封客訴信，主要集中在 A、B、C 類。
- 統計表：

| 分類 | 信件數 | 占比 | 代表性內容摘要 |
|---|---:|---:|---|
| 商品瑕疵 | 5 | 25% | 收到破損、缺件、功能異常等問題 |
| 出貨延遲 | 4 | 20% | 訂單超過預期時間未出貨 |
| 退款/退貨 | 3 | 15% | 申請退款流程卡住或未完成 |
| 其他/待確認 | 2 | 10% | 內容不足以明確分類 |

## 注意事項
- 不要憑空補寫不存在的信件內容。
- 不要把推測當成事實；不確定時標示為「待確認」。
- 若信件內容含個資，輸出時盡量去識別化，只保留必要資訊。
- 若使用者要求「上週」，但資料時間範圍不明，先依提供資料中的日期篩選，並說明採用的時間區間。
- 若資料量很大，先按分類統計，再抽取每類最具代表性的少量例子，不要逐封全文重述。
