# 裝潢工程報價提案書

依屋主提供的資料，製作一份可直接檢視及使用的繁體中文報價提案草稿；一次處理一個工程案。只使用輸入中的事實與數字，不查找或捏造市價、施工細節、工期、庫存、承諾或聯絡結果。

## 執行步驟

1. 整理工程需求、尺寸、材料、單價、數量、預算、幣別、稅務資料及丈量聯絡資訊。保留每項資料原本的寫法；同一項出現不一致數值（包括後文更改前文數值）時，逐項列出並請使用者確認，不能選一個數值代算。
2. 缺少設定時採常見做法，但不得假造工程事實或價格：幣別未提供就標示「幣別未提供，待確認」；沒有明確的損耗率、包裝覆蓋量、單價或稅務適用方式，就不自行補值，標示「待確認」並略過依賴該資料的計算。未提供的名稱、日期或標籤不妨礙其他內容製作，標示「未提供」即可。
3. 檢查可辨識的數值及完整日期。數值為負數、日期不存在或資料互相矛盾時，列出每個有問題的值，請使用者逐項確認；不要把該值傳入計算，也不要提供依賴它的總額。不要追問其他事項；在提案中寫清楚待確認內容。
4. 從工作目錄（也就是放置本 `SKILL.md` 的目錄）執行隨附計算腳本。只傳入已知且互相一致的值；多筆已報價項目各使用一個 `--item '名稱|數量|單價'`。磁磚計算範例命令格式如下，將參數換成屋主實際提供的資料：

   ```sh
   python scripts/quote_math.py --length 長度 --width 寬度 --waste-percent 損耗百分比 --coverage-per-box 每箱覆蓋面積 --tile-price-per-box 每箱單價 --item '人工|數量|單價'
   ```

   未提供的選用參數整段省略，不要輸入空值或猜測值。需要列入稅額時，只有在稅率及適用方式都明確時才傳入 `--tax-rate`；所有已計價項目都要以第四欄 `是` 或 `否` 明確標記是否應稅，例如 `--item '人工|1|48000|是'`，磁磚則以 `--tile-taxable 是` 或 `--tile-taxable 否` 標記。使用者提供的適用方式無法由這些明確標記表達時，不計稅，並將適用方式列為待確認。完整日期可用 `--date YYYY-MM-DD` 檢查；沒有年份的日期照原樣保留，不代填年份。
5. 將腳本輸出的計算結果原樣用於提案。腳本以錯誤碼 2 結束時，逐字列出它指出不能使用的值，請使用者確認；不提供依賴該值的總額。人工核對尺寸、單位、計價基礎與輸入資料，不能自行改變腳本結果或補上未提供的數字。
6. 撰寫提案，依序列出：
   - **工程摘要**：屋主、地點及工程內容；未提供的資料標示「未提供」。
   - **施工範圍**：只列屋主明確提出的工作及材料。
   - **估價明細**：列出可計算的數量、單價、金額、未稅小計及腳本算出的稅額（若適用）。說明幣別是否未提供。拆除清運等未報價項目列為「待報價」，不要併入小計；未提供稅率或適用方式時，稅額列為「待確認」，不自行估算。
   - **假設與不包含項目**：列出計算使用的輸入條件，以及沒有價格或資料的項目；不要把假設寫成已確認的工程事實。
   - **工期與待確認事項**：只列已提供的工期；未提供工期就標示「工期未提供」。逐項標出待丈量、待報價、待核對、日期年份未提供或其他待確認資料。列出無效或矛盾數值及請求確認的內容。
   - **丈量聯絡話術**：依提供的師傅姓名與可選時段，寫一段可供使用者自行聯絡的簡短話術。未提供的姓名或日期標示「未提供」；尚未約定的時間標示「待確認」。
   - **建材採購清單**：列出材料、按已知資料計算的採購數量及單位；無價格的材料仍可列數量，價格標示「待報價」。清楚註明這是待使用者確認及自行下單的清單。
7. 直接在本次回答交付完整提案草稿，資料不足處使用明確標記，不要只交計畫、承諾日後補寫，或以問題結束回答。保持輸入事實原樣；不得宣稱已丈量、聯絡、訂購、登入或完成任何外部動作。
8. 回答末尾用各一行交代無法代辦的動作及負責人：`無法從這裡代為打電話；由使用者自行聯絡師傅。`、`無法從這裡登入採購系統或下單；由使用者自行登入確認並下單。`
