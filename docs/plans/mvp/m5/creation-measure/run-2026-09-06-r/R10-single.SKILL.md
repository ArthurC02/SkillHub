## 目的
每週從指定的 3 個 Slack 頻道中，找出看起來尚未被回覆的問題，整理成附連結的清單。

## 先確認的資訊
如果以下資訊沒有明確提供，先向使用者確認：
1. 三個 Slack 頻道名稱或連結。
2. 報告涵蓋的時間範圍（預設為最近 7 天）。
3. 「未回覆」的判定方式：
   - 嚴格：原訊息下沒有任何回覆串。
   - 寬鬆：回覆串存在，但沒有實質回答問題。
4. 輸出語言與格式偏好（若未指定，使用與提問相同語言，輸出條列清單）。

## 作業流程
1. 逐一查看三個頻道在指定時間範圍內的訊息。
2. 只保留「問題」類訊息，通常特徵包括：
   - 有問號。
   - 使用疑問詞或請求協助的語氣。
   - 明確在尋求答案、確認、排除問題或請人處理。
3. 對每則候選問題檢查是否有回覆：
   - 若是嚴格模式，確認該訊息是否完全沒有 thread reply。
   - 若是寬鬆模式，檢查回覆內容是否只是表情、確認收到、轉貼、或未回答問題本身。
4. 排除以下內容：
   - 已被明確回答的問題。
   - 純公告、純討論、沒有提問意圖的訊息。
   - 明顯已結案或作者後續自行更正的訊息。
5. 將剩下的項目整理成清單，並附上可點擊的 Slack 訊息連結。

## 判定原則
- 優先保守：不確定是否已回答時，先列入「待確認」，不要直接當成未回覆。
- 若同一問題被多人重複提問，只保留最早且最完整的一則，並在必要時註記重複。
- 若訊息在 thread 中有回覆，但回覆只是「我也想知道」或「+1」，仍視為未被回答。
- 若回覆中包含實際解法、明確指示、或已解決問題的資訊，視為已回覆。

## 輸出格式
以三個頻道分段輸出，每段內列出未回覆問題：

### #頻道名稱
- 問題摘要｜發文者｜時間｜連結
- 問題摘要｜發文者｜時間｜連結

## 摘要寫法
- 以一句話濃縮問題內容，不要逐字抄錄整段訊息。
- 保留關鍵名詞、系統名稱、錯誤碼、截止時間等資訊。
- 若原文太長，摘要控制在 1 行內。

## 連結
- 使用該 Slack 訊息的永久連結。
- 若只能取得 thread 連結，使用 thread 連結並註明是 thread。

## 品質檢查
在輸出前確認：
1. 每個項目都來自指定的三個頻道。
2. 每個項目都在指定時間範圍內。
3. 每個項目都附有連結。
4. 沒有把已回覆的問題誤列進來。
5. 格式一致、可直接貼給團隊閱讀。
