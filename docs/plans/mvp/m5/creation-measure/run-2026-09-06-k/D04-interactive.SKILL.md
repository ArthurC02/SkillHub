# 目的
依照已確認的流程圖，將輸入的伺服器 log 文字整理成一份一致的處理流程說明。此技能只使用流程圖中出現的步驟與分支，不補充未確認的統計區間、摘要格式或額外動作。

# 輸入
- 一段伺服器 log 文字。
- 若輸入同時夾帶流程描述，先以流程圖中已確認的節點與分支為準。

# 輸出
輸出一份依流程順序排列的步驟說明，必要時標示是否進入「建立 Jira 問題單」與「通知值班工程師」分支，最後一定包含「寫入每日摘要」。

# 執行步驟
1. 讀取伺服器 log 檔
   - 先取得輸入中的 log 文字。
   - 若輸入中不包含 log 內容，只能依現有文字整理，不能自行補資料。

2. 篩出 ERROR 行
   - 從 log 中挑出包含 `ERROR` 的行。
   - 只做這個篩選，不新增其他條件。

3. 判斷錯誤是否超過 10 筆
   - 計算篩出的 ERROR 行數。
   - 依已確認流程判斷是否超過 10 筆。
   - 圖中未說明統計範圍或時間區間時，不得自行補充；只陳述已能確定的判斷結果。

4. 若錯誤超過 10 筆
   - 依流程依序執行：建立 Jira 問題單、通知值班工程師。
   - 只描述這兩個動作，不得新增其他通知、分派或升級步驟。

5. 寫入每日摘要
   - 不論分支結果如何，最後都要進入寫入每日摘要。
   - 圖中未說明摘要內容格式時，只保留這個節點名稱，不自行設計內容模板。

# 分支規則
- 若錯誤超過 10 筆，流程走「是」分支：先建立 Jira 問題單，再通知值班工程師，然後寫入每日摘要。
- 若錯誤不超過 10 筆，流程走「否」分支：直接寫入每日摘要。

# 寫作原則
- 只使用已確認的節點名稱與分支名稱。
- 不要新增未出現在流程圖中的步驟、角色、工具或判斷。
- 不要擴寫 Jira 問題單內容、通知內容或每日摘要格式。
- 若輸入文字不足以判斷，只能明確說明缺少哪一部分，不可推測。
