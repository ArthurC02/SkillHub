# 目的
將使用者提供的履歷改寫成適合資料分析職缺的版本，並控制在一頁以內。重點是突出與資料分析相關的技能、工具、專案成果與量化影響，同時保留真實性。

# 工作流程
1. **先確認輸入是否足夠**
   - 需要至少有原始履歷內容。
   - 若缺少關鍵資訊，先向使用者索取：
     - 原始履歷全文
     - 目標職缺或職稱（例如 Data Analyst、Business Analyst、Product Analyst）
     - 是否有特定工具或技能要強調（SQL、Python、Excel、Tableau、Power BI、A/B testing 等）
   - 若使用者沒有提供職缺描述，也可以依一般資料分析職缺來改寫，但要明確以通用資料分析版本處理。

2. **萃取與重組內容**
   - 找出與資料分析最相關的經歷、專案、實習、工作成果、學歷與技能。
   - 將一般性敘述改寫成可量化、可驗證、結果導向的表達。
   - 優先保留以下內容：
     - 資料清理、分析、視覺化、報表、自動化
     - SQL 查詢、Python/R、Excel、Tableau/Power BI、Looker、GA 等工具
     - 指標設計、商業洞察、實驗分析、A/B testing
     - 與跨部門合作、需求釐清、簡報與溝通
   - 將不相關或重複內容刪減，避免超過一頁。

3. **改寫原則**
   - 使用清楚、專業、偏成果導向的語氣。
   - 每段或每個條列都盡量包含：做了什麼、用什麼方法/工具、產生什麼結果。
   - 若原始履歷沒有數字，保留可推導的成果描述，但不要捏造數據；可用「提升」、「縮短」、「改善」等中性表述，或提醒使用者補充量化成果。
   - 將職稱、摘要、技能區塊調整為資料分析導向。

4. **建議的履歷結構**
   - 標題與聯絡資訊
   - 專業摘要 2–3 句
   - 核心技能（分組呈現，例如：資料分析、資料工具、商業分析、視覺化）
   - 工作經歷／專案經歷（每項 2–4 個條列，強調成果）
   - 學歷與證照（如有）
   - 其他補充（如作品集、GitHub、Kaggle、論文、競賽）視篇幅決定是否保留

5. **篇幅控制**
   - 產出內容必須以一頁內為目標。
   - 若內容過多，優先保留最能證明資料分析能力的經歷與成果。
   - 刪除冗詞、空泛形容詞與重複技能。

6. **輸出格式**
   - 直接輸出改寫後的履歷內容。
   - 若使用者要求，也可另外附上「可再補強的地方」簡短清單，但主體仍應是完整的一頁版履歷。

# 注意事項
- 不要編造經歷、職稱、公司名稱、學歷或數據。
- 不要把不相關的內容硬塞進資料分析履歷。
- 若原始履歷資訊不足以完成一頁版，先列出缺少的關鍵資訊並請使用者補充。
