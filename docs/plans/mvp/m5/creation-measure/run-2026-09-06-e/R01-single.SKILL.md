# 目的
將會議錄音逐字稿整理成結構化待辦清單，並確保每一條都包含：
- 任務內容
- 負責人
- 期限

# 適用時機
在收到會議逐字稿、會議紀錄、訪談紀錄或客戶口頭討論內容時使用，尤其是需要把零散對話轉成可追蹤的行動項目時。

# 工作流程
1. **先通讀全文**
   - 先理解會議主題、參與者、討論脈絡與結論。
   - 不要急著摘錄，先找出哪些句子是在描述決策、承諾、下一步、風險或待確認事項。

2. **辨識待辦項目**
   - 將所有明確或隱含的行動項目列出。
   - 只保留可執行的事項；背景說明、閒聊、重複確認可略過。
   - 若同一事項被多次提及，合併成一條。

3. **為每條待辦補齊三個欄位**
   - **任務內容**：用簡短、具體、可執行的語句描述。
   - **負責人**：優先使用逐字稿中明確提到的人名、職稱或團隊。
   - **期限**：優先使用明確日期、時間點或相對期限（例如「本週五前」、「下次會議前」）。

4. **處理缺漏資訊**
   - 如果逐字稿沒有明確負責人，標示為「未指派」或「待確認」。
   - 如果逐字稿沒有明確期限，標示為「未訂定」或「待確認」。
   - 不要自行臆測人名或日期。

5. **整理成清單格式**
   - 建議使用表格輸出，欄位至少包含：
     - 編號
     - 待辦事項
     - 負責人
     - 期限
     - 備註（可選，用於補充依據或待確認事項）
   - 每條待辦都要獨立成列，避免把多個任務混在一起。

6. **保留可追溯性**
   - 若有需要，可在備註中簡短註明來源句子或會議脈絡，方便回查。
   - 若某項任務是根據推論整理而來，應在備註中標示「推定」或「待確認」。

# 輸出原則
- 使用繁體中文。
- 內容要精簡、明確、可直接轉交執行。
- 不要加入逐字稿中沒有的事實。
- 不要把討論中的想法誤寫成已決定的待辦；只有明確承諾、決議或需要跟進的事項才列入。
- 若整份逐字稿沒有任何可執行事項，輸出「未辨識到明確待辦事項」，並簡述原因。
