# 任務
將使用者提供的員工報帳流程圖或等價文字描述，整理成結構化流程摘要。

# 使用時機
當輸入是一段報帳流程、流程圖文字、或可直接對應到該流程的描述時使用；輸出要依流程節點、條件、分支與不確定處整理。

# 必須遵守
- use only what the input contains — never add a date, name, assumption, step or branch the input does not give, and write 'not given' where it is silent;
- deliver the finished artifact itself in the output — never a description of the rules, a plan, or a request for access.

# 依圖面順序處理
1. 收到員工報帳申請
2. 發票是否齊全
3. 退回並要求 3 天內補件
4. 金額是否超過 5000
5. 送經理簽核
6. 財務直接入帳
7. 寄出付款通知信

# 依圖面內容輸出
- 先列出節點（nodes）。
- 再列出條件（conditions）。
- 再列出分支（branches）。
- 最後列出不確定處（uncertainties）。
- 輸出只使用圖面與輸入中明示的內容。
- 若某處圖意不明，保留為不確定處，不要自行補完。
- 若資訊在輸入中沒有給出，寫 `not given`。

# 圖面已確認內容
## 節點
- 收到員工報帳申請
- 發票是否齊全
- 退回並要求 3 天內補件
- 金額是否超過 5000
- 送經理簽核
- 財務直接入帳
- 寄出付款通知信

## 條件
- 發票是否齊全
- 金額是否超過 5000

## 分支
- 發票是否齊全 = 是 → 進入「金額是否超過 5000」
- 發票是否齊全 = 否 → 進入「退回並要求 3 天內補件」
- 金額是否超過 5000 = 是 → 進入「送經理簽核」
- 金額是否超過 5000 = 否 → 進入「財務直接入帳」
- 送經理簽核 → 財務直接入帳
- 財務直接入帳 → 寄出付款通知信

## 不確定處
- 圖中「退回並要求 3 天內補件」之後，是否代表補件完成後再回到「發票是否齊全」或直接進入「金額是否超過 5000」；圖面顯示箭頭接到金額判斷，但這段流程語意可能需要你確認。
- 圖中「發票是否齊全 = 是」的線路是直接繞到「金額是否超過 5000」，但左側連線畫法較繞，是否要視為明確的流程連接也請確認。
