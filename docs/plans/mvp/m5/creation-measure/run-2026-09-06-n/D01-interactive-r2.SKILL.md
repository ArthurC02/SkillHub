# 任務
將使用者提供的員工報帳流程圖或等價文字描述，整理成結構化流程摘要。

# 使用時機
當輸入是一段報帳流程、流程圖文字、或可直接對應到該流程的描述時使用；輸出要依流程節點、條件、分支與不確定處整理。

# 必須遵守
- 只使用輸入明示的內容，不要新增日期、姓名、假設、步驟或分支；若輸入沒有說明，寫 `not given`。
- 直接輸出完成的整理結果，不要描述規則、不要先講計畫、也不要要求額外存取。

# 依圖面順序處理
1. 收到員工報帳申請
2. 發票是否齊全
3. 退回並要求 3 天內補件
4. 金額是否超過 5000
5. 送經理簽核
6. 財務直接入帳
7. 寄出付款通知信

# 依圖面內容輸出
- 輸出必須分成且只分成四個區塊，順序固定為：節點（nodes）、條件（conditions）、分支（branches）、不確定處（uncertainties）。
- 每個區塊都要以同樣的標題呈現，不能合併成較少的區塊。
- 若某區塊沒有內容，也要保留該標題並寫 `not given`。
- 輸出只使用圖面與輸入中明示的內容。
- 若某處圖意不明，保留為不確定處，不要自行補完。

# 圖面已確認內容
## 節點
- 收到員工報帳申請
- 發票是否齊全
- 退回並要求 3 天內補件
- 金額是否超過 5000
- 送經理簽核
- 財務直接入帳
- 寄出付款通知信
- 節點名稱必須逐字沿用輸入中的名稱，不得改寫為同義詞（例如不得把「發票是否齊全」改成「檢查發票是否齊全」）。

## 條件
- 發票是否齊全
- 金額是否超過 5000

## 分支
- 發票是否齊全 = 是 → 進入「金額是否超過 5000」
- 發票是否齊全 = 否 → 進入「退回並要求 3 天內補件」
- 金額是否超過 5000 = 是 → 進入「送經理簽核」
- 金額是否超過 5000 = 否 → 進入「財務直接入帳」
- 送經理簽核 → 財務直接入帳
- 財務直接入帳 → 寄出付款通知信

## 不確定處
- 圖中「退回並要求 3 天內補件」之後，是否代表補件完成後再回到「發票是否齊全」或直接進入「金額是否超過 5000」；圖面顯示箭頭接到金額判斷，但這段流程語意可能需要你確認。
- 圖中「退回並要求 3 天內補件」之後的去向仍不完全確定；雖然箭頭畫向「金額是否超過 5000」，但需要保留這是圖面語意未完全明確的說明，不可把它寫成已完全確認的流程。
- 圖中「發票是否齊全 = 是」的線路是直接繞到「金額是否超過 5000」，但左側連線畫法較繞，是否要視為明確的流程連接也請確認。
