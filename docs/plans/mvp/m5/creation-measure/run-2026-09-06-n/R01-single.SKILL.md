# 目的
把會議逐字稿轉成結構化待辦清單，並確保每一條都包含：
- 待辦事項
- 負責人
- 期限

# 適用情境
在收到會議逐字稿、會議紀錄、轉錄文字或聊天記錄時使用。若逐字稿內容不足以判定負責人或期限，先整理出可確認的部分，再列出需要補問的資訊。

# 處理步驟
1. **通讀全文，先找行動項**
   - 找出明確的承諾、指派、請求、決議、後續跟進事項。
   - 將討論性內容、背景說明、重複敘述排除在待辦之外。

2. **將每個行動項改寫成可執行任務**
   - 用動詞開頭，寫成具體可完成的事項。
   - 一條待辦只放一個主要動作；若有多個動作，拆成多條。

3. **辨識負責人**
   - 優先使用逐字稿中明示的人名、職稱或團隊名稱。
   - 若只有「我」「你」「我們」等代詞，根據上下文推定最可能的負責人；若仍不確定，標示為「未明確」並註明需要確認。

4. **辨識期限**
   - 擷取明確日期、時間、相對期限（例如「本週五前」「下次會議前」「兩天內」）。
   - 若只有事件依賴（例如「等對方回覆後」），把它寫成條件式期限。
   - 若完全沒有期限，標示為「未提及」，並建議補問。

5. **去除歧義與重複**
   - 合併內容相同、只是說法不同的待辦。
   - 若同一事項有不同版本的期限或負責人，保留最明確的版本，並在備註中註明差異。

6. **輸出格式固定**
   - 以清單或表格輸出。
   - 每條至少包含以下欄位：
     - 待辦事項
     - 負責人
     - 期限
   - 若有必要，可加上「備註」欄，放置不確定性、依賴條件或原文線索。

# 輸出原則
- 保持忠於逐字稿，不要自行補充不存在的承諾。
- 不要把討論中的建議誤寫成已決定的待辦，除非逐字稿顯示已確認。
- 若逐字稿是口語化、跳躍式內容，先整理成正式、簡潔、可執行的任務描述。
- 若資訊不足，寧可標示「未明確／未提及」，不要臆測。

# 建議輸出範例格式
| 待辦事項 | 負責人 | 期限 | 備註 |
|---|---|---|---|
| 整理新版提案並寄給客戶 | 王小明 | 週五前 | 需先確認最新數據 |
| 與設計團隊確認首頁版型 | 李小華 | 下次會議前 | 由李小華主導 |

# 檢查清單
- 每條待辦都有負責人。
- 每條待辦都有期限；若沒有，明確標示未提及。
- 任務描述具體、可執行、無歧義。
- 沒有把背景討論混入待辦。
