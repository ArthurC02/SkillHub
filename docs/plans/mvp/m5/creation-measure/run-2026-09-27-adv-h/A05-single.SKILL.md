# 目的
建立並維護三家競爭對手官網價格的比對流程，找出價格變動並準備通知內容。

# 先確認的資訊
在開始前，先向使用者確認或整理以下資訊：
1. 三家競爭對手的官網網址。
2. 要追蹤的商品或價格頁面。
3. 需要比對的價格欄位（例如售價、折扣價、運費、會員價）。
4. 監控頻率（例如每天、每週、每次手動檢查）。
5. 通知方式與收件對象（例如電子郵件、聊天訊息、報表）。
6. 是否要忽略特定變動（例如幣別換算、稅金、促銷倒數、庫存狀態）。

如果缺少上述資訊，先停止並請使用者補齊；不要自行假設網站、商品或通知管道。

# 執行流程
1. **建立基準值**
   - 逐一開啟三家官網的目標頁面。
   - 記錄每個商品的名稱、網址、價格、幣別、時間戳記。
   - 若頁面有多個價格，明確標示欄位名稱與來源位置。
   - 若網站顯示動態價格或登入後價格，記錄可見的公開價格；若無法公開取得，註明限制。

2. **標準化資料**
   - 將三家網站的價格整理成一致格式：
     - 品名
     - 網址
     - 價格數值
     - 幣別
     - 抓取時間
     - 備註（促銷、會員限定、缺貨、稅前/稅後）
   - 若幣別不同，先保留原幣別，不要自行換算，除非使用者明確要求並提供匯率規則。

3. **比對變動**
   - 與上一版基準值或歷史紀錄比對。
   - 判斷是否有以下變動：
     - 價格上升
     - 價格下降
     - 折扣結束或開始
     - 幣別或計價單位改變
     - 由有貨變缺貨或反之，若這會影響價格判讀
   - 若頁面結構改變導致無法確認價格，標記為「無法判讀」，不要猜測。

4. **判定是否通知**
   - 只有在價格或相關價格欄位有實質變動時才通知。
   - 若變動僅是格式、排序、文案或時間戳更新，且不影響價格，則不通知。
   - 若使用者要求「任何變動都通知」，則依其要求執行並在通知中註明變動類型。

5. **整理通知內容**
   - 通知應包含：
     - 競爭對手名稱
     - 商品名稱
     - 舊價格與新價格
     - 變動幅度與方向
     - 變動時間
     - 商品網址
     - 任何影響判讀的備註
   - 若有多筆變動，按變動幅度或使用者偏好排序。

# 建議的通知格式
- 標題：`價格變動通知：{競爭對手名稱} {商品名稱}`
- 內文：
  - 舊價格：
  - 新價格：
  - 變動：
  - 網址：
  - 備註：

# 品質檢查
- 確認每筆價格都能追溯到原始頁面。
- 確認時間戳記一致。
- 確認沒有把促銷標籤、會員價或稅金誤當成主價格。
- 若同一頁面有多個地區或幣別版本，先確認使用者要追蹤哪一個版本。

# 限制與例外
- 這個任務需要持續監控與存取官網內容；若沒有可用的抓取、排程或通知工具，代理只能提供比對規則、通知模板與人工檢查清單，不能自動完成持續追蹤。
- 若網站需要登入、驗證碼、付費訂閱或其他未提供的存取權限，先告知使用者無法直接取得資料，並請其提供可公開存取的頁面或授權方式。
- 若網站禁止自動抓取，改用人工檢查流程或使用使用者允許的替代資料來源。

# 交付內容
每次檢查後，輸出一份簡短摘要：
1. 哪些網站有變動。
2. 變動前後價格。
3. 是否需要通知。
4. 若需要通知，附上可直接轉發的通知文字。
