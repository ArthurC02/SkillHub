# 目的
協助建立與執行「三家競爭對手官網價格追蹤」流程：蒐集指定頁面、比對前後價格、判定是否變動，並輸出可直接通知使用者的摘要。

# 適用範圍
- 只處理可公開存取的官網頁面。
- 不負責登入、購買、繞過驗證碼或其他需要人工授權的操作。
- 若頁面內容無法穩定抓取，應改以人工確認或請使用者提供可讀取的頁面/資料來源。

# 執行步驟
1. **確認監測對象**
   - 取得三家競爭對手的官網網址。
   - 對每一家確認要追蹤的「價格」是：單一商品、商品列表、方案頁、促銷價、訂閱價，或含稅/未稅價格。
   - 若同頁有多個價格，先定義要比對的欄位與商品名稱，避免誤報。

2. **建立基準資料**
   - 逐一記錄每個目標頁面的：
     - 網址
     - 商品/方案名稱
     - 幣別
     - 價格數值
     - 是否含稅、是否含運、是否為促銷價
     - 擷取時間
   - 若頁面有多個價格，保留完整上下文，避免只記單一數字造成誤判。

3. **後續比對**
   - 每次重新檢查時，使用相同頁面與相同比對規則。
   - 將新價格與基準或上次紀錄比較。
   - 判定是否變動時，至少檢查：
     - 數值是否不同
     - 幣別是否不同
     - 是否從促銷價切換為原價，或反之
     - 是否因稅金、運費、方案週期導致表面價格不同

4. **變動判定規則**
   - 只有在可確認為同一商品/方案的前提下，才判定為價格變動。
   - 若頁面改版、文案變更、幣別切換或無法確定對應關係，標記為「需人工確認」，不要直接當作價格變動。
   - 若價格相同但顯示方式改變，記錄為「顯示變更」而非價格變動。

5. **通知內容**
   - 一旦發現變動，整理成簡短通知，包含：
     - 哪一家競爭對手
     - 哪個頁面/商品/方案
     - 舊價格 → 新價格
     - 變動幅度（若可計算）
     - 擷取時間
     - 可能影響因素（例如促銷結束、方案週期變更）
   - 若有多筆變動，按公司分組列出。

6. **無變動時的回報**
   - 若三家皆無變動，回報「本次檢查未發現價格變動」，並附上檢查時間與頁面清單。

7. **資料保存**
   - 保留每次檢查結果，至少包含：
     - 日期時間
     - 網址
     - 擷取到的價格
     - 比對結果（變動/未變動/需人工確認）
   - 若可行，使用一致格式保存，方便下次比對。

# 注意事項
- 不要猜測價格；無法清楚辨識時，明確標示「無法確認」。
- 若網站使用動態載入，先確認頁面是否已完整呈現價格，再進行比對。
- 若同一頁面存在地區、會員、裝置或語言差異，需固定同一條件再比較。
- 若使用者未提供三家網址或目標商品，先請對方補齊資訊，再開始追蹤。
