# 目的
將客服信箱中「上週」收到的客訴信整理成分類統計表，並保留可追溯的分類依據。

# 適用範圍
- 只處理已提供給你的郵件內容、匯出檔或對話紀錄。
- 不主動登入信箱、不抓取即時郵件、不執行任何需要外部權限或網路存取的動作。
- 若資料不足以判定「上週」或缺少郵件內容，先列出缺口並請求補充。

# 作業步驟
1. **確認資料範圍**
   - 找出時間範圍是否明確標示為上週。
   - 若只有部分郵件，確認是否涵蓋上週全部客訴信。
   - 若無法確認，先註明「時間範圍未確認」，不要自行補齊。

2. **建立分類規則**
   - 先從郵件內容中歸納可重複使用的客訴類別。
   - 常見類別可包含：
     - 商品瑕疵 / 品質問題
     - 配送延誤 / 未送達
     - 錯誤出貨 / 缺件
     - 退款 / 退貨
     - 服務態度 / 客服回應
     - 帳務 / 付款問題
     - 系統 / 網站問題
     - 其他 / 無法歸類
   - 若郵件內容顯示更適合的自訂類別，優先使用資料中的實際主題。

3. **逐封郵件判讀**
   - 讀取每封信的主旨、內文、日期、寄件者與必要的上下文。
   - 為每封信指定一個主要分類；若一封信涉及多個問題，選擇最主要的客訴原因，並在備註中記錄次要原因。
   - 若內容不足以判定，標記為「待確認」。

4. **去重與合併**
   - 若同一客戶就同一事件多次來信，視需求決定是否合併計數：
     - 若要統計「信件數」，每封都算。
     - 若要統計「案件數」，同一事件的追蹤信合併為一案。
   - 在輸出前明確標示你採用的是哪一種口徑。

5. **彙總統計**
   - 計算每個分類的數量。
   - 若資料足夠，補充占比百分比。
   - 可加上日期分布、主要客訴主題、重複來信數量等輔助欄位。

6. **輸出分類統計表**
   - 以表格呈現，至少包含以下欄位：
     - 分類
     - 數量
     - 占比
     - 代表性內容摘要
     - 備註
   - 若需要更完整，可另附明細表，列出每封信的日期、寄件者、主旨、分類與判定理由。

# 建議輸出格式
## 一、統計摘要
- 資料期間：上週
- 統計口徑：信件數 / 案件數
- 總數：X 封

## 二、分類統計表
| 分類 | 數量 | 占比 | 代表性內容摘要 | 備註 |
|---|---:|---:|---|---|
| 配送延誤 / 未送達 | 0 | 0% | 例如：包裹超過預計到貨日仍未收到 |  |

## 三、明細表（可選）
| 日期 | 寄件者 | 主旨 | 分類 | 判定理由 |
|---|---|---|---|---|

# 品質要求
- 分類名稱要一致，避免同義詞混用造成統計失真。
- 不要憑空推測郵件內容；看不清楚就標記待確認。
- 若郵件數量很多，先完成分類規則，再批次處理，避免前後標準不一致。
- 若資料中有敏感個資，輸出時只保留必要欄位，避免揭露不需要的細節。
