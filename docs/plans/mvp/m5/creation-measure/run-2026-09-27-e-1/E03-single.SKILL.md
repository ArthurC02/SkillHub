# 目的
將農會社員傳來的訂購訊息整理成結構化訂單明細，排除寒暄、閒聊與無關內容，並計算總金額。

# 適用情境
- 訊息是自然語言、口語化、分段或混雜多個主題。
- 需要從訊息中找出實際要訂購的品項、數量、單價。
- 需要把每一項整理成清單並加總金額。

# 處理原則
1. 只整理「實際訂購」內容，不把寒暄、問候、抱怨、聊天、簽名檔、轉傳內容當成訂單。
2. 若同一品項出現多次，先判斷是否為重複確認；若是同一筆訂單的重述，合併為一筆並以最後明確數值為準。
3. 若數量、單價、品名有歧義，保留可確認的部分，並標示「待確認」。
4. 金額計算以「數量 × 單價」為準；若訊息已明示小計或總價，仍應自行核算並在有差異時標示。
5. 若訊息只提供總價、未提供單價，仍可列出品項與數量，但單價標示為「未提供」。
6. 若訊息只提供單價、未提供數量，數量標示為「未提供」，且無法計算該項小計。
7. 若有折扣、運費、手續費、稅金或其他附加費用，應另外列出，不要混入商品小計；若無法判定是否應納入總金額，標示待確認。

# 操作步驟
1. 通讀整段訊息，先找出所有與訂購有關的句子、數字、單位與品名。
2. 排除寒暄與無關內容，例如：
   - 問候、致意、感謝
   - 天氣、近況、聊天
   - 與訂購無關的說明
3. 將每個訂購項目拆成以下欄位：
   - 品項名稱
   - 數量
   - 單位（如斤、箱、包、袋、瓶、盒、組、份等）
   - 單價
   - 小計
   - 備註（如規格、口味、顏色、是否待確認）
4. 若數量與單位黏在一起，拆開理解，例如「3箱」視為數量 3、單位 箱。
5. 若價格寫法不完整，依常見語意判讀：
   - 「一箱 500」通常表示單價 500
   - 「500/箱」表示單價 500
   - 「3箱共1500」表示小計 1500，單價可反推為 500
6. 若同一行包含多個品項，逐項拆分。
7. 若有合計、總計、總額，將其與自行計算結果比對。
8. 若可計算，輸出總金額；若部分項目缺少必要資訊，則輸出「可計算總額」與「待確認項目」。

# 輸出格式
請用以下格式整理：

## 訂購明細
| 品項 | 數量 | 單位 | 單價 | 小計 | 備註 |
|---|---:|---|---:|---:|---|
| ... | ... | ... | ... | ... | ... |

## 總金額
- 可計算總額：XXX
- 訊息中原始總額（如有）：XXX
- 差異（如有）：XXX

## 待確認項目
- ...

# 判讀規則補充
- 數字與中文數量詞都要辨識，例如「兩箱」視為 2 箱。
- 若品名後面接規格或口味，應保留在品項名稱或備註中，避免誤拆。
- 若訊息中有「要」「訂」「麻煩」「幫我留」「再來」等語氣，且後面接品項與數量，通常視為訂購內容。
- 若出現「不用」「取消」「改成」等字樣，應以最新明確指示為準。
- 若訊息中有多位人名或多筆對話，僅整理發話者明確提出的訂購內容；不確定歸屬時標示待確認。

# 注意事項
- 不要自行補齊未提供的價格或數量。
- 不要把推測當成事實；凡無法確定者都要標示待確認。
- 若訊息內容不足以形成訂單，仍需輸出已辨識內容與缺漏項目。
