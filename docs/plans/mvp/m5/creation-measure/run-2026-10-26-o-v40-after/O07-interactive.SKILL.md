# 外送延誤道歉訊息

依照以下步驟，為輸入中的每筆訂單分別準備一則繁體中文顧客訊息。只使用已提供的資料，不代替使用者傳送訊息。

1. **檢核輸入。** 從 Skill 所在目錄執行 `python scripts/check_input.py`，依 `scripts/input_schema.json` 檢核訂單資料。只使用檢核後的值；逐字保留檢核程式輸出的每一行假設，並在答案中呈現。不得自行重新解析或驗證檢核值。
2. **處理每筆訂單。** 若訂單編號、延誤或補償金額缺漏，不猜值；提供可直接使用、以「未提供」標明缺漏欄位的訊息範本。若檢核指出延誤分鐘數不是正整數，該筆不寫道歉訊息；簡短指出該筆的原始延誤值，請提出請求的人確認並提供正整數。其他可判定的訂單仍照常處理。
3. **產生訊息。** 對每筆資料完整且已檢核的訂單，使用以下命令，將三個實際檢核值依序填入 `--record` 後：`python scripts/apology.py --record "訂單編號" 延誤分鐘數 補償金額`。命令可用重複的 `--record` 一次傳入多筆；每筆會分別產生一則訊息。呈現腳本輸出的訊息，不改寫輸入中的事實。延誤未滿 10 分鐘時只道歉，不提補償；延誤達 10 分鐘或以上時，道歉並提及補償金額。中文數字依檢核結果處理；若檢核輸出相關假設，保留該行，並使其讀法說明在答案中清楚可見。
4. **檢查並交付。** 將每筆訊息分別寫入文字檔，使用 `python scripts/check_output.py --max-sentences 2 --require "訂單編號" --require "延誤分鐘數 分鐘"` 檢查；達到補償門檻的訊息另加 `--require "補償金額 元"`。以每筆實際值替換引號內的文字，修整訊息直到程式輸出 `OK`。合併各筆已檢查的內容及須保留的假設行，答案只輸出這些內容；無效延誤的提示不冒充道歉訊息。每則道歉訊息最多兩句，以「。」「？」「！」結尾的句子計數。

若執行時遇到本 Skill 無法完成的外部動作，答案最後各用一行指出該動作、明確說明此代理無法執行，並指出必須由提出請求的人或其指定負責者完成。
