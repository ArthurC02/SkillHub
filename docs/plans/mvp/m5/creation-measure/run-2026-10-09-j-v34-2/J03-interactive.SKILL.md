# 社區團購訂單加總

依下列步驟處理使用者貼上的群組訂購訊息。只根據原文抽取資訊，不查價、不補造價格、數量、稅費或折扣。直接在本次回覆交付整理結果；缺資料時提供可用的明細與待確認標記，不以追問取代結果。

## 步驟

1. 閱讀所有訂購訊息，逐筆抽取商品品名、規格、計量單位、數量、單價、幣別及原文中相關的備註。宅配運費辨識為運費，不當作商品，也不放進計算資料。保留使用者提供的事實與寫法；不要把推測當成事實。
2. 數量明確但單價沒寫，或數量有歧義時，保留已知資訊並標註待確認，不猜測，也不讓該筆進入可計算小計或總額。品項和單價明確、數量省略時，按 1 個計量單位處理；單位也沒寫時，清楚標示原文未提供單位。缺少的幣別標示「幣別未提供」。
3. 為已抽取的商品建立 JSON 檔 `order_records.json`，格式如下；有幾筆訂購紀錄就放幾個物件。`quantity`、`unit_price` 使用數字字串，不能判定的值使用 `null`。將數量歧義或其他待確認原因寫入 `note`，幣別照原文填入；沒有提供幣別時用空字串。不要把運費放入檔案。

   ```json
   {
     "records": [
       {
         "item": "商品原文品名",
         "unit": "規格與計量單位",
         "quantity": "2",
         "unit_price": "30",
         "currency": "NT$",
         "note": ""
       }
     ]
   }
   ```

   `unit` 寫入可用來辨識同類訂單的規格和計量單位；若原文沒有提供，填「未提供」。若數量未寫而依規則採用 1，將 `quantity` 設為 `1`，並在 `note` 註明採用數量 1 的假設。
4. 從放有此 `SKILL.md` 的目錄執行：

   ```sh
   python scripts/sum_orders.py --input order_records.json
   ```

   以腳本列出的明細、待確認項目和各幣別總額為準，將其結果作為回覆。不同品名、規格／單位、單價或幣別不合併；同樣品名、規格／單位、單價與幣別的可計算訂單合併。幣別不同時分開列總額，不跨幣別相加。
5. 回覆用「品項、數量、單價、小計」表格呈現腳本結果，另列商品總額及待確認事項。說明未計入的待確認項目；若有任何未計入項目，明確指出總額尚未完整。計算能得出的總額，不要略過已知可加總部分。若腳本以代碼 2 結束，照其一行錯誤訊息指出不可使用的值，請提出請求的人確認該值；不提供依賴該值的總額，也不詢問其他事情。
