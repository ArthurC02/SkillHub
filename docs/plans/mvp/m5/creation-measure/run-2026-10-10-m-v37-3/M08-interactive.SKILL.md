# 魚苗訂單核對

依序整理訂單訊息、檢查資料並計算魚苗與水草的商品金額。只使用訊息明確提供的事實；不得猜測缺漏資料或自行挑選互相矛盾的值。

## 步驟

1. 從輸入中辨認訂單、日期、品項、數量、單價、幣別及其他費用。按明確訂單編號分組；沒有編號時，每則獨立訂單訊息為一筆。未給編號、品項名稱或日期時，標示「未提供」，不因此停止其他可做的核對。
2. 保留原訊息的數字、單位及幣別。只驗證明確提供的日期，按公曆檢查是否存在。把商品分類為魚苗、水草或其他；運費及其他非魚苗、水草項目不得納入商品總額。
3. 將整理出的記錄轉成 JSON，傳給計算腳本。每筆記錄使用 `order`、`item`、`quantity`、`unit_price`、`date` 欄位；未提供的值用 `null`。數量和單價只傳數值，不帶單位；單位和幣別另記在呈現用資料中，不推定缺少的幣別。可用 `unusable_values` 記下原訊息中無法辨識成數值的欄位及原文。例：`{"records":[{"order":"A","item":"魚苗","quantity":100,"unit_price":0.8,"date":"2026-10-08"}]}`。若同一品項被重複記載，保留各筆以供腳本核對。
4. 從持有本 `SKILL.md` 的目錄執行 `python scripts/check_order.py --data '<JSON>'`。如腳本以 exit code 2 拒絕參數，依原訊息修正自己整理錯的參數後重跑；若原值本身不能辨識，記入 `unusable_values` 後重跑，不得自行改寫該事實。使用腳本輸出的結果，不自行另算金額。
5. 以繁體中文表格呈現訂單編號、日期、品項、數量、單價、商品小計及核對狀態；另列腳本指出的矛盾、待確認資料及其他費用。缺漏值標為「未提供」或「待確認」，不猜單價、不推定折扣或稅費。把腳本輸出的訂單總額原樣呈現；只包括魚苗與水草商品金額，清楚註明其他費用不計入。若腳本沒有給出訂單總額，不可自行補算或稱為最終總額。
6. 若本次請求提到任何需要本代理人無法執行的動作，先交付可用內容；答案最後為每項動作各寫一行，明言本代理人不能代辦，並指出由提出請求的人或請求指定的負責人執行。不得聲稱已執行該動作。
