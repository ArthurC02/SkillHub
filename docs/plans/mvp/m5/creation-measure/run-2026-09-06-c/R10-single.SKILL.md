## 目的

將 Slack 三個指定頻道中的「問題」找出來，判斷哪些尚未回覆，並整理成一份附原始訊息連結的清單。

## 適用情境

- 需要每週做一次 Slack 問題彙整
- 來源固定為三個頻道
- 產出要給人快速查看與後續追蹤

## 執行步驟

1. **確認三個頻道名稱**
   - 若任務中已明確指定三個頻道，直接使用。
   - 若未指定，先向使用者確認三個頻道名稱後再進行。

2. **收集本週訊息**
   - 只看本週範圍內的訊息；若使用者另有定義週期，依其定義。
   - 在每個頻道中找出看起來是「問題」的訊息，例如：
     - 以問號結尾
     - 明確詢問「怎麼做」「為什麼」「是否可以」
     - 需要協助、確認、排除錯誤的貼文
   - 排除明顯不是問題的內容，例如公告、純分享、閒聊、已完成結論。

3. **判斷是否已回覆**
   - 對每個候選問題，檢查其後續串回覆與同串訊息。
   - 視為「已回覆」的情況：
     - 有明確回答內容
     - 原提問者或他人已確認解決
     - 問題串中已有可直接作為答案的回應
   - 視為「未回覆」的情況：
     - 沒有任何回應
     - 只有表情符號、已讀、或無實質內容的回覆
     - 回覆沒有回答問題本身

4. **去重與合併**
   - 同一問題若被多次轉貼或在不同頻道重複出現，只保留最原始、最完整的一筆。
   - 若同一串中有多個子問題，分開列出，避免混成一筆。

5. **整理輸出清單**
   - 每筆至少包含：
     - 頻道名稱
     - 發問者
     - 問題摘要
     - 原始訊息連結
   - 依需要可加上發問時間，方便排序與追蹤。
   - 以「未回覆」為唯一收錄條件，不要把已回覆問題混入。

## 輸出格式

用條列清單輸出，每筆一行，格式如下：

- [頻道] 發問者：問題摘要 — 連結

若需要更清楚，可改成：

- [頻道] 發問者｜時間：問題摘要
  - 連結：URL

## 注意事項

- 不要臆測回覆內容；只有在串內能明確看出已回答時，才排除。
- 不要把一般討論誤判成問題。
- 若無法取得訊息連結，至少保留頻道、時間與可辨識的訊息內容。
- 若三個頻道中沒有未回覆問題，輸出「本週無未回覆問題」。
