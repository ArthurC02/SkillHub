## 目的
將使用者的履歷改寫為更貼近資料分析職缺的版本，優先凸顯資料處理、分析、視覺化、報表、自動化、SQL、Python、Excel、統計與商業洞察等相關經驗，並控制在一頁以內。

## 先確認資訊
如果使用者沒有同時提供以下內容，先用最少問題補齊：
1. 目前履歷全文。
2. 目標職缺描述，或至少職稱與產業。
3. 是否必須保留一頁以內。
4. 是否有特定限制：中文或英文、是否要保留學歷/證照/作品集、是否要保留所有工作經歷。

如果缺少職缺描述，就以「資料分析職缺常見要求」為基準改寫，但不要捏造不存在的技能或經歷。

## 改寫原則
1. 以資料分析相關性排序內容：摘要 > 技能 > 工作經歷 > 專案 > 學歷。
2. 把泛用敘述改成可量化成果，優先使用數字、比例、規模、頻率、工具與影響。
3. 將職責改寫成「動作 + 工具/方法 + 結果」的句型。
4. 強調可轉移技能：資料清理、資料驗證、指標設計、儀表板、A/B 測試、需求溝通、跨部門協作。
5. 若原履歷偏向其他職能，保留與分析最相關的部分，刪除與目標職缺關聯低的內容。
6. 不新增未提供的學歷、證照、工具熟練度或工作成果。
7. 若資訊不足以量化，保留具體動詞與工具名稱，避免空泛形容詞。
8. 內容必須自然、專業、可直接使用，不要寫成說明稿。

## 改寫步驟
1. 讀取原履歷，找出與資料分析最相關的經歷、專案與技能。
2. 對照職缺需求，標記應強化的關鍵字與能力。
3. 重寫履歷摘要，讓第一段直接對準資料分析角色。
4. 重整技能區塊，將工具與方法分組，刪除不相關項目。
5. 重寫每段工作經歷：
   - 每個職位保留 2–4 個最相關條列。
   - 每條以成果導向表述，盡量包含數字。
   - 若有分析、報表、儀表板、SQL、Python、Excel、BI 工具、資料驗證、流程改善，優先保留。
6. 若有專案，將最能證明分析能力的專案放在工作經歷後或獨立專案區。
7. 壓縮整體篇幅到一頁以內：刪除重複、過度細節、與目標職缺無關內容。
8. 最後檢查是否符合資料分析職缺語氣，並確認沒有捏造內容。

## 輸出格式
直接輸出改寫後的履歷內容，不要加前言、不要解釋修改原因、不要列出修改清單。

## 版面建議
若使用者未指定格式，採用以下結構：
- 姓名 / 聯絡方式
- 專業摘要
- 核心技能
- 工作經歷
- 專案經驗（如有且相關）
- 學歷 / 證照（如有且必要）

## 長度控制
- 目標為一頁以內。
- 若原始內容過長，優先保留最近、最相關、最具量化成果的內容。
- 若使用者要求更短版本，可進一步壓縮為精簡版。
