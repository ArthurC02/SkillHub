## 目的

每週從三個 Slack 頻道中找出「未回覆的問題」，整理成可直接追蹤的清單，並附上每則訊息的連結。

## 適用範圍

- 只處理使用者指定的三個 Slack 頻道。
- 只列出看起來是「問題／請求／待確認事項」且在該訊息串中沒有任何回覆的項目。
- 若無法確認是否為問題，先保守排除，並在備註中標示「需人工確認」。

## 作業步驟

1. 取得本週範圍
   - 以最近 7 天為「本週」；若使用者或工作環境另有明確週期定義，依其定義。
   - 若需要更精準的週起訖，先確認時區與週起始日。

2. 檢視三個頻道
   - 逐一查看三個指定頻道中本週的新訊息。
   - 只關注看起來是在提問、請求協助、要求確認、或等待他人回應的訊息。

3. 判定是否「未回覆」
   - 若該訊息串沒有任何回覆，視為未回覆。
   - 若只有表情符號、已讀、或非實質文字回應，不算回覆。
   - 若有回覆但內容只是轉貼、補充資訊、或同一人自問自答，仍需人工判斷是否算已回覆；不確定時標示需確認。

4. 排除不該列入的項目
   - 非問題型內容，例如公告、閒聊、純資訊分享，不列入。
   - 已有明確解答或已被接手處理的，不列入。
   - 重複貼文只保留一筆，優先保留最新且資訊最完整的一筆。

5. 建立清單
   - 每筆至少包含：
     - 頻道名稱
     - 發文者
     - 訊息摘要
     - 發文時間
     - 訊息連結
   - 摘要要短，保留問題核心，不要改寫成長篇說明。

6. 排序
   - 先依頻道分組，再依時間由新到舊排序。
   - 若需要更高優先順序，可把較急迫、較明確需要回覆的項目排前面，但不要改變頻道分組原則。

## 輸出格式

使用以下格式輸出：

### #頻道名稱
- [摘要](連結) — 發文者，時間
- [摘要](連結) — 發文者，時間

### #另一個頻道名稱
- [摘要](連結) — 發文者，時間

## 品質檢查

- 每一筆都必須能點開到原始訊息。
- 每一筆都必須是「問題」且「未回覆」。
- 若某筆是否未回覆無法確定，先不要硬列；改為在最後加上「需人工確認」區段，列出疑點與原因。
- 若三個頻道都沒有符合項目，輸出「本週沒有找到未回覆的問題」。
