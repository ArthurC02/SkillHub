# 目的
把會議逐字稿整理成清楚、可執行的待辦清單。每一條待辦都必須包含：
- 具體任務
- 負責人
- 期限

# 處理流程
1. **先通讀逐字稿**
   - 找出所有明確的行動項目、決議、待確認事項、後續跟進事項。
   - 分辨哪些是「要做的事」，哪些只是討論內容或背景資訊。

2. **抽取待辦**
   - 只保留可執行的事項。
   - 若同一事項被多次提到，合併成一條。
   - 若一段話包含多個動作，拆成多條待辦。

3. **補齊三個必要欄位**
   - **負責人**：優先使用逐字稿中明確提到的人名、職稱或團隊。
   - **期限**：優先使用明確日期、時間點、會議後多久、或相對期限。
   - **任務內容**：用簡短、具體、可執行的語句重寫。

4. **處理缺漏資訊**
   - 如果逐字稿沒有明確說出負責人，標記為「未指派」或「待確認」。
   - 如果沒有明確期限，標記為「未定」或「待確認」。
   - 不要自行捏造人名、日期或承諾。

5. **整理成清單**
   - 以條列或表格輸出皆可，但每條都要有三欄：任務、負責人、期限。
   - 內容要精簡，避免保留冗長口語。

# 判斷原則
- 優先抓取帶有以下訊號的句子：
  - 「我來…」
  - 「請…」
  - 「麻煩…」
  - 「下週前…」
  - 「這件事由…負責」
  - 「我們要…」
  - 「先…再…」
- 若一句話只是討論、意見、抱怨、背景說明，通常不列入待辦。
- 若期限是相對時間，保留原文並盡量轉成清楚格式，例如「本週五前」、「下次會議前」。
- 若負責人是團隊而非個人，可寫團隊名稱。

# 輸出格式
使用以下格式之一：

## 格式 A：條列
- 任務：...
  - 負責人：...
  - 期限：...

## 格式 B：表格
| 任務 | 負責人 | 期限 |
|---|---|---|
| ... | ... | ... |

# 品質檢查
輸出前確認：
- 每條待辦都有負責人
- 每條待辦都有期限
- 任務描述具體且可執行
- 沒有把背景討論誤寫成待辦
- 沒有自行補造未出現的資訊
