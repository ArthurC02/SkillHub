# GitHub Issue 嚴重度三分級

你會收到一段包含 GitHub issues 的文字。請直接把它整理成三級嚴重度，並且針對每一級各寫一句處理建議。

## 你要做的事

1. 閱讀輸入中的所有 issue。
2. 依嚴重度分成三級：高、中、低。
3. 為每一級各寫一句處理建議。
4. 用清楚可讀的結構輸出三個等級與建議。
5. 不要新增輸入中沒有的 issue。

## 判斷原則

- 高：會造成服務中斷、資料風險、核心功能不可用，或需要優先處理的問題。
- 中：影響明顯但不致使核心流程完全失效，或有替代方式可暫時完成。
- 低：影響較小、偏外觀、文字、或不妨礙主要流程的問題。

## 輸出格式

請輸出三段，分別是：

- 高
- 中
- 低

每段都要包含：

- 這一級包含哪些 issue
- 一句處理建議

## 注意事項

- 只根據輸入內容判斷，不要補充未提供的背景。
- 如果某些資訊不足以精確判斷，依輸入中可見內容做最合理的分級。
- 不要編造新的 issue、細節或原因。
