## 目的

每週從 Slack 的三個指定頻道中，找出「尚未回覆」的問題，整理成可直接貼出的清單，並附上每則訊息的連結。

## 適用範圍

- 只處理使用者指定的三個 Slack 頻道。
- 只列出「問題」且目前看起來沒有任何回覆的訊息。
- 若無法直接存取 Slack、無法查看頻道內容，或無法取得訊息連結，則明確說明需要哪些資訊，並停止，不要臆測。

## 作業步驟

1. **確認三個頻道名稱**
   - 先從使用者提供的資訊中辨識三個 Slack 頻道。
   - 若三個頻道未明確列出，先詢問使用者提供頻道名稱或連結。

2. **收集本週範圍內的訊息**
   - 以最近七天為預設週期，除非使用者另有指定。
   - 逐一檢視三個頻道中本週的訊息。
   - 只保留看起來是在提問、求助、請確認、請協助處理的訊息。

3. **判定是否「未回覆」**
   - 對每則候選問題，檢查其串接回覆、thread reply、或明顯的後續回應。
   - 若有任何實質回覆，視為已回覆，不列入清單。
   - 若只有表情符號反應、已讀、或與問題無關的短句，仍視情況判斷；原則上只有真正文字回覆才算已回覆。
   - 若無法確認是否有回覆，標記為「待確認」，不要直接當成未回覆。

4. **整理輸出清單**
   - 每筆至少包含：
     - 頻道名稱
     - 發問者
     - 問題摘要
     - 訊息連結
   - 依時間由新到舊排序，或依頻道分組後再按時間排序；若使用者未指定，優先採用時間由新到舊。

5. **去除重複與雜訊**
   - 同一則訊息不要重複列出。
   - 若同一問題被多次轉貼，只保留最原始的那則，除非使用者要求保留所有版本。
   - 排除明顯不是問題的公告、閒聊、純貼圖、純反應訊息。

## 輸出格式

使用以下格式輸出：

- `# 頻道名稱`
  - `發問者｜問題摘要｜連結`

若有待確認項目，另外列在最後：

- `待確認`
  - `頻道名稱｜發問者｜問題摘要｜原因`

## 注意事項

- 不要捏造 Slack 內容、回覆狀態或連結。
- 不要把已回覆的問題列入未回覆清單。
- 若資料不足以判定，寧可標示待確認，也不要猜測。
