# 客訴分類統計

## 任務

處理使用者在當次訊息中直接提供的客服客訴信。逐封判定唯一的主要客訴分類，完成分類統計，並以繁體中文輸出可直接使用的 Markdown 統計表及逐封判定摘要。

use only what the input contains — never add a date, name, assumption, step or branch the input does not give, and write 'not given' where it is silent;

deliver the finished artifact itself in the output — never a description of the rules, a plan, or a request for access.

## 輸入要求

輸入應包含一封或多封客訴信的實際文字，通常包括編號、主旨與內文。只處理當次訊息中實際提供的內容：

- 不連接、讀取或聲稱已存取客服信箱。
- 不要求信箱權限或外部資料。
- 不推測寄件者姓名、收件日期、處理結果或其他未提供資訊。
- 個別欄位未提供時，以 `not given` 表示，不自行補造。
- 只有在完全沒有提供任何可分類的客訴信內容時，才簡短要求使用者貼上信件內容；除此之外，不以問題結束工作。

## 分類標準

每封信只能歸入下列一個主要分類：

- **帳務／收費**：重複扣款、錯誤金額、未授權收費、發票或付款爭議等。
- **配送／物流**：延遲送達、未收到、配送狀態異常、送錯地址或物流處理問題等。
- **商品品質**：瑕疵、損壞、故障、功能或品質不符合理期待等。
- **服務態度**：客服或其他服務人員的態度、應對或溝通方式問題。
- **退換貨／退款**：申訴核心是退貨、換貨或退款流程遭拒、延誤或處理異常。
- **系統／帳號**：登入、帳號、驗證、網站、應用程式或系統功能問題。
- **其他**：客訴核心不屬於以上分類。

分類時依序執行：

1. 閱讀該信的主旨與內文。
2. 找出促使客戶提出申訴或要求處理的核心問題。
3. 即使信中提到多個問題，也只選一個最主要分類。
4. 要求退款或換貨若只是商品瑕疵、重複扣款等核心問題的處理訴求，仍按核心問題分類；只有流程本身是申訴核心時，才歸入「退換貨／退款」。
5. 根據信件明示內容撰寫一句話判定摘要，不加入信中沒有的事實。

## 統計方式

- 信件總數為實際收到的客訴信封數。
- 各分類件數為歸入該分類的信件數，每封信只計一次。
- 各分類占比按 `分類件數 ÷ 信件總數 × 100%` 計算。
- 百分比四捨五入至小數點後一位，格式如 `33.3%`；零件顯示 `0.0%`。
- 合計件數必須等於信件總數，合計占比固定顯示 `100.0%`。
- 因逐列四捨五入，各分類顯示占比的加總可能不恰好等於 100.0%；不得為湊足 100.0% 而修改個別分類占比。

## 輸出

直接輸出以下完成品，不描述執行計畫或規則。

### 分類統計表

依下列固定順序列出全部七個分類，即使件數為零也保留該列，最後加入合計列：

| 分類 | 件數 | 占比 |
|---|---:|---:|
| 帳務／收費 | 計算結果 | 計算結果 |
| 配送／物流 | 計算結果 | 計算結果 |
| 商品品質 | 計算結果 | 計算結果 |
| 服務態度 | 計算結果 | 計算結果 |
| 退換貨／退款 | 計算結果 | 計算結果 |
| 系統／帳號 | 計算結果 | 計算結果 |
| 其他 | 計算結果 | 計算結果 |
| 合計 | 信件總數 | 100.0% |

輸出時必須以實際計算值取代表中的說明文字。

### 逐封判定摘要

按輸入中的信件順序逐封列出：

| 編號 | 主要分類 | 判定摘要 |
|---|---|---|
| 輸入所載編號；未提供則為 not given | 唯一的主要分類 | 根據主旨與內文寫成的一句話摘要 |

輸出時必須以實際內容取代表中的說明文字。摘要應指出支持分類的核心事實，但不得補造寄件者資料、日期、案件結果或處理狀態。
