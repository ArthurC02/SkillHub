# 請假申請審核

收到請假申請後，在一次執行中完成全部申請的計算、判定與結果表格，不要只說明規則或提出執行計畫。

## 核心限制

- use only what the input contains — never add a date, name, assumption, step or branch the input does not give, and write 'not given' where it is silent;
- deliver the finished artifact itself in the output — never a description of the rules, a plan, or a request for access.
- 不使用外部工具。
- 只審核事假與病假的固定規則，不處理主管裁量、假期餘額、國定假日或其他假別。
- 只依輸入的「是否附證明」判定，不驗證證明的真偽或內容。

## 必要輸入

每筆申請應包含以下欄位：

- 申請人
- 假別
- 申請日期
- 請假開始日
- 請假結束日
- 是否附證明

日期使用 `YYYY-MM-DD` 格式。如果申請資料本身缺少必要欄位，僅指出缺少哪些欄位並請使用者補充，不得猜測缺漏值；缺漏處標示為 `not given`。

## 審核步驟

對每筆申請依序完成以下處理：

1. 計算請假日數：以請假開始日與請假結束日含首尾計算。計算式為「結束日減開始日的日曆日差 + 1」。
2. 依假別套用對應規則，只計算日曆日，不改用工作日。
3. 將結果判定為「通過」或「退回」。
4. 寫出簡短但明確的原因；退回時必須指出實際違反的規則。
5. 完成所有申請後，直接輸出最終 Markdown 表格。

## 事假規則

1. 計算提前天數：請假開始日減申請日期的日曆日差。
2. 提前天數大於或等於 3 時，判定為「通過」。原因須指出已提前至少 3 個日曆日申請；可包含實際提前天數。
3. 提前天數小於 3 時，判定為「退回」。原因須包含實際提前天數，並明確指出不符合至少提前 3 個日曆日申請的規則。

## 病假規則

1. 申請日期不得晚於請假開始日；病假可在請假開始日當天提出。
2. 申請日期晚於請假開始日時，判定為「退回」，並指出病假不得晚於請假開始日提出。
3. 請假日數不超過 2 日時，不要求附證明。若申請日期未晚於請假開始日，判定為「通過」，原因指出病假日數不超過 2 日，可免附證明。
4. 請假日數超過 2 日且「是否附證明」為「是」時，若申請日期未晚於請假開始日，判定為「通過」，原因指出病假超過 2 日且已附證明。
5. 請假日數超過 2 日且「是否附證明」為「否」時，判定為「退回」，原因明確指出病假超過 2 日但未附證明。
6. 若同時違反申請日期與證明規則，原因須列明兩項實際違規事項。

## 輸出格式

只輸出一個 Markdown 表格，每筆輸入申請對應一列，並維持輸入順序。使用以下五個欄位：

| 申請人 | 假別 | 請假日數 | 審核結果 | 原因 |
|---|---|---:|---|---|

輸出要求：

- 「請假日數」填寫含首尾計算後的整數日數。
- 「審核結果」只能填寫「通過」或「退回」。
- 通過原因須簡短說明符合哪項規則。
- 退回原因須明確包含違反的規則及輸入可推導出的實際天數或缺少證明情形。
- 不在表格前後加入規則摘要、計畫、免責聲明或額外問題。
