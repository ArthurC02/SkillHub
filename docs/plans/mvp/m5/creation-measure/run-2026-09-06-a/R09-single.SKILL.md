## 目的
將使用者提供的履歷內容，改寫成更符合資料分析職缺的一頁版履歷。重點是保留真實經歷，重新排序與措辭，讓內容更聚焦在資料處理、分析、視覺化、商業洞察與跨部門溝通。

## 工作原則
- 只根據使用者提供的履歷內容改寫，不要捏造學歷、職稱、技能、數據或成果。
- 若資訊不足以完成一頁版改寫，先列出需要補充的關鍵資訊，再進行可完成的部分。
- 以資料分析職缺常見關鍵字與能力為導向，但必須與原始經歷一致。
- 目標篇幅控制在一頁內；內容要精簡、可掃讀、以成果與工具為主。

## 改寫流程
1. **讀取原始履歷**
   - 找出學歷、工作經歷、專案、技能、證照與其他相關資訊。
   - 標記與資料分析最相關的內容：
     - 資料整理、清理、建模
     - SQL、Python、R、Excel
     - BI 工具（如 Tableau、Power BI、Looker）
     - 報表、自動化、儀表板
     - A/B test、指標分析、商業洞察
     - 與產品、營運、行銷、業務合作

2. **判斷可強調的主軸**
   - 若使用者有分析相關經驗，優先放在工作經歷與專案。
   - 若分析經驗較少，將可轉移技能寫成資料分析語言，例如：
     - 將「整理報表」改寫為「建立週/月報表並追蹤關鍵指標」
     - 將「處理資料」改寫為「清理與整併多來源資料，提升分析效率」
     - 將「協助主管」改寫為「提供數據摘要與洞察，支援決策」
   - 若有量化成果，保留並優先前置；若沒有，避免自行補數字。

3. **重組履歷結構**
   建議順序如下：
   - 標題：姓名、聯絡方式、LinkedIn/GitHub（若有）
   - 個人簡介：2–3 句，聚焦資料分析能力與產業/領域背景
   - 核心技能：分組列點，避免過長
   - 工作經歷：每段 3–5 點，先寫成果再寫方法
   - 專案經驗：若與資料分析高度相關，優先保留
   - 學歷與證照：簡潔列出

4. **撰寫個人簡介**
   - 用 2–3 句概括：
     - 目前背景
     - 資料分析相關能力
     - 想應徵的職務方向
   - 例如的寫法方向：
     - 「具備 X 年在 Y 領域的經驗，熟悉資料整理、報表分析與跨部門溝通。能使用 SQL / Python / Excel / BI 工具支援營運與決策，擅長將複雜資料轉化為可行洞察。」
   - 不要寫空泛形容詞堆疊。

5. **整理技能區塊**
   - 依類別分組，例如：
     - 資料分析：SQL、Python、Excel、統計分析
     - 視覺化：Tableau、Power BI
     - 資料處理：資料清理、ETL、資料整併
     - 商業能力：KPI 設計、報表製作、需求溝通
   - 只保留與目標職缺相關的技能。
   - 若原始履歷沒有明確工具名稱，不要自行補上。

6. **改寫工作經歷與專案**
   - 每個條目使用動詞開頭，並盡量包含：
     - 做了什麼
     - 用了什麼方法/工具
     - 帶來什麼結果
   - 優先使用資料分析導向動詞：
     - 分析、建立、整併、清理、追蹤、視覺化、優化、驗證、監控、預測、彙整
   - 若原文偏行政、營運或其他職能，轉寫時要保留真實工作內容，但突出可轉移能力。

7. **控制篇幅到一頁內**
   - 刪除與資料分析無關的細節。
   - 每段經歷保留最有價值的 3–5 點。
   - 避免長句與重複描述。
   - 若內容仍過長，優先刪除：
     - 與目標職缺無關的早期經歷
     - 細碎職責描述
     - 重複技能

## 輸出要求
- 直接輸出改寫後的履歷內容。
- 使用清楚的標題與條列。
- 保持專業、精簡、可直接貼入履歷文件。
- 若使用者要求特定語言，依其語言輸出；否則沿用使用者輸入語言。

## 資訊不足時的處理
若缺少以下任一項，先詢問或註明無法完整最佳化：
- 原始履歷全文
- 目標職缺名稱或職缺描述
- 想強調的工具或經驗

在資訊不足時，仍可先提供：
- 一版通用資料分析履歷
- 一份需要補充的資訊清單
- 可替換的措辭建議
