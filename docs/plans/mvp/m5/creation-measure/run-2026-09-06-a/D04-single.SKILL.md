# 伺服器 log 錯誤處理流程

依照下列流程執行，不要跳步。

1. **讀取伺服器 log 檔**
   - 取得當日或指定期間的伺服器 log。
   - 確認來源、時間範圍與檔案是否完整。

2. **篩出 ERROR 行**
   - 從 log 中只保留包含 `ERROR` 的行。
   - 若需要統計，先計算 ERROR 行數。

3. **判斷錯誤是否超過 10 筆**
   - 若 ERROR 行數 **大於 10**，走「是」分支。
   - 若 ERROR 行數 **不超過 10**，走「否」分支。

4. **若超過 10 筆：建立 Jira 問題單**
   - 建立一張 Jira issue，內容至少包含：
     - log 時間範圍
     - ERROR 數量
     - 主要錯誤摘要或代表性錯誤行
     - 影響範圍與初步觀察
   - 確保問題單可供後續追蹤與處理。

5. **通知值班工程師**
   - 將 Jira 問題單與錯誤摘要通知值班工程師。
   - 通知內容應清楚說明：
     - 已發現超過門檻的 ERROR
     - Jira 編號或連結
     - 需要立即關注的原因

6. **寫入每日摘要**
   - 不論是否超過 10 筆，最後都要寫入每日摘要。
   - 摘要至少記錄：
     - log 檢查時間
     - ERROR 數量
     - 是否超過 10 筆
     - 是否建立 Jira
     - 是否已通知值班工程師

## 分支規則

- **超過 10 筆**：`讀取 log → 篩出 ERROR → 判斷超過 10 → 建立 Jira → 通知值班工程師 → 寫入每日摘要`
- **不超過 10 筆**：`讀取 log → 篩出 ERROR → 判斷不超過 10 → 寫入每日摘要`

## 注意事項

- 不要把非 `ERROR` 行算進門檻判斷。
- 若 log 檔無法讀取或內容異常，先記錄問題，再依現場流程補充處理，但仍需保留每日摘要。
