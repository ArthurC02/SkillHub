# 目的
依照輸入的流程圖，將伺服器 log 處理流程整理成一個可攜式 Agent Skill。此 Skill 用於：讀取 log、篩出 ERROR 行、統計錯誤數是否超過 10 筆，並根據結果決定是否建立 Jira 問題單與通知值班工程師，最後都要寫入每日摘要。

# 使用時機
當你拿到一張描述 log 監控與告警處理的流程圖，並希望把它轉寫成可重複使用的 Agent Skill 時使用。特別適合需要保留流程順序、分支條件與不確定項目標註的情境。

# 輸入
- 流程圖內容。
- 與流程圖對應的已知資訊：log 來源、ERROR 判定方式、門檻值 10 筆、Jira 與通知動作、每日摘要動作。

# 輸出
- 一份結構化 Skill。
- Skill 內容需包含：
  - 目的與使用時機
  - 流程步驟
  - 分支條件
  - 已知限制與不確定項目
  - 工具需求說明（若流程圖沒有提供工具細節，必須明確標示未定）

# 製作原則
1. 先按照流程圖的順序寫出步驟，不要自行改變順序。
2. 保留明確條件：先篩出 ERROR，再判斷是否超過 10 筆。
3. 對兩個分支分別描述：
   - 超過 10 筆：建立 Jira 問題單、通知值班工程師、寫入每日摘要。
   - 不超過 10 筆：直接寫入每日摘要。
4. 不要補充未提供的 Jira 欄位、通知管道、摘要格式、保存位置或值班工程師定義。
5. 若流程圖未說明工具，將工具需求寫成「未提供，需由使用者補充」或等價表述，不要臆測。

# 寫作步驟
1. 讀取流程圖並列出所有節點。
2. 將節點整理成一個有順序的流程。
3. 找出所有條件與分支，並用明確語句描述。
4. 標記所有未確定資訊，例如摘要格式、保存位置、Jira 欄位、通知管道。
5. 產出可直接納入 Skill 的文字，維持中文敘述。

# 驗證檢查
在完成 Skill 草稿後，確認以下事項：
- 是否完整包含「讀取 log、篩出 ERROR、判斷是否超過 10 筆」三個核心步驟。
- 是否清楚分出超過門檻與未超過門檻兩條分支。
- 是否保留每日摘要動作，且不遺漏其在流程中的位置。
- 是否有標出所有未提供細節，而不是自行補寫。
- 是否維持與流程圖一致的順序與條件關係。

# 限制
- 不可捏造任何未提供的工具、欄位、格式或外部系統細節。
- 不可改寫流程圖的判斷順序。
- 不可假設 Jira 或通知系統的具體實作方式。
- 不可將不確定內容寫成既定事實。
