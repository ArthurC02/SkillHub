## 目的
從 Slack 的三個頻道中找出「問題訊息」且目前看起來尚未被回覆的項目，整理成可直接貼出的清單，並附上每則訊息的連結。

## 適用時機
- 需要每週彙整 Slack 裡尚未回覆的提問
- 需要把三個頻道的待處理問題做成清單
- 需要附上原始訊息連結方便追蹤

## 作業步驟
1. 先確認這次要檢查的三個 Slack 頻道名稱。
   - 如果使用者沒有明確提供，先詢問三個頻道名稱。
   - 若有時間範圍要求，預設只看最近 7 天；若使用者指定其他週期，依指定週期處理。

2. 在每個頻道中找出「問題訊息」。
   - 優先辨識帶有問號、明確詢問、請求協助、請人確認、請求決策的訊息。
   - 排除純公告、純資訊分享、已完成通知、閒聊。

3. 判斷是否「未回覆」。
   - 若訊息下方沒有任何回覆串，視為未回覆。
   - 若有回覆，但只是表情符號、已讀式回應、或與問題無關的雜訊，仍可視情況列入；但若已有實質答覆，則不列入。
   - 若原訊息已在後續訊息中自行更新為已解決，也不列入。

4. 為每個符合條件的項目收集以下資訊。
   - 頻道名稱
   - 發問者
   - 發問時間
   - 問題摘要：用一句話濃縮原問題
   - 原始訊息連結

5. 去重與整理。
   - 同一問題若被轉貼到多個頻道，只保留最早或最完整的一則，並註明重複來源如有必要。
   - 依頻道分組，或依時間由新到舊排序；若使用者未指定，採時間由新到舊。

6. 輸出清單。
   - 每一項都要附上可點擊的 Slack 訊息連結。
   - 若無法取得連結，明確寫出無法取得，並保留可辨識資訊。
   - 不要編造回覆狀態；不確定時標示為「待確認」。

## 建議輸出格式
- 頻道名
  - 發問者｜時間｜問題摘要｜連結

## 注意事項
- 這個任務需要能存取 Slack 訊息內容與訊息連結；若目前沒有 Slack 存取權限或無法讀取指定頻道，應明確說明無法完成，並改為列出需要使用者提供的資訊。
- 不要把已經有實質回覆的問題列入「未回覆」。
- 不要憑空推測訊息內容；摘要必須忠於原文。
