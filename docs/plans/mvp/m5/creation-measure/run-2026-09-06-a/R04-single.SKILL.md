# 目的
將輸入的 GitHub issue 依嚴重度分成三級，並為每一級提供一句簡短、可執行的處理建議。

# 分級原則
使用以下三級：

1. **高**：會造成服務中斷、資料遺失、資安風險、核心功能完全不可用，或影響大量使用者。
2. **中**：會影響主要功能、造成明顯錯誤或工作受阻，但有替代方案或影響範圍有限。
3. **低**：文字修正、外觀調整、輕微錯誤、可接受的改善需求，或不影響主要流程。

# 處理步驟
1. **讀取 issue 內容**：確認每個 issue 的標題、描述、重現步驟、影響範圍、是否有錯誤訊息或截圖。
2. **判斷嚴重度**：
   - 若有明確的服務中斷、資料安全、資安、金流、登入失敗、核心流程無法完成，標為 **高**。
   - 若影響主要功能但仍可繞過，標為 **中**。
   - 若僅是小問題、優化、文案或低風險缺陷，標為 **低**。
3. **寫一句處理建議**：每個嚴重度只寫一句，內容要具體且可執行，例如：
   - 高：先暫停相關變更並立即修復，必要時回滾或加上臨時防護。
   - 中：排入近期修正，補上測試並確認是否有替代方案。
   - 低：納入一般待辦，於例行迭代中處理即可。
4. **輸出結果**：用清楚的表格或條列列出三級與建議；若有多個 issue，逐一標示其級別。

# 輸出格式
若只有分級總覽，請輸出：
- 高：一句處理建議
- 中：一句處理建議
- 低：一句處理建議

若有多個 issue，請輸出：
- Issue 標題／編號
- 嚴重度：高／中／低
- 處理建議：一句話

# 注意事項
- 不要把「重要」和「緊急」混為一談；以實際影響為準。
- 若資訊不足，根據已知影響做保守判斷，並在建議中提醒補充重現資訊或影響範圍。
- 保持每個建議只有一句話，避免延伸成多步驟說明。
