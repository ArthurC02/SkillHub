## 目的
將使用者提供的履歷內容，改寫成更適合資料分析職缺的一頁版履歷。重點是保留真實經歷，重新排序與改寫成更貼近資料分析工作的語氣、關鍵字與成果表述。

## 先確認的資訊
如果使用者沒有一併提供以下內容，先用最少問題補齊：
1. 原始履歷全文或可編輯內容
2. 想投遞的資料分析職缺類型（例如：資料分析師、商業分析師、產品分析師、營運分析師）
3. 是否有特定技能要強調（例如 SQL、Python、Excel、Tableau、Power BI、A/B test）
4. 是否有字數、版面或語言偏好

若資訊不足以安全改寫，先請使用者貼上履歷內容，不要自行編造經歷。

## 改寫原則
1. 只使用使用者提供的真實資訊，不新增學歷、工作經歷、證照或數據。
2. 以資料分析職缺常見關鍵字重寫，但不要硬塞不符合事實的技能。
3. 優先呈現可量化成果、分析方法、工具、商業影響。
4. 內容控制在一頁內：通常約 300–600 字，視版面而定。
5. 以清楚、精簡、成果導向的語氣撰寫。
6. 若原履歷偏長，刪除與資料分析無關或重複的內容，保留最相關的 2–4 段經歷。

## 建議結構
依下列順序重寫：
1. **姓名與聯絡資訊**：保留必要資訊即可。
2. **職涯摘要**：2–3 句，概括分析背景、工具能力、商業理解與主要成果。
3. **核心技能**：列出與資料分析相關的技能群組，例如：
   - 資料處理：SQL、Excel、Python、R
   - 視覺化與報表：Tableau、Power BI、Looker
   - 分析方法：A/B test、回歸分析、漏斗分析、分群、指標設計
   - 商業應用：營運分析、產品分析、行銷分析、需求預測
4. **工作經歷**：每段經歷用 2–4 個條列，格式建議為「動作 + 方法/工具 + 成果」。
5. **學歷與證照**：只保留與職缺相關者。

## 改寫技巧
- 把「負責」改成「分析、建置、優化、監控、預測、驗證」。
- 把模糊描述改成具體成果，例如：
  - 「協助整理資料」→「使用 SQL 與 Excel 整理跨部門資料，建立每週報表」
  - 「提升效率」→「自動化報表流程，將製作時間縮短 40%」
- 若有數字，優先保留；若沒有，不要捏造，改寫成可驗證的描述。
- 若使用者背景不是純資料分析，也要找出可轉譯的能力，例如：
  - 業務經驗 → 客戶分群、銷售分析、成效追蹤
  - 行銷經驗 → 活動分析、轉換率優化、受眾洞察
  - 營運經驗 → 流程分析、KPI 監控、異常排查

## 輸出要求
- 直接輸出改寫後的履歷內容。
- 保持一頁內的精簡程度。
- 若使用者要求，可另外提供「可直接貼到履歷中的版本」或「條列修改建議」，但預設只輸出改寫稿。
- 不要加入說明性前言、改寫過程或額外評論，除非使用者要求。
