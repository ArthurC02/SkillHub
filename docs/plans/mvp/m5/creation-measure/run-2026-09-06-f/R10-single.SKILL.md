## 目的

從 Slack 的三個指定頻道中，找出「未回覆的問題」，整理成一份可直接分享的清單，並附上每則訊息的連結。

## 適用情境

- 每週例行整理待跟進事項
- 需要從三個 Slack 頻道中彙整尚未被回覆的提問
- 需要輸出給團隊追蹤、分派或提醒回覆

## 作業步驟

1. **確認範圍**
   - 先確認要檢查的三個 Slack 頻道名稱。
   - 若頻道名稱未提供，先向使用者詢問三個頻道名稱與時間範圍。
   - 預設以「最近 7 天」為檢查範圍；若使用者指定其他週期，依指定週期處理。

2. **蒐集訊息**
   - 逐一查看三個頻道在指定時間範圍內的訊息。
   - 只保留看起來是「問題、請求、待確認事項」的訊息。
   - 排除以下內容：
     - 已經有明確回覆或解決方案的串
     - 純公告、閒聊、表情回應
     - 不是提問或請求的訊息

3. **判定是否未回覆**
   - 對每則候選訊息，檢查其 thread 或後續回應。
   - 若該訊息下方沒有任何實質回覆，視為未回覆。
   - 若只有表情符號、簡短確認、或與問題無關的回應，不算已回覆。
   - 若原訊息已在後續訊息中自行補充答案，也不列入。

4. **整理清單**
   - 每則未回覆問題至少記錄以下資訊：
     - 頻道名稱
     - 發問者
     - 發問時間
     - 問題摘要
     - 訊息連結
   - 問題摘要要簡短、忠實，不要改寫成新的意思。
   - 若同一串有多個問題，分開列出，或合併成一條清楚的摘要，但要保留原始連結。

5. **排序原則**
   - 先依頻道分組。
   - 每個頻道內依時間由舊到新排序，或依使用者要求排序。
   - 若未指定排序，優先列出較早發問且仍未回覆者。

6. **輸出格式**
   - 以清單方式輸出，讓人可以直接點連結查看原文。
   - 建議格式如下：

     - [頻道名稱] 發問者｜問題摘要｜時間｜連結

   - 若有多筆，請保持一致格式。
   - 若某個頻道沒有未回覆問題，明確寫出「無」。

## 注意事項

- 這個任務需要能讀取 Slack 訊息與訊息連結；若目前沒有 Slack 存取權限或無法查看指定頻道，應明確告知無法完成，並請使用者提供匯出內容或可讀取的訊息資料。
- 不要臆測回覆內容；只有在看得到 thread 或後續訊息時才判定是否已回覆。
- 不要把已解決但未標記的討論誤判為未回覆；若有明確答案，排除。
- 若訊息內容模糊，寧可先保留並在摘要中標示為「疑似提問」，但仍需附上原始連結供人工確認。
