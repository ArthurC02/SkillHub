# 目的
將會議逐字稿轉成結構化待辦清單，每一條都必須包含：
- 待辦事項
- 負責人
- 期限

# 適用範圍
使用於：
- 客戶提供會議逐字稿、會議紀錄、轉錄文字
- 需要整理出 action items、owner、due date

不適用於：
- 只有錄音檔、沒有逐字稿
- 逐字稿內容無法辨識或缺少足夠資訊，且無法從上下文合理推定

# 工作步驟
1. **先通讀全文**
   - 找出所有明確的待辦、承諾、決議後續事項、追蹤事項。
   - 將純討論、背景說明、意見交換與已完成事項排除。

2. **辨識待辦項目**
   - 優先抓取帶有行動語意的句子，例如：
     - 「我來處理」
     - 「請 XX 在…前完成」
     - 「下週前補上」
     - 「需要再確認／補資料／發送／修改／聯絡」
   - 若同一事項被多次提及，只保留一條，避免重複。

3. **為每條待辦補齊三個欄位**
   - **待辦事項**：用簡潔、可執行的動詞開頭描述。
   - **負責人**：
     - 優先使用逐字稿中明示的人名、職稱或部門。
     - 若只有「我／我們／你們」等代稱，改寫成最可能的具體角色；若仍無法判定，標示為「未明確」並在備註中說明依據。
   - **期限**：
     - 優先擷取明確日期、時間、週期或相對期限（例如「本週五前」、「下週二」、「月底前」）。
     - 若只有相對時間，保留原文並盡量轉成清楚格式。
     - 若完全沒有期限，標示為「未提及」。

4. **處理模糊資訊**
   - 不要憑空補寫不存在的資訊。
   - 若負責人或期限不明確，保留原文線索並標示不確定性。
   - 若一句話包含多個動作，拆成多條待辦，前提是每條都能獨立執行。

5. **輸出格式**
   - 以條列或表格輸出皆可，但每條都要有以下欄位：
     - 待辦事項
     - 負責人
     - 期限
   - 建議使用表格，方便客戶直接複製使用。

# 輸出原則
- 保持精簡、可執行、可追蹤。
- 優先忠實反映逐字稿，不自行延伸會議未提及的內容。
- 若逐字稿中有明確優先順序或依賴關係，可在待辦事項中簡短註明。
