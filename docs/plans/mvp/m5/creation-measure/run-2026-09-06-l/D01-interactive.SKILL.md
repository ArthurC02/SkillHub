# 員工報帳流程圖結構化整理

將使用者提供的「員工報帳流程圖」整理成四個固定區塊：`nodes`、`conditions`、`branches`、`uncertainties`。此技能只處理流程圖內容，不補寫圖上沒有明說的步驟；若有圖上未標示清楚的連線、回圈或推定，必須保留在 `uncertainties`。

## 處理步驟

1. **讀取流程內容**
   - 先辨識流程中的所有明確節點。
   - 再辨識所有判斷條件。
   - 接著整理每個條件對應的分支走向。
   - 最後整理圖上未明確標示、但需要保留為推定的部分。

2. **輸出固定四區塊**
   - `nodes`
   - `conditions`
   - `branches`
   - `uncertainties`

3. **節點寫法**
   - 每個明確節點各自獨立列出。
   - 節點只寫圖上確實出現的動作或狀態。
   - 不把推測的補充流程寫進節點。

4. **條件寫法**
   - 只列出圖上的判斷問題或分支條件。
   - 每個條件各自獨立列出。

5. **分支寫法**
   - 逐一對應每個條件的分支結果。
   - 分支描述要能看出條件成立與否各會走向哪裡。
   - 若圖上連線含義需要推定，寫入 `uncertainties`，不要在 `branches` 內假裝確定。

6. **不確定處寫法**
   - 只列出圖上沒有明講、但讀圖時必須保留的疑點或推定。
   - 例如：回圈是否存在、否分支是否代表略過某步驟、連線是否表示特定順序等。

## 目前這張報帳流程圖的整理原則

依已確認的圖意，請保留以下內容：

### nodes
- 收到員工報帳申請
- 退回並要求 3 天內補件
- 送經理簽核
- 財務直接入帳
- 寄出付款通知信

### conditions
- 發票是否齊全
- 金額是否超過 5000

### branches
- 發票齊全：直接往下進入金額是否超過 5000 的判斷
- 發票不齊全：退回並要求 3 天內補件，再進入金額是否超過 5000 的判斷
- 金額超過 5000：送經理簽核後，由財務直接入帳
- 金額不超過 5000：財務直接入帳
- 最後都會寄出付款通知信

### uncertainties
- `退回並要求 3 天內補件` 後是否一定會重新檢查發票齊全，圖上未明確標示回圈
- `金額是否超過 5000` 的否分支直接連到 `財務直接入帳`，這只能視為依圖形連線的推定

## 輸出要求

- 使用繁體中文。
- 保持四區塊清楚可辨識。
- 內容要忠於圖上可見資訊，並把推定留在 `uncertainties`。
- 不要新增圖上沒有的條件、節點或分支。
