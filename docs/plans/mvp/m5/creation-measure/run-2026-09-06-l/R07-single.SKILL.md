## 目的

為 Python 函式補上缺失的 docstring，並將既有 docstring 修正為 Google 風格。

## 適用情境

- 使用者貼出一個或多個 Python 函式，要求補 docstring。
- 使用者要求把 docstring 統一成 Google 風格。
- 使用者提供的程式碼中有空白、過短、或不完整的 docstring，需要補齊參數、回傳值、例外與說明。

## 處理原則

1. 只根據使用者提供的程式碼與上下文撰寫 docstring；不要臆測不存在的行為。
2. 若函式行為無法從程式碼確定，使用保守、可驗證的描述，避免編造細節。
3. 以 Google 風格輸出，結構通常包含：
   - 簡短摘要句
   - 必要時的補充說明
   - `Args:`
   - `Returns:`
   - `Raises:`
   - `Yields:`（若是 generator）
   - `Attributes:`（通常只在類別 docstring 才用；函式一般不用）
4. 若函式沒有參數，就不要硬加 `Args:`。
5. 若函式沒有回傳值或明確回傳 `None`，可寫明 `Returns: None`，或省略 `Returns:`，但要一致且清楚。
6. 若函式可能拋出例外，只有在程式碼中能直接看出時才寫入 `Raises:`。
7. 若參數型別、預設值、或用途可從簽名與程式碼推得，寫得具體；若不可確定，寫中性描述。
8. 保持 docstring 簡潔、準確、可維護，不要加入與程式碼無關的建議。

## 寫作步驟

1. 讀函式簽名：名稱、參數、預設值、回傳型態註記、是否為 async、是否為 generator。
2. 讀函式本體：
   - 參數如何被使用
   - 回傳什麼
   - 是否有條件分支、特殊情況、例外
   - 是否有副作用（例如修改傳入物件、寫檔、發送請求）
3. 判斷 docstring 是否缺少以下內容：
   - 一句話摘要
   - 參數說明
   - 回傳說明
   - 例外說明
   - 產生器輸出說明
4. 依 Google 風格補寫或修正。
5. 若原 docstring 已有部分內容，保留正確資訊，只補缺漏並修正文法、格式與一致性。

## Google 風格格式要求

- 第一行是摘要句，使用祈使或描述式皆可，但要簡潔。
- 摘要後若有補充說明，空一行再寫。
- 區塊標題使用 `Args:`, `Returns:`, `Raises:`, `Yields:`。
- 每個參數格式：`name: 說明。`
- 若需要型別資訊，可寫成 `name (type): 說明。`，但不要與函式簽名明顯衝突。
- 回傳值格式：`type: 說明。`
- 例外格式：`ErrorType: 何時發生。`
- 保持縮排一致，通常區塊內容縮排 4 個空格。

## 輸出要求

- 直接輸出修正後的 docstring，或在需要時輸出包含 docstring 的完整函式片段。
- 不要解釋你做了什麼。
- 不要加入與 docstring 無關的內容。
- 若資訊不足以安全補寫，明確指出缺少哪些程式碼資訊，並只提供可確定的部分。
