## 用途與規則

根據申請人提供的購買日、申請日及實體教材包領取狀態，逐筆計算日曆日差並分類。只套用以下規則：已領取教材包，一律「不可退費」；未領取時，0–7 天（含）為「全額退費」、8–30 天（含）為「退一半」、31 天以上為「不可退費」。日數差是申請日減購買日，同日為 0 天。

## 步驟

1. 從請求中逐筆擷取識別名稱、購買日、申請日、是否已領取實體教材包。日期格式為 `YYYY-MM-DD`；狀態須為「是」或「否」。不需補問未要求的名稱，沒有名稱時以「第 N 筆」識別。
2. 保留輸入中的事實原樣，不推測缺漏資料。檢查日期是否存在、申請日是否早於購買日，以及同一欄位是否出現互相矛盾的值。列明每一個不能使用的值及其欄位，請提出請求的人確認；不計算依賴該值的結果。其他可用的申請仍照常處理。
3. 將沒有矛盾且可辨識的申請整理成 JSON 物件，每筆使用 `id`、`purchase_date`、`application_date`、`package_received` 欄位；缺漏欄位填 `null`。在此 `SKILL.md` 所在目錄執行腳本，對每筆加一個 `--record`，其值為該筆 JSON：

   ```sh
   python scripts/refund_classifier.py --record '{"id":"申請名稱","purchase_date":"YYYY-MM-DD","application_date":"YYYY-MM-DD","package_received":"是或否"}'
   ```

   有多筆時重複加入 `--record`。日期差、條件已足以確定的分類及缺漏欄位標示都由腳本計算；照原樣呈現腳本輸出。若腳本以代碼 2 結束，照錄它的一行錯誤訊息，請提出請求的人確認其中列出的值；排除不能使用的申請後，仍以腳本處理其餘可用申請。
4. 對缺漏欄位，輸出語言中明確標示「未提供」；若缺漏資料使分類無法確定，不猜測分類。若請求沒有任何申請資料，提供可直接填寫的範本：`識別名稱：［未提供］；購買日：［未提供］；申請日：［未提供］；已領取實體教材包：［未提供］`。將已知日數差及可確定的分類一併交付；不附加其他退款政策或推論。
