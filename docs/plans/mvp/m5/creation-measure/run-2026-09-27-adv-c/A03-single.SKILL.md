# 客訴信分類統計

使用這個技能時，目標是把「上週收到的客訴信」整理成可讀的分類統計表。你只能根據使用者提供的郵件內容、匯出檔或貼上的文字進行整理；如果沒有提供信件內容，就先請對方提供資料，不能自行假設或存取信箱。

## 先確認可用資料

1. 檢查是否已提供以下任一種資料：
   - 郵件匯出檔
   - 信件清單或全文貼上
   - CSV、Excel、JSON、純文字等內容
2. 如果資料不足，請明確詢問至少這些欄位中的可取得項目：
   - 收件時間或日期
   - 寄件者
   - 主旨
   - 信件內容
3. 如果使用者只說「上週收到的客訴信」，但沒有提供信件內容，回覆時要說明你需要郵件資料才能整理，不能直接產出統計。

## 整理流程

1. 篩選出屬於「客訴」的信件。
   - 若資料中已標記為客訴，直接採用。
   - 若未標記，根據主旨與內容判斷是否為抱怨、申訴、退貨爭議、服務不滿、物流問題、產品瑕疵等。
2. 排除非客訴內容。
   - 例如一般詢問、感謝信、行銷信、系統通知、重複轉寄但非原始客訴。
3. 為每封客訴信建立標準化分類。
   - 優先使用使用者指定的分類。
   - 若沒有指定，使用下列常見分類：
     - 產品品質
     - 物流配送
     - 服務態度
     - 退款/退貨
     - 訂單/付款
     - 網站/系統問題
     - 其他
4. 若一封信同時涉及多個問題，選擇最主要的分類；必要時可加註次要分類。
5. 統計每個分類的數量，並計算總數。
6. 如資料足夠，另外整理：
   - 主要抱怨主題摘要
   - 重複出現的關鍵字
   - 高頻寄件者或重複案件
   - 日期分布（例如按天或按週內日期）

## 輸出格式

請輸出一個清楚的分類統計表，建議包含以下欄位：

- 分類
- 件數
- 佔比
- 代表性案例或摘要

範例結構：

| 分類 | 件數 | 佔比 | 代表性案例或摘要 |
|---|---:|---:|---|
| 物流配送 | 5 | 31.3% | 延遲到貨、包裹未送達 |
| 產品品質 | 4 | 25.0% | 瑕疵、破損、功能異常 |
| 退款/退貨 | 3 | 18.8% | 退款進度慢、退貨流程不清楚 |
| 服務態度 | 2 | 12.5% | 客服回覆慢、態度不佳 |
| 其他 | 2 | 12.5% | 無法歸類或資訊不足 |

## 品質要求

- 不要憑空補資料。
- 不要把同一封信重複計入多個分類，除非使用者明確要求多重標記統計。
- 若分類依據不明確，將其放入「其他」並註明原因。
- 若信件數量很少，也要如實呈現，不要為了湊表而合併不相干案件。
- 若資料中有個資，輸出時盡量只保留必要資訊，避免揭露完整姓名、電話、地址或訂單號。

## 建議的附加摘要

在表格後可加一段簡短結論，例如：

- 本週客訴以物流配送為主，占比最高。
- 產品品質問題集中在破損與功能異常。
- 建議優先處理退款/退貨案件與重複來信客戶。

## 如果資料格式混亂

1. 先把每封信拆成獨立案件。
2. 以日期、寄件者、主旨、內容摘要建立暫時清單。
3. 再進行分類與統計。
4. 若有缺漏欄位，照現有資訊處理，並在結果中註明限制。
