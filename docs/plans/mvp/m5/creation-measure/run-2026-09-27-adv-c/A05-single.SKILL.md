# 目的
監控三家競爭對手官網的公開價格變化，並在價格有變動時產出可通知的變更摘要。

# 先確認的資訊
在開始前，先向使用者確認或收集以下內容：
1. 三家競爭對手的網站名稱與價格頁面網址。
2. 要追蹤的商品或方案名稱。
3. 需要比對的價格欄位：例如售價、折扣價、月費、年費、運費、稅前/稅後價格。
4. 比對頻率：例如每天、每週、每小時。
5. 通知方式：例如電子郵件、Slack、簡訊、或只輸出摘要供人工轉發。
6. 是否要忽略某些可預期變動：例如促銷標籤、幣別符號、千分位格式、稅額顯示。

# 能做與不能做
- 可以：整理監控規則、建立比對基準、比較新舊價格、彙整變更摘要、準備通知內容。
- 不能：保證持續背景執行、直接登入受保護網站、或主動發送通知，除非執行環境另外提供對應工具與權限。
- 若沒有即時網路存取或排程能力，明確告知使用者只能提供監控規格與比對邏輯，無法自行持續抓取網站。

# 執行流程
## 1. 建立監控清單
對每一家競爭對手建立一筆記錄，至少包含：
- 名稱
- 價格頁 URL
- 追蹤項目名稱
- 幣別
- 初始價格
- 最後檢查時間
- 備註（例如是否含稅、是否需登入）

## 2. 取得基準價格
第一次執行時：
- 讀取每個價格頁面上的目標價格。
- 若頁面有多個價格，優先使用使用者指定的欄位；若未指定，選擇最明確、最接近商品主價格的數值，並記錄判斷依據。
- 將抓到的價格與頁面可辨識的上下文一起保存，避免之後誤比對。

## 3. 標準化價格
比對前先標準化：
- 移除貨幣符號與千分位分隔。
- 統一小數格式。
- 若同頁面同時顯示折扣前與折扣後價格，依使用者指定欄位比對；未指定時以頁面主要顯示價格為準。
- 若價格以區間、起價、或依地區/方案變動顯示，先標記為「非單一固定價格」，不要直接當作一般價格比較。

## 4. 定期重新檢查
每次檢查時：
- 重新抓取同一頁面。
- 以相同規則抽取價格。
- 與上一次保存的基準值比較。
- 若頁面結構改變，先確認是否仍能找到同一商品/方案；找不到時標記為「頁面結構變更」而不是價格變動。

## 5. 判定變動
視為需要通知的情況：
- 價格上升或下降。
- 幣別改變。
- 原本顯示單一價格，現在改為區間或起價。
- 原本可見價格消失。
- 折扣價、月費、年費等使用者指定欄位改變。

不視為價格變動、但仍可記錄的情況：
- 促銷文案變更但價格不變。
- 排版、字體、順序變動但數值相同。
- 非目標欄位的附加資訊變動。

## 6. 產出通知內容
若有變動，通知內容應包含：
- 競爭對手名稱
- 商品/方案名稱
- 舊價格與新價格
- 變動幅度與百分比（若可計算）
- 檢查時間
- 來源網址
- 變動類型：上漲、下跌、幣別變更、結構變更、價格消失

通知文字要簡潔，方便直接轉寄或貼到訊息工具。

# 建議的輸出格式
每次檢查後輸出一份結構化摘要，例如：
- 無變動：列出已檢查的網站與時間。
- 有變動：逐家列出舊值、新值、差額、百分比、網址。
- 無法判定：列出原因，例如需要登入、頁面載入失敗、價格非固定值。

# 異常處理
遇到以下情況時，不要猜測價格：
- 頁面需要登入且未提供登入方式。
- 價格由 JavaScript 動態載入但目前環境無法讀取。
- 頁面顯示多個地區價格且無法判定目標地區。
- 價格被圖片、PDF、或其他非文字格式呈現。

此時應回報：
- 無法取得價格的原因
- 需要使用者補充的資訊
- 下一步建議

# 維護規則
- 若使用者更新了追蹤對象或欄位，先重建基準值再開始比較。
- 若網站改版，先重新定位價格元素，確認後再恢復監控。
- 保留歷史紀錄，方便回溯每次變動。
