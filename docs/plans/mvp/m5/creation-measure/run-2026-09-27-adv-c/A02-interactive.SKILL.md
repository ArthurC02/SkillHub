# 請假申請審核

依輸入中的文字欄位審核一筆請假申請，並直接輸出完成的審核結果，不要輸出審核計畫或規則說明。

## 執行方式

1. 從輸入讀取假別、申請日期、請假開始日、請假天數與病假證明狀態。只使用輸入明確提供的值；缺少的值不得推測。
2. 若輸入未包含足以判斷的欄位，直接輸出固定格式，將無法判定的資訊寫為 `not given`，不要向使用者提問。
3. 若假別為事假，計算申請日期至請假開始日之間的日曆天數：
   - 至少提前 3 天時，判定為核准，並在原因中明確寫出已提前的天數。
   - 少於 3 天時，判定為退回，並在原因中明確寫出事假未提前至少 3 天。
4. 若假別為病假：
   - 請假開始日與申請日期相同時，視為符合可於當天申請的規則。
   - 請假天數不超過 2 天時，判定為核准，不要求病假證明。
   - 請假天數超過 2 天且病假證明明確表示已提供時，判定為核准。
   - 請假天數超過 2 天且病假證明明確表示未提供時，判定為退回，並指出超過 2 天但未附證明。
   - 病假申請日期與請假開始日的其他情況，輸出 `not given` 表示規格未提供該情況的判定；不要自行補充規則。
5. 對不符合規則的申請，列出具體退回原因。若同時有多個可由輸入確認的不符合事項，以分號分隔全部原因。
6. 以繁體中文純文字輸出，固定使用以下格式，不加 Markdown 標題或額外說明：

`結果：核准／退回；原因：……`

核准時，原因須簡述已符合的規則；退回時，原因須列出具體違規事項。任何輸入未提供或規格未涵蓋的資訊都寫 `not given`。

Use only what the input contains — never add a date, name, assumption, step or branch the input does not give, and write 'not given' where it is silent.

Deliver the finished artifact itself in the output — never a description of the rules, a plan, or a request for access.
