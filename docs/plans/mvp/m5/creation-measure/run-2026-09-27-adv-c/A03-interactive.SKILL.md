# 客服客訴分類統計

依照以下步驟一次完成任務，不要要求使用者另行指定分類方式或輸出格式；採用本 Skill 定義的預設值，並在完成的輸出中清楚呈現結果。

1. **接收客訴信資料**
   - 將使用者在本次輸入中貼上的客訴信視為唯一資料來源。
   - 逐封辨識輸入中提供的日期、主旨與內文；保留原文中的日期、主旨與內文，不改寫成輸入沒有提供的資訊。
   - 只整理使用者本次輸入提供的信件，不連線、不讀取或推測客服信箱中的其他信件。

2. **依主要客訴主題分類**
   - 讀取每封信的主旨與內文，判斷該信最主要的客訴主題。
   - 每封信只能計入一個主要分類，以避免統計重複計算。
   - 若一封信涉及多個主題，選擇與主要訴求最直接相關的一個主題，並在輸出中用一句話簡短說明判定依據。
   - 優先使用能準確概括輸入內容的繁體中文分類名稱；例如配送延遲使用「配送問題」、退款未入帳使用「退款問題」、登入失敗使用「帳號／登入問題」。只在輸入內容支持時使用這些名稱，不要把未提供的內容加入分類依據。

3. **統計分類數量**
   - 每封輸入信恰好計數一次。
   - 彙總各主要分類的信件數量。
   - 檢查所有分類數量的總和等於實際整理的信件數；不要加入輸入未提供的信件。

4. **交付完成的 Markdown 統計表**
   - 輸出標題「客訴分類統計」。
   - 先輸出 Markdown 表格，欄位為「分類」與「數量」；每個分類一列，填入實際統計數量。
   - 在表格後輸出「分類判定說明」，逐一列出需要說明的信件或分類及其簡短判定依據。說明只能引用或概括輸入已提供的主旨與內文。

5. **交付完成的 CSV 內容**
   - 在 Markdown 表格與判定說明後，輸出標題「CSV」。
   - 提供可直接儲存的 CSV 文字區塊，第一列必須是 `分類,數量`，其後每列包含一個實際分類及其數量。
   - 若分類名稱或內容含有逗號、雙引號或換行，依 CSV 規則以雙引號包住欄位，並將欄位內的雙引號加倍。

6. **處理資料不足**
   - 若本次輸入沒有提供任何可整理的客訴信，不能捏造統計資料；直接說明無法產生統計表，並指出缺少客訴信資料。除此之外不要以問題結束回覆。
   - 若個別信件缺少日期、主旨或內文，只使用實際提供的欄位，缺少的欄位在對應位置寫「not given」；仍依可取得的內容分類，不補造日期、主旨、內文或其他信件。

使用者提供的資料是唯一依據。use only what the input contains — never add a date, name, assumption, step or branch the input does not give, and write 'not given' where it is silent.

deliver the finished artifact itself in the output — never a description of the rules, a plan, or a request for access.
