# 週五業績週報自動寄送與 Slack 公告

這個技能用來處理「每週五下午自動把本週業績數字寄給全部門，同時在 Slack 公告」的需求。

## 先確認這件事是否可直接完成
這類任務通常**需要**：
- 可用的郵件系統與收件群組
- 可用的 Slack 工作區與發文權限
- 排程工具或自動化平台
- 本週業績數字的來源系統或報表

如果目前沒有這些存取權限、沒有排程工具，或沒有明確的業績資料來源，**不能直接完成自動化**。此時只能先整理需求、確認必要資訊，並提供可執行的設定清單。

## 執行步驟

### 1. 確認報告內容
先確認以下資訊：
- 「本週」的定義：週一到週五、還是最近 7 天
- 「業績數字」包含哪些指標：營收、訂單數、成交數、轉換率、達成率等
- 是否需要與上週、目標值或去年同期比較
- 是否要附上明細、圖表或只寄摘要
- 收件對象：全部門的郵件群組名稱或名單
- Slack 發文位置：指定頻道名稱或頻道 ID
- 發送時間：每週五下午的確切時間與時區

### 2. 確認資料來源
找出業績數字從哪裡來：
- CRM
- ERP
- BI 報表
- 試算表
- 資料庫查詢
- 人工整理的固定報表

如果資料來源不是自動可讀，先要求提供可機器讀取的格式，例如：
- CSV
- Google Sheets
- Excel
- API
- SQL 查詢結果

### 3. 定義輸出格式
建立一致的訊息格式，讓郵件與 Slack 內容一致或近似一致。建議至少包含：
- 標題：本週業績週報（日期區間）
- 核心數字：3 到 5 個最重要指標
- 簡短結論：本週表現摘要
- 必要提醒：異常、風險、下週重點

若需要，將內容拆成兩個版本：
- **Email 版**：較完整，可含表格與附件
- **Slack 版**：較短，重點摘要加連結

### 4. 檢查發送名單與權限
確認：
- 郵件群組是否存在且可寄送
- Slack 頻道是否存在且可發文
- 自動化帳號是否有權限寄信與發 Slack 訊息
- 是否需要抄送主管或特定角色

### 5. 設計排程邏輯
排程應符合：
- 每週五執行一次
- 以指定時區為準
- 若遇假日或資料尚未更新，是否延後或改為跳過
- 若資料抓取失敗，是否重試、通知維運或只發錯誤警示

### 6. 設計失敗處理
至少定義以下情況的處理方式：
- 找不到本週資料
- 數字為空或格式錯誤
- 郵件寄送失敗
- Slack 發文失敗
- 部分成功、部分失敗時如何通知

建議在失敗時：
- 記錄錯誤原因
- 通知負責人
- 不要重複對全員發送錯誤內容

### 7. 產出可執行的自動化規格
如果你有自動化平台或腳本環境，將流程整理成：
1. 讀取本週業績資料
2. 生成摘要內容
3. 寄送 Email 給全部門
4. 發送 Slack 公告到指定頻道
5. 記錄執行結果

### 8. 若缺少必要條件，先回覆需要補齊的資訊
如果目前無法直接設定自動化，請先向使用者索取：
- 業績資料來源
- 收件群組或名單
- Slack 頻道
- 發送時間與時區
- 報告格式需求
- 是否需要附件或圖表

## 交付標準
當條件齊備時，這個任務的完成標準是：
- 每週五下午自動寄出 Email
- 同步在 Slack 指定頻道公告
- 內容使用同一份本週業績資料
- 失敗時有明確錯誤處理與通知機制

## 注意事項
- 這不是純文字撰寫任務；它通常需要外部系統權限與排程能力。
- 若沒有郵件、Slack 或資料來源的存取權，請不要假設可以直接完成。
- 若使用者只提供需求但沒有系統資訊，先做需求澄清，不要編造設定。
