## 目的
每週從三個指定的 Slack 頻道中，找出「未回覆的問題」，整理成可追蹤的清單，並附上每則訊息的連結。

## 適用情境
- 使用者要你做每週 Slack 問題盤點
- 來源固定是三個頻道
- 需要辨識哪些訊息是「問題」且「尚未回覆」
- 需要輸出可點擊的訊息連結，方便後續跟進

## 先確認的資訊
如果以下資訊沒有在對話中明確提供，先向使用者確認：
1. 三個 Slack 頻道名稱或連結
2. 盤點的時間範圍（例如：最近 7 天、上週一到週日）
3. 「未回覆」的判定規則
   - 例如：原訊息下沒有任何回應
   - 或：沒有同頻道內的直接回覆串
   - 或：沒有被指定人員回覆
4. 輸出語言與格式偏好

## 判定規則
將訊息視為「問題」時，優先找出符合以下特徵的內容：
- 明確提出疑問、請求協助、等待確認、需要決策
- 句尾有問號，或包含「請問」「想確認」「有人知道」「需要」「麻煩」等語意
- 內容不是純公告、閒聊、轉貼、已解決摘要

將訊息視為「未回覆」時，依下列原則判定：
- 原訊息下沒有任何回應串
- 或只有表情符號、已讀、非實質回答，不算回覆
- 若有回覆但只是補充提問、未解答原問題，仍可列入「未解決」但要註明
- 若原訊息已被明確回答、解決、轉移到其他串，則不列入

## 工作步驟
1. 取得三個指定頻道在指定時間範圍內的訊息。
2. 逐則檢查是否為問題或需要回覆的訊息。
3. 檢查每則問題是否有回覆串或實質回應。
4. 只保留未回覆的問題；若有模糊案例，標註為「待確認」。
5. 為每則保留的訊息整理：
   - 頻道名稱
   - 發訊者
   - 訊息摘要
   - 發送時間
   - 訊息連結
6. 若同一問題被重複提及，保留最早且最完整的一則，其他作為重複項合併處理。
7. 依時間由新到舊或依頻道分組輸出；若使用者未指定，預設依時間由新到舊。

## 輸出格式
使用清單形式，每筆一行，至少包含：
- 頻道
- 發訊者
- 問題摘要
- 連結

建議格式：
- [#頻道] 發訊者：問題摘要 — 連結

若需要補充判定，附上簡短理由，例如：
- [#頻道] 發訊者：問題摘要 — 連結（未見回覆）
- [#頻道] 發訊者：問題摘要 — 連結（僅有表情回應，未算實質回覆）

## 品質檢查
輸出前確認：
- 是否只包含三個指定頻道
- 是否只列出未回覆的問題
- 是否每筆都有可追蹤連結
- 是否避免把公告、討論結論、已解決事項誤列為問題
- 是否保留了足夠資訊讓人能直接點進去跟進

## 注意事項
- 這個任務需要能存取 Slack 訊息內容與訊息連結；若目前沒有 Slack 存取權限或沒有提供頻道資訊，先請使用者補充。
- 不要臆測訊息是否已回覆；看不到回覆串時要標示為待確認，而不是直接判定已回覆。
