# 手作文具網店退貨受理判定

依下列步驟處理使用者提供的訂單資料；每筆完整訂單各判定一次。

1. 從輸入辨認每筆訂單的訂單編號、到貨日、申請日、商品種類、使用狀態及瑕疵狀態。商品種類使用「客製」或「非客製」；使用狀態與瑕疵狀態分開辨認。同一訂單可以是已使用且有瑕疵。
2. 日期按 `YYYY-MM-DD` 日曆日解讀。缺少的欄位標為「未提供」，不猜測；提供一列可補齊的資料模板，並只判定可由已知資料確定的訂單。不得把可由日期算出的天數標成未提供。
3. 若同一訂單編號出現互相矛盾的欄位值，逐一列明衝突的欄位與原值，請提出請求的人確認；不為該筆選值或判定。對日期格式無效或申請日早於到貨日的資料，亦列明原值，請提出請求的人確認，不為該筆判定。不要詢問其他事項。
4. 對每筆資料完整且無衝突的訂單，從含有 `scripts/decide_return.py` 的目錄，將該筆實際資料代入以下命令執行：`python scripts/decide_return.py --order-id "$order_id" --arrival-date "$arrival_date" --application-date "$application_date" --product-type "$product_type" --usage "$usage" --defect "$defect"`。其中六個 shell 變數分別取自該筆訂單的相應欄位；`product_type` 使用 `客製` 或 `非客製`，`usage` 使用 `未使用` 或 `已使用`，`defect` 使用 `有瑕疵` 或 `無瑕疵`。逐筆執行並保留程式輸出。若程式以代碼 2 結束，照錄它指出的值，請提出請求的人確認，且不為該筆判定。
5. 回覆輸入中的每筆訂單及其唯一判定，依程式輸出逐字列出訂單編號和結果；不得自行改算或更改結果。結果只可為「全額退款」、「換貨」或「不受理」。缺少必要資料或值待確認的訂單，列出訂單編號、未提供欄位或需確認的原值，並明示該筆未判定；不要把它冒充為三種結果之一。若欄位缺少，附上可補齊的模板：`訂單編號｜到貨日｜申請日｜商品種類｜使用狀態｜瑕疵狀態`。

套用缺少資訊、矛盾值及無效值的通用處理規則：不編造事實，已提供的事實逐字保留；缺少事實標為「未提供」，可由已知資料算出的值則自行算出。總計只有在每個組成部分都已知時才提供。遇到互相矛盾或無法使用的值，列明每個值並請提出請求的人確認；依賴該值的判定不提供。資料不足時交付可用的模板或部分結果，不以提問或承諾代替交付。
