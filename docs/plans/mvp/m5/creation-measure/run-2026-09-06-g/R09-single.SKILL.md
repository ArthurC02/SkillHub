---

# 目的
將使用者提供的履歷改寫成適合資料分析職缺的版本，並控制在一頁以內。重點是突出與資料分析相關的技能、工具、專案成果與量化影響，同時保留真實資訊，不自行捏造經歷。

# 工作流程
1. **先確認輸入是否足夠**
   - 需要至少有原始履歷內容。
   - 若缺少關鍵資訊，先向使用者索取：
     - 原始履歷全文
     - 目標職缺或職稱（例如 Data Analyst、Business Analyst、Product Analyst）
     - 是否有特定工具或技能要強調（SQL、Python、Excel、Tableau、Power BI、A/B testing 等）
   - 若使用者沒有提供職缺，也可依「資料分析職缺」做通用版，但要以可轉用性為主。

2. **萃取與重組內容**
   - 找出與資料分析最相關的內容：
     - 數據整理、分析、報表、自動化、儀表板、實驗設計、商業洞察、流程優化
     - 使用過的工具與語言：SQL、Python、R、Excel、Tableau、Power BI、Looker、BigQuery、Excel VBA 等
     - 量化成果：提升效率、降低成本、增加轉換率、縮短報表時間、改善準確率
   - 將不相關或較弱相關的內容縮短、合併或移到較後面。
   - 保留可證明能力的專案、工作成果與指標。

3. **改寫原則**
   - 用資料分析職缺常見語言重寫，但不得捏造不存在的技能或經歷。
   - 優先使用動詞開頭的成果敘述，例如：
     - 分析、建置、優化、自動化、監控、視覺化、驗證、預測、彙整
   - 每段都盡量包含「做了什麼 + 用了什麼 + 帶來什麼結果」。
   - 若原履歷缺少量化數字，可保留定性成果，但建議標示可補強的地方，或用較保守的表述。

4. **建議版面結構**
   - 以一頁內為目標，通常採用以下順序：
     1. 姓名與聯絡資訊
     2. 專業摘要 2–3 行
     3. 核心技能
     4. 工作經歷（每份 2–4 個條列）
     5. 專案經驗或作品集（若有且相關）
     6. 學歷與證照
   - 若內容過長，優先保留：
     - 最近且最相關的經歷
     - 最能證明分析能力的專案
     - 最具代表性的技能與成果

5. **專業摘要寫法**
   - 用 2–3 句概括：
     - 年資或背景
     - 主要分析能力
     - 常用工具
     - 代表性成果或產業領域
   - 例如方向應是：
     - 「具 X 年資料分析／營運分析經驗，熟悉 SQL、Python 與 Tableau，曾透過自動化報表與數據洞察提升決策效率。」
   - 不要寫空泛形容詞堆疊。

6. **核心技能整理**
   - 分類呈現，避免長串堆砌：
     - 資料處理：SQL、Python、Excel
     - 視覺化：Tableau、Power BI
     - 統計／分析：A/B testing、回歸、分群、漏斗分析
     - 商業應用：報表自動化、KPI 監控、需求分析
   - 只列出使用者確實具備的技能。

7. **工作經歷改寫**
   - 每段經歷以 2–4 點條列，依重要性排序。
   - 每點盡量包含：
     - 任務或問題
     - 方法／工具
     - 成果／影響
   - 將偏行政、協調、一般性描述改寫成分析導向語句，只要內容真實且合理。
   - 若原文有大量非分析工作，保留與數據、流程、報表、決策支持相關的部分。

8. **專案與作品集**
   - 若有 GitHub、Kaggle、作品集、儀表板連結或分析專案，應優先保留。
   - 每個專案用一句到兩句說明：
     - 問題背景
     - 使用資料與方法
     - 結果或洞察
   - 若沒有專案，可略過，不要硬塞。

9. **長度控制**
   - 目標是一頁以內，因此要主動刪減重複內容。
   - 若使用者提供的內容過多，輸出時保留最能打動資料分析職缺的資訊。
   - 不要加入冗長說明、教學或改寫理由；直接輸出可用版本。

10. **輸出格式**
   - 直接輸出改寫後的履歷內容。
   - 使用清楚標題與條列，方便使用者貼到履歷版面。
   - 若資訊不足以完成完整改寫，先列出需要補充的資訊，並說明可先提供原始履歷全文。
