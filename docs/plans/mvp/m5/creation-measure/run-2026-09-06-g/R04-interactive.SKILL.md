# GitHub Issue Severity Triage

這個 Skill 用來把使用者提供的 GitHub issue 依嚴重度分成三個等級，並為每個等級各寫一句處理建議。當你收到一段 issue 清單、單一 issue 描述，或其他可判斷影響程度的文字時，就直接依下列規則完成分類與建議，不要反問補充資料，也不要引用外部背景。

## 目標

輸出一份可直接閱讀的分級結果，包含：
- 三個嚴重度級別：高、中、低
- 每個級別對應的 issue
- 每個級別一句處理建議

## 判定原則

以 issue 對使用者完成核心任務的影響來判斷：

- **高**：核心流程中斷、主要功能不可用、使用者無法完成關鍵任務。
- **中**：有明顯不便、部分情境受影響，但仍有替代方式或可繼續使用。
- **低**：低風險、瑕疵型問題、文案或格式問題、可延後處理。

若描述不足以精確判定，採取最保守且最合理的分類，並只根據已提供內容判斷。

## 處理步驟

1. 讀取每個 issue 的描述。
2. 依上述判定原則把每個 issue 分到高、中、低其中一級。
3. 為每一級寫一句處理建議，建議要貼近該級常見處置方式。
4. 輸出結果時，讓每個 issue 都能清楚對應到其級別。

## 輸出格式

使用清楚的標題與條列，格式可以是：

- **高**
  - Issues：...
  - 建議：...
- **中**
  - Issues：...
  - 建議：...
- **低**
  - Issues：...
  - 建議：...

如果某一級沒有對應 issue，仍保留該級標題，並寫明「無」。

## 注意事項

- 只根據輸入中的 issue 內容判斷，不補充未提供的背景、數據或技術原因。
- 不使用外部資料。
- 不要把分類過程寫成冗長說明；直接給出結果與一句建議即可。
- 輸出應可直接給人閱讀，語言簡潔明確。
