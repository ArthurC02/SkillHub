# 競爭對手價格追蹤

這個技能用來監控公開網站上的價格頁面，並在偵測到變動時整理差異並通知使用者。

## 適用範圍
- 只適用於可公開存取的網頁。
- 不處理需要登入、付費、驗證碼、購買流程或其他需要即時人工操作的情況。
- 若目標網站無法穩定抓取，先回報限制與可行替代方案，不要臆測價格。

## 執行步驟
1. **確認監控目標**
   - 收集三家競爭對手的官網網址。
   - 確認每一家要追蹤的具體價格位置，例如商品頁、方案頁、定價頁或搜尋結果頁。
   - 若頁面有多個價格，明確指定要追蹤哪一個欄位或哪一個商品。

2. **建立基準值**
   - 讀取每個目標頁面的目前價格。
   - 記錄價格、幣別、商品名稱、頁面標題、網址與擷取時間。
   - 若頁面顯示折扣價與原價，兩者都記錄，並標明哪一個是主要監控價格。

3. **標準化價格資料**
   - 將價格轉成可比較的格式。
   - 保留原始顯示文字，以便回報時引用。
   - 若網站使用不同幣別，先保留原幣別，不自行換算，除非使用者明確要求。

4. **持續比對**
   - 每次重新檢查時，將新價格與上次記錄的基準值比較。
   - 判定以下變化：
     - 價格上升
     - 價格下降
     - 幣別改變
     - 顯示方式改變但數值未變
   - 若頁面內容無法辨識價格，標記為「無法確認」，不要猜測。

5. **偵測到變動時的處理**
   - 只要任一目標頁面價格有變動，就整理通知。
   - 通知內容至少包含：
     - 競爭對手名稱
     - 頁面網址
     - 舊價格
     - 新價格
     - 變動方向與幅度
     - 擷取時間
   - 若多個目標同時變動，合併成一則清楚的摘要。

6. **未變動時的處理**
   - 若價格沒有變動，回報「未偵測到變動」並列出已檢查的頁面。
   - 不要重複發送相同內容的通知。

7. **異常處理**
   - 若網站回傳錯誤、被阻擋、內容載入不完整或價格被動態渲染而無法取得，記錄原因。
   - 先嘗試重新整理或改用頁面中可見的結構化資料；若仍失敗，回報限制。
   - 不要使用未授權的繞過方式。

## 通知格式
- 標題：`價格變動通知`
- 內文建議格式：
  - `對象：` 競爭對手名稱
  - `頁面：` 網址
  - `舊價格：` 舊值
  - `新價格：` 新值
  - `變動：` 上升 / 下降 / 幣別改變 / 顯示變更
  - `時間：` 擷取時間

## 維護原則
- 每次檢查都使用同一組頁面與同一個價格欄位，避免比較錯誤。
- 若使用者更新監控目標，先重建基準值，再開始比較。
- 保留最近一次成功擷取的結果，作為下一次比對依據。
