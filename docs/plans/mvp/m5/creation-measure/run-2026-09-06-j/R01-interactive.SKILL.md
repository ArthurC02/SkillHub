# 客戶會議逐字稿待辦整理

將使用者直接貼上的客戶會議純文字逐字稿，在一次執行中整理成繁體中文 Markdown 待辦清單。

## 輸入限制

- 只處理訊息中實際貼出的純文字逐字稿。
- 不嘗試存取音檔、附件、行事曆、通訊錄或其他外部資料。
- 若訊息完全沒有提供逐字稿內容，簡短請使用者貼上逐字稿後停止；除此之外，不以問題結束執行。

## 處理步驟

1. 完整閱讀逐字稿，辨識所有可能的行動事項。
2. 只保留會中已被明確指派或由某人明確承諾執行的行動。可採納的依據包括「我會……」、「由我處理……」、「某人負責……」或語意同等的確定表述。
3. 排除以下內容：
   - 背景資訊、情況說明或一般討論。
   - 尚未形成行動的構想、可能性、建議或考慮事項。
   - 已明確表示暫不安排、先不用處理或取消的事項。
   - 無法從逐字稿確定負責人或期限的事項。
4. 對每個保留項目，僅從逐字稿擷取：
   - **任務**：具體要完成的工作；保留會影響交付內容的明確細節。
   - **負責人**：逐字稿明確指出的姓名、稱謂或角色。
   - **期限**：逐字稿明確說出的日期、時間或相對期限，沿用原文表達。
5. 不補寫或猜測任何未出現在逐字稿中的姓名、角色、日期、年份、時間、任務範圍或其他細節。不要用「待確認」、「未指定」等文字代替缺少的負責人或期限；缺少任一欄位的候選事項不列入清單。
6. 合併內容實質相同的重複待辦：
   - 若後續提及補充了同一任務的具體交付細節，將細節整合進同一條。
   - 只有在任務、負責人與期限可一致整合時才合併。
   - 若負責人不同或期限不同，即使任務相似也分開保留。
   - 若重複表述互相衝突，不自行判定哪一項正確；分開保留逐字稿中各自明確成立的項目。
7. 依期限由早到晚排序。使用逐字稿可直接支持的日期與時間關係，例如同一天的「中午前」早於「下班前」。若原文不足以判定兩項期限的先後，不推測缺少的年份或日期，並讓這些項目維持其首次出現順序，排在所有可明確排序的項目之後。
8. 直接輸出結果，不附加分析過程、推理、未採納事項、摘要或反問。

## 輸出格式

每條待辦使用一個未勾選的 Markdown 核取方塊，固定採用以下單行欄位順序：

```markdown
- [ ] **任務：** 具體工作；**負責人：** 姓名或角色；**期限：** 原文期限
```

所有文字使用繁體中文；人名、專有名詞及期限表達則忠實保留逐字稿內容。每個核取方塊必須同時具備「任務」、「負責人」與「期限」。

若逐字稿存在但沒有任何同時符合明確行動、明確負責人及明確期限的事項，輸出：

```markdown
未找到同時具有明確任務、負責人與期限的待辦事項。
```
