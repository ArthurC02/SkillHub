# 報帳流程判定

根據使用者提供的單筆報帳申請，一次完成流程判定並只輸出一個合法 JSON 物件。這項判定僅是處理建議；不得聲稱已實際完成簽核、入帳、寄信或任何外部操作。

## 輸入

從輸入中取得：

- 申請編號
- 發票是否齊全
- 金額
- 幣別

四項資料都屬於執行判定所需的輸入。若輸入本身缺少任何一項，停止流程判定，直接以簡短 JSON 錯誤物件列出缺少的欄位；不要猜測資料，也不要以問題作結。

金額按輸入數值直接與門檻 `5000` 比較，不查詢或換算匯率。「超過 5000」採嚴格大於，即金額等於 `5000` 時視為未超過。

## 流程

必須依下列節點順序處理，不增加圖中沒有的流程節點、條件或分支。

### 1. 開始：收到員工報帳申請

讀取單筆申請，保留其申請編號，並判斷「發票是否齊全」。

- 發票齊全時，不加入退回補件動作，直接進入「金額是否超過 5000」的判斷。
- 發票不齊全時，下一個適用動作是「退回並要求 3 天內補件」。

將 `invoice_status` 設為能明確表達「發票齊全」或「發票不齊全」的字串。

### 2. 處理：退回並要求 3 天內補件

僅在發票不齊全時，把 `退回並要求 3 天內補件` 加入 `ordered_actions`。

圖中未顯示補件後重新送件或再次檢查發票的機制，因此不得自行加入這些動作或分支。依圖中現有箭頭，在記錄退回補件後進入「金額是否超過 5000」的判斷。若發票齊全，略過本節點的動作並直接進行該金額判斷。

以輸入金額直接比較 `5000`，建立 `amount_assessment`：

- `amount`：輸入金額
- `currency`：輸入幣別
- `threshold`：數值 `5000`
- `comparison`：金額大於門檻時為 `greater_than`，否則為 `not_greater_than`
- `statement`：以文字明確說明輸入金額是否大於門檻 5000

### 3. 處理：送經理簽核

若金額嚴格大於 `5000`：

- 將 `manager_approval_required` 設為 `true`。
- 把 `送經理簽核` 加入 `ordered_actions`。

若金額未超過 `5000`：

- 將 `manager_approval_required` 設為 `false`。
- 不加入經理簽核動作。

### 4. 處理：財務直接入帳

把 `財務直接入帳` 加入 `ordered_actions`。這是建議執行的流程動作，不表示入帳已完成。

### 5. 結束：寄出付款通知信

把 `寄出付款通知信` 加入 `ordered_actions`，並完成結果。這是建議執行的流程動作，不表示通知信已寄出。

## 輸出

只輸出一個合法 JSON 物件，不加 Markdown 程式碼圍欄、前言、結語或 JSON 外文字。物件必須包含：

- `application_id`：輸入的申請編號
- `invoice_status`：明確表示發票齊全與否
- `amount_assessment`：包含 `amount`、`currency`、`threshold`、`comparison` 與 `statement`
- `manager_approval_required`：布林值
- `ordered_actions`：依流程實際適用順序排列的字串陣列
- `uncertainties`：字串陣列，陳述圖中未定義之處及本次採用的明示處理方式

`uncertainties` 應包含以下兩項，不得據此新增流程分支：

1. 圖中未顯示補件後是否須重新提交申請或再次判斷發票是否齊全；本判定依現有箭頭在退回補件後直接進入金額判斷。
2. 圖中未另外說明金額等於 5000 或不同幣別的處理；本判定採嚴格大於並直接比較輸入數值，不進行匯率換算。

`ordered_actions` 只能按適用情況使用下列圖示動作名稱，並維持其先後順序：

1. `退回並要求 3 天內補件`，僅發票不齊全時
2. `送經理簽核`，僅金額大於 5000 時
3. `財務直接入帳`
4. `寄出付款通知信`

不要要求匯率或其他未提供且非必要的資料，也不要聲稱任何列出的動作已實際執行。
