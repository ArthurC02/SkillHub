# 目的
協助使用者把週報設定成每週五自動寄給主管，並在之後持續依排程執行。

# 先判斷是否可由代理直接完成
這個任務通常**需要**可用的郵件帳號、排程工具、以及對寄信系統的存取權限。若目前沒有這些權限，代理**不能直接替使用者完成實際寄送或建立排程**，只能協助整理需求、確認資訊、產出設定步驟或自動化腳本。

# 執行流程
1. **確認可用環境**
   - 使用者是否已提供可用的郵件服務（例如 Gmail、Outlook、公司信箱、SMTP 伺服器）。
   - 是否有可用的排程方式（例如系統排程器、雲端自動化平台、郵件客戶端規則、腳本排程）。
   - 是否允許使用者授權或提供必要的帳號設定。

2. **蒐集必要資訊**
   - 週報內容來源：固定模板、文件、試算表、資料夾、或每週手動整理後的文字。
   - 收件人：主管的電子郵件地址。
   - 寄送時間：每週五的具體時間與時區。
   - 郵件主旨格式：例如「週報 - YYYY/MM/DD」。
   - 郵件內容格式：純文字、HTML、附件、或含連結。
   - 是否需要抄送、密送、附件、簽名檔。

3. **判斷可行方案**
   - 若使用者有現成自動化平台可用，優先建議用該平台建立排程。
   - 若只能用腳本與排程器，整理成可執行的腳本與排程步驟。
   - 若無法存取任何寄信或排程工具，明確說明無法直接代為設定，只能提供操作清單。

4. **建立排程邏輯**
   - 設定每週五觸發。
   - 在觸發時讀取最新週報內容。
   - 組裝郵件主旨與內文。
   - 寄送到主管信箱。
   - 記錄成功或失敗結果，方便追蹤。

5. **加入安全與驗證步驟**
   - 先用測試收件人或自己信箱試寄一次。
   - 確認時區、日期與時間正確。
   - 確認內容不會重複寄送。
   - 若有附件，確認檔案存在且大小符合限制。

6. **交付結果**
   - 若能實作：提供完整的排程設定步驟或腳本。
   - 若不能實作：提供一份清楚的待辦清單，列出使用者需要提供或完成的項目。

# 回覆原則
- 不要假設已經有登入權限或系統存取權。
- 不要聲稱已經完成排程，除非實際具備可執行的工具與授權。
- 若資訊不足，先問最少必要問題：
  1. 用哪個寄信服務？
  2. 週報內容從哪裡來？
  3. 每週五幾點寄？
  4. 收件人是誰？
- 若使用者只想要「之後不用手動做」，請提醒：這需要先完成一次設定，之後才會自動執行。
