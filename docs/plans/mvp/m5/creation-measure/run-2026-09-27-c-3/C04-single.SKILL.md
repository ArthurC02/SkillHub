# 目的
將長篇會議記錄整理成清楚、可掃讀的摘要，保留決策、待辦、爭議點與關鍵背景，刪除重複與冗詞。

# 適用情境
- 使用者貼上會議逐字稿、會議紀錄、聊天紀錄或零散筆記。
- 使用者要求「重點摘要」、「整理成條列」、「抓出決議/待辦」等。
- 需要把長內容壓縮成可快速閱讀的版本。

# 工作原則
1. 只根據提供的內容整理，不補寫未出現的事實。
2. 優先保留：
   - 決議 / 結論
   - 待辦事項與負責人
   - 重要爭點與未決問題
   - 影響後續行動的背景資訊
3. 移除：
   - 重複敘述
   - 口語贅字
   - 與主題無關的閒聊
4. 若資訊不足，明確標示「未提及」或「不明」。
5. 若內容混雜多個主題，先分主題再摘要。

# 處理流程
## 1. 先辨識內容結構
閱讀整份會議記錄，找出：
- 主題或議程項目
- 參與者與角色
- 討論焦點
- 結論與決策
- 待辦與期限

## 2. 去重與濃縮
- 合併同義或重複的說法。
- 將長句改寫成短句。
- 保留原意，不加入推測。

## 3. 分類整理
將內容整理成以下優先順序：
1. 一句話總結
2. 主要重點
3. 決議
4. 待辦事項
5. 風險 / 爭議 / 未決事項
6. 補充背景（必要時）

## 4. 若有多個議題
對每個議題分別輸出：
- 議題名稱
- 討論重點
- 結論 / 決議
- 待辦事項

# 輸出格式
除非使用者另有指定，請使用以下格式：

## 會議摘要
**一句話總結：** 用 1 句話概括整場會議。

**主要重點：**
- 重點 1
- 重點 2
- 重點 3

**決議：**
- 決議 1
- 決議 2

**待辦事項：**
- [負責人] 事項內容，期限（若有）
- [負責人] 事項內容，期限（若有）

**未決事項 / 風險：**
- 項目 1
- 項目 2

**補充背景：**
- 只有在有助於理解決策時才保留。

# 若使用者要求更短版本
改用以下極簡格式：
- 一句話總結
- 3–5 個重點條列
- 待辦事項

# 若使用者要求更正式或可直接轉寄
可改寫成：
- 標題
- 摘要段落
- 條列重點
- 行動項目表

# 品質檢查
輸出前確認：
- 是否保留了所有關鍵決議與待辦？
- 是否刪除了重複與冗詞？
- 是否避免加入未提供的資訊？
- 是否清楚標示不明之處？

# 注意事項
- 不要把每個發言都逐條列出，除非使用者明確要求逐字整理。
- 不要自行推論會議結果。
- 若原文含有日期、數字、負責人、期限，優先保留原樣。
