# Meeting Notes Summary Skill

## 目的
把使用者提供的長篇會議記錄整理成精簡、可掃讀的摘要，保留會議重點、決議、待辦事項與必要背景。

## 使用時機
當使用者貼上會議記錄，並希望你幫他濃縮成重點摘要、條列重點、整理決議或列出待辦事項時，使用這個 Skill。

## 工作原則
- 只根據使用者提供的會議記錄內容整理，不自行補充未出現的事實。
- 若內容缺少某項資訊，就標示為「未提供」或省略，不要猜測。
- 預設輸出中文、條列式、精簡但完整。
- 以使用者實際給的原文為準，不要把理解到的背景當成確定事實。

## 執行步驟
1. 通讀會議記錄，抓出主題、結論、決議、待辦事項、關鍵數字與時間點。
2. 刪除冗詞、重複敘述、寒暄與無關細節。
3. 依重要性排序，優先保留：
   - 主要討論主題
   - 明確決議
   - 待辦事項與負責人（若原文有提供）
   - 重要背景限制或風險
4. 以條列方式輸出，讓使用者能快速掃讀。
5. 若原文有明確分段或多個主題，則按主題分組整理；若沒有，就用通用分段。

## 輸出格式
預設使用以下結構；若原文不含某段資訊，則不必硬寫，或標註「未提供」。

- 重點摘要
- 決議
- 待辦事項
- 風險 / 後續觀察（如原文有）

## 內容規則
- 決議要寫成明確句子，避免只寫「有討論」或「有共識」。
- 待辦事項要盡量寫出任務內容、負責人與期限；若原文只提到其中一部分，就只寫有提供的部分。若原文沒有明示負責人，不要自行補指定人選，也不要用「全體」或其他推測性主體代替。
- 不要加入原文沒有提到的新結論、新數字或推測。
- 若原文提到不確定事項、可能性或條件，保留其不確定性，不要改寫成定論。

## 輸出示例風格
- 簡潔
- 條列式
- 每點盡量一句話
- 用詞清楚，避免長篇解釋

## 例外處理
- 如果使用者提供的內容不是會議記錄，仍然嘗試以摘要方式整理，但要忠實反映原文。
- 如果內容太短，則輸出精簡摘要，並在必要時保留原文中唯一的重要資訊。

## 你要做的事
直接輸出整理好的摘要，不要描述你的處理流程。
