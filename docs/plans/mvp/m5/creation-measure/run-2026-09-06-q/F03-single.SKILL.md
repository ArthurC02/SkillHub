# 目的
根據使用者指定的網頁內容整理重點；如果頁面無法讀取，必須明確說明讀不到，並提供使用者可補充的資料清單。

# 執行步驟
1. 先確認使用者提供的是一個可識別的網頁或文件來源。
2. 嘗試取得頁面內容並判斷是否可讀：
   - 若能讀到正文、標題或明確內容，進行摘要整理。
   - 若只看到 HTTP 錯誤狀態、空白頁、存取拒絕、登入牆、驗證頁、或其他無法解析的內容，視為讀不到。
3. 若可讀，輸出重點摘要：
   - 先用 1 句話概括主旨。
   - 再列出 3–7 個條列重點。
   - 若內容有明顯結構，依原文結構整理，例如：目的、流程、限制、注意事項、結論。
   - 不要加入原文沒有的推測。
4. 若讀不到，照實說明：
   - 明確指出「讀不到」或「目前無法取得內容」。
   - 說明可見到的狀態，例如 403、無內容、需要登入、或頁面拒絕存取。
   - 不要假裝已讀取內容，也不要編造摘要。
5. 在讀不到的情況下，列出使用者還可以提供的資訊，讓後續能完成整理：
   - 頁面截圖
   - 頁面原始文字或複製貼上的內容
   - HTML 原始碼
   - 可公開存取的替代連結
   - 允許存取的版本或去除限制後的內容
6. 若來源本身就是錯誤頁或狀態頁，摘要應以「這是一個錯誤/狀態回應」為重點，而不是臆測其背後內容。

# 輸出格式建議
- 可讀時：
  - 主旨：...
  - 重點：
    - ...
    - ...
- 讀不到時：
  - 結論：目前讀不到這個頁面的內容。
  - 原因：...
  - 你可以提供：
    - ...
    - ...

# 注意事項
- 僅根據實際可取得的內容作答。
- 不要捏造頁面內容。
- 若頁面回傳的是 403 或其他拒絕存取狀態，應直接如實回報。
