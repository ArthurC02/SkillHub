# 目的

將使用者提供的需求句逐句分類，依 RFC 2119 的語意標示為 **MUST / SHOULD / MAY**，並輸出成表格。

# 適用範圍

- 只處理文字中的需求句。
- 依 RFC 2119 的關鍵詞語意判定，不自行發明新等級。
- 若句子沒有明確需求強度，標示為「未明示」或依上下文判斷為最接近的等級，但要保守。

# 判定原則

1. **MUST**：表示絕對必要、必須遵守、不可省略。
2. **SHOULD**：表示強烈建議、通常應該遵守，但允許例外。
3. **MAY**：表示可選、允許、可以但不要求。
4. 若句子同時包含多個要求，拆成多列分別標示。
5. 若一句話包含條件與結果，保留原句，不要改寫語意；只標示等級。
6. 若句子是描述事實、背景、定義、範圍，而不是要求，標示為「非需求」或「未明示」。
7. 若出現「必須」「一定要」「不得」「只能」等中文強制語氣，通常對應 **MUST**。
8. 若出現「建議」「最好」「應該」等語氣，通常對應 **SHOULD**。
9. 若出現「可以」「可」「得以」「允許」等語氣，通常對應 **MAY**。
10. 若原文同時有多個關鍵詞，以最強約束為準；例如同句同時有「應該」與「必須」，標示為 **MUST**。

# 作業步驟

1. 讀取使用者貼上的需求文字。
2. 以句號、分號、換行、條列符號等為切分依據，拆成逐句項目。
3. 對每一句判定其需求強度：
   - 找出明確的強制、建議、允許語氣。
   - 若沒有明確語氣，根據上下文判斷是否為需求；若無法判斷，標示「未明示」。
4. 將每句保留原文，避免自行摘要到失真。
5. 輸出成表格，至少包含以下欄位：
   - 序號
   - 原句
   - 等級
   - 判定依據
6. 若句子可拆成多個獨立需求，拆列處理，不要把不同等級混在同一列。
7. 若使用者提供的內容不足以判定，直接指出哪些句子需要補充上下文。

# 輸出格式

使用 Markdown 表格：

| 序號 | 原句 | 等級 | 判定依據 |
|---|---|---|---|
| 1 | ... | MUST | 含「必須」等強制語氣 |
| 2 | ... | SHOULD | 含「應該」等建議語氣 |
| 3 | ... | MAY | 含「可以」等允許語氣 |

# 注意事項

- 不要把 RFC 2119 的定義本身當成使用者需求來標示。
- 不要自行補寫規範內容。
- 不要把同一句中的背景敘述誤判為需求。
- 若使用者貼的是多段文字，先逐段再逐句處理。
- 若句子是英文 RFC 風格，直接依 MUST / SHOULD / MAY 等詞判定；若是中文，依語氣對應判定。
