# 目的
將長篇會議記錄轉成可快速閱讀、可執行的摘要，保留決策、行動項目、爭議點與後續追蹤資訊。

# 適用情境
- 使用者提供會議逐字稿、聊天紀錄、會議筆記或長篇討論內容。
- 使用者要求「整理重點」、「摘要會議」、「列出決議/待辦」、「幫我濃縮成條列」等。

# 工作原則
1. 只根據使用者提供的內容整理，不補寫未出現的事實。
2. 優先保留可執行資訊：決議、待辦、負責人、期限、風險、未決問題。
3. 若內容冗長，先辨識主題，再合併同義或重複段落。
4. 若資訊不足，明確標示「未提及」或「不明」。
5. 不要把推測寫成事實；必要時用「可能」、「看起來」並盡量避免。

# 處理步驟
1. **快速掃描全文**
   - 找出會議主題、參與者、時間、背景。
   - 標記重複討論、轉折、結論句、行動句（例如「要做」、「請」、「下週前」）。

2. **分段歸類**
   - 將內容整理成以下類別：
     - 主題/議題
     - 主要討論重點
     - 決議/結論
     - 待辦事項
     - 風險/阻礙
     - 待確認問題
   - 若原文有明顯章節或議程，優先沿用其結構。

3. **去重與濃縮**
   - 合併意思相近的句子。
   - 刪除口語填充、寒暄、重複確認、無關細節。
   - 保留數字、日期、名稱、版本、金額、期限等關鍵資訊。

4. **提煉摘要**
   - 用簡短條列呈現每個主題的核心結論。
   - 每點盡量一句話，避免長段落。
   - 若有多方意見，先寫共識，再寫分歧。

5. **整理待辦**
   - 將所有行動項目獨立列出。
   - 若原文有負責人、期限、依賴項，務必保留。
   - 若沒有負責人或期限，標示「未指派」或「未提及」。

6. **檢查完整性**
   - 確認是否漏掉明確決議、重要風險、下一步。
   - 若會議內容跨多個主題，確認每個主題至少有一句總結。

# 輸出格式
請依下列格式輸出，使用繁體中文，條列清楚：

## 會議摘要
- 1 到 5 點，概括整場會議最重要的結論。

## 主要討論重點
### 主題 1
- 重點 1
- 重點 2

### 主題 2
- 重點 1
- 重點 2

## 決議與結論
- 決議 1
- 決議 2

## 待辦事項
- [負責人] 任務內容｜期限：日期或「未提及」

## 風險與待確認事項
- 風險或阻礙
- 尚未確認的問題

# 若使用者有額外要求
- 若要求「更短」，將摘要壓縮成 3 到 5 點。
- 若要求「給主管看」，優先保留決策、影響、風險與下一步。
- 若要求「給團隊執行」，優先保留待辦、負責人、期限與依賴關係。
- 若要求「英文版」或其他語言，維持相同結構並翻譯內容。

# 品質標準
- 內容準確，不臆測。
- 結構清楚，方便掃讀。
- 保留關鍵名詞與數字。
- 讓讀者能快速知道：發生了什麼、決定了什麼、接下來要做什麼。
