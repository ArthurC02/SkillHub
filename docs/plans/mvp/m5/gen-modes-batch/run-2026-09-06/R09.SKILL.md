## 目的
將使用者提供的履歷內容重寫為更貼近資料分析職缺的版本，優先凸顯資料處理、分析、報表、洞察、商業影響與工具能力，並將篇幅控制在一頁以內。

## 先確認的資訊
如果使用者沒有同時提供以下內容，先用最少問題補齊：
1. 原始履歷全文。
2. 目標職缺名稱或職缺描述。
3. 是否要保留特定經歷、技能或格式偏好。

若缺少職缺描述，仍可依「資料分析職缺」通用需求改寫，但要避免捏造經歷或技能。

## 改寫原則
1. 以資料分析職缺常見關鍵字重寫內容：資料清理、資料分析、SQL、Excel、Python、Tableau、Power BI、A/B test、報表、自動化、商業洞察、跨部門溝通。
2. 把每段經歷改成「動作 + 方法/工具 + 成果」的句型，盡量量化成果。
3. 優先保留與分析相關的專案、報表、流程改善、指標追蹤、決策支援經驗。
4. 刪除與目標職缺關聯低、重複、過度細節或冗長敘述。
5. 若原文沒有量化數據，改寫時可提示使用者補數字，但不要自行編造。
6. 語氣專業、精簡、以成果導向為主。
7. 控制整體長度在一頁以內；若內容過多，優先保留最近、最相關、最有成果的經歷。

## 建議輸出結構
依下列順序重寫：
1. 姓名與聯絡資訊（若原文有提供）
2. 專業摘要：2–4 行，聚焦資料分析能力與產業/領域經驗
3. 核心技能：以條列呈現，分成工具、分析能力、商業能力
4. 工作經歷：每段 2–4 個條列，強調成果與工具
5. 學歷與證照：僅保留與職缺相關者
6. 專案經驗：若比工作經歷更能證明分析能力，可優先呈現

## 改寫步驟
1. 讀取原始履歷，標記可轉成資料分析語言的內容。
2. 找出最能證明分析能力的經歷與成果。
3. 將每個條列改寫為更具體、可量化、與資料分析相關的表述。
4. 移除不必要的敘述，壓縮篇幅。
5. 檢查是否仍然像一份可直接投遞的履歷，而不是說明文件。
6. 若資訊不足以完成高品質改寫，先列出需要補充的關鍵資訊，再等待補件。

## 注意事項
- 不要捏造職稱、公司、工具、數字或成果。
- 不要把不相關的經歷硬改成資料分析經驗；只能重新表述既有內容。
- 若使用者要求「一頁以內」，優先精簡內容而不是縮小字體或改版面。
- 若原始履歷明顯不足以支撐資料分析職缺，應直接指出缺口，並建議補強方向，例如 SQL、Python、報表工具、專案成果或量化指標。
