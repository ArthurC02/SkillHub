---
name: readme-installation-rewrite
description: Rewrite a README’s installation steps into a beginner-friendly version with an expected output after each step. Use when the user asks to make installation instructions easier to follow or to add step-by-step verification.
---

# 目標
將 README 中的安裝步驟改寫成新手也能照做的版本，並且在每一步後面補上「預期輸出」或「你應該看到的結果」。

# 做法
1. 先找出 README 裡所有與安裝相關的內容：安裝前置條件、下載/安裝指令、設定環境變數、初始化、驗證安裝、常見錯誤提示。
2. 保留原本的技術事實，不新增未確認的需求、指令或版本號。
3. 把每個步驟拆小：
   - 一步只做一件事。
   - 先說明要做什麼，再給指令。
   - 如果原文有多個指令，分成多個步驟，除非它們必須連續執行且不可分開。
4. 每一步都加上預期輸出，格式要清楚可掃讀。可用以下其中一種寫法：
   - `預期輸出：...`
   - `你應該看到：...`
   - `成功時會顯示：...`
5. 預期輸出要具體，但不要捏造不確定的細節：
   - 如果原文有明確輸出訊息，就直接改寫成白話。
   - 如果沒有明確輸出，就寫使用者應該觀察到的結果，例如「終端機沒有錯誤訊息」、「安裝完成後可執行 `xxx --version` 並看到版本號」。
   - 不要編造精確數字、檔名、路徑或畫面文字，除非原文已提供。
6. 用新手友善語氣改寫：
   - 避免只寫「執行此命令」；改成「打開終端機，輸入以下指令，然後按 Enter」。
   - 第一次出現的專有名詞可加簡短說明。
   - 若有風險步驟，先提醒再執行。
7. 若 README 的安裝流程依賴作業系統、套件管理器或版本差異，請分開列出，讓使用者能找到對應情境。
8. 若原文缺少驗證步驟，補上一個最基本的驗證方式，但只能使用 README 已提到的工具或指令；若無法安全補充，就明說缺少驗證資訊。
9. 保持結構清楚，建議輸出順序如下：
   - 安裝前準備
   - 安裝步驟
   - 驗證安裝
   - 常見問題（若原文有）

# 輸出要求
- 直接輸出改寫後的 README 安裝段落。
- 每個步驟都要有預期輸出。
- 不要保留過於簡略或只適合熟手的寫法。
- 不要加入與原 README 無關的新功能說明。
