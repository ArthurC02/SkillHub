## 目標

補齊或修正 Python 函式的 docstring，並統一成 Google 風格。

## 適用範圍

- 只有在輸入包含 Python 函式、方法或類別中的函式級 docstring 時使用。
- 若程式碼不是 Python，或沒有可辨識的函式簽名與 docstring，先說明無法可靠補寫，不要臆測。

## 處理步驟

1. 讀取函式定義、參數名稱、預設值、型別註記、回傳型別、例外與現有 docstring。
2. 判斷 docstring 缺少哪些部分：
   - 簡短摘要
   - 詳細說明
   - `Args:`
   - `Returns:`
   - `Raises:`
   - `Yields:`
   - `Examples:`
   - `Attributes:`（僅限類別屬性或資料類別情境）
3. 只根據程式碼本身可確定的資訊補寫；不要憑空新增行為、例外或副作用。
4. 若參數名稱、型別註記、回傳型別與 docstring 不一致，以程式碼為準，並修正文案。
5. 若函式沒有型別註記，從程式碼邏輯推斷可確定的型別；推不出來就保留通用描述，不要硬猜。
6. 若函式是 `__init__`、屬性 setter/getter、或簡單包裝函式，docstring 仍需符合 Google 風格，但可精簡。
7. 若原 docstring 已有內容，只補缺漏並修正格式，不要改變原意。

## Google 風格規則

- 第一行是簡短摘要，使用祈使句或描述句，結尾通常不加句點，除非專案慣例已有句點。
- 空一行後再寫詳細說明（若需要）。
- 區段標題使用 `Args:`, `Returns:`, `Raises:`, `Yields:`, `Examples:`。
- `Args:` 下每個參數格式：`name: 說明`，必要時可在名稱後補型別，但優先與專案既有風格一致。
- `Returns:` 說明回傳值內容；若回傳 `None`，可寫明 `None: 無回傳值` 或省略，依專案慣例一致處理。
- `Raises:` 只列出程式碼中明確會拋出的例外。
- 保持縮排一致，通常為 4 個空格。

## 輸出要求

- 直接輸出修正後的 docstring，或輸出包含修正後 docstring 的函式片段，依使用者提供內容而定。
- 不要額外解釋審查過程。
- 不要改寫與 docstring 無關的程式碼。
- 若資訊不足以安全補寫，明確指出缺少哪些資訊，並列出需要使用者提供的內容。
