## 瀏覽器觀察

- 從第一個結果頁點「與另一個 Run 比較」，候選清單列出同一 Test Case 的另一個 Run；點選後兩側顯示各自的輸出、耗時、Run 費用與獨立評估費用。
- 版本差異呈現 ALPHA → BETA，重跑連結各自帶正確的 Skill、版本與 Test Case，先進權限確認頁，不直接執行。
- 第三次剛完成執行、評估尚未回來時，比較頁顯示「未評估（不是通過）」與未評估矩陣；評估完成後重新整理，顯示「未符合／符合」及「未通過／通過」。
- 長中文輸出在原始畫面跨欄覆蓋右側 BETA。回歸測試以中文長句與無空白長字串，在 1280／375px 量文字實際矩形，不只查 DOM 文字存在。

## 回歸與突變證據

`apps/web/e2e/run-comparison.spec.ts` 共五個案例：桌面／手機欄位邊界、結果與比較導覽、兩側差異的精確對應，以及未評估／未知成本／輸入已刪除的缺席情境。零點與未測量刻意分開。

修正前兩個欄位邊界案例失敗；修正後三引擎共 **15 passed、0 skipped**。其後還原換行修正，並分別將結果文字移除、耗時改零、未評估改成符合，五個 Chromium 案例全部出現失敗標記；測試程序在收尾停滯後中止，exit 1，因此這次突變的證據是各案例失敗與錯誤產物，不是自然結束的摘要。突變均已還原，無關產品檔案的 diff 為空。
