# 同意書重新確認包（2026-08-30）

**這份文件是給法務看的，不是給工程看的。** 它只回答一個問題：**自 2026-08-23 法務確認之後，[同意書與資料保存政策](consent-and-data-policy.md)改了什麼，以及為什麼那些改動需要再看一次。**

## 為什麼要再看一次（規則的出處）

同意書自己在開頭寫著這條規則，逐字：

> **日後任何一個保存期限再變動，都要重新確認一次，因為那是法務判斷的輸入而不只是附註。**

2026-08-23 之後有**三列**變動，其中兩列改的正是保存期限，第三列是一整類資料的**首次揭露**。

## 要確認的三件事

### 一、Run Artifact 的保存期由 30 天改為 90 天

| | 內容 |
| --- | --- |
| **改動** | 使用者的試跑產出，保存期 **30 天 → 90 天** |
| **為什麼** | 平台自己的規格（`02:NFR-002a` 第 2 條）要求「Run Artifact 的保存期 ≥ 可重評窗」，而可重評窗是 Trace 的 90 天。**在此之前這條一直是被違反的**：第 31～90 天之間重新評估，會拿到一份空的產出清單。 |
| **對受測者的方向** | **往寬**。他們的產出多留兩個月，重評也拿得到東西。 |
| **法務要看的點** | 這是**延長**保存期，不是縮短。延長需要在告知同意的範圍內；若貴部門認為延長需要重新取得同意（而非僅重新告知），請明示。 |
| 裁定紀錄 | `05` R-11（2026-08-29） |

### 二、封測質性回饋新增保存期，**並補上一件從未揭露過的事**

| | 內容 |
| --- | --- |
| **改動 A** | 受測者用自己的話寫的回饋（最長 2000 字元）**首次有了保存期限**（環境變數 `FEEDBACK_RETENTION`，未設定則清除工作拒絕啟動），期滿刪除。 |
| **改動 B（重點）** | **首次向受測者揭露**：**刪除帳號時，這些文字不會跟著刪掉，只會被去識別化**（拿掉作者，文字留下）。 |
| **為什麼是重點** | 在 2026-08-29 之前，這是整個系統裡唯一一類「已經在收、卻沒有任何期限也沒有任何清除工作」的資料，而且是三類自由文字裡最敏感的一種（受測者描述自己卡在哪）。**而「刪除帳號」與「你寫的字會留下」之間的落差，受測者有權在簽名之前知道。** |
| **法務要看的點** | 「刪除帳號 ≠ 刪除你寫的字」這個落差，現在的措辭是否足以構成有效告知；以及去識別化保留是否需要獨立的同意項目。 |
| 依據 | ADR-029 決策 5 |

### 三、使用者自己寫的 Test Case，**首次有刪除路徑，也首次被揭露**

| | 內容 |
| --- | --- |
| **改動** | 使用者用自己的話寫的測試題（他描述想做什麼的原話）**在 2026-08-30 之前沒有任何刪除路徑，帳號刪除也刪不掉**。現在：帳號刪除時實體刪除，**除非**某一次試跑已經把它凍結成那次執行的輸入。 |
| **凍結的那一份會怎樣** | 留下，但**不再指向本人**——工作區與帳號在同一筆交易裡被去識別化。理由是一份已經做出的評估判定不能事後失去它的輸入。 |
| **為什麼要看** | 這一類資料**此前連揭露都沒有**，而同意書對受測者說的是「你可以要求刪除你的資料」。封測 12 位受測者**每一位都會寫測試題**（那是核心流程的必經動作）。 |
| **法務要看的點** | 「沒被跑過的完全消失、被跑過的以匿名形式留下」這個區分，措辭是否清楚；以及是否需要在簽署頁另立一句。 |
| 裁定紀錄 | `05` R-29（2026-08-30） |

## 不在這次範圍內（但法務 2026-08-23 看過的版本裡就有）

- 產品分析事件 **365 天**、Download Artifact **30 天**、稽核事件 **400 天** — **未變動**。
- 「刪除 vs 去識別化保留」的原則性段落 — 未變動，但第二、三項各自往裡面加了一個新的具體案例。

## 給法務的一句話版本

> 上次您看過之後，我們把試跑產出的保存期從 30 天延長到 90 天（因為原本的 30 天違反我們自己的規格），並且發現有兩類「使用者自己打的字」在同意書裡沒有被誠實交代：一類是回饋文字——刪帳號時它不會被刪、只會被匿名；另一類是測試題——它在此之前根本刪不掉。兩者現在都寫進了同意書。想請您確認的是措辭，特別是「刪除帳號」與「你寫的字會留下」這個落差要怎麼講才算講清楚。
