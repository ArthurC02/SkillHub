## 1. 測試目標

閘門敘述（`01` §10）：

> **測試使用者以自然語言能找到相關 Skill 並理解符合原因，否則先修正搜尋與內容，不進入 M2。**

這句話有兩半，測試要分別量到：

1. **能找到** — 受測者用自己打的字，在結果前五名內**自行指認**出一個可用的 Skill（不是主持人指給他看）。
2. **理解符合原因** — 受測者說得出「為什麼這個符合我的任務」，而且理由的依據**來自畫面上的資訊**（白話摘要、符合原因、依賴、風險提示），不是既有知識或猜測。

**本測試不量 recall。** 檢索召回率已由 [golden-query-set.md](../m1/golden-query-set.md) 以 60 條查詢／31 份語料量過（v2 增強索引 recall@5 = 48/48）。使用者測試要量的是那份量測**量不到**的東西：真人會怎麼打字，以及看到結果後敢不敢往下走。兩者的落差本身就是最有價值的產出（audit §7.3）。

## 2. 通過／不通過判準

### 2.1 四條判準

| 代號 | 判準 | 門檻 | 樣本 |
| --- | --- | --- | --- |
| **G1（主）** | 有效任務題次的**通過率** | **≥ 70%** | 9 人 × 5 題 = 45 題次 → 需 **≥ 32/45** |
| **G2（人）** | **個人通過率 ≥ 60%** 的受測者比例 | **≥ 2/3（6/9 人）** | 每人 5 題 → 個人需 ≥ 3/5 |
| **G3（次）** | 干擾查詢題次中，受測者**認同「沒有結果」是正確回應** | **≥ 75%** | 9 人 × 2 題 = 18 題次 → 需 **≥ 14/18** |
| **G4（否決）** | 任一類別（documents／writing／data）通過率 < 50%，或任一成熟度層 3 人**全部**個人通過率 < 60% | 觸發即**不通過** | 每類別 15 題次 → < 8/15 即觸發 |

**四條全過才算通過。** G4 是否決條款：即使 G1～G3 達標，只要某一類別或某一成熟度層整片失效，就不通過——那代表問題有結構，只是被平均值蓋住了。

### 2.2 單一題次「通過」的定義

一個題次同時滿足**三件事**才算通過：

1. **在 Top-5 內** — 受測者最終採用的查詢，其結果前五名包含該卡的 gold skill（含 acceptable 清單，見 `task-cards.md` 主持人版）。
2. **自行指認** — 受測者在主持人**未給任何提示**的前提下，指出該項並說「我會用這個」。
3. **理由落地** — 受測者說出的理由能對應到畫面上的具體資訊。記錄員逐字記下理由並判定其**依據來源**（見 `recording-sheet.md` 的 `reason_source` 欄）：
   - `on_screen`：引用了摘要／符合原因／依賴／風險提示 → **算通過**
   - `prior_knowledge`：靠既有認知（「我知道 docx 就是 Word」）→ **不算通過**，另記
   - `guess`：說不出理由或僅憑名稱猜 → **不算通過**

> **`prior_knowledge` 為何不算通過。** 閘門敘述是「找到**並理解符合原因**」。靠既有知識認出 `docx` 的人，證明的是他認得 Word，不是平台把符合原因說清楚了。這一欄同時會是分析階段區分「搜尋問題 vs 呈現問題」的主要訊號（`analysis.md` §3）。

**重試規則**：受測者可自由改寫查詢，**改寫次數不影響通過與否**，但必須逐次記下每一版查詢原文。第 3 次改寫後仍找不到即判該題次不通過，主持人結束該題。改寫次數是分析階段的獨立指標（`analysis.md` §2.3）。

### 2.3 70% 是怎麼推出來的

70% 不是拍腦袋的圓整數，是三段相乘：

| 段 | 係數 | 依據 |
| --- | --- | --- |
| **A. 檢索能把 gold 排進 Top-5** | **0.926** | golden set v2 增強索引 recall@5 = **48/48（100%）**。單點 100% 不能直接當期望值——以 Wilson 95% 信賴區間下界取保守值：n=48、k=48 → **92.6%**（rule of three 給 93.75%，取較保守者） |
| **B. 真人打字的懲罰** | **0.85** | golden set 的 60 條查詢是人工撰寫、每條刻意寫清楚一個意圖；真人會更短、更含糊、夾帶無關脈絡。唯一可用的實測代理是 v1 最弱格 **documents／繁中 recall@5 = 80%**，該格的失效原因（口語、未明說檔案格式）正是真人打字的典型樣態。取 0.85，介於該格的 0.80 與滿分之間，偏保守 |
| **C. 在 5 列中指認出來並說出落地理由** | **0.90** | 無實測基線。DISC-002 的七欄與逐筆 `match_reason` 已上線且有測試覆蓋（audit §5.2），資訊確實在畫面上；扣的 10% 是版面與文案的閱讀成本 |

**0.926 × 0.85 × 0.90 = 0.708 → 取 70%。**

**這個數字的性質**：它是「在已知檢索品質下，一個資訊呈現得還可以的介面應該達到的水準」。**達標不代表介面很好，只代表沒有比 golden set 的量測結果掉得更多。** 掉得更多，問題就不在檢索（B、C 兩段之一失效）——這正是 `analysis.md` §3 決策樹要分辨的事。

### 2.4 G3 的 75% 是怎麼推出來的

golden set v2 在門檻 `MaxCosineDistance = 0.75` 下，12 條干擾查詢**全部正確拒答（12/12）**，召回損失 0/48（§10.5）。Wilson 95% 下界：n=12、k=12 → **75.7%**。

這個數字恰好落在 ADR-013 移交的「離題拒答 ≥ 75%」目標上，兩條路徑獨立得到同一個門檻，因此取 **75%**。

**G3 量的不是機器**——機器側 12/12 已經量過了。G3 量的是**人**：系統回「沒有結果」時，受測者是否認為這是正確且誠實的回應，而不是「壞掉了」或「這平台東西很少」。

### 2.5 統計精度（讀數字前必看）

- 45 個有效題次：**單一題次進退 = 2.2 個百分點**。G1 的 70% 對應 32/45（71.1%），31/45 是 68.9%。**擦邊過與擦邊不過的差距只有一題**，結論必須連同質性證據一起讀，不能只看百分比。
- 18 個干擾題次：單題 = 5.6 個百分點。G3 更粗。
- 三個成熟度層各 3 人：**層級間的差異不具統計意義**，只能當作質性訊號使用（`analysis.md` §2.4）。
- 本套件的所有百分比應讀作**量級**，不是精確值——與 golden-query-set.md §6-7 同一條紀律。

## 4. 與 golden set 的關係

### 4.1 取什麼、不取什麼

| 取 | 不取 |
| --- | --- |
| **查詢的「意圖家族」**——某張卡對應 golden set 哪一條的任務意圖 | **查詢原句** |
| **gold skill 標註**（`gold_primary` ∪ `gold_acceptable`）作為判定基準 | golden set 的 recall 數字（那不是使用者測試判準） |
| **題型分布**（直述／口語模糊／干擾）與語言分布 | golden set 的 31 份語料（測試打的是**線上 44 筆目錄**，不是評測語料） |

> **原句必須保密。** 受測者版卡片只有**任務情境敘述**，沒有任何可直接貼進搜尋框的句子。理由：golden set 量的是「原句直接進檢索」的降級路徑，那條路徑的成績已知；把原句給受測者等於把答案給檢索器，量到的會是 golden set 的重跑，不是真人的打字行為（audit §7.3）。
>
> **執行紀律**：`task-cards.md` §2（受測者版）可以印給受測者看；§3（主持人版對照表，含 golden query family 與 gold skill）**不得出現在受測者視線內**，遠端模式不得分享含 §3 的畫面。

### 4.2 情境取自哪些 query family

**重要落差：線上目錄（45 筆）≠ golden set 語料（31 份）。** 兩者只有 15 筆重疊。golden set 裡的 `report-designer`、`deck-publisher`、`html-express`、`document-design`、`pitchcraft`、`minimax-*`、`economist-style`、`newsroom-style`、`academic-writing`、`doc-coauthoring`、`high-stakes-analytics`、`data-journalism` **都不在線上目錄**；線上目錄另有 golden set 沒有的 `handoff`、`humanizer`、`line-edit`、`cringe-check`、`full-review` 等。

因此卡片的做法是：**取 golden query 的意圖家族，把 gold 重新對到線上目錄實際存在的 Skill**。對照如下（完整版在 `task-cards.md` §3）：

| 卡片 | golden query family | 線上 gold skill | 家族原 gold（若不同） |
| --- | --- | --- | --- |
| DOC-1 | D01（從大綱產出 Word 文件） | `docx` | 同 |
| DOC-2 | D02（掃描檔抽表格再合併） | `pdf` | 同。**v1 唯一的 recall@5 miss，v2 修復到第 3 名**——保留它作為診斷題 |
| DOC-3 | D03／D09（要向上簡報，不提檔案格式） | `pptx` | D09 原 gold `pitchcraft` 不在線上目錄 |
| DOC-4 | D04／A14（試算表要看得懂、格式一致） | `excel-freeze` | 原 gold `xlsx`／`minimax-xlsx`；改對到簡中文件的 YuYY 系列以取得**反向跨語言**案例 |
| WRI-1 | W01（品牌語氣與字型規範） | `brand-guidelines` | 同 |
| WRI-2 | W02（公司內部公告） | `internal-comms` | 同 |
| WRI-3 | W05／W13（讀起來像 AI 寫的，要改回人味） | `humanizer` | 原 gold `humanize`，線上為同性質的 `humanizer` |
| WRI-4 | W06／W14（判斷文字是否 AI 生成） | `ai-written-check` | 原 gold `ai-check` |
| DAT-1 | A05（CSV 轉 JSONL） | `csv-to-json` | 同 |
| DAT-2 | A07（標出個資欄位） | `pii-flag` | 同 |
| DAT-3 | A08／A09（一堆資料看不出所以然） | `data-analyst` | 同 |
| DAT-4 | A01／A13（Excel 去除重複列） | `excel-deduplicate` | 同 |
| X-1 | D11／A11 家族（生活題，離題） | **無結果** | 同 |
| X-2 | A20（機械維修，離題） | **無結果** | 同 |

**三張卡的 gold 是待 CONTENT-005 改寫的簡中 Skill**：`DOC-4`（`excel-freeze`）、`DAT-3`（`data-analyst`）、`DAT-4`（`excel-deduplicate`）。這是刻意的——它們是 CONTENT-005 是否真的解決了問題的**直接檢驗**。若 CONTENT-005 已完成而這三張卡仍集中失敗，問題不在語言而在別處（`analysis.md` §3）。

**跨語言在本測試有三個方向**（正向繁中→英文、反向英文→簡中、同語言英文→英文對照組），完整定義與卡片歸屬見 `task-cards.md` §1.1。

### 4.3 兩個回歸把關（測試期間持續）

1. 每次動語料或索引管線，跑 `python tools/goldenset/evaluate.py --selfcheck`（零成本、零網路）。測試期間本應凍結，此指令用於確認**確實沒被動過**。
2. golden-query-set.md §4.4 的三個門檻過期觸發條件中，**條件 1（語料成長一個數量級）與條件 3（查詢改寫上線）仍然有效**。測試期間若任一觸發，本次結論作廢，需重推門檻後重測。

## 5. 本套件的限制（先寫在前面）

1. **9 人不是統計樣本。** 質性可用性問題在 5～6 位後飽和，取 9 是為了容納三個成熟度層；層與層之間的差異不具統計意義。這也**不取代 PDM-009 的封測人數決策**（該項屬 M4，仍未定）。
2. **測的仍是降級路徑。** 查詢改寫（ADR-013 §2）尚未上線，受測者打的字直接進向量檢索。改寫上線後成績應該更好，本次結果是**下界**。
3. **不測 DISC-003 的四個無資料維度**——它們是停用的。測的是「停用是否被誤讀」，不是篩選功能本身。
4. **不測下載。** `docx`／`pdf`／`pptx`／`xlsx` 是 source-available，永遠不會有 Download Artifact（seed-skills.json 註記）。主持人不得引導受測者往下載走。
5. **不測試跑。** 試跑屬 M2；受測者若問「可以馬上試嗎」，記下這個訊號但不提供。
6. **`reason_source` 的判定是主觀的。** 由記錄員當場判、由第二人事後覆核（`analysis.md` §1.3）；覆核不一致的題次逐筆列出。
