# 主持腳本

- 對應：[README.md](README.md) 判準、[task-cards.md](task-cards.md) 卡片、[recording-sheet.md](recording-sheet.md) 記錄欄位
- 每場 **30～45 分鐘**，主持人 1 名＋記錄員 1 名

---

## 1. 開場前 10 分鐘（受測者尚未進場）

- [ ] 開啟環境，確認搜尋、詳情、進階檢視、比較四條路徑都能走通（自己先打一條無關的查詢，**不要用任何一張卡的內容**）
- [ ] 確認目錄筆數仍是 44（凍結未被破壞）
- [ ] 準備受測者版卡片：**只有 `task-cards.md` §2**。現場模式印成單張，遠端模式逐張貼進聊天視窗
- [ ] 主持人版對照表（§3）另開一個受測者看不到的視窗或紙本
- [ ] 記錄員開好 `recording-sheet.md` 的逐場表，填好場次編號、日期、受測者代號、成熟度層
- [ ] 確認錄影／錄音同意書已簽（若採用錄影——待負責人定，見 `recruit.md`）

## 2. 時間表

| 段 | 時長 | 內容 |
| --- | --- | --- |
| A. 開場與同意 | 3 分 | 自我介紹、說明目的、同意錄影、聲明「我們測系統不測你」 |
| B. 暖身 | 3 分 | 兩個背景問題，讓受測者開口 |
| C. 任務 1～5 | 20～28 分 | 每題 4～5 分鐘，硬性上限 6 分鐘 |
| D. 干擾任務 ×2 | 4～7 分 | 每題 2～3 分鐘；**干擾②多一句非閘門追問，約 40 秒**（分派表是交錯的，D 段不在 C 段之後，見 §3.D） |
| E. 收尾訪談 | 4 分 | 四個固定問題 |
| F. 致謝與報酬 | 1 分 | — |
| **合計** | **35～45 分** | 順利時 35 分，卡點多時 45 分封頂 |

**超時處理**：任務段超過 28 分鐘，砍掉第 5 張情境卡，**干擾卡兩張一定要做完**（G3 的樣本比 G1 更脆弱，18 題次少 2 題就是 11 個百分點）。被砍的題次在記錄表標 `skipped`，不計入分母。

## 3. 逐段腳本

### A. 開場與同意（3 分）

> 「你好，我是 ⬜⬜，今天由我陪你走一段。旁邊這位是記錄員，他不會說話，只負責打字。
>
> 我們在做一個找 Agent Skill 的工具。Skill 你可以先想成『一段給 AI 助理的專業說明書』——不用先懂它是什麼，等一下你會看到。
>
> **今天測的是這個系統，不是你。** 你卡住、找不到、覺得莫名其妙，那都是我們要的資料，而且是最有用的那種。你不用替我們客氣。
>
> 有一件事想拜託你：**請盡量把心裡想的講出來。** 你在看什麼、在猶豫什麼、為什麼點這個不點那個。我可能會安靜一段時間，那不是我在等你答對，是我在聽。
>
> 全程大概 40 分鐘。你隨時可以喊停。（錄影同意確認。）」

### B. 暖身（3 分）

只問兩題，目的是讓受測者開口與確認招募篩選的自陳無誤：

1. 「你平常做的東西大概是什麼？文件、文章、資料，還是別的？」
2. 「你有用過 AI 助理幫你做這些嗎？如果有，最近一次是什麼情況？」

**記錄員記**：受測者自述的主要工作類型（用於分析階段對照卡片類別）。

### C. 任務段（每題 4～5 分）

**每題固定四步：**

**① 給卡**

> 「這是一個情境。**你就是這個情境裡的人。** 請你先看完，然後用你自己的話，在這個網站上把你要的東西找出來。」

現場模式遞紙本，遠端模式貼文字。**卡片給完就閉嘴。**

**② 觀察打字（不介入）**

受測者打字時**完全不說話**。記錄員逐字記下**查詢原文**（含錯字、標點、空白，一字不改）。

**③ 受測者停在結果頁時**

等他自己說話。真的完全沉默超過 20 秒才問一句：

> 「你現在在看什麼？」

**④ 他指認某一項後（關鍵步驟）**

> 「你會用這個嗎？」→（若是）→ **「為什麼是這個？」**

這句「為什麼是這個」是整場測試的核心。**問完就等，不要補充、不要換句話說、不要遞台階。** 記錄員逐字記下答案原話，並當場判 `reason_source`（`on_screen`／`prior_knowledge`／`guess`，定義見 README §2.2）。

判不出來時，**只能追問這一句**：

> 「你剛剛說的那個，是在畫面上哪裡看到的嗎？」

（這句是允許的，因為它問的是**來源**不是**答案**。若受測者指得出畫面位置 → `on_screen`；若說「不是，我本來就知道」→ `prior_knowledge`。）

**⑤ 收題**

該題次結束的三種情形：
- 受測者指認並說了理由 → 記錄後進下一題
- 受測者第 3 次改寫查詢後仍找不到 → **主持人結束該題**：「好，這題我們先到這裡，不影響後面。」記 `fail_not_found`
- 超過 6 分鐘 → 同上，記 `fail_timeout`

### D. 干擾任務（每題 2～3 分）

給卡方式與情境卡完全相同，**絕不能暗示這題不一樣**。受測者送出後系統會回「無結果＋改寫建議」。

觀察兩件事，然後問兩題：

**觀察**：受測者的第一反應是「照建議改寫」還是「放棄／認為壞了」？（記 `distractor_reaction`）

**問**：
> 「你覺得系統這樣回，合理嗎？」
>
> （不論答什麼，追一句）「為什麼？」

判 G3 的通過標準：受測者**認同這是正確且誠實的回應**（例如「對啊，這網站就不是做這個的」「它跟我說沒有，總比硬塞給我好」）。以下**不算**通過：
- 「應該是壞了吧」
- 「這網站東西是不是很少」
- 「不知道，可能吧」（模糊敷衍）

**只在該場的第二張干擾卡（干擾②）判完 G3 之後，追最後一句**（2026-08-23 新增；來由與用途見 [m5/README.md §前期驗證](../m5/README.md)）：

> 「那接下來你會做什麼？」

（記 `next_step_raw` 逐字，並當場判 `next_step_class`。）

**這一題有三條紀律，違反任何一條，這筆資料就沒有用：**

1. **順序不能換，而且只問一次。** 它排在 G3 的兩題**之後**，因為它會把受測者的注意力從「這個回應誠不誠實」移到「我還能幹嘛」。
   **干擾①不問。** [task-cards.md §4](task-cards.md) 的分派表把干擾①排在第 3 題與第 4 題之間——**它後面還有兩張計入 G1／G2／G4 的情境卡**。在那裡把受測者推去想「我可以自己做一個」，然後立刻遞第 4 張卡，就是這條紀律自己描述的污染機制，只是對象從 G3 換成 G1。**干擾②是該場最後一張卡，之後沒有任何計分題次。**
   （順帶：§2 時間表與 §3 的段落順序把 D 段畫在 C 段之後，而分派表是交錯的。**以分派表為準**——那是操作事實來源。這個既有落差在加掛這一題之前無害，之後不是。）
2. **絕對不能問引導題。** 不准出現「你會想要系統幫你做一個嗎」「有沒有想過自己生一個」這類句子——**那必定拿到假的 yes**。開放問，問完就等，不補充、不換句話說、不遞台階（同 §3.C 的既有紀律）。受測者說「不知道」或「就算了」也是答案，如實記。
3. **它不影響 G1～G4 任何一條判準。** 這一題量的是 MVP 之外的東西（`01` §7.3 已明文列 M5）。**閘門通不通過與這一題的答案無關**，不得因為這一格好看就放寬 G3，也不得反過來。

### E. 收尾訪談（4 分）

四個固定問題，**照順序問，不加不減**：

1. 「整個過程裡，最讓你卡住的是哪一刻？」
2. 「你剛剛有幾次是先看了下面那行『為什麼符合』才決定點進去的嗎？還是看名字就決定了？」（→ 對應 README §1.1 第 1 題）
3. 「你有注意到篩選那一排嗎？裡面有幾個是灰的、按不動的。你當時怎麼想？」（→ 對應 §1.1 第 3 題；**若受測者全程沒注意到篩選列，如實記錄「未注意到」，這本身是答案**）
4. 「如果這是你自己的工作，你會再回來用嗎？為什麼？」

### F. 致謝（1 分）

> 「今天真的很有幫助，尤其是你 ⬜⬜ 那段。報酬會在 ⬜⬜ 之前寄給你。謝謝。」

（⬜⬜ 引用一件受測者實際說過的具體事，不要泛泛道謝。）

## 4. 觀察要點（記錄員的優先序）

按重要性排，時間不夠時從下往上放棄：

| 序 | 觀察什麼 | 落到記錄表哪一欄 |
| --- | --- | --- |
| 1 | **查詢原文逐字**（每一次改寫都要，含錯字） | `query_raw_1..3` |
| 2 | **指認的項目**與**理由原話** | `picked`、`reason_quote` |
| 3 | **理由的依據來源** | `reason_source` |
| 末 | **干擾②的「接下來你會做什麼」原話**（優先序最低：**時間不夠時可以放棄，因為它不影響閘門**——見 §3.D 紀律 3） | `next_step_raw` |
| 4 | Top-5 是否含 gold（主持人事後對照 §3 填） | `gold_in_top5` |
| 5 | 是否展開／閱讀符合原因才點進去 | `used_match_reason` |
| 6 | 卡點時刻與原話 | `friction_quote` |
| 7 | 是否使用篩選、比較、排序說明 | `used_filter`／`used_compare`／`used_ranking` |
| 8 | 停頓超過 10 秒的位置 | `friction_quote` 附註 |

**「原話」的紀律**：引號內只能是受測者真的說出口的字。整理、通順化、補主詞都算污染。聽不清就寫 `[聽不清]`，不要腦補。

## 5. 追問句庫（只能用這些）

| 情境 | 可以說 |
| --- | --- |
| 受測者沉默超過 20 秒 | 「你現在在看什麼？」 |
| 受測者指認後 | 「為什麼是這個？」 |
| 理由來源判不出來 | 「你剛剛說的那個，是在畫面上哪裡看到的嗎？」 |
| 受測者表情有變化但沒說話 | 「剛剛那個表情是什麼意思？」 |
| 受測者說「這個看起來不錯」 | 「哪裡不錯？」 |
| 受測者說「這個不對」 | 「怎麼看出來不對的？」 |
| 受測者問「我這樣打對嗎」 | 「沒有對不對，你平常怎麼問就怎麼打。」 |
| 受測者問「這個是什麼意思」（指畫面元素） | 「你猜是什麼意思？」（**不要解釋**） |
| 受測者要求幫忙 | 「如果我今天不在，你會怎麼做？」 |
| 受測者第 2 次改寫後洩氣 | 「還想再試一次嗎？不想也完全可以。」 |
| 干擾題後 | 「你覺得系統這樣回，合理嗎？」→「為什麼？」 |
| **干擾②判完 G3 後**（干擾①不問） | 「那接下來你會做什麼？」（**問完就等，不補充、不換句話說、不遞台階**；不得改成任何提到「做一個」「生成」的問法） |

## 6. 不可提示清單（違反即該題次作廢）

**絕對不可以：**

1. ❌ **說出或寫出任何 golden query 原句**，或卡片以外的任何具體查詢措辭
2. ❌ **說出任何 Skill 的名字**——包含 `docx`、`pdf`、`humanizer` 等。受測者說出來可以，主持人不行
3. ❌ **暗示答案在第幾個**：「再往下看看」「上面那個呢」「你確定嗎」都算
4. ❌ **暗示某題是干擾題**：「這題可能比較特別」「這題找不到沒關係」
5. ❌ **解釋畫面元素**：符合原因是什麼、來源層級是什麼、為什麼有些篩選是灰的
6. ❌ **示範打字**，或建議「你可以試試加上『Excel』這個字」
7. ❌ **評價受測者的查詢**：「這樣打很好」「這樣可能太模糊了」都算
8. ❌ **在受測者猶豫時填補沉默**——沉默是資料
9. ❌ **替受測者操作滑鼠鍵盤**（純技術故障除外，且要記錄）
10. ❌ **讓受測者看到 `task-cards.md` §3 或本檔**

**如果不小心提示了**：當場不必道歉打斷，**事後在記錄表該題次標 `contaminated`**，該題次**不計入分母**。誠實標記比湊滿 45 題次重要——45 題次少 1 題只是 2.2 個百分點，一個被污染的題次卻會讓結論失真。

**受測者主動問「這個要怎麼用」「有沒有其他辦法」時**：一律回「如果我今天不在，你會怎麼做？」

## 7. 遠端模式注意事項

| 項目 | 做法 |
| --- | --- |
| **畫面共享方向** | **受測者分享他的畫面**，主持人不分享。主持人若要分享（例如貼卡片），只分享**單一應用程式視窗**，絕不分享整個桌面——`task-cards.md` §3 與本檔可能開著 |
| **卡片遞送** | 逐張貼進聊天視窗，**一次一張**。不要一次貼完，受測者會先讀後面的題目 |
| **沉默的處理** | 遠端的沉默比現場更難忍。主持人**把麥克風靜音**是好辦法——避免不自覺的「嗯」「對」變成暗示 |
| **技術故障** | 連線斷、頁面白畫面：暫停計時，記錄故障時間；同一題次故障兩次即標 `skipped` |
| **錄影** | 需事前同意。受測者拒絕錄影仍可進行，改由記錄員全程打字（此時建議把該場排在較晚，記錄員手比較熱） |
| **看不到表情** | 遠端無法可靠觀察表情，`friction_quote` 只記語音與操作停頓，**不要臆測情緒** |
| **家庭環境干擾** | 受測者被打斷（門鈴、小孩）→ 暫停計時，該題次不受影響 |

## 8. 現場模式注意事項

| 項目 | 做法 |
| --- | --- |
| **座位** | 主持人坐在受測者**斜側後方**，不要正面對坐（正面對坐會讓受測者頻繁看主持人臉色找答案） |
| **記錄員位置** | 受測者**視線外**。記錄員的皺眉會被讀成「我答錯了」 |
| **紙本卡片** | 一張一張遞，用完收回。**不要讓多張卡同時攤在桌上** |
| **裝置** | 用受測者熟悉的裝置最好（自帶筆電）。若用測試機，開場先給 1 分鐘適應鍵盤與輸入法——**中文輸入法必須先確認可用**，這是最常見的現場事故 |
| **飲水與中斷** | 45 分鐘不安排中場，但受測者可隨時喊停 |
| **報酬交付** | 現場交付或當場確認匯款資訊（見 `recruit.md`） |

## 9. 場次結束後 10 分鐘內（趁記憶還熱）

- [ ] 主持人與記錄員**各自**寫下一句「這場最重要的一件事」，**寫完再互相看**（先討論會互相污染）
- [ ] 主持人對照 `task-cards.md` §3，逐題填 `gold_in_top5`
- [ ] 記錄員檢查所有 `reason_quote` 是否為原話、有無自行通順化
- [ ] 標記所有 `contaminated`／`skipped` 題次並寫明原因
- [ ] 把逐場表數字加進匯總表（`recording-sheet.md` §3）

**不要在場次之間討論「目前看起來會不會過」。** 中途形成的結論會改變後面場次的主持方式，這是最難察覺的污染來源。
