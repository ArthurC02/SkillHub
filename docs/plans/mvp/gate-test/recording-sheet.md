## 2. 欄位定義（判定不一致時以此為準）

| 欄 | 定義 | 常見誤判 |
| --- | --- | --- |
| `gold_in_top5` | 受測者**最終採用的那一版查詢**，其結果前 5 名含 primary 或 acceptable 任一項 | 不是「任何一版查詢曾經出現過」。改寫過就以最後一版算 |
| `picked` | 受測者在**無提示**下明確說「我會用這個」的那一項 | 受測者只是點開看看不算指認；要有「會用」的意思表示 |
| `reason_source: on_screen` | 理由引用了畫面上的具體資訊（摘要、符合原因、依賴、風險提示、來源） | 受測者說「它寫說可以處理 CSV」→ `on_screen`（引用摘要） |
| `reason_source: prior_knowledge` | 理由來自既有認知，與畫面無關 | 「我知道 docx 就是 Word 啊」→ `prior_knowledge`，**即使指認正確也不算通過** |
| `reason_source: guess` | 說不出理由，或僅憑名稱像 | 「看名字應該是這個吧」→ `guess` |
| `outcome: fail_no_reason` | 指認正確，但理由不是 `on_screen` | **不要記成 `pass`。** 閘門敘述是「找到**並理解符合原因**」 |
| `outcome: contaminated` | 主持人違反不可提示清單 | **不計入分母。** 誠實標記優先於湊滿題次 |
| `outcome: skipped` | 超時被砍、技術故障兩次、受測者要求跳過 | 不計入分母 |
| `g3_pass` | 受測者認同「沒有結果」是**正確且誠實**的回應 | 「應該是壞了吧」「這網站東西很少吧」「不知道，可能吧」皆記 N |
| `used_filter: 點了停用維度` | 受測者實際點擊了灰掉的篩選器 | 這是 README §1.1 第 3 題的行為證據，比訪談自陳可靠 |

## 4. 通過率計算式

設：
- `N_eff` = 有效題次 = 45 − `skipped` − `contaminated`
- `N_pass` = `outcome = pass` 的題次數
- `N_dist_eff` = 有效干擾題次 = 18 − 干擾題的 `skipped`／`contaminated`
- `N_g3` = `g3_pass = Y` 的題次數

| 判準 | 計算式 | 門檻 | 滿樣本時 | 結果 |
| --- | --- | --- | --- | --- |
| **G1** | `N_pass / N_eff` | ≥ 70% | ≥ 32／45 | ⬜% → 通過／不通過 |
| **G2** | 個人通過率 ≥ 60% 的人數 ÷ 受測人數 | ≥ 2/3 | ≥ 6／9 人 | ⬜／9 → 通過／不通過 |
| **G3** | `N_g3 / N_dist_eff` | ≥ 75% | ≥ 14／18 | ⬜% → 通過／不通過 |
| **G4** | 檢查：任一類別通過率 < 50%？任一層 3 人全部個人通過率 < 60%？ | 皆否 | 類別 < 8／15 即觸發 | 觸發／未觸發 |

**四條全過 ⇒ 閘門通過。任一條不過 ⇒ 進 `analysis.md` §3 決策樹。**

### 4.1 邊界處理

| 情況 | 處理 |
| --- | --- |
| G1 落在 68%～72%（±1 題） | **不得只憑數字宣告結論。** 逐題檢查該區間內每一個 `fail_*` 的記錄，連同質性證據一起判；若仍無法收斂，補 3 場（每層各 1 人）後重算 |
