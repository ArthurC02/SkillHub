## 0. 這份文件是什麼，以及它為什麼有兩個版本

**兩種測試蒐集的東西不一樣，所以同意的範圍不能一樣。**

| | **A. 驗證閘門**（M1） | **B. 封閉測試**（M4） |
| --- | --- | --- |
| 形式 | 一對一主持，40 分鐘 | 自己用，14 天 |
| 誰在旁邊 | 主持人 ＋ 記錄員 | 沒有人 |
| 主要資料 | **錄影／錄音／逐字稿**、查詢原文、觀察筆記 | **平台自己產生的紀錄**（分析事件、Run、評估、下載） |
| 有沒有帳號 | 不需要（`DISC-010` 未登入即可搜尋） | 需要 GitHub 登入 |
| 有沒有花錢 | 幾乎沒有（只搜尋不試跑） | **有**：每次試跑都會呼叫模型（§4） |

因此本文件是**一份政策、兩份同意書**：§1～§7 是共用政策，§8 是兩份可直接列印／寄送的同意書本體（A 版、B 版）。**受測者只會看到 §8 那一份**，前面的章節是給負責人與法務看的依據。

**一個原則貫穿全文**：受測者同意的是**具體的一份清單**，不是「本產品可能蒐集的資料」這種空白支票。清單以下有一條就必須重新徵得同意。

## 2. 分析事件：逐欄公開，因為它是唯一「你沒主動提交任何東西就會產生」的資料

`02:O11Y-004` 明文：**分析事件是唯一一類使用者未主動提交任何東西就會產生的資料，揭露義務因此不低於其他類別。** 所以這一節逐欄列出，不寫「等使用行為資料」。

**只有四個事件**（`0029_beta_analytics.sql` 的 CHECK 是封閉集合，加第五個要先說明既有領域表為何答不出來）：

| 事件 | 什麼時候產生 | 記了什麼 | **沒有記什麼** |
| --- | --- | --- | --- |
| `search_performed` | 送出一次搜尋 | 查詢**長度**、語言**分類**（`han`／`latin`／`mixed`）、結果數、有無結果、有無套用篩選 | **查詢原文一個字都沒有** |
| `skill_detail_viewed` | 打開一個 Skill 詳情 | Skill 的公開識別、從搜尋來還是直接來、在結果中的名次 | — |
| `session_started` | 開始一段使用 | 只有時間與 session 識別 | — |
| `download_started` | 按下下載 | artifact 識別、打包目標 | — |

**三件必須一起被讀到的事**：

1. **表上沒有自由文字欄位。** 不是「遮罩過的自由文字」，是**一個都沒有**——schema 未宣告的屬性由寫入端直接丟棄。想看查詢原文只能走 §1.2 的 B-8／B-9 那條有明示同意的管道。
2. **session 識別不是登入憑證。** 它是一個獨立的隨機值，**不是登入 Session 的 token 也不是它的雜湊**，且無法反查回登入 Session。未登入時它是唯一的串接方式（漏斗第一段發生在登入之前）。
3. **保存期限未定值前，平台一行都不收。** 部署未設定 `ANALYTICS_RETENTION` 時，**cookie 不發、事件不寫**（`NFR-002`：未定值前不得開始收集）。ADR-029 提案 **180 天**，**待 PDM-006 一併追認**（§3）。

| Trace 明細事件（B-6） | **90 天**，按月分割 `DROP PARTITION` | **2026-08-23 追認值**（`TRACE_RETENTION=2160h`），與 PDM-006 提案一致 |
| Run metadata、狀態轉換、Evaluation 結果（B-3） | **永久**（去識別化後） | PDM-006；跨季度指標需要 |

| 封測質性回饋（B-7／B-8／B-9） | **去識別化保留**，不設刪除期限 | ADR-029 決策 5；範圍複審的依據 |

**兩件事要一起講清楚，因為它們看起來矛盾**：

- **「刪除」與「去識別化保留」不是同一件事。** 帳號刪除時，私有內容（上傳檔案、Run Artifact、Download Artifact、未被他人 Fork 的私有版本）**實體刪除**；而已被他人 Fork 的 Skill Version、被歷史 Run 引用的版本與快照**內容保留、作者身分去識別化**（顯示為「已刪除的使用者」）。理由是鐵律 4 與 `02:DISC-003`——硬刪除會讓下游 Fork 的溯源鏈斷掉，**傷害的是第三方而不是本人**。
- **封測回饋跟著同一條規則**：質性回饋去識別化保留，與 PDM-006 §6.1 對 Run metadata 的既有處理同型。**這一點必須在同意書上明說**，因為它是「我刪了帳號，我說的話還在嗎」這個問題的答案。

## 4. 模型呼叫與成本（只適用 B 版）

**這一節必須明說，因為它是受測者的內容離開本平台的唯一途徑。**

- **每一次試跑都會呼叫大型語言模型。** 你的 User Prompt、驗收條件、Skill 內容與上傳資料的相關片段會**送往模型供應商**（OpenAI），一律經平台的模型閘道（LiteLLM），**平台程式不直連供應商**（ADR-017、鐵律 8）。
- **供應商會依其自身政策處理這些請求。** 平台無法代供應商承諾保存期限。
- **平台另有一個工程用的觀測平台**（Langfuse Cloud），會記錄模型呼叫的明細（含 Prompt）。它**明文不是事實來源**，僅供調校；提案保存期限 **30 天**（PDM-006）。
- **費用由平台付，受測者不付任何錢。** ~~免費額度（PDM-010 提案：首個 30 天窗口 ⬜⬜ 次、其後每月 30 次、每日 5 次）是**成本上限的執行機制**……**額度用完時平台會擋下新的試跑並顯示重置時間**——那是設計行為，不是故障。~~ **2026-08-23 改寫：本次封測不套用免費額度**（[ADR-055](../../../adr/ADR-055-the-run-allowance-is-turned-off-and-that-took-an-action.md)，`RUN_QUOTA=off`）。**受測者不會被額度擋住，畫面上也不會出現額度**。原文承諾的「額度用完會擋下並顯示重置時間」**不會發生**，因此不得留在送交受測者的文件裡（`02` §2.2：不得顯示沒被強制的承諾）。<br>**每一次試跑本身仍有硬上限**（每 Run 閘道預算 $0.50、300K input／60K output），那與額度是兩件事，受測者不會感覺到。
- **免費額度不計為報酬**（[`recruit.md` §5.1](recruit.md) 第 1 條：拿產品額度折抵會讓受測者對平台產生預期立場）。

## 6. 退出機制

**四條，每一條都要能在同意書上單獨勾選或單獨行使。**

1. **隨時退出，不需要理由，不需要事先通知。** 閘門測試中途喊停即結束；封測寄一封信即可。
2. **退出照領報酬。** 技術故障、提前結束、未完成完整旅程一律照給全額（[`recruit.md` §5.1](recruit.md) 第 3、4 條；[`pdm-009-beta-proposal.md` §6.2](../m4/pdm-009-beta-proposal.md) 的兩段式給付，**第二段的條件是「交問卷」不是「完成旅程」**）。
3. **可以要求刪除你的資料**，範圍如下——**這是本節最重要的一格，因為它是唯一「我們做不到全部」的地方**：

   | 你可以要求刪除 | 我們會照做 |
   | --- | --- |
   | 錄影、錄音、逐字稿（A-1～A-3） | ✅ 全部刪除 |
   | 上傳的 Dataset、Run Artifact、Download Artifact（B-4 等） | ✅ 實體刪除（平台已有的 `CORE-007` 刪除流程） |
   | 未被他人 Fork、未被歷史 Run 引用的私有 Skill 版本與 Test Case | ✅ 實體刪除 |
   | 分析事件（B-2） | ✅ 移除與帳號的關聯（去識別化）；彙總數字不受影響 |
   | **已被他人 Fork 的 Skill 版本、被歷史 Run 引用的版本與快照** | ⚠️ **內容保留、你的身分去識別化。** 硬刪除會弄斷第三方的溯源鏈（§3） |
   | **質性回饋與結束問卷（B-7～B-9）** | ⚠️ **去識別化保留。** 它是範圍複審的依據；**若你要求連內容一起刪除，請在退出時明說，我們會照辦** |
   | **稽核事件** | ⚠️ 只保留去識別化的 actor 識別（合規紀錄，400 天） |

4. **可以事後撤回錄影／錄音的同意**（A-1／A-2）：撤回後刪除原始檔與逐字稿，已寫入分析報告的**匿名引述**若你要求一併移除，我們移除。

**刪除請求的處理時限**：⬜⬜（**建議：收到後 14 天內完成，並回信確認**）。刪除工作具可追蹤狀態，完成後不再出現在一般存取介面（`NFR-002`）。
