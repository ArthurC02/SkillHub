## R-3｜`skills.redistribution` 的寫入路徑（`04` 乙-17）

**先講一件會改變這一項急迫性的事**：[ADR-045](../adr/ADR-045-self-supplied-content-is-not-redistribution.md)（2026-08-23）已經把最痛的那一半移走了——**使用者現在下載得了自己上傳的 Skill**（匯入時直接寫第四個值 `self_supplied`，不需要任何人去改任何東西）。

所以這一項剩下的是**別人的內容**：誰能把它標成可散布、要什麼證據。**沒有人在等它才能用產品**，但治理強度的不對等每天都在跑。

### R-3a｜誰能改

| 選項 | 代價 |
| --- | --- |
| **(a) 只有 operator** | 使用者匯入第三方內容而授權判定不足時，他看到的是「你的 Skill 不能下載」而**沒有任何自助路徑**。以現況的 `unknown` ＝ 擋為預設，這會是常態 |
| **(b) Skill 擁有者對自己匯入的內容也能改** | 把一個**授權判定**交給沒有義務做那個判定的人。ADR-021 §5.3 記著本次查核最重要的單一發現：**兩個 repo 的根目錄 `LICENSE` 是合法的 MIT 檔，但它涵蓋的內容並非該作者所有**——「repo 根有 MIT ⇒ 子目錄是 MIT」是錯的，**而且錯在放行方向** |

**建議 (a)**，理由不是保守而是 §5.3 那個發現：**這個判斷連做過查核的人都會錯，交給按下按鈕的人不會更準。** (b) 的真實需求訊號要等封測——`N-2` 的第一個訊號就是它。

### R-3b｜改成 `allowed` 要什麼證據

**ADR-021 已經給了一半判準**：誤判必須錯在**擋**的方向。所以「放寬的門檻不能只是一個按鈕」不是意見，是那條規則的直接推論。

**建議**：沿用 ADR-021 已經定義的**來源層級（license source tier）**——要把一個 Skill 從 `unknown` 改成 `allowed`，必須附上**該層級可接受的證據**，而不是一個確認框。這不需要新的概念，只需要讓端點要求它。

### R-3c｜治理強度 ✅ **已落地（2026-08-23），這一格不再等任何人**

`redistribution` 是**全庫唯一一個沒有稽核就能改的閘門欄位**——`access_restriction` 有 `PUT`／`DELETE /admin/skills/{id}/restriction` 與 audit event，這一個只能直接跑 SQL。

**兩道鎖擋的是同一件事，而治理強度差一整級。** 加端點與 audit 的技術補法很小（沿用 `SEC-011` 同一組形式），**而且它不依賴 R-3a 的答案**——不論最後是誰能改，都應該留下紀錄。

**已補**：`PUT /admin/skills/{id}/redistribution`——operator-only、`note` 必填、before／after／note 與欄位寫入**同一個交易**（稽核 action `skill.redistribution_set`），沿用 `access_restriction` 的同一組形式。

**它刻意沒有回答 R-3a 與 R-3b**，而這一點值得寫下來：路由取 operator-only 是因為那是 R-3a 兩個選項裡**較窄的那一個**——之後放寬是加呼叫者，先放寬再收回是**拿走東西**；請求帶的是自由文字 `note`，**不是 R-3b 可能會要求的來源層級證據**，因為**半套的證據要求讀起來和整套一樣**，那個誤會比缺一個端點貴。

**順帶多了一個守門**：`self_supplied` 不接受。0036 定義它是「誰帶進來的位元組」這個**事實**、由匯入路徑建立，不是任何人能斷言的**判定**——接受它等於讓 operator 用「這是擁有者自己的內容」把別人的內容放出去。反方向（`self_supplied` → `blocked`）允許，因為擁有者自己上傳的東西仍可能是平台必須停止交還的。

**原本的「不決定的代價」**：一個閘門欄位可以被沒有紀錄地改動，而它決定的是「內容能不能交出去」。**這一句現在不成立了。**

**已查到的**：

- [ADR-046](../adr/ADR-046-generating-a-skill-from-a-task-description.md) 的整個前提是「使用者搜不到會想要生成一個」，而 [m5/README](mvp/m5/README.md) 逐字寫著這個假設**至今零證據**——這一題**一次都沒問過**。

- **這一題不需要一場正式閘門。** 它是一個訪談題，向 5 個對象各問一次就會有訊號，而且問的人不必是閘門受測者（**問完就不能再當閘門受測者**，這是唯一的成本，見 `m4/README §5.3` 理由②）。

**建議**：**脫離 D 日，這週單獨問 5 個人**，並把它訂為 M5 的 kill switch——在有訊號之前，M5 的投入限制在「假設不成立就丟得掉」的量（規格與契約可以先寫，`GEN-003` 的生成管線先不鋪）。**零成本但無限期，不如低成本但這週有答案。**

**不決定的代價**：M5 繼續在一個沒有人驗過的假設上累積程式，而那個假設的檢驗被綁在一個至今未宣告的日期上。**這是路線圖上唯一一個「越晚知道越貴」的風險**——其餘各項晚一天的代價是晚一天，這一項晚一天的代價是多寫一天會丟掉的程式。

**決定之後**：訊號回寫 `m5/README` 的前期驗證表與 ADR-046 §0；若脫離，`moderator-guide §3.D` 標明該題已在閘門外問過、閘門當日**不重複問**（同一個人問兩次不會得到第二次自發反應）。

**✅ 2026-08-23 裁定：照建議脫離** → [ADR-053](../adr/ADR-053-the-assumption-under-m5-gets-its-own-five-people.md)。材料已就緒可直接拿去用：[m5/ask-5.md](mvp/m5/ask-5.md)（5 人、5～8 分鐘、三題、不需要產品，從候補名單取不動正式 9 人）。**同批把建議的「kill switch」寫成了硬的**：`GEN-002`～`011` 在有訊號之前暫停，可做的只有契約 schema、`redistribution` 值域與 `GEN-009` 量測——**分界線是「假設不成立時這段東西丟得掉嗎」**。門檻三段（0／1～2／3+）寫在問之前。**閘門版不刪**，兩者驗的不是同一件事。

**本項到此關閉**，剩下的是去問。

**⚠️ 2026-08-23 稍晚：負責人授權 M5 全面開工，投入上限解除** → [ADR-054](../adr/ADR-054-the-cap-was-lifted-by-authorisation-not-by-evidence.md)。**解除它的是授權不是證據**——`ask-5` 一次都沒執行。這一項因此**沒有真的關閉**，只是換了角色：它從「不做就不准往下」變成「已經在做了，這 5 個人告訴我們方向對不對」。**本項在清單上的順位反而該往前**——上限解除之後，晚一天知道的代價從「多寫一天會丟掉的程式」變成「多寫一天已經在丟的程式」。

## R-8｜產品願景那句話還剩四個動詞，而現在做的是五個

**要決定什麼**：`01` §3 的長期願景是「成為個人與團隊**探索、驗證、改善及發佈** Agent Skill 的可信任基礎平台」。M5 加了第五個動詞——**生成**——而且已經全面開工（ADR-046／052／054）。願景句要不要納入它？

**已查到的事實**：

- `01` §7.3 已經正確處理了範圍層：「從零生成 Skill」列在「MVP 不包含」，並明文寫著**那是時程不是永久排除**。所以**範圍沒有矛盾，矛盾在定位句**。
- 生成入口已經在畫面上（旗標後面，[資訊架構 §2.4](../design/information-architecture.md)），程式面不等定位句。
- ADR-046 決策 2 已經替生成物劃了一條線：**不進公開目錄、不進搜尋索引**。

**這不只是加一個詞。** 前四個動詞的受詞都是**別人寫的 Skill**，第五個的受詞是**平台自己寫的**。「可信任」在這兩種情況下要證明的東西不一樣：

- 對別人的 Skill，可信任 = 來源可追溯、授權清楚、有試跑證據（現行三層內容策略＋信任三軸）。
- 對平台生成的東西，可信任 = **誠實說出它沒有那些**。`02:GEN-004` 已經要求詳情與列表寫出「沒有經過任何人工檢視、沒有任何試跑證據」，`01` §12 最後一列也把它列為風險。

**建議措辭（三選一，不是我來選）**：

| 選項 | 措辭 | 代價 |
| --- | --- | --- |
| (a) 納入，並列 | 「探索、**生成**、驗證、改善及發佈」 | 最直接。但把生成放在驗證**之前**，讀起來像在推薦「先生成再說」，與 ADR-046 決策 7「先搜尋、搜不到再生成」的產品主張相反 |
| (b) 納入，但附屬 | 「探索、驗證、改善及發佈 Agent Skill——**必要時從任務描述生成起點**」 | 措辭保住了決策 7 的順序。長一點 |
| (c) 不納入 | 維持四個動詞 | 表示生成永遠只是探索失敗的補救、不是產品主張之一。**這也是一個立場，只是要有人說出來**——目前的狀態是沒人說過，而不是選了 (c) |

**不決定的代價**：低，但會持續累積成同一種東西。願景句是新加入者（人與 Agent）讀的第一段，也是 ADR-038 §3 規則 5「新產品用語必須先能回對 `01` 的使用者成果」所指向的那份文件。**生成現在回不到它。** 於是每一份談 M5 的文件都要自己解釋一次它為什麼存在——這正是本專案反覆出現的「一個事實好幾份定義」的上游。

## R-9｜M5 生成額度的四個數字（`04` 乙-22）

**2026-08-23 新增。** 這一項與其他九項不同的地方是：**它今天不擋任何人**，因為 `GENERATE_QUOTA=off`（[ADR-056](../adr/ADR-056-the-generation-allowance-is-its-own-switch-and-it-is-off.md)）。它進這份清單的理由是**這份文件是「我現在要簽什麼」的唯一入口**，而 `04` 乙-22 記著一個等簽名的東西——一個只活在另一本帳裡的簽名，就是 `QA-008` 那個病。

**要決定什麼**：生成額度的四個數字。`policy.DefaultGenerateQuotaLimits()` 目前給 **每日 10／每窗 30／首窗 20／窗長 30 天**，四個全部標「待追認」。

## R-10｜生成前的「預估成本」：單價、上限，還是一個有出處的區間（`04` 丙-53）

**2026-08-24 新增。** `02:GEN-001` 逐字要求「生成前顯示預估成本」。畫面上現在有三個**被強制的界**（描述 4,000 字、推理加輸出 16,000 token、最多嘗試 2 次，副本由 `one-number:` 機械比對），成本的位置印的是 `尚未定值`。

**要決定什麼**：那個位置怎麼變成一個金額。三條路，**前兩條要簽名，第三條要資料**：
- **(a) 把單價釘進部署設定**——一個每千 token 的輸入／輸出單價（今天連 `GENERATE_SKILL_MODEL` 都不在 `.env.example` 裡，只在 `generate.py` 的 `os.getenv` 預設），由它與三個界算出「一次最多約 $X」。**平台因此對一個會變的供應商數字背書**；漂掉時要出聲（設定與閘道回報的 `usage.cost_usd` 對不上就記一筆）。算出來的也只是**估計的上界**，不是被強制的上限——輸入界是 runes 不是 token、且不含 system prompt。
- **(b) PDM 給一個每次上限並強制它**——「一次生成最多花 $X」，超過即停。那才是一個被強制的數字，但要有人簽，而且強制點要寫（今天沒有）。
- **(c) 照 Run 的既有形式：一個有出處的區間＋一句 basis，標示「估計值，非報價」**——`RunPreflight` 就是這樣做的（`preflight.go` 的三個量測常數 `$0.01／$0.06／$0.30`，`Basis` 開頭寫「估計值,非報價」），而 `02:PDM-005` §5.3 **接受了這個形式**。它**不需要任何人簽名**。**今天做不到的原因是資料**：B 輪只記下 mini **每次平均 $0.00553**（[m5/report-generate-baseline.md](mvp/m5/report-generate-baseline.md) :7、:80），沒有逐次分布，印不出區間；印平均值當預估就是 `04` 丙-53 說的那種承諾。

**已查到的事實**：
- flagship 每次 **$0.1186**（B 輪，[report-generate-baseline.md](mvp/m5/report-generate-baseline.md) :80；spike 報告的 08-23 訂正是 A 輪的 $0.1184）。R-9 與 `04` 丙-53 先前寫的 $0.113 是 spike 報告**訂正前**的數。
- Run 那一側的「預估成本」是**量測分布**（45 次，中位 $0.0566／均 $0.0702／最大 $0.2367）寫成三個常數加來源句；它**不是**上限——`preflight.go` 自己逐字這樣寫。Run 另有一把帶 `max_budget` 的短效 key，那是另一件事。
- `04` 乙-2 與設計系統 §2.2：**沒被強制的數字不得出現在畫面上**——而 (c) 的形式已被接受為例外：**有出處、標示估計值、不進 `summary_hash`**。

**2026-08-25 訂正一個會讓建議 (c) 落空的前提**：這一項一直寫著「成本分布是丙-56 那次呼叫的**副產品**」，而**在同日之前那不成立**——`GenerateSkillResponse.Usage` 一直存在，`generate.go` 從來沒有讀過它，每一次生成的成本在 `generateOnce` return 之後就地蒸發。**丙-56 就算今天跑完，也不會留下任何一筆逐次成本。**同日補上兩半（失敗寫進 `skill.generate.failed`、成功寫進它那一列 `skill.import` 的 metadata），**兩半必須同時有**：只有失敗那半的話，分布全部來自「付了一通、然後沒能打包」的呼叫，而成功的可能付了兩通，用它估成本會系統性低估。**建議不變，前提現在才真的成立。**

**建議**：**(c)**，在第一批逐次記成本的真實生成跑完之後——那批正是 `GEN-009` ③／`04` 丙-56 要跑的，成本分布是它的副產品，不另外花錢。**在那之前這一格維持 `尚未定值` 是對的**，不是欠款。(a)／(b) 都不必。

**不決定的代價**：不簽沒有代價——這一項不等簽名，等一批資料。它在這份清單上的理由是 08-23 那句「小到不必開乙、就地裁定」被查出站不住（`04` 丙-53 的 08-24 段），而這份文件是「我現在要簽什麼」的唯一入口，**要在這裡明說它不需要簽**。`GEN-008` 停在 ◐ 直到那批資料進來。

## R-11｜Run Artifact 的 30 天要不要拉到 90 天（`02:NFR-002a` 第 2 條現在是被違反的，`04` 乙-16 連帶）

**2026-08-25 新增，而它遲到了。** `02:NFR-002a` 第 4 條逐字寫著「任何一個值的變更必須同時對這三條檢查一次，**並在 `05` 記錄檢查結果**」——這一頁**從那條規則寫下來到今天，一次都沒有記錄過**。第 1 條（下載產物 30 天 ≥ 14 天觀察窗）在 R-1b 有一整格，第 2 條連一句都沒有，而**第 2 條正是那三條裡唯一目前不成立的**。

**要決定什麼**：兩條路擇一。**(a) 把 Run Artifact 拉到 90 天與 Trace 齊平**——改值不改程式，`03:EVAL-014` 隨即整項消失。**(b) 維持 30 天**，並把 `EVAL-001` 的過期分支做完（`03:EVAL-014` 自己列的兩條處置擇一）。

**已查到的事實**：

- `02:NFR-002a` 第 2 條：「Run Artifact 的保存期限 ≥ 可重評窗」，可重評窗＝Trace 的保存期限。Trace 是**追認值** `TRACE_RETENTION=2160h`（90 天），Run Artifact 是 **PDM-006 提案表的 30 天**（**它至今沒有對應的環境變數**，期限寫在 `artifacts.expires_at` 上、由 Run 結算時寫入）。**下界被違反這件事，是那一節自己的背景段裡就舉出來的例子**——規格承認它，然後沒有人簽任何東西。
- **2026-08-25 之前，那個 30 天沒有任何東西在執行**（[consent-and-data-policy.md](mvp/gate-test/consent-and-data-policy.md) 該列的同日訂正：`reconcile.sql` 的保存期掃描只走 `download_package`，全 repo 沒有任何路徑刪過 `run_output` 的位元組）。同日補上 `ListRunOutputsPastRetention` 與 `maintenance purge-run-artifacts`——**於是這條違反從紙上的不一致，變成會真的發生的刪除**。
- `devctl automation-check` 的 `retention-floor` 已經把這個缺口釘住（同日新增）：**它守的是缺口不會長大、不會移動、不會在沒刪掉宣告的情況下被悄悄補上**——**不是缺口會消失**。機器讓這一項不會惡化，它不能替人選 (a) 或 (b)。
- `03:EVAL-014` 未勾，且它自己寫明另一條路是改值：「那是 PDM-006 的追認範圍，**不是本工作項能決定的**」。它也寫明 ②（第三態 `expired`）比 ①（拒絕重評）便宜但更危險——**第三態要一路傳到 Judge 的 prompt，漏一段就退化回今天的行為，而那個退化沒有症狀**。
- **同意書已經對受測者宣告「試跑產出的檔案 30 天」**，而該文件開頭自己立的規則是：**任何一個保存期限再變動都要重新確認一次，因為那是法務判斷的輸入而不只是附註**。

**建議**：**(b)，並取 ②＋`03:EVAL-014` 自己要求的那支具名反證測試**。理由不是省事：(a) 會讓**一類使用者沒得選就會產生的資料**多留兩個月，而 `NFR-002a` 第 4 條說得很清楚——**下界由「這類資料被收集的理由」決定，上界由隱私決定**，而重評需要的不是那些位元組還在，是**那份清單不要被靜靜地當成空的**。第三態剛好給的就是後者。**但②沒有那支測試就不要選**——沒有症狀的退化，等於選了 ① 的成本卻買不到 ① 的保證；那時 ① 才是對的。

**不決定的代價**：封測 14 天，**所以這次封測本身撞不到第 31 天**——撞到的是封測結束之後的重評。屆時 Judge 會在「這個 Run 沒有任何產出」的前提下逐條判定，而評估是 append-only：**錯的不是報告上的一句話，是判定本身的輸入**（`04` 丙-13 修好的正是這個形狀）。**這是本頁上唯一一個「不決定也會自己發生」的項**，其餘各項不簽就是停著。

**決定之後**：**這一項要與 R-4 的乙-16 同一次送，不要分兩次**——不論選 (a) 或 (b)，同意書那一列的措辭都要動，而動它就要重走一次乙-16 的確認。取 (a)：進 PDM-006 的追認範圍（併 R-1b），同意書、`retention-floor` 的宣告與 `03:EVAL-014` 同批改；取 (b)：`03:EVAL-014` 照它自己寫的處置落地，同意書那一列補上「第 31 天之後的重評會看到產出已過期，而不是沒有產出」。

## R-12｜ADR-020 要不要從 `Proposed` 升格

**2026-08-25 新增。** 這一項只改一個狀態欄，**但那個欄位是「這個決策能不能被當成既成事實引用」的唯一機器可讀訊號**。

**已查到的事實**：

- **`AGENTS.md` 把它列在標題為「已定案的技術棧速覽」的那張表裡**（2026-08-25 該列補上了 `（Proposed）` 標記，**那讓矛盾看得見，沒有讓它消失**：一列 `Proposed` 坐在一張叫「已定案」的表裡）。
- **全 repo 只有兩個 ADR 還是 `Proposed`**，另一個是 ADR-019（Monorepo 與 CI/CD），而**它也描述著已經在跑的東西**。**所以這不是 ADR-020 一個人的事**，值得一次看兩列。

**建議**：**升 ADR-020 為 `Accepted`**，並在同一次順帶裁定 ADR-019 要升還是留。**升格不新開 ADR**：`AGENTS.md` 的「不可原地改寫」管的是**決策內容**，而這裡改的是狀態欄、決策一個字都不動，兩者不是同一件事。**若裁定維持 `Proposed`，那同樣要有人說出來**——目前的狀態是沒人說過，不是選了維持（與 R-8 的 (c) 同一種形狀）。

**不決定的代價**：低，但**它會持續產生同一種東西**：一個事實好幾份定義。每一份談身分或授權的新文件都會自己決定一次要不要相信那個狀態欄。

**決定之後**：改 [`ADR-020`](../adr/ADR-020-authentication-and-session-model.md) 第 3 行**與** [`docs/adr/README.md`](../adr/README.md) 索引該列——**兩處同批，索引是狀態的唯一入口**；`AGENTS.md` 速覽表的標記隨之。**決策內容不動。**
