# Skill Hub MVP：目標與計畫內容

## 1. 背景

Agent Skill 生態正在成長，但個人創作者仍面臨四個主要問題：

1. 知道想完成的任務，卻不知道該搜尋哪個 Skill。
2. 找到 Skill 後，難以判斷是否可信、是否適合自己的 Agent 與環境。
3. 單看 `SKILL.md` 無法證明 Skill 在真實 Prompt、資料與工具下有效。
4. 即使完成試跑，也可能不知道如何改善、打包與安裝到目標 Agent。

Skill Hub MVP 將以「探索、試跑、評估、下載」建立第一個完整價值閉環。

## 2. 目標使用者

### 2.1 主要 Persona：個人創作者

個人創作者可能處於不同成熟度階段，而非固定角色：

- 學習者：有明確任務意圖，但不了解 Skill 規格與建立方式。（**2026-08-23 補記**：這個 persona 在 MVP 內的路徑是「你永遠不從零寫」——自動建議驗收條件、改善建議直接回完整檔案內容，他不必打開編輯器。**「從零生成一個 Skill」不在 MVP，列 M5**，見 §7.3 與 [ADR-046](../adr/ADR-046-generating-a-skill-from-a-task-description.md)。）
- 改善者：已有或找到 Skill，但不知道如何判斷問題與改善效果。
- 精深者：能自行調整 Skill，希望降低搜尋、比較、測試與維護成本。

MVP 預設介面以非技術使用者可理解的任務語言呈現，並提供可展開的進階技術資訊。

## 3. 產品願景與 MVP 承諾

長期願景：

> 成為個人與團隊探索、驗證、改善及發佈 Agent Skill 的可信任基礎平台。

> **⚠️ 這句話的四個動詞已經蓋不住現在在做的事（2026-08-23）。** M5 加了第五個：**生成**（[ADR-046](../adr/ADR-046-generating-a-skill-from-a-task-description.md)，同日 [ADR-052](../adr/ADR-052-m5-starts-in-parallel-with-an-unfinished-mvp.md)／[ADR-054](../adr/ADR-054-the-cap-was-lifted-by-authorisation-not-by-evidence.md) 全面開工）。**願景句是產品定位，不是事實對帳，所以本檔不自行改寫它**——問題與建議措辭列為 [`05` R-8](05-pending-rulings.md)，等負責人一句話。<br>要留意的是這不只是加一個詞：前四個動詞的受詞都是**別人寫的 Skill**，第五個的受詞是**平台自己寫的**。「可信任」在這兩種情況下要證明的東西不一樣，而 §12 的最後一列已經在處理後者。

MVP 承諾：

> 個人創作者能在 10 分鐘內找到一個可能符合需求的 Skill，用自己的 Prompt 與測試資料驗證效果，並下載可安裝的版本。

## 4. MVP 目標

### 4.1 產品目標

- 驗證使用者是否願意透過自然語言描述任務來探索 Skill。
- 驗證「可先試跑」是否能提高使用者選擇及下載 Skill 的信心。
- 驗證 Trace 與具體改善建議是否能幫助使用者修正 Skill。
- 建立從網路來源到可追溯、可驗證、可下載套件的基本流程。
- 建立可替換 Sandbox Provider 的執行邊界，避免綁定單一執行環境。

### 4.2 使用者成果

使用者完成核心旅程後，應獲得：

- 一個與任務意圖相符的候選 Skill。
- 一份可理解的來源、授權、依賴、權限與相容性摘要。
- 一次使用自有 Prompt 與測試資料的執行結果。
- 一份說明成功、失敗、限制與改善方式的評估報告。
- 一個可下載的標準 Agent Skill 套件與安裝說明。

### 4.3 平台成果

- 所有執行皆可追蹤至特定 Skill 版本、輸入與執行環境。
- 未受信任的 Skill 不直接在 Web/API 主機程序中執行。
- Skill 的原始來源、版本、授權與修改關係可被追溯。
- Cloud Sandbox、第三方 Sandbox 與 Local Runner 可透過共同介面被調度。

## 5. 產品原則

1. 使用任務語言：使用者不需要先理解 Skill 規格才能開始。
2. 證據優先：品質判斷以來源、試跑與驗收證據為主，不只依賴 Star。**（2026-08-22 由 [ADR-042](../adr/ADR-042-roadmap-product-rulings-evidence-aggregate-in-flight-axis-and-enforcer-attribution.md) 決策 1 收緊：不是「不只依賴」，是全域評分與排行榜**永久不做**——名次要求可比較，而本產品的證據天生不可比較，A 的驗收條件不是 B 的驗收條件。替代品是帶分母、非預設排序、有 k 門檻的試跑證據彙總。見 §7.3。）**
3. 權限透明：執行前說明預計使用的資料、工具、MCP 與網路權限。
4. 可解釋改善：每項建議都需指出原因、位置與可能影響。
5. 可攜但不過度承諾：分開呈現規格有效、能力相容與實際測試通過。
6. 使用者可帶走成果：Skill、測試案例、評估與必要安裝資訊可被匯出。
7. 漸進式揭露：一般模式提供白話資訊，進階模式提供檔案、Trace 與技術細節。

## 6. MVP 核心旅程

### 6.1 探索

1. 使用者以自然語言描述想讓 Agent 完成的任務。
2. 系統分析輸入、輸出、工具、資料與環境需求。
3. 系統顯示候選 Skill，並解釋符合原因與限制。
4. 使用者查看詳情、來源、授權、風險與相容性。
5. 使用者選擇 Skill 並 Fork 到個人工作區。

### 6.2 試跑

1. 使用者選擇快速 Demo 或自己的測試情境。
2. 使用者輸入 User Prompt，並視需要加入資料集。
3. 系統提出可編輯的驗收條件。
4. 系統顯示預計使用的權限、執行環境與可能成本。
5. 使用者確認後啟動 Run。
6. 系統顯示一般進度，並提供可展開的進階 Trace。

### 6.3 評估、改善與下載

1. 系統依驗收條件將結果分成符合、部分符合、未符合或無法判斷。
2. 系統列出格式、啟用、執行、效果、相容性與成本問題。
3. 使用者檢視並選擇是否採用改善建議。
4. 使用者使用相同 Test Case 重新試跑並比較結果。
5. 使用者選擇目標 Agent，取得標準套件與安裝說明。

## 7. MVP 功能範圍

### 7.1 必須包含

- 自然語言意圖搜尋。
- 精選、已索引及外部 Skill 的基本來源分級。
- Skill 結果列表、詳情、來源、License、依賴、權限與風險摘要。
- Skill Fork 與個人工作區。
- Skill 格式驗證與基本靜態檢查。
- User Prompt 與可編輯驗收條件。
- 測試資料上傳與執行期間存取。
- 自建 Cloud Sandbox Provider。
- 標準 Run 狀態、取消、逾時與清理流程。
- Tool Call、MCP Call、Log、錯誤、延遲及成本 Trace。
- 結果評估、具體改善建議與重新試跑。
- 標準 Agent Skill 套件與安裝說明下載。
- 基本帳號、Run 歷史及使用者主動刪除資料。

### 7.2 MVP 可簡化

- 初期只提供少量人工整理的 Skill 類別與內容。
- 初期只設定一個主要 Agent Runtime 作為平台驗證基準。
- Skill 比較可先採用靜態比較，不必同時平行執行多個 Skill。
- 改善建議可先提供差異預覽與人工確認，不必支援完全自動改寫。
- 驗收條件可先純手動建立，自動建議為可選強化。
- 目標 Agent 打包可先支援標準套件與少量安裝 Profile。

### 7.3 MVP 不包含

- Local Runner 與本機工具絕對路徑存取（架構決策已成立，見 ADR-006；實作依 M2 後需求訊號啟動）。
- 遠端 MCP Server 整合（同上，依需求訊號啟動）。
- 完整公開發佈與創作者 Marketplace。
- 付費 Skill、收益分成與創作者結算。
- 團隊協作、企業組織與進階多租戶管理介面。
- 社群留言。
- 完整評分機制與排行榜——**這一項不是時程，是定位**（[ADR-042](../adr/ADR-042-roadmap-product-rulings-evidence-aggregate-in-flight-axis-and-enforcer-attribution.md) 決策 1，2026-08-22）：名次必須可比較，而本產品的證據天生不可比較（A 的驗收條件不是 B 的驗收條件），所以全域評分與排行榜**永久不做**。社會證明的替代品是 MVP 之後的**試跑證據彙總**（帶分母、非預設排序、k 門檻、需同意書與逐工作區 opt-in）。
- GPU、長時間工作或任意自訂基礎映像。
- 所有 Agent 的行為一致性保證。
- 大規模、無限制的全網爬取。
- 多個 Skill 的大規模平行 Benchmark。
- 從任務描述**從零生成** Skill——**這一項不是永久排除，是時程**（[ADR-046](../adr/ADR-046-generating-a-skill-from-a-task-description.md)，2026-08-23）：需求 ID 與允收準則已立於 [`02` §4.9](02-specifications-and-acceptance-criteria.md)（`GEN-001`～`004`），實作列 **M5**。放在 MVP 之外的理由是時序不是意願——封測漏斗第一段量的正是「輸入意圖後查看至少一個 Skill 詳情的比例」，那個數字要在「沒有第二條出路」的條件下量才有意義。在此之前這件事的狀態是**沒人決定過**（`04` 乙-21），本列結束該狀態。

## 8. 初期內容策略

Skill 內容分為三層：

| 層級 | 定義 | MVP 行為 |
| --- | --- | --- |
| 精選 | 已人工檢視來源、License、內容與至少一次試跑 | 可直接查看並進入試跑 |
| 已索引 | 已取得來源並完成規格及靜態檢查，尚未驗證效果 | 顯示未試跑標示，試跑前再次確認 |
| 外部結果 | 即時或透過 URL 找到，尚未進入平台管理流程 | 先匯入、掃描與建立來源紀錄後才能試跑 |

初期建議先選擇三個類別，每類整理少量高品質 Skill。~~類別仍屬待決策事項。~~ → **已定案（2026-08-14，PDM-001）**：`documents`／`writing`／`data`。

三層的收錄政策、白名單制與各層判準的允收準則見 [`02` 第 4.7 節「內容供應與策展」](02-specifications-and-acceptance-criteria.md)（2026-08-15 新增，`CONTENT-001`～`009`）。注意精選層的「至少一次試跑」（上表）由 `03:CONTENT-008` 承接，該項已於 2026-08-15 改列 M2。

## 9. 執行環境策略

### 9.1 控制平面

Skill Hub 管理：

- Run 定義與排程。
- 權限、Secrets 與資源政策。
- Run 狀態機。
- Trace、評估與歷史資料。
- Sandbox Provider 選擇。

MVP 先提供：

- `SelfHostedProvider`：執行上傳資料與公開資源。

## 12. 主要產品風險

| 風險 | 影響 | MVP 對策 |
| --- | --- | --- |
| 搜尋結果多但難以選擇 | 無法進入試跑 | 顯示符合原因、限制與可比較摘要 |
| 初期內容品質不足 | 失去信任 | 精選優先、來源分級、限制全網內容 |
| 評估結果過度主觀 | 改善建議缺乏價值 | 結合結構檢查、執行結果、驗收條件與**其他工作區的試跑證據**（原文為「使用者評分」；ADR-042 決策 1 之後緩解手段改為量測而非意見，其餘三項不變） |
| Skill 符合規格但無法執行 | 下載後失敗 | 分開呈現規格、能力與已測試相容性 |
| 未受信任程式碼或 MCP 外洩資料 | 造成安全事件 | 隔離執行、權限預覽、Secrets 隔離及預設封鎖網路 |
| Sandbox 成本不可持續 | 無法提供足夠試跑額度 | 限制資源、顯示預估、保存用量並保留未來計費能力 |
| Local Runner 權限過高（後 MVP） | 影響使用者電腦 | 明確授權、限制路徑、顯示命令與可中止執行 |
| **內容涵蓋不到使用者的任務**（2026-08-23 新增，`04` 乙-21） | 學習者 persona 走不完第一步：精選只有 `documents`／`writing`／`data` 三類，落在三類外就掉到「外部結果」層，而那一層要使用者自己提供 URL——不會寫 Skill 的人通常也不知道去哪找 | MVP 內只有誠實：無結果狀態說出下一步而不是只給改寫建議。**封測要看的數是漏斗第一段**；M5 的生成路徑（[ADR-046](../adr/ADR-046-generating-a-skill-from-a-task-description.md)）是它的解，但刻意排在讀數之後 |
| **生成物看起來像一個 Skill，但沒有任何人或任何 Run 檢視過**（M5 新增風險，2026-08-23） | 使用者把一份沒有證據的產出當成與精選內容同級 | 三道：不進公開目錄也不進搜尋索引（ADR-046 決策 2）、Script 的揭露與匯入物逐字相同不享寬待（決策 6）、詳情與列表必須說出「沒有經過任何人工檢視、沒有任何試跑證據」（`02:GEN-004`） |
