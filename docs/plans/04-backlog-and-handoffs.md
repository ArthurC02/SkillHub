## 這份文件是什麼

**活文件**，與 [01 目標與計畫](01-goals-and-plan.md)／[02 規格與允收準則](02-specifications-and-acceptance-criteria.md)／[03 工作項目](03-work-items.md) 並列，是「**目前還缺什麼、誰在等誰**」的**唯一入口**。開工前先看這份。

與其他文件的分工：`03` 記工作項本身與勾選狀態，**本文件記擋住工作項的東西**——環境上結構性做不到的、等人拍板才動得了的，以及沒有任何工作項承接的。它專收「**已定值但沒有強制**」與「**已量到但沒查根因**」那一類洞，因為那正是逐項對帳最容易漏掉的一種。

里程碑目錄（`mvp/mX/`）記的是**某一時點的帳**，完結後不回溯修正；**本文件隨時更新**。

維護方式：

- **一項解除就把那一列刪掉**，並把解除的理由與證據寫進 commit message。歷史在 git，不留在本文件裡——**本文件只回答「現在還缺什麼」**。
- 解除時若留下了新的缺口，那個缺口**另立新列**，不寫成舊列的續段。
- 新殘項直接加列，同時更新該類的計數與 `<!-- open: … -->`。
- 里程碑交替時把新里程碑的殘項**併進本文件**，不另開一份——兩份清單一定會漂移。
- 逐項證據留在各里程碑的對帳文件（`mvp/mX/*-work-items-audit.md`），本文件只做入口與現況。

## 殘項清單（三類）

分類原則：**甲**只能在真實部署環境驗收，本機結構性做不到；**乙**缺的是一個決策不是一段程式，寫程式之前得先有人拍板；**丙**是實作或資料工作，不是等人拍板的東西。

**這三個數字有一台機器在對帳**（`devctl automation-check` 的 `backlog-tally`）。每一格末尾的 `<!-- open: … -->` 是該類宣稱還開著的列，機器比對三件事：**數字等於清單長度**、**清單上的每一列都真的存在**、**沒有一列被列為未結卻在自己的狀態欄寫著已結案**。它**故意不檢查**一個沒在清單上的列是不是真的結了——那需要逐列的狀態欄，而本文件的解除規則是刪列，所以「不在檔案裡」就是結案的形式。

這是全 repo 唯一的殘項總數來源；[`01` §10](01-goals-and-plan.md) 與 `AGENTS.md` 都只指過來、不複製數字。
