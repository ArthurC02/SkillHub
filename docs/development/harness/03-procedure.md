# 工序：在一個 repo 裡建立或擴充 harness

七步。每一步的產出都是下一步的輸入；跳過第一步的 harness 是憑信仰蓋的。

## 第一步：量測送達

目標：知道**哪些機制真的會把文字送到 agent 面前**，而不是文件說會。

1. 列出每個 coding agent（本 repo：Claude Code、Codex）啟動時保證載入的鏈——對 Claude 是全域 `CLAUDE.md` → 專案 `CLAUDE.md` → 根 `AGENTS.md` → 記憶索引；量它的位元組數。
2. 對每個候選機制（目錄層 `AGENTS.md`、按路徑觸發的 rules、frontmatter 的 `skills:` 預載）**建一個帶唯一標記的探測檔**，派一個子代理去讀會命中它的檔案，看標記有沒有出現在回報裡。
3. 掛儀器：`InstructionsLoaded` hook 寫 log（`file_path`＋`load_reason`），之後每一次「有沒有送達」都去看 log，不推論。
4. 記下每個工具的硬限制（Codex 32 KiB、只沿路徑往上走）。

產出：一張「機制 → 誰吃得到 → 條件」表。**每一列都要有探測記錄**。

## 第二步：量測攔阻

1. 每條打算加的 deny，先寫下「它該擋什麼、不該擋什麼」。
2. 在**乾淨的工作樹**上，用會被擋的指令撞（`--dry-run` 能用就用）；用結構相同但合法的指令做對照。
3. 派一個子代理撞同一條，確認子代理也被擋。
4. 記下工具的陷阱（路徑型規則只認 `Edit`／`Read`）。

產出：deny 清單，每條附「撞過：擋／對照：過」。

## 第三步：分層

對每一條想放進 harness 的知識，依序問：

1. **換一個 repo 還成立嗎？** 成立 → 技能；不成立 → 往下。
2. **它是判準還是入口？** 判準 → `docs/`（權威）；入口 → 該目錄的 `AGENTS.md`（分區卡）＋ 一條 rule 指過去。
3. **它已經在哪裡了？** 已在根 `AGENTS.md` → 引用，不複述。
4. **它有時效嗎？** 有（閘門期間、放行批次）→ 指向裁定表，不抄日期。
5. **它是角色專屬的嗎？** 只有「風險等級」是角色專屬（能不能寫、要不要留下編輯）；「哪個目錄」不是。

產出：每條知識一個家，且只有一個。

## 第四步：建置

順序：分區卡 → rules → 技能 → 角色 → deny。理由：後者引用前者，反過來蓋會在角色檔裡寫進本該在分區卡的內容。

- **分區卡**（`<dir>/AGENTS.md` ＋ 一行 `@AGENTS.md` 的 `CLAUDE.md`）：表格「你要做的事 → 先讀哪段 → 沒讀會被哪個閘門擋」，加「哪些檔不屬於單一寫入者」。**只放指標，不抄數字**。
- **rules**（`.claude/rules/<area>.md`）：`paths:` ＋ 三到十行，內容只有「先讀哪份、判準在被指的那一份」。
- **技能**（`.claude/skills/<name>/SKILL.md`）：`name`＋`description` 合 Agent Skills 規格；正文是程序、快速檢查、回報格式；不引用本地文件。
- **角色**（`.claude/agents/<role>.md`）：frontmatter 只有 `name`／`description`／`model`（下限）／`skills`（預載）／`tools`（唯讀角色限制）；正文：先讀、路徑範圍由簡報給、禁令一行引用、「簡報與程式碼衝突時以程式碼為準」。
- **deny**（`.claude/settings.json`）：只放第二步撞過的。

## 第五步：放機器

每條規則落地時同批放它的機器，不另開批次：

1. 在 `automation-check` 名冊加一條 checker（本 repo 的形狀：`<name>Problems(root) []string`，檔頭寫「為什麼存在、抓到過什麼、不檢查什麼」）。
2. 名冊測試加名字；「壞樹」種子測試加一個會讓它出聲的違規。
3. 對真樹跑一次確認綠；**種一個違規確認紅**；還原。
4. `automation.md` 名冊表加一列。
5. 產品本身若有相關驗證器（本 repo 的 `skillpkg.Validate`），拿來驗 harness 自己——dogfood。

## 第六步：審視（對照路線圖）

蓋完隔天做，不當天做。對每一層問：

- 下一階段的工作在哪個目錄、哪種任務？現有角色與分區卡蓋得到嗎？蓋不到的話，是加一張卡（對）還是加一個角色（借了便宜）？
- 有沒有東西抄了兩份？
- harness 自己有機器守嗎？
- 每條 deny 都撞過嗎？漏了哪些同義指令（`commit -a`、`restore`、`checkout .`）？
- 有時效的規則有沒有被寫死？

產出：MECE 調整清單，一次改完，不留「之後再說」。

## 第七步：縮寫入口

根 `AGENTS.md` 只做一件事：讓 agent 讀完建立心智模型。量它：位元組、日期數、刪除線數、最長一行。日誌搬去狀態文件，故事搬去手冊，三張「去哪看」合成一張，補「系統怎麼跑」。上限設成棘輪（貼著現況），不是懸崖。

## 檢核表

**新增一個區域**（不新增角色）
- [ ] `<dir>/AGENTS.md` 指標表 ＋ `<dir>/CLAUDE.md` 一行 `@AGENTS.md`
- [ ] `.claude/rules/<area>.md` 的 `paths:` 指向它
- [ ] 根 `AGENTS.md`〈分區指標與攔阻〉加一列
- [ ] 派子代理讀該目錄一個檔，看儀器 log 有沒有 `path_glob_match`

**新增一條 deny**
- [ ] 寫下該擋／不該擋
- [ ] 乾淨樹上撞：擋
- [ ] 對照組：過
- [ ] 子代理撞：擋
- [ ] 記進 `automation.md`〈Harness〉的清單

**新增一條檢查**
- [ ] checker ＋ 檔頭三段（為什麼、抓到過什麼、不檢查什麼）
- [ ] 名冊 ＋ 名冊測試 ＋ 壞樹種子
- [ ] 真樹綠、種違規紅、還原後 `git diff` 空
- [ ] `automation.md` 名冊表一列

**新增一個技能**
- [ ] 通過「換一個 repo 還成立嗎」
- [ ] `name`／`description` 合規格（dogfood 測試會驗）
- [ ] 不出現 `docs/`、ADR 編號、需求 ID（`harness` 檢查會驗）

**改根 `AGENTS.md`**
- [ ] 沒有新增日期或刪除線
- [ ] 砍掉的每個事實在別處有家（逐條核對）
- [ ] `automation-check` 的必要字串仍在
- [ ] 大小在上限內
