# 歷程：兩天、七批、四次推翻自己

時間是 2026-09-03～09-04，全部在 `main` 上，每批一個 commit、一次 CI。寫成時間軸不是為了記帳，而是因為**好幾個當時的判斷後來被量測推翻**——那些推翻才是這份文件最有價值的部分。

## 0. 起點：一個沒有答案的問題

負責人問：「Coding agent 在開發的時候，會適當地讀取 docs 中的內文嗎？很多開發和設計的精髓都在 docs 中。」

第一個反應是給意見。改成量測之後，問題變了形：

- `docs/` 有 165 份、4.38 MB；子代理啟動時**保證進入 context 的只有約 19 KB**（根 `AGENTS.md` 那一條鏈）。
- 有機器守著的文件約 15 份；其餘 150 份被讀到與否，取決於它們**有沒有在通往這段程式碼的路上**。
- 當天早上找到 16 條死連結，每一條**讀起來都是對的**——沒有人點過。

所以判準不是「agent 勤不勤勞」，是「那份文件有沒有在路上」。harness 的工作是把路鋪出來，並在路的盡頭放一台會叫的機器。

## 1. 量測（09-03 上午）

先確認什麼機制真的有效，每一項都用「試著違反它」而不是「讀文件相信它」：

| 假設 | 量測結果 |
| --- | --- |
| 目錄層 `AGENTS.md` 會自動送達 | **不保證**：剛建立的檔案同 session 內兩次探測都沒出現，稍後才生效；Codex 只走「repo 根 → cwd」 |
| `.claude/rules/` 的 `paths:` 只對主線有效 | **錯**：子代理也吃得到，首次命中注入一次 |
| `permissions.deny` 要 workspace trust、對子代理無效 | **兩個都錯**：即時生效、子代理同樣被擋（對照組通過） |
| 子代理 hook 無法按角色掛 | **錯**：frontmatter 支援 `hooks`，payload 有 `agent_type` |
| Codex 讀不到巢狀 `AGENTS.md` | 讀得到，但只沿路徑往上；總量上限 32 KiB |

同時量到兩個**陷阱**：deny 的路徑型規則只認 `Edit(...)`／`Read(...)`，寫成 `Write(...)`／`Glob(...)` 會被接受但永不查詢；`Bash(*git add .*)` 這種 glob 會誤擋 `git add .claude/…`。

## 2. 建置（09-03 下午，commit `51e135d`）

依量測結果蓋四層：兩張分區卡、四條 rules、五個技能、五個角色、九條 deny。技能刻意不引用 `docs/`——負責人明言「doc 是權威文件，skill 要輕量且高可複用」。

**同一天發生了本歷程唯一的事故**：`git add <一個檔> && git status --short --cached && git commit -F -` 因為不存在的 `--cached` 旗標失敗；重試成 `git diff --name-only --staged && git commit -F -`，清單印出來了，但 commit 在同一條 `&&` 鏈裡**已經跟著執行**——把另一位寫入者 25 個未完成的檔案掃進了 `2bd0df6`。沒有東西遺失、沒有推送；撤銷的 `git reset --soft` 被權限分類器擋下兩次，於是停下來把三個選項交給負責人，他選擇直接推。

事故變成規則：「**串在一起的檢查不是檢查，只是輸出**」——`parallel-writers` 技能第 6 條，以及之後每一次 commit 都把「看索引」當成獨立的一步。

## 3. 審視（09-04 上午，commit `34aa43b`）

負責人要求「用系統思考審視，讓設計跟得上產品發展，不是佔現況的便宜」。對照 `01` §10 的路線圖，找到七處：

1. **角色按目錄切**（web／platform），但接下來一個月的工作在 cleanmode、infra、runbooks——要嘛角色隨目錄膨脹，要嘛退回沒護欄的通用代理。
2. 五個角色**各抄一份禁令**，而根 `AGENTS.md` 已在每個子代理的 context 裡。
3. **harness 自己沒有機器守著**；而這個產品本身就是 Skill 驗證器，拿它驗自己的技能，當場抓到兩份沒 `name:`。
4. deny 去撞一次：`commit -a`、`restore`、`checkout .` 沒擋。
5. 有時效的規則（閘門期間「一律不動」）進不了 harness，分區卡該指向裁定表而不是抄日期。
6. `docs/design/` 有機器解析它，卻沒有 rule 會跳；序列化區的 rule 漏了 generated 目錄與 lockfile。
7. `automation.md` 自稱完整來源，一字沒提 `.claude/`。

負責人的回覆是「MECE 式的調整，不要有遺漏」。七處全改：角色縮成三個按風險切、禁令只留一份、`harness` 檢查加入名冊（第 25 條）、`skillpkg.Validate` 跑在 `.claude/skills/` 上、deny 補六條並逐條撞過、rules 補兩條。**每台新機器都先種一個違規確認會紅**。

順帶更正一件事：前一天我說 `InstructionsLoaded` 儀器「從沒觸發」，其實 log 已有 16 列——我沒去看。

## 4. 縮寫 `AGENTS.md`（09-04，commit `e3edc14`）

負責人：「AGENTS.md 要足夠精煉，讓 agent 讀完馬上建立整個 repo 的心智模型。」

量：22.1 KB、159 行、11 個日期、4 處刪除線、最長一行 1,059 字元；**一半是施工日誌**——而它自己第 11 行寫著「狀態變動改 `01` §10，不改這裡」。它違反了自己的規則。

重寫成 13 KB：新增「系統怎麼跑」五行（原本沒有這一段，要從技術棧表自己拼）、鐵律原樣、紅線各一句、三張「去哪看」合成一張。**逐條核對被砍掉的每個日期事實都已在 `01` §10**；自己回頭比對時抓到兩句差點搬丟的話（里程碑目錄骨架規則、Langfuse 列指向 R-24），補回。上限從 28 KiB 降到 16 KiB，讓它是棘輪。

## 5. 模型規則（09-04，commits `433c798`→`9e214bb`→`8169e61`→`b6bc8d9`）

負責人連續四次修正，每次都把規則推向更穩的形狀：

1. 「子代理絕不能指定 Fable、Sol；禁 Fable 之後九成指定 Opus，我不認同」→ 檢查器加 `sol`，角色預設下限降到 sonnet／haiku，brief 技能加階梯。
2. 「Luna 和 Terra 是 Codex 用的模型，repo 有多個 agent」→ 規則從 `.claude/` 搬到根 `AGENTS.md` 與 `automation.md`——**Codex 讀不到 `.claude/`**，寫在那裡等於沒寫。
3. 「不要講死模型名稱，用特性描述」→ 四級：旗艦（派工者自己用、子代理禁用）／深度推論／快速執行／機械執行；名稱只留在表的「現行對應」欄與檢查器。
4. 「Luna 介於 Sonnet 和 Haiku 之間」→ 兩級都對到 Luna，加註。

每一次修正都不是推翻，是**把規則從「名字」往「特性」、從「Claude 專屬」往「跨工具」推一格**。

## 6. 回覆格式

負責人：「指派大量子代理之後，主代理輸出超大量文字，冗長、重點不多。」改成三段：執行結果／待辦清單／需要確認，每節 2～5 點；根 `AGENTS.md` 要求的白話段縮到兩三句。這一條記在 session 記憶，不在 repo——它是對人的偏好，不是 repo 的規則。

## 7. 具名 workflow（09-04 稍晚，丙-142 第二批）

第一次把「量測 → 反駁 → 落地 → 驗證 → 突變 → 閘門」寫成兩支 `.claude/workflows/*.js`，拿 UI 文字預算這件事當第一個案子。三件量到的事：

- **`agentType` 只認內建代理**，讀不到 `.claude/agents/` 的三個角色——第一次跑四個寫入者全部 `agent type 'skillhub-writer' not found`。角色要求得寫進 prompt；角色檔仍是 Agent 工具的事。
- **裸 `agent()` 繼承派工者的旗艦級**。一行 wrapper 把 `model:` 釘在同一行，`harness` 檢查逐行看——它第一次跑就在自己的註解上誤報（「a bare agent() would inherit」被當成呼叫），加了「註解不算」才綠。
- **反駁階段是這套流程裡最值錢的一步**：九個讀檔子代理提了七個 Tip 候選，三個反駁子代理以「Tip 是最後一步」駁回六個、把三句 D 改判 C。沒有這一步，第二批會做出六個不該做的開關。突變階段則抓到一次假紅——把一行換成 `<></>` 造成 parse error 也算「紅」，機械執行級的子代理分不出「測試抓到了」與「檔案壞了」，主線自己重做一次才算數。

## 被推翻的判斷（誠實清單）

| 我當時說 | 後來量到 |
| --- | --- |
| 巢狀 `AGENTS.md` 對 Claude 完全無效 | 有效，只是新檔案有發現延遲 |
| hook 不能按子代理掛 | 可以 |
| `docs.md`／`serialized-areas.md` 兩條 rule 不會跳 | 會跳；是我的探測檔沒命中 glob |

這張表的存在理由，與根 `AGENTS.md` 那句「看不懂的綠燈與看不懂的紅燈一樣沒有用」相同：**沒有量測的判斷，對的和錯的長得一模一樣**。
