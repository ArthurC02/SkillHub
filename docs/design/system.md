# 前端設計系統與 UI/UX 評估準則

本文件是 [ADR-039](../adr/ADR-039-frontend-design-system-and-ui-evaluation-criteria.md) 與 [ADR-041](../adr/ADR-041-trust-signal-vocabulary-typed-absence-and-rule-precedence.md) 的操作手冊，**活文件**。ADR 記的是「為什麼要有一把尺」與否決了哪些做法；本檔記的是**現在這把尺長什麼樣**，隨 `apps/web` 一起改。

**允許值在本檔，實際值在 [`apps/web/src/index.css`](../../apps/web/src/index.css)，[`design-system.test.ts`](../../apps/web/src/design-system.test.ts) 比對兩者。** §4.1／§4.2／§5 的粗體 px 儲存格是測試直接讀的政策來源——改 CSS 而沒改這裡，或改這裡而沒改 CSS，測試都會 FAIL。其餘章節不重抄 CSS 的值。

**這份文件管一頁之內；一頁與一頁之間——有哪些位址、怎麼互相到達、叫什麼名字——見 [資訊架構](./information-architecture.md)。**

五層，由上往下：**優先序**（§0，規則互相牴觸時誰贏）→ **義務**（§1，產品推出來的，不可談判）→ **原則**（§2，十一條）→ **系統**（§4，字級、間距、表面、狀態、版面）→ **強制對照表**（§6，誰在把關，以及誰沒有）。§3 的 checklist 把上面全部折成一張逐頁可用的表；§5 是偏離帳；§7 是這把尺對**還沒寫的功能**說得出什麼。

## 0. 優先序

**原則會互相牴觸，而且已經在正式畫面上牴觸過。** 一份沒有優先序的原則清單不是系統，是願望表。

首頁手機版是實例：三個停用的篩選各自帶一整段理由（原則 2.4 正確執行），加總把第一筆搜尋結果推到 **1180px**，也就是義務 1.2 所禁止的「為了拿到頭條而費力」。兩條規則都對，畫面壞了。

牴觸時的順位，由上而下：

| 順位 | 誰 | 為什麼排這裡 |
| --- | --- | --- |
| 1 | **安全與不誤導**（§1.1、§2.2、§2.3、§2.9） | 讀者據此決定要不要執行別人的程式碼。錯了的代價不對稱：多看一眼是麻煩，看漏一項是執行了不該執行的東西 |
| 2 | **§2.10 的「永不折疊」清單** | 上面那條的具體化。它是封閉清單，不是判斷題 |
| 3 | **可及性硬需求**（`02:NFR-007`、WCAG AA） | 不是品味，是允收準則 |
| 4 | **速度與版面**（§1.2） | 讓步的方式是**改變揭露的形狀，不是刪掉內容** |
| 5 | 一致性、尺度、美觀 | 前四項都成立之後才輪到 |

**解法的形狀，不是二選一。** 首頁那個例子的正解不是「刪掉停用理由」（違反 2.4），也不是「忍受 1180px」（違反 1.2），而是把六個篩選在窄螢幕收進一個 `<details>`，`<summary>` 上留「3 個條件目前無法篩選」——**數量留在外面，段落收進去**。順位低的規則讓步時，讓的是形式；順位高的規則的**內容一個字都不能少**。

## 1. 三個 UX 義務

這三條不是風格偏好，是 [`01-goals-and-plan.md`](../plans/01-goals-and-plan.md) 直接推出來的。違反它們是產品缺陷，不是品味爭議。

> **更正（2026-08-22）：本文件前一版在這裡寫錯了。** 它說 `01` §2.1（「可展開的進階技術資訊」）與 §5 原則 7（「**一般模式**／**進階模式**」）互相矛盾，並裁定本產品「不做模式切換」。查證後：**不矛盾，而且模式切換早就出貨了。** `02` §DISC-003 與 §TRACE-001 各自定義兩種模式的內容，`03` 的 `TRACE-006`／`TRACE-007` 都已勾選（`?mode=advanced` 是 API 參數），`m0` 威脅模型把「進階模式」當成一個安全情境，而 [`RunTrace.tsx`](../../apps/web/src/pages/RunTrace.tsx) 有一個真的切換器（兩顆帶 `aria-pressed` 的按鈕）。錯的是設計文件，不是 `01`。§1.3 已改寫成三種機制與它們的選用判準。

### 1.1 可判斷

願景是「成為個人與團隊探索、驗證、改善及發佈 Agent Skill 的**可信任基礎平台**」（`01` §3），而四個問題裡的第二個是「找到 Skill 後，**難以判斷是否可信**、是否適合自己的 Agent 與環境」（`01` §1）。使用者的核心動作是**決定要不要信任並執行別人寫的程式碼**。

所以每個畫面必須讓證據看得見，**也必須讓證據的缺席看得見**。缺席比證據更容易出錯，因為它的預設呈現方式（空白）會被讀成「通過」。

**這一條有外部實驗背書，不只是推理。** Song & Szafir（IEEE VIS 2018）量到**零值填補得到最低的資料品質感與信心**——把缺失當成零不只是語意錯誤，讀者會把它當真值採信；而把缺失標示出來反而提高信心。`02:DISC-004`「缺少資料的欄位顯示未知，**不得自行推定為通過**」是同一句話的產品版本。

### 1.2 快到第一個判斷

MVP 承諾是「**10 分鐘內**找到 → 驗證 → 下載」（`01` §3）。10 分鐘要走完整個閉環，代表沒有任何一個畫面可以讓讀者為了拿到頭條而費力。

**判準的視窗要講明，否則兩個人會給相反的結論**（那正是 ADR-039 要終結的事）：**桌面 1280×900、手機 375×900**，與 `e2e/shots.spec.ts` 拍的兩個尺寸一致。

### 1.3 一個介面服務三種成熟度

`01` §2.1 明文：「MVP 預設介面以**非技術使用者可理解的任務語言**呈現，並提供**可展開的進階技術資訊**」，且同節說目標使用者「**可能處於不同成熟度階段，而非固定角色**」（學習者／改善者／精深者）。

產品實際用了**三種**揭露機制，而且它們選用的判準不是「這東西有多技術」，是**被藏起來的東西是什麼**：

| 機制 | 現行用處 | 什麼時候選它 |
| --- | --- | --- |
| **模式切換**（一般／進階） | `RunTrace` 的兩顆按鈕 | **同一份事實的兩種保真度**：摘要 vs 經遮罩的原始事件。兩邊回答的是同一個問題，只是解析度不同 |
| **另一個位址** | `/skills/:id/files` | 進階內容是**另一個物件**（套件的檔案），不是同一份事實的另一種呈現。位址可以分享，這是它勝過前兩者的地方 |
| **`<details>`** | 版本 id、內容雜湊、產生摘要的模型 | 一個**屬於本頁某個事實的細節**。它不是一個獨立的視圖 |

**三者共同的約束只有一條，而它比機制的選擇重要得多：§2.10 清單上的十項，哪一個都不准進去。** 這一條在切換器上尤其容易破——降級自述（第 9 項）必須在**兩個模式下都渲染**，而不是只在進階模式裡。目前成立：`IncompleteNotice` 在一般模式與進階模式各渲染一次。

**持久化的「總是展開技術細節」偏好不是第四種機制**（[ADR-042](../adr/ADR-042-roadmap-product-rulings-evidence-aggregate-in-flight-axis-and-enforcer-attribution.md) 決策 5）：**偏好只能改變「預設開合」，不能改變「有沒有這個東西」**。單向展開、不動文字與版面、可在一處反轉 → 可做。一旦它會**收起**任何東西（「精簡模式」），它就是模式，禁止。

**已知缺口：`RunTrace` 的模式是 component state，不在 URL 裡**（`useState<"general" | "advanced">`），所以一個進階視圖無法被連結、被分享、被貼進 issue。`03` `TRACE-007` 把 `?mode=advanced` 定為 API 參數，UI 從來沒有把它提到位址上。這削弱了「另一個位址」那一列本來提供的好處，而 Trace 恰好是最需要把「你看，這裡少了三筆」寄給別人的畫面。

## 2. 原則

十一條。前八條標了出處——它們不是新發明的，是已經散在程式碼註解、規格與殘項清單裡的判斷。後三條（2.9～2.11）是 2026-08-22 依外部調查與逐頁對帳新增的，出處是外部證據加本產品的推導，見 ADR-041。

**每一條都要能被反對。** 「簡單」「清楚」這種形容詞不是原則；一條沒有人可能不同意的規則，不會擋掉任何東西。

### 2.1 未知不是空白

缺資料的欄位顯示「未知」，不留白。空白會被讀成「通過」。

出處：[`02:DISC-004`](../plans/02-specifications-and-acceptance-criteria.md)；實作與推理見 [`Compare.tsx`](../../apps/web/src/pages/Compare.tsx) 檔頭——每一列宣告 `signature` 回傳 `undefined` 表示「沒有資料」，而不是空字串，正是為了讓「沒有」有一個渲染得出來的形狀。

**缺席有型別，見 §2.9。** 只寫「未知」已經不夠了。

同型例：[`RunEvaluation.tsx`](../../apps/web/src/pages/RunEvaluation.tsx) 的「**未評估不等於通過，也不等於未通過**」。

**這一條的強形式已經是既有實作，也一併寫進規則**：空狀態要說出這個「空」**不是**什麼。`WorkspaceSkills.tsx`「這裡是空的代表你還沒有建立過，不是清單讀取失敗」、`WorkspaceRuns.tsx`「代表沒有發生過，不是紀錄被清掉了」、`RiskIndicator.tsx`「這不等於安全」——三處以上的一致行為，只寫「說出來」會讓下一個人退回弱形式。

### 2.2 顯示與強制成對——**三向**

**不強制的東西不要顯示；會擋住人的東西必須在他撞上之前顯示；而每一條限制都要說得出誰在強制它。**

- **顯示但不強制**是最壞的一種：它讓使用者按下「我確認」。出處：[`04` 乙-2](../plans/04-backlog-and-handoffs.md)——`TokenBudget` 曾經寫進 `policy_snapshot`、顯示在權限摘要上要求確認，而平台與沙箱都不強制；原文是「**現狀（顯示但不強制）是兩者中最壞的一種**」。相同形狀後來又出現兩次（丙-18、丙-25）。
- **強制但不顯示**是第二壞的。匯入頁一個數字都沒有，而平台強制五項：32 MiB zip 上限、256 MiB 解壓上限、1 MiB 單檔掃描上限（**這一項還會靜默地限縮頁面回報的證據**）、三個 host 的來源白名單、https-only 且 URL 不得帶憑證。使用者只會在 4xx 訊息裡遇到它們。頁面上寫著「GitHub 或**允許的** URL」——點名了一份白名單，然後不給看。
- **強制了、也顯示了，但沒有出路**是第三種，`04` N-2 說它即將變成常態而非例外：使用者匯入的 Skill 一律 `redistribution: unknown`（＝擋），且目前沒有任何路徑可以改。**擋住人的訊息必須說下一步是什麼，或誠實說目前沒有下一步。**

**第三向：強制者必須具名**（[ADR-042](../adr/ADR-042-roadmap-product-rulings-evidence-aggregate-in-flight-axis-and-enforcer-attribution.md) 決策 4）。`01` §7.3 的 Local Runner 與遠端 MCP 會讓前兩向結構性失效——**平台對使用者自己的機器強制不了任何東西**，但那些限制是真的存在，隱藏它們比顯示它們更糟。

- 每一條限制帶一個強制者：**`平台`／`你的機器`／`第三方服務`**，三者措辭不同，而且**平台不得為它強制不了的事情背書**。
- **平台強制不了的事情不得用完成式。** 不寫「已阻擋」「不允許」，寫「這個 Skill 會做 X」＋「要不要讓它做，由你的機器決定」。
- **預設拒絕，而且拒絕狀態必須是可用的**（VS Code Restricted Mode 的形狀：未授權時內容仍可讀，只是不執行）。
- **授權是一次阻斷式的決定，不是被動通知。** 這條有實測撐著：VS Code 原本刻意做成不打擾的被動提示，結果授權率極低、而且使用者花時間以為自己弄壞了東西，最後改回強制對話框。本產品在這裡沒有比他們更好的條件。
- **執行前顯示命令**（`01` §9.2）。遠端 MCP 的名稱驗證要說出上限（§2.11(c)）：「這個名稱屬於 X」沒有說它做什麼。

判定的做法在 §3 第 11 條：**指出強制它的那一行**。指不出來就移除顯示。

> 引用校正：舊版本文把 `02:NFR-001` 寫成「UI 不得誤導」。`02:NFR-001` 標題是「安全」，其 UI 條款很窄——「靜態掃描通過不等於安全保證，UI 必須避免此類誤導」。本原則的權威來自 `04` 乙-2 那三次裁定與該窄條款，不是一條泛用的反誤導準則。

### 2.3 狀態先給文字，顏色是第二訊號

出處：[`02:NFR-007`](../plans/02-specifications-and-acceptance-criteria.md) 第 3 條「風險、相容與評估狀態必須**同時提供文字，不只依賴顏色**」。

實作上這條逐條寫進 CSS 註解：`.compare-differs` 的色底旁邊永遠有「有差異」徽章；`.badge-unverified` 的註解寫明色調是第二通道；`.criterion-unverifiable` 的虛線邊框註明「a third channel, **never the only one**」。

**外部佐證：** Chrome 與 Firefox 先後**移除**了網址列的鎖頭與 EV 綠條，因為量到 89% 的使用者把它讀成「這個網站可信」。正向的安全指示器被讀得比它的主張大，是有紀錄的失效模式，不是假想。

### 2.4 停用要說原因，**而且原因不能只活在 `title` 裡**

停用而不說原因會被讀成 bug。**原因才是這個功能誠實的部分。**

出處：[`index.css`](../../apps/web/src/index.css) `.filter-bar` 上方註解——「a disabled control with no stated cause reads as a bug, and the cause is the honest part of the feature」。

**這一條的範圍比原本寫的寬，因為同一個失效有四種形狀：**

1. 停用的控制項沒有原因（原本就涵蓋）。
2. 控制項被**拿掉**而不是停用，替代文字只說「目前不提供」不說為什麼。
3. 但書只存在於 `title=`：`LabelledBadge` 把伺服器給的每一句限定都放進 tooltip，包括「收錄不等於精選。」——那句話的存在理由就是阻止讀者把徽章當背書，而它在觸控裝置上不存在。
4. 徽章渲染原始 enum 而不是標籤。

`title` 只能重複已經看得見的東西。QA-009 拔掉那段文字上的 `opacity: 0.65` 正是因為它一度是整個 filter bar 裡**最難讀**的東西（2.18:1）。

### 2.5 執行狀態與任務判定是兩軸

執行成功 ≠ 任務完成。兩者永遠兩列，**任務判定排在前面**。

出處：[ADR-025](../adr/ADR-025-run-terminal-state-and-evaluation-verdict-separation.md)；實作在 [`RunEvaluation.tsx`](../../apps/web/src/pages/RunEvaluation.tsx) 的 `RUN_STATUS_LABEL`，宣告上方註明「Execution wording for a run's terminal state. **Never a pass/fail of the task.**」。

這條是全 app 被破壞得最頻繁的一條：`RunCompare` 曾把執行狀態排在判定之前（連註解都把錯的順序寫成本意）；`/runs/:id` 的執行狀態一度落在「有幫助／沒幫助」按鈕與版本選單之間，讀起來像回饋表單的一部分。

### 2.6 平面答案優先，識別符折疊

白話結論在上面；版本 id、內容雜湊、產生摘要的模型折進 `<details>`。

出處：`01` §2.1 與 §5 原則 7；實作在 [`SkillDetail.tsx`](../../apps/web/src/pages/SkillDetail.tsx) 的三個折疊區。

**推論一條：模型寫的東西不是答案。** SkillDetail 曾經把 AI 產生的白話摘要放在第一屏、把風險揭露推到 1.4 個視窗之後。在一個以「可判斷」為義務的產品上，模型的複述不能排在人可以查核的判定之前。

### 2.7 禁止用 `opacity` 弱化文字，也禁止色彩字面值

**次要文字只用字級降階，不用 `opacity`，也不另立一支更淡的灰。所有顏色都是 token。**

出處：`index.css` 的 QA-009 註解與 [`contrast.test.ts`](../../apps/web/src/contrast.test.ts) 檔頭。舊值把 `--text` 壓到 **2.18:1 ~ 3.71:1**，全數低於 AA。理由是「whatever value `--text` holds, **a multiplier lands somewhere else**」——`opacity` 是**任何色彩 token 都攔不住**的破壞方式，而 `contrast.test.ts` 量的是靜態 hex，量不到乘數（該檔「What it does not prove」第 2 點自己寫明）。

**這條原本是全文件唯一沒有任何守門、也沒有出現在 §6 對照表裡的原則。** 2026-08-22 補上：`design-system.test.ts` 現在對 token 區塊以外的任何 `#hex`／`rgb(`／`opacity:` FAIL。

### 2.8 毀滅性動作兩段式，且第二段要說會毀掉什麼

出處：[`ConfirmDelete.tsx`](../../apps/web/src/components/ConfirmDelete.tsx) 檔頭。機制共用（**七個呼叫點**），**只有範圍那句話每次不同，而那句話就是整個揭露**。

**四段式範本**，見 [`WorkspaceSkills.tsx`](../../apps/web/src/pages/WorkspaceSkills.tsx) 的 `scope`：會消失什麼、**還救得回來多久**、**什麼不受影響**、**還要另外刪什麼**。四段缺一段就是缺一段，寫的時候逐段對。**沒有救回期就寫「沒有」**——驗收條件刪掉就是沒有，不准為了湊滿四段而發明一個。

無障礙的兩個行為是承重的：確認鈕 `autoFocus`（前一顆按鈕離開 DOM，焦點會掉回 `<body>`），以及 `aria-describedby` 指向範圍句。**範圍句排在兩顆按鈕之前**——`aria-describedby` 帶得到螢幕閱讀器，帶不到眼睛，而確認鈕已經 `autoFocus` 了。

> 引用校正：`02:SEC-006` 的四條允收準則**沒有一條提到刪除範圍揭露**（它談的是刪除任務狀態、沙箱拆除與上傳授權）。`02:WS-002` 第 3 條寫的是「系統**應**說明刪除範圍」，沒有「在執行前」，而且是「應」不是「必須」。本條的實作比它引用的規格嚴——那是好事，但不要把它講成規格要求的。

### 2.9 缺席有型別，而且型別是資料層的列舉，不是渲染層的 falsy

**每一個「沒有值」的位置都要渲染一個具名詞，且該詞來自固定表。**

| 詞 | 意思 |
| --- | --- |
| `0` | 真值。零筆、零項、零位元組 |
| `不適用` | 這個物件在結構上沒有這個欄位 |
| `未測量` | 檢查沒有跑，或這個伺服器版本不回報 |
| `測量失敗` | 檢查跑了而且錯了 |
| `無權檢視` | 你的 Workspace scope 看不到（ADR-011） |
| `尚未定值` | **平台自己還沒決定**。與 §2.2 成對：這裡不准印一個沒被強制的數字，也不准留白 |

判法（單張截圖）：找 `—`、`N/A`、空欄、空判定區。**出現任何一個非表列的缺席呈現即 FAIL。「0」與「未測量」在同一張截圖上必須長得不一樣。**

出處與佐證：Grafana 把「查詢成功但零筆」（`No Data`）與「查詢失敗」（`Error`）分成兩個具名狀態，Datadog 另有 `Not Reporting`——兩家獨立收斂到同一條線。**沒有任何觀測工具處理 `無權檢視`，因為它們沒有這個問題；本產品有。** 學術上最接近的前例是 Eaton et al. (2011) 的 Coded 呈現：缺失處掛一個圖示說明**為什麼**缺，受試者明確偏好它；2024 的綜述直說這一塊「缺乏總覽與設計指引」。**沒有現成元件可抄，但形狀一致：缺席是列舉值。**

**繼承來的量測不是缺席。** 位元組相同的複本（Fork）沿用祖先的靜態掃描時，它是**有值且有歸屬**，不進上面那張表；規則與它的四個前提見 [ADR-042](../adr/ADR-042-roadmap-product-rulings-evidence-aggregate-in-flight-axis-and-enforcer-attribution.md) 決策 6。這裡只留一條邊界：**可繼承的只有「對位元組成立」的量測**（靜態掃描、規格驗證、License 判定）；相容性、試跑與評估量的是內容在某個環境下的行為，換工作區就換條件，**不可繼承，缺席就是 `未測量`**。

已知的兩個實例：`RunPreflight` 的成本區註解寫「Absent on an older server: rendered as nothing rather than as a zero」——避開了零值填補（對），落到了空白（本條 FAIL）；Run 產出的保存期限因為 PDM-006 未追認而不能印數字，正解是`尚未定值`，兩邊都不是。

### 2.10 判準是後果不對稱，不是使用頻率——「永不折疊」清單

`<details>` 對**識別符與推導過程**是好工具，對**判斷依據**是設計缺陷。三種已記錄的失效：GOV.UK 的使用者研究發現有人不敢點（以為會離開本頁）；NN/g 說折疊內容無法被掃視，而本產品的十分鐘承諾整個建立在掃視上；NVDA 不播報 `<details>` 的開合狀態。

**文獻給的判準是「多少人需要看」，對本產品是錯的軸。** 風險摘要不是多數人需要，是**看漏了會出事**。改用後果不對稱推導出的封閉清單——以下每一項必須在**不互動**的情況下可見，不得進 `<details>`、`title`、hover 或第二個 tab：

1. **風險摘要的存在與最高嚴重度**（細項可折，「有 3 項風險，最高為 error」不可折）
2. **驗證狀態**（已驗證／未驗證／**未檢查**——三者是三個詞，見 §4.4）
3. **License 與可散布性判定**
4. **任何「不能打包／不能下載」的理由**（人工 hold、不可散布、授權未知、驗證未過）
5. **任一停用或被移除控制項的原因**（§2.4）
6. **執行前的權限、網路、工具與 MCP 清單**（`01` §5 原則 3；限額細節可折，權限語意不可折）
7. **任務判定**，含`未評估`（ADR-025；`未評估`尤其不可折，它的預設呈現是空白）
8. **毀滅性動作的範圍句**（折疊會讓 `aria-describedby` 的指向失效）
9. **平台的降級自述**（部分索引、證據無法回驗、已被取代、部分事件未送達）
10. **缺席的型別詞**（§2.9）。缺席的「為什麼」可以折；缺席「是哪一型」不可折

### 2.11 不做綜合分數，不把人氣放在信任主張旁邊，證據要說出自己的上限

三條，同一個推理，見 ADR-041。

**（a）不做綜合分數。** 最強的反對理由不是它不準，是**綜合分數必然把「沒檢查」映射到與「檢查過、沒事」同一條軸上**——OpenSSF Scorecard 的空 repo 在某些檢查上拿 10 分，就是義務 1.1 的失效在正式產品裡的樣子；Zahan et al.（ICSE-SEIP 2023）甚至量到分數與實際漏洞的關聯方向不對。分數是**把缺席轉換成看起來像核可**最有效率的機器。支持它的理由（十分鐘旅程裡只有一個數字活得下來、讓學習者不必讀六塊證據、讓排序可解釋）是真的，但輸給上面那一條。

**（b）風險用具名能力表達，不用等級；人氣不得與信任主張相鄰。** Socket.dev 的做法是對的形狀：它點名一個行為（安裝腳本、shell、網路、環境變數、混淆），不給等第——那天然滿足 §2.3。反面是下載數與星數：Aqua 的 Prettier typosquat 48 小時得到 1500 次安裝，惡意 VS Code 擴充達到數百萬次安裝，而安裝數是攻擊者可以灌的。`01` §5 原則 2 早已寫「不只依賴 Star」；本條把它變成禁令——**人氣數字不得出現在信任主張旁邊，也不得是預設排序**。

**（d）社會證明用試跑證據，不用評分**（[ADR-042](../adr/ADR-042-roadmap-product-rulings-evidence-aggregate-in-flight-axis-and-enforcer-attribution.md) 決策 1）。評分與排行榜是**永久不做**，不是延後：名次必須可比較，而本產品的證據天生不可比較——A 的驗收條件不是 B 的驗收條件。替代品是 MVP 之後的**試跑證據彙總**（「在 12 個工作區的 37 次試跑中，28 次符合**各自的**驗收條件」），四個入場條件缺一不可：**帶分母且在同一句話裡**、**永遠不是預設排序**、**同區塊說出它不涵蓋什麼**、**少於 5 個不同工作區時顯示 `未測量` 而不是隱藏**（且擁有者自己的工作區不計入分母）。它跨工作區，所以前置是同意書與逐工作區 opt-in；在那之前正確的呈現是 `尚未定值`。唯一允許的「排名」是逐次查詢的候選比較（現有的 Compare 畫面）。

**（c）每一個驗證徽章要在同一個區塊、以文字說出它不涵蓋什麼。** npm 的文件裡有「provenance 不保證套件沒有惡意程式碼」這句話，**頁面上的徽章沒有**；2026 年 5 月的 TanStack worm 帶著合格的 provenance 發了 84 個惡意版本。SLSA 等級的已記錄失效是同一個形狀（「L3 所以安全」）。這條是 §2.2 的手足：§2.2 擋掉顯示沒在強制的東西，本條擋掉顯示會被讀得比它主張更大的東西。

### 2.12 進行中是第三軸，不是判定的一個值

ADR-025 把執行狀態與任務判定分成兩軸（§2.5）。**進行中再切一刀**：它不是判定的一個較淺的值，也不是狀態的一個特例。全文件原本沒有時間軸——`RUN_STATUS_LABEL` 有五個非終態，而 §4.4 的四種視覺全是終態判定，app 裡的載入狀態當時是十二處各寫一次的 `<p>載入中…</p>`，那是慣例不是規則（**2026-08-25 訂正：慣例已經換掉了**——現在是 `components/Loading.tsx` 一個元件、**24 個呼叫點**，每一個都帶 `role="status"` 與一個具名的主詞 `載入{what}中…`。`04` 丙-35 裁定這些**不是** §2.12：200ms 的讀取不需要「會不會自己結束」與「能不能離開」。剩下的兩處字面「載入中…」是「載入更多」按鈕的進行中標籤，不是頁面的載入狀態；`Compare` 另有一條帶分母的 `載入中…（N 個裡讀到 M 個）`）。規則如下（[ADR-042](../adr/ADR-042-roadmap-product-rulings-evidence-aggregate-in-flight-axis-and-enforcer-attribution.md) 決策 2）：

1. **進行中不得產生判定。** 還在跑的 Run，任務判定是 `未評估`（§2.9、§2.10 第 7 項），不是空白、不是樂觀猜測、不是一個較淺的顏色。
2. **進行中的畫面必須說出三件事**：現在在哪一步、這一步**會不會自己結束**、**使用者能不能離開**。第三件是十分鐘承諾裡最重要而最常被忘記的——可以關掉分頁就要說可以（而且依 §2.2，說之前要有人確認過那是真的）。
3. **必須有一個會變的量，以及一個「多久沒動了」的事實。** 永遠不動的轉圈分不出「在跑」與「卡住」；最後更新時間是最便宜的反卡死訊號，Trace 事件本來就帶時間戳。
4. **逾時、上限與配額在進行中畫面上同樣受 §2.2 約束。**
5. **部分資料必須標記為部分，而且分母要在**（與 §4.3 的截斷規則同一條）。

### 4.1 字級尺度

`index.css` 宣告 **11** 個 `font-size` 值。其中 **3** 個只在 `@media (max-width: 1024px)` 出現（36、30、16），其餘 8 個是桌面實際使用的階。20px 與 18px 各自**同時**是某一階的桌面值與另一階的 ≤1024px 值，所以「12 減 5」那種算法是錯的（舊版本文如此，結論對而算式錯）。

### 4.3 表面（surface）

| 表面 | 樣式 | 什麼時候用 | 不要用在 |
| --- | --- | --- | --- |
| **卡片** | `border: 1px solid var(--border)` ＋ `border-radius: 8px` ＋ `padding: 10px 12px` | 見下方判準 | 導覽清單。整份確認裡的條目（判斷單位是整份摘要，不是它的一行） |
| **notice** | `border-left: 3px solid var(--accent)` ＋ `background: var(--accent-bg)` ＋ `padding: 8px 12px` | **平台對這一頁講的一個持續狀態**：降級、部分索引、未評估、已被取代、不能打包的理由 | 使用者自己動作的**當下結果**（那是 `role="status"` 的一句話）；**內含按鈕的確認對話**；單純的補充說明（那是 `.note`）。不是「非阻斷」的同義詞 |
| **裸區塊** | 無 | 敘述文字、說明段落 | — |

**卡片判準（2026-08-22 改寫）：**

> **一列是卡片，若且唯若它帶著（a）自己的控制項或連結，或（b）自己的巢狀子清單。**

**為什麼換掉舊判準。** 舊的「一則可以被單獨採信或拒絕的東西」不可證偽——任何清單都能論證成可獨立判斷。曾經提過的收緊是「自己的動作**或**自己的識別」，那更糟：**每一列都有識別碼**，這個析取式對全部十二個清單都成立，其中七個答錯（檔案樹、Trace 事件、`.tag-list`、`.risk-list`、`.compat-list`、`.evidence-list` 都不該是卡片）。新判準對十二個清單全部給出正確答案，**而且它抓到了一個當時還沒修的缺陷**：`.finding-list` 的每一則都帶著自己的 `<EvidenceList>`，就排在 `.criterion` 卡片正下方，卻是一疊裸段落——那是 commit `90ade82` 修掉的「Test Case 列不是卡片」的現行未修版本。

**現行卡片族與它們的真實用途**（舊版本文按 class 名稱猜用途，猜錯兩個）：

| class | 誰在用 |
| --- | --- |
| `.search-result` | 搜尋結果、Test Case 列、**Workspace Skill 列**（三處，不是兩處） |
| `.criterion` / `.suggestion` | 驗收條件、改善建議、**匯入與打包的驗證發現**（`.finding-list` 於 2026-08-22 套用） |
| `.packaging-target` | 打包目標 |
| `.download-item` | **這是全 app 的通用卡片，不是「下載紀錄」**——四個呼叫點裡三個不是下載：Run 產出、Workspace Run 歷史、Test Case 執行歷史 |

**修法一律是套用既有的卡片族，不是發明第五種樣式。**

**清單長到數百列時怎麼辦**（[ADR-042](../adr/ADR-042-roadmap-product-rulings-evidence-aggregate-in-flight-axis-and-enforcer-attribution.md) 決策 3）。判準**不是列數**——卡片在大清單上塌掉的原因不是視覺密度，是 §2.10：一則卡片要放得下風險摘要、驗證狀態、可散布性與停用理由，那些一項都不准折疊，而把卡片壓扁成表格列的唯一方法就是把它們擠掉。判準是**這一頁在問什麼**：

- 問「**這一則行不行**」→ 卡片（逐則判斷，§2.10 的十項要放得下）。
- 問「**哪一則最好**」→ 表格（跨則比較；此時 §2.10 的項目改以**欄**存在，每一則仍然看得到）。
- 一個螢幕裝不下時，正解是**把它縮小到可判斷的數量**（篩選、搜尋、範圍），不是把每一則削薄。

**外加一條硬規則：任何被截斷的清單都必須說出總數與截斷理由**——「共 N 筆，這裡顯示 M 筆，因為 X」。本產品四種分頁策略並存而只有 Trace 做對；策略收斂為三種：**「載入更多」**用於使用者自己的、只增不減的時間序資料；**cursor 上一頁／下一頁**用於需要穩定位置的證據流；**硬截斷**只有在同時給出總數與理由時才允許。~~**「完全不設限」不再是選項**——搜尋結果目前落在這一格。~~ **（2026-08-25 訂正：半格，不是整格。）** 搜尋結果與 Workspace Skill 清單現在都**說出自己被截斷了**（`pages/Home.tsx`、`pages/WorkspaceSkills.tsx`，各一段 `notice` `role="status"`），所以「完全不設限」那一半已經不成立。**但另一半還在**：兩處說的都是「**超過 N 個**」，那是一個**下界**，而同一段硬規則要的是「**共 N 筆**」——一個下界說不出「共」，讀者無法從 `超過 20 個` 分辨 21 與 2100。**截斷理由那一半是齊的**（兩處都寫了為什麼、也都誠實說目前沒有翻頁），**總數那一半沒有**，而缺的是伺服器的一個計數欄位，不是頁面的一句話。**這一格記成半關，不是關。**

### 4.4 狀態語彙

| 視覺 | 主張 | 現行 class（**完整**） |
| --- | --- | --- |
| **badge（永遠帶文字）** | 一個事實的標籤 | `LabelledBadge` 的文案由伺服器給——**但這條規則只對 `LabelledBadge` 的三種 kind 成立**，見下方 |
| **`--danger` 邊框＋文字** | 這件事不通過／會擋住你 | `.badge-danger`、`.badge-expired`、`.badge-compat-failed`、`.badge-risk`、`.badge-risk-flag`、`.badge-criterion-failed`、`.badge-severity-error`、`.script-tag`；`.criterion-failed` **只有邊框沒有文字色** |
| **`--accent-border`（僅邊框）** | 這件事未知、未驗證或**未檢查** | `.badge-license-unknown`、`.badge-trust-unknown`、`.badge-compat-unverified`、`.badge-source-model`、`.badge-untested`、`.badge-unverified`、`.badge-criterion-undetermined`、`.badge-severity-warning`、`.criterion-undetermined`、`.badge-criterion-unverifiable`；`button:hover` 也用它 |
| **虛線邊框** | 這個東西**不是完整有效的**：平台自己降級了判定，或控制項現在不能用 | `.criterion-unverifiable`、`button:disabled` 等 |
| **無修飾的 badge** | 通過／正常。**這是合法的**——§2.3 只要求詞在前面，沒要求每個狀態都有顏色 | `.badge` 本身 |

**四條規則：**

1. **一個檢查產生的徽章，必須是 `通過` / `未通過` / `未執行` 三者之一，而 `未執行` 要說出是哪個檢查沒跑。** 業界的主流失效正是「沒跑的檢查」與「跑過而通過」長得一樣（Hugging Face 的安全標記自陳 best-effort；OpenSSF 空 repo 拿 10 分）。目前 `--accent-border` 同時承載「未驗證」與「未檢查」，**詞分開了、視覺沒分開**——§2.3 允許這樣，但那正是為什麼詞不能省。
2. **顏色與線型永遠是第二或第三訊號。** `--accent`（`#aa3bff`）在 `--bg` 上是 4.39:1，低於 AA，所以它可以描邊，**不能當文字顏色**；連結另有 `--link`。
3. **class 名字要命名主張，不要命名某一個領域的理由。** `.badge-expired` 的宣告與 `.badge-severity-error` 完全相同，但名字寫死了「過期」，於是「清理失敗」需要同一個視覺時無處可去。`.badge-danger` 是主張的名字；兩個舊名保留，因為使用它們的頁面命名的是真實的東西。
4. **`--accent-border` 目前有一個名不副實的用法**：`.badge-differs` 指的是「有差異」，那是一個肯定的發現，不是未知。這一格待裁。

**§4.4 第 1 列的規則與契約現在是矛盾的，這裡直說。** 全 app 有 **20 個**前端 enum→中文對照表，因為契約在 `tier`／`trust`／`license`／`redistribution` 上送 `{value, label, note}`，在 `status`／`cleanup_status`／compatibility 三軸／risk flags／artifact status 上只送裸 enum。**刪掉對照表會讓 `pending` 直接出現在畫面上，那違反 `02:NFR-007` 第 3 條**（「風險、相容與評估狀態必須同時提供文字」——它剛好點名了風險與相容）。所以：規則對，契約沒跟上，這是**契約缺口不是前端缺陷**。逐項裁定與補法見 [丙-29](../plans/04-backlog-and-handoffs.md)。

**兩件要記住，免得把這一格想得比它大或比它小：**

- **引用更正**：本檔前一版把「兩個平面不得把同一件事講成兩種話」記成 `02:NFR-001`。`02:NFR-001` 標題是「安全」，其唯一的 UI 條款是「靜態掃描通過不等於安全保證，UI 必須避免此類誤導」，**沒有一句談兩平面措辭一致**。那句話是詮釋，站得住腳但不是規格文字；真正承重的是 `NFR-007` 第 3 條。
- **五個缺口只解釋 20 份對照表裡的 8 份。** 補完契約還會剩 12 份。這一格不是靠一次契約改動關掉的。

~~**這條規則不是理論——它已經抓到兩處現行分歧，兩處都不需要契約改動就修得掉**：風險旗標有兩份清單，搜尋列那份把「**可執行**」拿掉了（不是比較短的標籤，是比較小的主張）；`Home.tsx` 用行內三元把 `spec_validation` 的三個值壓成兩個，`failed` 會被講成「未驗證」。~~

**這條規則不是理論——它抓到的兩處現行分歧都已經修掉了**（2026-08-25 複驗於程式，原文以現在式留在上面當證據）：

- **風險旗標的兩份清單併成一份**，而且是**伺服器措辭**的那一份：`components/RiskIndicator.tsx` 現在只渲染 `risk.disclosures` 的 `label`，兩個端點讀同一份目錄。少掉「可執行」那件事因此不可能再發生——它不再是前端的兩個 boolean 集合。附帶效果是一個 `keyof` 聯集拿不到的性質：**這個 build 沒見過的代碼也渲染得出來**。
- **`Home.tsx` 的行內三元換成了伺服器給的標籤**：`hit.compatibility.spec_validation.label`，三個值原封不動，`failed` 不再被講成「未驗證」。

**這一格因此從「規則抓到了兩件事」變成「規則抓到的兩件事修完了」，但上一格的 20 份對照表沒有跟著少到零**——這兩處走的是契約補完那條路（`04` 丙-29），不是前端自己改字。

## 5. 偏離帳

**形狀比照 [`db/query-owners.yaml`](../../db/query-owners.yaml) 的 `allow:`：具名、有理由、只能縮短不能增加。**

### 5.1 入場規則（新的值想成為一階，要過這一關）

> **兩處才成階。** 新的字級／間距／表面／狀態樣式只有在 `apps/web/src` 有 **≥2 個 call site**、**且既有的階涵蓋不了**時，才進 §4。只有一處，或既有的階蓋得住，就改回尺度上。

這條直接裁掉了兩個懸而未決的案子：`6px` 有八個 call site（過第一關），但 `8px` 蓋得住（第二關不過）→ **收掉**；`2px` 只有三處視覺微調且無推導 → **收掉**。

### 5.2 現存偏離（2 條，均為保留）

| 值 | 出現在 | 判定 |
| --- | --- | --- |
| **5px** | `button/select/textarea/input` 的 `padding: 5px 10px` | **保留，有推導**：`20px` line-height ＋ 上下 5px ＋ 上下各 1px 邊框 = `min-height: 32px`（WCAG 2.2 2.5.8 的 24px 下限之上）。不是隨手挑的值 |
| **10px** | 同上的水平 padding，以及卡片的 `padding: 10px 12px` | **保留，單一來源**：一組值服務四個卡片族，改它就是改全部卡片 |

已收（2026-08-22）：`13px`（`.badge` → meta 14px）、`12px 非等寬`（`.filter-unavailable .note`，規則整條移除）、`2px`（三處）、`6px`（八處）。**五條縮到兩條。**

### 5.3 開放缺口（不是偏離）

- **沒有 `--danger` 版的 notice**，所以阻斷性訊息（`Packaging` 的「不能打包」）與降級說明用同一個外觀。目前靠文字分辨（§2.3 允許），但這是 §4.3 那張表講不清楚的一格。
- **`.badge-differs` 用 `--accent-border` 表達一個肯定的發現**（§4.4 規則 4）。
- **`.verdict-*` 的 class 插值已於 2026-08-22 移除**：四個判定只有兩個 token 可用，「部分符合」與「無法判斷」必得共用一個，比不上色更糟。`.criterion-passed` 刻意不存在——安靜的預設就是它的視覺。

## 7. 這把尺對還沒寫的功能說得出什麼

**一份設計系統如果第一次遇到新功能就啞了，它就沒有達成它宣稱的目的。** `01` §7.3 列了 MVP 之後要做的事；逐項問這份文件現在說得出什麼。

**2026-08-22 更新：下表原本有六格寫著「這是產品決策，要在 ADR 裡先解決」。[ADR-042](../adr/ADR-042-roadmap-product-rulings-evidence-aggregate-in-flight-axis-and-enforcer-attribution.md) 把那六格全部裁定了，規則已寫進上面的章節；下表保留缺口的原始描述作為證據，並在「具體缺口」欄註明現在的答案落在哪裡。** 剩下真正沒有答案的只有兩格（多租戶的所有權軸、評估報告的第二個「未驗證」狀態）。

| 即將到來的能力 | 這份系統已經有的 | **具體缺口** |
| --- | --- | --- |
| **團隊協作、多租戶** | 無 | §4.4 的狀態語彙**沒有所有權這條軸**：沒有「別人的」「共用」「唯讀」的視覺；§4.3 的卡片表沒有署名的位置。而且已經有一個現行實例走在錯誤的方向——`04` 丙-14 記載，別人的 Skill 的版本清單回空陣列，也就是**「不是你的」目前渲染成「沒有版本」**，正是 §2.9 的 `無權檢視` 該擋掉的那一格 |

| **遠端 MCP Server** | `RunPreflight` 的權限摘要與 `summary_hash` 綁定 | 同上一格，加上一件事：MCP Registry 的 namespace 驗證只證明名稱歸屬，**什麼都沒說行為**。§2.11(c)（證據要說出自己的上限）就是為這種徽章寫的。**已回答**：§2.2 第三向最後一項給了措辭形狀——「這個名稱屬於 X」沒有說它做什麼 |
| **更豐富的評估報告**（`04` 乙-13 G7／G8 待決） | §4.4 的虛線邊框已經被 `.criterion-unverifiable` 用掉 | 若選項 (b) 成立（「在 UI 上明確標示『此引文未經回驗』」），**第二個「未驗證」狀態會落在同一頁而語彙沒有空頻道**：顏色已經三分（danger／accent-border／無），而 §2.3 禁止只靠顏色。這格要在釘板被塞滿之前先決定 |

**兩條 `01` 明文寫了、而 §1 沒有推導出來的義務**，兩者都已經有實作、也都沒有指引：

- **`01` §5 原則 3「權限透明：執行前說明預計使用的資料、工具、MCP 與網路權限」**——`RunPreflight` 整頁是它，而它的操作形式（同意綁定當下摘要的雜湊，舊的同意永不重送，`02:TEST-005`）是全 app 最強的一條慣例，卻只寫在那個檔案的檔頭。**它應該升成原則，並推廣到每一個確認：第二段確認必須綁定畫面上此刻顯示的事實。**
- **`01` §11.3「所有『通過』或『未通過』結論都能展開查看依據」**——`EvidenceList` 是它，但 §2.10 只說判定不可折疊，沒說**判定的依據必須可展開**。
