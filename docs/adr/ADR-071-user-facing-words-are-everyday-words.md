# ADR-071：畫面上的名詞用日常用語——受控術語縮限為「跨文件與跨程序」的規則

- 狀態：**Accepted**（2026-09-10 負責人裁定「簽署所有待辦清單」，本份為 [`05` R-56](../plans/05-pending-rulings.md) 取 (a) 的落地）
- 日期：2026-09-10
- 相關：[ADR-038](./ADR-038-platform-product-domain-language-and-value-stream-navigation.md)（§3 規則 2 的受控術語，本份**縮限其適用面而不推翻其目的**）、[ADR-041](./ADR-041-trust-signal-vocabulary-typed-absence-and-rule-precedence.md)（信任訊號詞彙）、[ADR-065](./ADR-065-hot-path-text-budget-and-the-fourth-disclosure-mechanism.md)（熱路徑字數預算）、`02` NFR-001、`03` DESIGN-014、`04` 丙-182、`05` R-56

## 背景

**外部審查四輪裡有三輪提了同一件事**：非技術同仁看不懂畫面上的名詞。這是「看不懂」這個問題最大的單一來源——**比任何版面問題都大**，而版面整改一分都改善不了它。

擋住它的不是難度，是 [ADR-038](./ADR-038-platform-product-domain-language-and-value-stream-navigation.md) §3 規則 2 把 `Skill` 定為受控術語，而 ADR 不原地改寫決策——所以第一步必須是一份新的 ADR。**這件事被列為「刻意留給下一次裁定」已經三次**（第七批、第八批、第九批），每一次的理由都相同，而**三次都是因為沒有這份 ADR，不是因為沒有時間**。

實測 blast radius（2026-09-07 逐檔數過）：`apps/web/src` **382 處、31 個檔案**、**沒有 i18n 集中層**；加上 **2 個 Go 常數**（`creator/workspace/http.go` 的 `deletionScope`、`entrypoint/api/apiserver/creation.go` 的 422 文字）與 **10 份 `__outlines__` 標題快照**。

## 決策

### 1. 對照表——只換畫面上看得見的字

| 受控術語 | 畫面用語 | 為什麼 |
| --- | --- | --- |
| `Skill` | **小工具** | 審查四輪裡被點名最多的一個；「Skill」對非技術同仁沒有可推測的意思 |
| `Run` | **試跑**（動詞）／**試跑紀錄**（名詞） | 中文的動名詞同形會造成歧義，所以分開給兩個詞而不是一個 |
| `Test Case` | **測試題** | 「Case」在中文語境裡最常被讀成「案例／個案」，而它實際上是一道有輸入與期待的題目 |
| `Fork` | **複製一份** | 版本控制的隱喻對目標受眾不成立；它在畫面上要說的就是字面的意思 |
| `Workspace` | **不改** | 它在畫面上一直伴隨「我的」出現（「我的 Workspace」），語意已經清楚；**而且它是唯一一個換掉會讓權限邊界變模糊的詞**——「工作區」與「資料夾」的差別正是租戶邊界（ADR-011），換一個更日常的詞會把那條邊界一起換掉 |

### 2. 縮限的範圍，逐項寫死

**改**：`apps/web/src` 的使用者可見字串、上表那 2 個 Go 常數所產生的可見文字、以及隨之更新的 `__outlines__` 標題快照。

**一個字都不改**：`contracts/`（OpenAPI 的 schema 名與欄位）、資料庫（表名、欄名、migration）、程式碼識別字（型別、函式、套件、檔名）、ADR 內文、`02`／`03` 的需求 ID 與其標題、以及本 repo 的 `AGENTS.md` 家族。

**縮限的理由，是 ADR-038 §3 規則 2 自己的目的**：受控術語的存在是為了**跨文件與跨程序的指稱一致**——讓 `contracts/` 說的 `Skill`、Go 的 `Skill`、`02` 的 `SKILL-*` 指同一個東西。**那個目的在畫面文案上不成立**，因為沒有任何一個機器讀畫面上的那個名詞。所以本份不是推翻它，是把它的適用面收回它真正在服務的那一層。

### 3. 一次換完，不做過渡期

不做「括號並列」（「小工具（Skill）」）、不做設定開關、不做逐頁分批。三者都會讓同一個東西在同一個產品裡有兩個名字，**而那正是受控術語規則當初要防止的事**——用一個違反它精神的過渡方案去執行它的縮限，是最壞的一種一致性。

### 4. 落地時點：版面批合併之後

`apps/web/src` 正由另一個代理在改版面（2026-09-10 指派）。382 處散在 31 個檔案，**兩個 Writer 同時改同一批檔案是 `AGENTS.md`〈共享工作樹、單一 Writer〉直接禁止的事**。承接工作項 `03:DESIGN-014`，前置寫死為「版面批合併之後」；`04` 丙-182 結在那個工作項做完，**不隨本 ADR 結案**。

**這是一個排程判斷，不是一個保留意見**：對照表與範圍在本份已經定死，執行者不需要再問任何人。

## 後果

- 正面：Demo 的目標受眾是非技術同仁，而畫面上第一個名詞從此是他們聽得懂的字。這是四輪審查裡最常被提、而至今零進展的一項。
- 正面：ADR-038 §3 規則 2 的目的被寫清楚了——它守的是跨程序指稱，不是畫面用字。下一次有人問「這個詞可不可以換」，有一條可以照著判的線。
- 成本：382 處是一次大範圍的機械修改，`__outlines__` 快照會整批變動，review 時難以逐行看。**緩解是它必須單獨成一個 commit**，不與任何行為改動混在一起。
- 成本：文件與畫面從此用不同的詞講同一件事。**接受**——文件的讀者是開發者與 Agent，畫面的讀者不是，而本份的整個論點就是這兩群人不該被同一張詞表服務。

## 待決策

- **其餘候選詞**：`Dataset`、`Profile`、`Artifact`、`Provider` 在畫面上也出現，但它們的出現次數與受眾暴露度遠低於上表五個，且沒有一個在四輪審查裡被點名。等 `DESIGN-014` 做完、有人真的在畫面上讀過一遍之後再看，不在本份預先裁定。
