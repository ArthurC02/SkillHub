# ADR-020：設計系統、信任訊號與畫面用語

- 狀態：Accepted

## 背景

`apps/web` 的核心動作是讓使用者決定要不要信任並執行別人的程式碼。這個判斷只有在**證據、以及證據的缺席都看得見**時才做得出來；產品同時承諾十分鐘內走完找到到下載，且要服務從非技術到進階三種成熟度的讀者。這三件事（可判斷、快到第一個判斷、一個介面服務三種成熟度）是產品義務，不是視覺偏好。

沒有一把共同的尺時，同一個視覺或文字判斷會在不同批次得到相反的結果，而且沒有機制能指出這件事發生過。畫面本身也**沒有任何東西比別的東西重要**：沒有層級、沒有主要動作、失敗與成功共用同一種外觀，這不是缺裝飾，是缺乏能分辨輕重的系統。另一方面，畫面上的文字量會隨功能增加而膨脹，若不分類就沒有能安全刪減的目標；而名詞若持續使用工程術語，非技術讀者將完全看不懂介面在說什麼。

本 ADR 定義：畫面上什麼時候該建立系統而不是加框架、信任相關的資訊如何呈現與排序、缺席與進行中如何被畫面表達、大清單與文字量如何被治理、視覺層級由什麼承載，以及畫面上的名詞用什麼語言。

## 決策

### 決策 1：不引入第三方設計系統或 UI 框架，維持最小依賴面

`apps/web` 除框架本身與資料抓取函式庫外不引入 UI 元件庫、CSS-in-JS 或 utility framework；樣式表的組織方式由 [ADR-019](./ADR-019-frontend-architecture-and-styles.md) 定義，圖表函式庫是這條規則目前唯一的具名例外（見 [ADR-021](./ADR-021-operator-backoffice.md)）。

理由：

1. 本產品的元件語彙（風險旗標、License 徽章、相容性狀態、判定標籤）承載的是特定的信任語意——「這件事未知還是未通過」「這個判定是誰下的」「平台自己降級了這個判定」，通用元件庫沒有這些概念，套上去等於付了依賴的代價卻拿不到它的好處。
2. 對比度、色彩 token 與版面尺度背後有可稽核的推導過程（例如文字對比從某個不足 AA 的舊值改到現在的值），且有測試直接讀取樣式來源反覆驗證；換掉底層等於同時作廢那些測試與它們守住的東西。
3. 框架的預設外觀會讓產品在被人用眼睛評分的階段變得不可辨識；框架自帶的語意色（success／info／warning）會把留給路線圖尚在等待的頻道（見決策 9 的「保留頻道」）提前填滿。

系統的建立方式是把既有程式碼與規格裡已經存在、但只活在少數人記憶與程式註解裡的規則寫成一份可被引用的文件，而不是發明新規則；新增的規則只補真正的缺口。凡是分不清品味與規則的爭議，先查文件裡的既有規則，不在規則裡才是新決策。

### 決策 2：三個不可談判的義務，牴觸時有固定優先序

可判斷、快到第一個判斷、一個介面服務三種成熟度三者是產品義務，違反是缺陷而非品味爭議。

原則彼此牴觸時（例如「說明缺席理由」與「不讓首屏被推遲」在窄螢幕上互相排擠），順位固定為：

> **安全與不誤導 → 永不折疊清單 → 可及性硬需求 → 速度與版面 → 一致性與美觀**

順位低的規則讓步時，讓的是**形式**，不是內容：說明可以收進可展開的容器，但關鍵的數量與結論必須留在收合狀態就看得到的位置。

### 決策 3：缺席是資料層的型別化列舉值，強制者必須具名

任何非表列的缺席呈現（空白、破折號、「N/A」）都不通過；固定六種缺席型別，且視覺上必須彼此可分辨：**沒有發生過**、**不適用**、**尚未測量**、**測量失敗**、**沒有查看權限**、**平台自己尚未決定值**。這六者互不相同：例如平台自己還沒做出決定的值，既不能印一個沒有依據的數字，也不能留白。

「顯示與強制成對」擴為三向：每一條會限制使用者的規則，畫面上都必須具名它的強制者——**平台**、**使用者自己的執行環境**、或**第三方服務**。平台對自己強制不了的事情不得使用完成式措辭（不能寫「已阻擋」，只能寫清楚會發生什麼、由誰決定要不要發生）；預設一律拒絕，且拒絕狀態下的內容仍必須可讀；需要授權的動作是一次阻斷式的決定，不是可被忽略的被動提示；會執行的動作必須在執行前先顯示將要執行的命令；第三方服務的名稱驗證必須說出自己的上限——「這個名稱屬於 X」不等於「它會做什麼」，兩者都要說。

位元組相同的複本（例如以既有內容為起點建立的新版本）可以繼承**對位元組成立**的量測（靜態掃描、規格驗證、License 判定），但不能繼承**對環境成立**的量測（執行環境相容性、試跑結果、評估判定）——後者量的是內容在特定環境下的行為，換了環境條件就不再成立。繼承需具名歸屬並標示祖先掃描當下的時間戳（不是繼承當下的時間；較舊的時間戳是誠實的呈現）、當下重新比對內容雜湊、只從公開可見的來源繼承，來源被下架後繼承立即失效；繼承來的量測不算六種缺席之一，而是有值且標明來源。

### 決策 4：不做綜合信任分數，風險以具名能力呈現

不引入任何把多項證據壓成單一數字或等第的呈現方式。理由是結構性的：綜合分數必然把「沒有被檢查過」與「檢查過、沒有問題」映射到同一條軸上，這正是「可判斷」義務要防止的失效，而且是把缺席包裝成核可最有效率的做法。

配套的兩條紅線：**人氣類數字不得與信任主張相鄰，也不得作為預設排序依據**；每一個驗證徽章都必須在同一個區塊用文字說出它**不涵蓋**什麼（例如「僅證明檔案存在，未回驗引文內容」）。

### 決策 5：不做評分與排行榜，改以試跑證據彙總取代社會證明

永久不做全域評分與排行榜，理由是名次要求可比較，而本產品的驗收條件天生因 Skill 而異、不可比較。但完全不提供社會證明，使用者只會轉去看下載數與星等——那正是決策 4 要禁止的訊號。

替代方案是**試跑證據彙總**：呈現「在 N 個不同工作區的 M 次試跑中，有多少次符合各自的驗收條件」，這是量測不是意見。四個入場條件缺一不可：

1. 分母必須與比例出現在同一句話裡。
2. 永遠不是預設排序依據，也永遠不是唯一顯示的數字。
3. 必須在同一區塊說明它不涵蓋什麼（「這些是別人的驗收條件，不是你的」）。
4. 少於 5 個不同工作區時顯示「尚未測量」而不是隱藏；Skill 擁有者自己的工作區不計入分母。

這是跨工作區彙總出的產品內容，不是漏斗量測（兩者邊界見 [ADR-010](./ADR-010-product-analytics-and-audit-boundaries.md)），上線前提是使用者同意書與逐工作區明確 opt-in；未取得同意前，這格的正確呈現是「平台自己尚未決定值」而不是空白或隱藏欄位。唯一允許的「排名」是同一次查詢內、有具名比較維度的候選比較，不構成跨查詢的全域順序。

### 決策 6：進行中是獨立的第三軸

執行狀態與任務判定已分屬兩軸；進行中不是這兩軸上的一個值，而是第三個獨立的軸：

1. 還在執行中的項目，其任務判定是「尚未評估」，不是空白、不是樂觀猜測、也不是用較淺的顏色代替。
2. 進行中畫面必須說出三件事：現在在哪一步、這一步會不會自己結束、使用者能不能離開這個畫面。
3. 必須有至少一個會變化的量，以及一個「多久沒有更新」的事實，避免無法區分「還在跑」與「卡住了」。
4. 逾時、上限與配額在進行中畫面上同樣要具名強制者，指不出來就不顯示。
5. 部分完成的資料要標記為部分，並帶上分母。

### 決策 7：大清單依「這一頁在問什麼」決定呈現方式，並強制截斷理由

清單的呈現不是由列數決定，而是由頁面意圖決定：問「這一則行不行」用卡片逐則呈現，每一則要放得下決策 8 要求的完整資訊；問「哪一則最好」用表格，讓欄位對齊便於跨列比較，此時原本卡片裡的每一項改以欄的形式存在，但仍然逐列可見。清單長到一屏放不下時，正解是縮小到可判斷的數量（篩選、搜尋、限縮範圍），不是把每一則的內容削薄。

硬規則：**任何被截斷的清單都必須說出總數與截斷理由**（「共 N 筆，這裡顯示 M 筆，因為……」）。允許的分頁策略收斂為三種：只增不減的時間序資料用「載入更多」；需要穩定位置的證據流用游標式上下頁；固定截斷只在同時給出總數與理由時才允許。沒有任何形式的上限與總數是不允許的狀態。

### 決策 8：卡片的判準

一列算作卡片，若且唯若它帶有（a）自己的控制項或連結，或（b）自己的巢狀子清單。單純「有一個可以被獨立判斷的東西」或「有自己的識別碼」不構成卡片——幾乎每一列都有識別碼，這樣的判準無法證偽。

### 決策 9：視覺層級由 token 承載，深度用表面分層，一頁一個主要動作

視覺層的目的是層級，不是裝飾；每一項視覺變更都必須能回答「它讓哪個東西比別的東西更重要，為什麼該更重要」，答不出來的屬於美觀順位，需要被單獨評估與放行。

規則：

- 用一組具名的 token 角色表達層級：**面**（這是一個東西：卡片、控制項、頁首）、**互動態**（hover／active 用預先混合好的平色，不用透明度疊層）、**強邊框**（控制項邊界的可及性硬需求）、**主要動作色**與其上的文字色、**阻斷底色**（供阻斷性訊息使用，與非阻斷的降級說明區分開）。
- 次要文字的弱化只能用字級降階，不得使用 `opacity`：`opacity` 是任何色彩 token 都攔不住的破壞方式，而對比度的自動化檢測量的是靜態色值，結構上量不到它。
- 深度用**地／面／凹**三層表面表示，不用陰影——陰影在深色模式下會消失，表面分層在明暗模式下都成立；只有在畫面上真的出現「浮在其他東西之上」的物件（下拉、對話框）時才需要陰影 token。
- **主張永遠用描邊，動作永遠用填色**：徽章一律描邊，底色只用中性色，避免任何主張讀起來像背書；填色這個頻道保留給動作。
- **一頁至多一個主要動作**，即完成這一頁核心工作的那一個操作；沒有這種動作的頁面，零個主要動作是合法狀態。毀滅性動作永遠不是主要動作，且採兩段式確認，第二段必須說明這個動作會毀掉什麼。
- 動效只用固定的時長與一個曲線，`prefers-reduced-motion` 在 token 層直接歸零，一次性地關掉所有動效；只轉場顏色與外框類屬性，不轉場透明度。
- 明確不做：不引入 webfont、不做漸層、不做主題切換開關（跟隨系統偏好即可）、不建立圖示集合、不做代表「已檢查沒事」的成功色、不做視覺回歸的截圖基準線。第四個語意色相、以底色表達「非本工作區所有」、填色徽章、以及對應多種強制者的訊息樣式，是刻意保留給尚未落地的路線圖項目的頻道，不得被目前的裝飾需求佔用。

### 決策 10：畫面文字依類別分流，只治理能安全減少的類別

每一段可見文字歸屬且僅歸屬一類：**判斷依據**（決策 3／6 要求逐項可見的十類事實）、**原因**（停用、缺席、被擋的理由）、**但書**（信任訊號的涵蓋範圍聲明）、**限制**（平台真的會強制的上限與規則）、**進行中的三件事**——以上五類**不計入文字預算**，只能因為合併重複語句而變少；**說明性教學文字**與**識別符／推導過程**才計入預算：平鋪呈現的這兩類合計不得超過同頁判斷依據、原因、但書三類的字數之和，且單一說明區塊不得超過 100 字。判準是：同一個人第二次看到這段文字時，這段文字會不會改變他這次要做的決定——會改變的不入預算，不會改變的才入。

三條去重規則：

1. **逐列複述**：一段文字在同一份清單裡逐字重複超過一次，代表它是這份清單的事實而不是那一列的事實，應該提到清單層級講一次，只要清單裡仍有另一個可辨識的標記讓讀者知道自己在看哪一種列；如果去重後會讓讀者分不出眼前這一列屬於哪一種型別值，就不能去重。
2. **同頁同義句**：一句話不能同時存在於可見文字與滑鼠停留提示（如原生 `title`）裡；原因移出停留提示後，停留提示本身要一併移除，否則會留下第二份沒人維護的副本。
3. **跨頁複本**：同一段證據文字如果整段抄錄自另一個頁面且使用者剛看過，是否保留由個案決定，不預先一律裁定去留。

### 決策 11：標籤——一句話能變成一個帶字的名詞短語就變

一段文字如果內容是一個狀態、一個分類或一個計數，一律改用標籤呈現，不用句子。標籤在這套系統裡只有兩種合法形式：**帶文字的徽章**（依決策 9，永遠描邊、不得填色）與用於分類計數的 **chip**。解釋性的句子不留在標籤裡，改放進附屬的揭露機制（見決策 12 的 Tip）。例如引文回驗的結果可以收斂成具名徽章，解釋句移出到 Tip；目錄頁的分類計數 chip 是同一條規則已經做對的樣板。

### 決策 12：第四種漸進式揭露機制——Tip（點擊觸發的揭露）

在既有的模式切換、獨立頁面、可展開容器三種機制之外，新增第四種：**Tip**，一個由點擊（而非滑鼠停留）觸發的小型揭露元件，只用來裝「已經說完的一句話的原因」，不能裝完成判斷所需的任何事實。六條入場條件缺一不可：

1. 只能裝決策 10 定義的「說明」與「識別符／推導」兩類文字，判斷依據、原因、但書、限制、進行中的內容一律不得放進去。
2. 一律用點擊／鍵盤觸發並可鍵盤到達，不得只靠滑鼠停留或原生 `title` 屬性呈現；有明確的開合語意，可用 Esc 關閉；開合不能改變周圍內容的版面高度。
3. 觸發用的錨點文字必須自己成立，能被讀者理解在問什麼；不能是純粹的圖示或無意義的通用詞。
4. 觸發元件必須帶有可見文字，並符合最小可觸控尺寸與可及的名稱，不能只靠不可見的輔助標籤替代可見文字。
5. 同一頁至多三個 Tip。
6. 如果一個頁面需要大量 Tip，代表的是文案或設計本身需要簡化，不是把內容分流到 Tip 裡的訊號；應該優先去重與改寫文案，Tip 是最後手段。

### 決策 13：圖示是第三訊號，永遠伴隨文字

允許使用少量、固定形狀上限的 inline SVG 圖示，但圖示永遠是繼文字、顏色之後的第三訊號：拿掉圖示後，畫面上每一個狀態必須仍然可以只靠文字讀懂。圖示只出現在既有狀態語彙表列出的位置與 Tip 的觸發元件上，一列至多一個，全站形狀數量至多六個；不建立圖示資源目錄或引入圖示字型／套件；圖示顏色取自它所在徽章的既有 token，不新增語意色。這條規則存在的目的是讓讀者掃視時少讀一點字，不是為了避免誤讀——避免誤讀的責任仍在文字本身。

### 決策 14：持久化偏好只能改變預設開合，不能改變有無；不記住「已讀」

使用者的持久化偏好只允許單向展開（把預設收合的內容改成預設展開），不允許收起任何原本可見的內容；一旦某個偏好會讓已顯示的東西消失，它就是被禁止的「模式」。

「使用者看過一次之後可以收合」這個目標不透過記住個別使用者的已讀狀態達成——因為需要一份跨裝置未必同步的持久狀態，會讓同一個人在不同時候看到不同的畫面——而是透過**對所有人一律預設收合**在一個有意義的錨點（Tip 或可展開容器）之後：第一次來的人多點一下，之後來的人不用點，兩者最終看到同一種畫面。

### 決策 15：新的視覺數值只有在有重複需求且既有階不夠用時才能加入

新的字級、間距、表面樣式或狀態樣式，只有在程式碼裡已經有至少兩處獨立的使用需求、且既有的尺度階完全無法涵蓋時，才能被納入正式的尺度表；未達門檻的既有偏離值，只允許被收斂進最接近的既有階，不允許再增加新的偏離。這是用最低成本的方式（搜尋既有使用次數）防止尺度表無限增生，取代真正的使用者研究。

### 決策 16：畫面上的名詞使用日常用語，受控術語限縮為跨文件與跨程序一致性

契約、資料庫欄位、程式碼識別字、需求 ID 與架構文件內的名詞維持既有的受控術語，理由不變：讓不同文件與不同程序談論同一件事時使用同一個詞。但**畫面上使用者看到的文字**不受這條規則約束，因為沒有任何機器讀取畫面上的名詞——受控術語原本要防止的「跨程序指稱不一致」在畫面文案這一層不成立。

畫面用語與受控術語的對照：`Skill`→**小工具**、`Run`（動詞）→**試跑**、`Run`（名詞）→**試跑紀錄**、`Test Case`→**測試題**、`Fork`→**複製一份**；`Workspace` 維持不譯，因為它在畫面上總是與「我的」搭配出現、語意已經清楚，且它是唯一一個換成更日常的詞會讓租戶邊界（見 [ADR-006](./ADR-006-identity-workspace-admission-and-allowances.md)）變得模糊的詞——「工作區」與泛用的「資料夾」之間的差別正是那條邊界本身。

範圍與做法：只改使用者可見的顯示字串，契約 schema、資料庫、程式碼識別字、ADR 內文與需求 ID 一個字都不動；一次性全面替換完成，不做「日常詞（術語）」的括號並列、不做可切換的顯示開關、不分批逐頁替換——這三種過渡方式都會讓同一個東西同時擁有兩個名字，正是受控術語原本要避免的狀況。其餘尚未被指名要換的畫面詞彙留待之後逐一審查，不預先裁定。

## 影響

### 正面

- 視覺、文字與信任呈現的爭議有了共同的裁決依據：先查既有規則，不在規則裡才是新決策，避免同一個判斷在不同批次得到相反結果。
- 缺席、進行中與強制者三組規則讓「沒有被檢查過」與「檢查過、沒有問題」在任何畫面上都不會被混成同一種呈現，這是本系統對抗表面友善但誤導性設計的核心防線。
- 試跑證據彙總把產品在信任量測上真正握有的結構性優勢（每個使用者都在自己資料上真的跑過並留下驗收判定）轉成可呈現的內容，同時用固定的入場條件排除星等排行榜的已知失效模式。
- 視覺層以少量具名 token 角色而非整套框架承載層級，任何一項都可在 token 層一行還原，不綁死到某個外觀。
- 畫面用語改用日常用字後，非技術讀者第一次能看懂介面在說什麼，且不影響任何跨程序或機器可讀的介面。

### 成本與限制

- 多條規則（缺席型別、卡片判準、文字分類、進行中三件事）目前只能由人工核對，尚未有機器驗證覆蓋；文件與程式碼的事實來源不一致時，只能靠紀律而非機制發現。
- 試跑證據彙總在取得使用者同意書與逐工作區 opt-in 之前無法上線，該欄位在此之前必須呈現為「平台自己尚未決定值」。
- 文字預算的判準（哪些文字改變讀者的下一步決定）需要持續依實際量測結果校準門檻，目前的門檻是初次量測推導出的起點，而非最終值。
- 畫面用語與文件、契約用語從此永久分離為兩套詞彙；文件與程式的讀者和畫面的讀者本來就不是同一群人，但任何要把畫面文案回頭核對規格的工作，都需要跨越這層翻譯。
- 卡片與表格的判準、大清單截斷規則、Tip 的六條入場條件都會隨著新頁面出現而需要重新核對，屬於每次新增畫面都要付出的固定檢查成本。

## 待決策

- 是否要提供帶理由的使用者留言功能，做為評分與排行榜之外的另一種意見呈現方式。
- 試跑證據彙總要求的最少不同工作區門檻，目前是推導值，需在有真實流量後依實際分佈校準，且只能調高不能調低。
- 對環境成立的量測（執行環境相容性、試跑結果）在完全相同的釘選執行環境下要不要允許繼承，目前一律不繼承、允許重複量測。
- 畫面文字預算的門檻值（說明性文字上限）需要在有機器化量測之後，依實測分佈重新收緊。
- 詳情頁與其他頁面之間逐字重複的證據段落，是保留在兩處還是把後者改成指回前者，尚未逐案裁定。
- 畫面用語對照表之外、出現頻率較低的詞彙是否也要改成日常用語，留待整體審查後再定。
