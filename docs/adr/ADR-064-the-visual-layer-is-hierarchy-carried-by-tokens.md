## 背景

產品進入推廣與封測階段，負責人提出：目前的畫面**像線框圖**，功能足夠但「裝飾與特效能更吸引使用者，視覺效果也會是被評量的重點」，並要求參考 Bootstrap／Material UI 這類框架的做法，納入設計系統，**但不可貿然加入日後要大幅回調的東西**。

先講清楚問題到底是什麼——2026-09-03 對 `index.css`（987 行）與 18 條路由 ×3 視圖的截圖逐項盤點：

| 事實 | 數字 |
| --- | --- |
| `box-shadow`／`transition`／`transform`／`animation`／`:active`／`position`／`z-index`／`::before`／`::after` | **全部 0 條**——沒有深度、沒有動效、沒有按下狀態、沒有任何圖形 |
| `:hover` 規則 | **2 條**，都只換 `border-color` |
| 卡片族 | 4 族，**3 族逐位元相同**，第 4 族只差 padding |
| 按鈕階級 | **沒有**：`搜尋`、`刪除`、`接受`、`建立下載套件` 是同一個灰底框；打包頁的終點動作與同頁其他 8 顆按鈕無法分辨 |
| 全 app 的填色 | 只有 `--bg` 與 `--code-bg` 兩種；`--code-bg` 同時服務程式碼、按鈕、徽章與停用態 |
| 頁面框 | `#root` 兩條 1px 直線；1280px 視窗下右側三分之一永遠空白 |
| 字體 | `--heading` 與 `--sans` 字串相同，全 app 一種字體；標題與內文只靠字級與 500 字重分辨 |
| 失敗／成功／空／載入 | 同一種 `<p>`：`role="alert"`、`role="status"`、`[data-loading]` **都沒有任何 CSS 規則** |
| 圖示、favicon、`public/` 目錄 | 都沒有 |

**所以「線框感」的來源不是缺顏色，是「畫面上沒有任何東西比別的東西重要」。** 這一句把問題從 §0 順位 5（美觀）搬到了順位 4（§1.2 快到第一個判斷）與順位 3（可及性）：讀者的眼睛沒有一條路通往頭條與唯一該按的那顆按鈕，而輸入框的 1px `#e5e4e7` 邊框在白底上只有 1.27:1，達不到 WCAG 1.4.11 對控制項邊界要求的 3:1。裝飾是修這件事的**副產品**，不是目的。

### 外部參照的結論，反過來支持本 repo 既有的限制

對 Bootstrap 5.3、Material Design 3／MUI、GitHub Primer、GOV.UK／USWDS、Radix／shadcn 的比對（報告見本 ADR 提案當日的研究紀錄；重點如下）：

- **Bootstrap 預設關掉陰影與漸層**（`$enable-shadows: false`、`$enable-gradients: false`）；**GOV.UK 完全不用陰影**；**Material 3 自己從陰影退回「較亮的表面表示浮起」**（tonal elevation），因為陰影在深色模式會消失。本 repo「禁 `opacity`、全 token、`prefers-color-scheme`」的限制**剛好就是這條路**。
- 五家都把「狀態層」做成**預先混好的平色 token**（Bootstrap `--bs-btn-hover-bg`、Primer `--control-*-hover`、Radix 第 3／4／5 階），而不是 Material 文件裡那個自相矛盾的 8%／10%／16% 透明疊層。**本 repo 禁 `opacity` 因此不是障礙。**
- Bootstrap 5.3 的核心新功能是每個語意色的 **subtle／default／emphasis 三態**（`-bg-subtle`／`-border-subtle`／`-text-emphasis`）；Primer 同型（`muted`／`default`／`emphasis`）。**這是本 repo 沒有的那一層**——`--danger` 今天只有一個值，所以「不能打包」的阻斷訊息與降級說明共用同一種外觀（`system.md` §5.3 缺口 ①）。
- 明確不要抄的：Material 動態配色（要 JS 函式庫）、五層陰影（官方 web 套件仍是 Alpha）、Bootstrap 半透明焦點環（需 alpha 且在有色背景上會不過 1.4.11）、shadcn 的預設外觀（**「所有 AI 生出來的網站長一樣」已是公開的嘲笑對象**，而本產品正要進入被人用眼睛評分的階段）、以及任何「成功綠」——那是把「沒檢查」畫成「檢查過沒事」最短的路（§2.11(a)）。

## 評估選項

### 選項 A：引入 Bootstrap／MUI／shadcn 之類的框架或元件庫

- 優點：一次拿到完整的視覺語彙、深色模式、動效與元件狀態；「看起來像成品」最快。
- 缺點（否決；**ADR-039 的三條否決理由一條都沒有失效**，另加兩條）：
  1. `apps/web` 零 UI 依賴、單一樣式表是**機器守住的不變式**（`design-system.test.ts` 的 `readdirSync` 斷言）。
  2. 本 app 的元件語彙承載的是**信任語意**（誰下的判定、未知還是未通過、平台自己降級了），通用元件庫沒有這些概念——ADR-039 原文。
  3. 換底層會作廢 `contrast.test.ts` 與 `index.css` 註解裡的全部推導。
  4. **新增**：框架的預設外觀就是「跟大家一樣」；推廣階段要的是可辨識，不是可辨認出是哪個框架。
  5. **新增**：框架自帶的語意色（success／info／warning）會把 §4.4 刻意留白的頻道填滿——而 ADR-042 的路線圖（所有權軸、評估報告的第二個「未驗證」、三種強制者）**還在等那些頻道**。

### 選項 B：在既有系統內加一層「由 token 承載的層級」（**採用**）

- 內容：不新增任何依賴、不新增樣式表、不新增字級或間距階；只在 `index.css` 的 token 區塊加**七個具名角色**（表面、互動態、主要動作、阻斷底色、強邊框），把「重要的東西」與「其他東西」分開；動效只有兩個時長一個曲線，`prefers-reduced-motion` 在 token 層歸零。
- 優點：**每一項都可以在 token 層一行還原**（把 `--surface` 指回 `--bg`，畫面就回到今天）；既有測試全部沿用，只需擴充 `contrast.test.ts` 的配對清單；不佔用路線圖等著的頻道。
- 缺點：做不到框架那種「元件全套到位」的完成度；圖示、資訊版面（右側空白）這兩件事本選項不解決，要另外裁定（見待決策）。

### 選項 C：維持現狀

- 優點：零風險、零工時、不碰凍結。
- 缺點（否決）：背景那張表列的不是品味問題——**控制項邊界不過 1.4.11、失敗訊息沒有第二訊號、打包頁的終點動作認不出來**，這三件事各自綁得到一條既有規則，維持現狀就是留著三個已知缺陷。

## 決策

**採選項 B。** 規則與現值進 [`system.md` §4.6](../design/system.md)；本節只記決策本身。

### 1. 視覺層的目的是層級，判準是 §0，不是品味

每一項視覺變更必須回答「它讓哪一個東西比別的東西更重要，而那件事為什麼該更重要」。答不出來的是裝飾，裝飾排在 §0 順位 5，**要單獨被放行**（決策 8）。

### 2. 七個新 token 角色，兩個既有 token 改色調，零個改名

| 角色 | 工作 | 亮／暗 |
| --- | --- | --- |
| `--surface` | 「這是一個東西」：卡片、控制項、頁首 | `#ffffff`／`#1b1c24` |
| `--surface-hover`／`--surface-active` | 互動態，**預混平色**，不是疊層 | `#f3f0f8`／`#23242e`；`#efebf5`／`#2a2b36` |
| `--border-strong` | 控制項邊界（≥3:1，WCAG 1.4.11） | `#8f87a0`／`#6e6a80` |
| `--cta`／`--on-cta` | **一頁一個**的主要動作的填色與其上的字 | `#9b2ae6`／`#c084fc`；`#ffffff`／`#0d0812` |
| `--danger-bg` | 阻斷性 notice 的底色（§5.3 缺口 ①） | `#fdecec`／`#3b1a1a` |

既有的 `--bg` 從純白改為**帶紫調的地色** `#f7f6fa`（暗 `#121218`），`--code-bg` 由暖米色 `#f4f3ec` 改為冷紫灰 `#f1eef6`（暗 `#24252f`），`--border` 改 `#e3dfea`（暗 `#31303d`）。**灰階往主色調靠攏**是五套外部系統裡回報成本最低、還原最容易的一項（Radix 為此替每個主色配一組染色灰階）。全部配對已算過：所有文字／背景 ≥4.5:1、`--accent` 描邊 ≥3:1、深色模式同樣通過；落地時 `contrast.test.ts` 的 `PAIRS` 要一併擴到新配對，**沒有進配對清單的 token 等於沒有被守**。

### 3. 深度用表面層級表示，不用陰影

三層：**地**（`--bg`）／**面**（`--surface`）／**凹**（`--code-bg`）。亮色模式面比地白，暗色模式面比地亮——與 Material 3 的 `surface-container-*` 同向，而且是**深色模式唯一成立的做法**。陰影只給「真的浮在別的東西上面」的物件（下拉、對話框、toast），**而本 app 今天一個都沒有**，所以本 ADR 不定義陰影 token；第一個浮起物出現時再加兩個（key ＋ ambient），且 alpha 只能住在 token 裡。`#root` 的兩條直線隨之退場——地與面的色差就是框。

### 4. 主張用描邊，動作用填色；一頁一個主要動作

- **徽章（主張）永遠是描邊**，底色只能是 `--code-bg`。這條不是美學，是 §2.3 與 §2.11 的防線：填色徽章讀起來像背書，而路線圖上第一個會想要填色徽章的是 Marketplace 的付費標章。**「填色」這個頻道從此屬於動作，不屬於主張。**
- **主要動作**（`--cta` 填色）一頁至多一個：**完成這一頁的工作的那一個**（首頁＝搜尋、Skill 詳情＝打包並下載（可打包時）否則 Fork、打包頁＝建立下載套件、Test Case＝建立、匯入＝匯入）。沒有這種動作的頁（比較表、Trace）零個主要動作是合法的。
- **毀滅性動作永遠不是主要動作**：`ConfirmDelete` 的確認鈕維持 `--danger` 描邊（§2.8 的兩段式靠的就是它不顯眼）。
- **授權確認**（`RunPreflight` 的同意）可以是主要動作——§2.2 引用的 VS Code 實測正是「被動、不顯眼的授權提示會失敗」。
- 其餘按鈕＝次要：`--surface` 底、`--border-strong` 邊。

### 5. 動效兩個時長一個曲線，載入態不轉圈

`--dur-fast: 120ms`、`--dur: 200ms`、`--ease: cubic-bezier(0.2, 0, 0, 1)`（Material 3 standard）；`@media (prefers-reduced-motion: reduce)` 把兩個時長設為 `0ms`，**一個區塊關掉全部**。只轉場 `background-color`／`border-color`／`color`／`outline-color`／`transform`，永遠不轉場 `opacity`（本來就禁）。**不加 `@keyframes`、不加進場動畫、不加 spinner**——§2.12 逐字點名「永遠不動的轉圈分不出在跑與卡住」，`Loading.tsx` 的 24 個呼叫點維持文字。

### 6. 為路線圖保留的頻道（本 ADR 不准用掉）

| 頻道 | 留給誰 | 為什麼現在不能碰 |
| --- | --- | --- |
| 第四個語意色相（attention／in-progress） | §2.12 進行中；乙-13 評估報告的第二個「未驗證」 | `system.md` §7 明寫「這格要在釘板被塞滿之前先決定」 |
| 凹面（`--code-bg`）當**整張卡**的底 | 多租戶的所有權軸（「別人的」「唯讀」） | §4.4 沒有所有權軸；把它拿去做視覺變化就沒有地方放「不是你的」 |
| 填色徽章 | **永遠不給任何主張**（決策 4） | 付費標章、Verified Publisher 都會想要它 |
| 三種強制者的 notice 變體 | Local Runner／遠端 MCP（§2.2 第三向） | 本 ADR 只加 `--danger-bg` 一種；`平台`／`你的機器`／`第三方服務` 的分法要等那兩個功能的措辭 |

### 7. 明確不做的

不引入 webfont（外部請求進入同意書的第三方清單、字型載入的版面跳動、以及 ADR-039 否決的依賴面；**字重對比**——標題 600、`.app-title` 700——就是 GOV.UK／USWDS 拿到視覺品質的槓桿）；不做漸層；不做主題切換按鈕（`prefers-color-scheme` 就是使用者的偏好，而 IA R4 說偏好不進網址、凍結說新能力不進產品）；不做圖示集（沒有一條規則缺它，且 §2.3 已要求文字先行——圖示要等一個「沒有它會誤讀」的實例）；不做成功綠；不做任何「Verified」填色；不做視覺回歸截圖基準線（`system.md` §6 已證偽兩次）。

### 8. 凍結下的分類與時間窗

`01` §10 裁定 4 只有兩個桶：修既有缺陷（可）與新能力（不可）。本 ADR 的項目逐一歸類：

| 項目 | 綁到的既有規則 | 桶 |
| --- | --- | --- |
| 控制項邊框 `--border-strong` | WCAG 1.4.11（§0 順位 3） | 修缺陷 |
| 一頁一個主要動作 | §1.2「不讓讀者為了拿到頭條而費力」；閘門分析 §5.1 允許的修法 P1「提升視覺層級」 | 修缺陷 |
| `--danger-bg` 阻斷 notice、`role="alert"` 有第二訊號 | §5.3 缺口 ①；§2.3；§3 第 2 條「答案有被標記成答案嗎」 | 修缺陷 |
| `prefers-reduced-motion` | 順位 3（一旦有動效就必須有） | 隨動效 |
| 地／面／凹三層、染色灰階、字重、favicon、`.app-title` 記號、hover／active、轉場 | **綁不到既有規則——這是順位 5** | **需負責人一句放行（R-38）** |

**時間窗**：閘門 D 日 2026-09-11，`gate-test/analysis.md` §5.1 明寫「動的是版面或文案 → 全套 9 人重測」。本 ADR 的第一階段**不動版面、不動任何文案**（只有 token、字重、class），所以它在 09-10 前落地不會讓閘門不可比；**09-11 至 09-20 一律不動**；任何動版面的第二階段（右側空白、操作欄）在 09-20 之後另行裁定。

## 影響

- **正面**：三個已知缺陷（1.4.11、失敗無第二訊號、終點動作認不出）隨視覺層一起關閉；每一項都可在 token 層還原；路線圖的四個頻道被具名保留，下一個功能不會在無人注意時把它們用掉。
- **成本**：`contrast.test.ts` 的配對從 9 對擴到約 25 對；`a.action` 的 7 個呼叫點要逐頁確認「一頁一個」（`SkillDetail` 今天有兩個）；`e2e/rendered.spec.ts` 那條「事實與但書不同色」的斷言在新 token 下要重跑三引擎確認仍然成立。
- **限制**：本 ADR 不解決右側三分之一的空白，也不解決「一頁 25 個資訊區塊全部同一種灰」——後者是資訊版面問題，要的是一次量測後的版面裁定，不是 token。

## 落地紀錄（2026-09-03）

三個 Writer 平行、路徑互不重疊（`index.css`／markup／測試），主 Agent 序列化收尾。與決策不同或決策沒說的：

- **`[role="alert"]` 的框不套在行內 `<span>` 上**（`AuthControls`、`SignIn`、`RunPreflight` 三處把 alert 放在一句話裡）：行內盒的 padding 不撐行高，會壓到上下行；改成 block 是版面變更，第一階段不做。那三處的第二訊號仍然只有字。
- **`--dur` 宣告了但沒用到**：第一階段的轉場全部用 `--dur-fast`（120ms）。留著它是因為 §4.6.4 定義了兩個；第一個要 200ms 的轉場出現時再用。
- **主要動作的判定多了一條**：`/skills/$id` 在版本清單讀取中或讀取失敗時是**零個**，不是先給一個再收回；`ForkAction` 因此讀同一個 query key（去重，不多一個請求）。`/lab/test-cases/$id` 保留「前往執行前權限確認」——它是那一頁的工作，與清單頁是兩條路由。
