# ADR-061：淨測試模式的放行開關長在鍵盤上，不長在產品裡

- 狀態：Accepted
- 日期：2026-09-02
- 關聯：[ADR-059](./ADR-059-the-clean-mode-execution-driver-is-honest-about-not-being-a-sandbox.md)（`isolation.level = "clean"` 的意思是沒有邊界）、[ADR-060](./ADR-060-the-clean-test-mode-is-the-real-system-with-three-strategies-swapped.md)（同一套產品換三個實作）、[ADR-045](./ADR-045-self-supplied-content-is-not-redistribution.md)（`self_supplied` 講的是誰帶進來的，不是可不可信）、[ADR-057](./ADR-057-releasing-content-takes-named-evidence-not-a-button.md)（放行要具名證據，不是一個按鈕）、`02:PORT-010` 第 5 條、`02:SEC-011`、[`05` R-37](../plans/05-pending-rulings.md)、[`04` 丙-114／丙-124](../plans/04-backlog-and-handoffs.md)

## 背景

使用者 2026-09-02 實地回報：**在淨測試模式下用不了自己做的 Skill。** 查下去是**兩道牆疊在一起**，而只有第一道是意外。

第一道是**登入**：全 app 唯一的登入入口是一個寫死的 GitHub 連結，在 `02:PORT-005` 講的那台機器上它**離開產品**、落在瀏覽器的連線錯誤頁。`DEV_LOGIN=1` 一直都由 `tools/cleanmode/start.mjs` 設、`POST /auth/dev/login` 一直都能動——缺的是畫面上沒有人呼叫它。已於同日修掉（`04` 丙-124），**不是本 ADR 的題目**。

第二道是本 ADR 的題目：`requireCuratedContent()`（2026-08-30 為 `02:PORT-010` 第 5 條補上的強制點）只放行**目錄工作區**的內容，或 `curation_tier = 'curated'` **且正是那一版**。使用者自己匯入、fork 或生成的 Skill 兩個條件都不符合，所以在這個模式下**結構性地跑不起來**。

**這道牆是刻意的，理由沒有變**：這個模式的 Driver 宣告 `isolation.level = "clean"`，而 ADR-059 已經把那個名字讀死了——**沒有邊界，不是比較弱的邊界**。程式註解逐字寫著「the cost of a wrong 'yes' is somebody else's code running on the operator's laptop as the operator」。而且平台**分不出「我自己寫的」與「我從網路上抓來再上傳的」**（ADR-045 的同一條推理），所以「這是我自己的」不能當作「可以在沒有沙箱的機器上執行」的依據。

於是要決定的不是「要不要拆掉閘門」，而是**要不要給操作者一個逐版本、具名理由的放行動作**。負責人 2026-09-02 裁定：**要**（`05` R-37 取 (c)）。

## 決策

### 1. 放行的單位是一個 Skill Version，永遠不是一個 Skill

閘門今天已經分得出「精選過，但不是要跑的這一版」——`curated_version_id` 那半條判斷就是為此存在。放行如果黏在 Skill 上，下一次推版就會**自動放行一批沒有人看過的位元組**，那正是那半條判斷擋掉的東西。

### 2. 放行的宣告在部署設定裡，不在產品的 UI 裡

**這一條是本 ADR 真正的內容，而它不是為了省工。**

`02:SEC-011` 已經對「單人團隊的 operator 授權」回答過同一個問題，答案寫在 `creator/workspace/http.go`：角色表需要自己的授予端點、那個端點自己的授權、以及授予本身的稽核，**而三者存在的唯一目的是讓一個帳號提拔自己**；所以「授予＝改部署環境並重啟，凡是不能部署的人就做不到」。

在淨測試模式裡，這個論證不只是可用，而是**被逼出來的**：這個模式跑在 `DEV_LOGIN=1` 上，**任何到得了那個頁面的人都能以任何身分登入，包含 operator**——`start.mjs` 在把 operator 名冊交給展示匯入者之前，自己的註解就這麼寫。因此一個長在該 UI 裡、寫著「允許這個不經沙箱執行」的按鈕，**按得動它的人包含剛剛上傳那個 Skill 的人**，而那正是這道閘門存在要擋的那隻手。

**那台機器唯一還剩下的權限，是啟動 launcher 的那個鍵盤。** 開關就長在那裡：檔案 `SKILLHUB_CLEAN_MODE_RELEASES`，一行一筆 `<skill_version_id> <為什麼>`。

### 3. 具名的理由不是附在控制上的文件工作，它就是控制本身

一行只有 id、後面沒有理由的，**不是放行**。因為這個開關關掉的是一道保護，而它唯一留下的東西就是那句理由——沒有理由的放行，事後與「不知道誰按過」無法區分。

紀錄有兩半，兩半都在操作者眼前：①**檔案本身**（他寫下的那句話，重啟後還在）；②**每一次被用到時的一行 `slog.Warn`**，說出 run、版本與**放棄了什麼**。刻意**不寫 DB audit event**——這個模式的載體是記憶體內的 PGlite（ADR-060），一列關機就沒的稽核，比操作者終端機裡那一行更差。

### 4. 拒絕訊息必須說出「怎麼放行」以及那一版的 id

在只有一台機器、沒有第二個部署可以搬過去的地方，一句「anything else needs a deployment with a real sandbox」是死路。拒絕現在多一句：**這一版的 id、放行檔的路徑、以及「沒有理由的那一行不算放行」**。變數沒設時說的是另一句話（沒設，所以什麼都沒放行），因為「開關壞了」與「開關沒開」是操作者會做出不同動作的兩件事。

### 5. 這個開關在淨測試模式以外不存在

判斷整段在 `requireCuratedContent()` 的 `cleanTestMode()` 早退之後，所以生產機上就算有人把那個變數設起來、把檔案放好，**它一行也不會被讀到**。這一點有測試（`TestTheReleaseListIsNeverEvenReadOutsideTheCleanTestMode`），而且測試自己先證明「讀得到就會出聲」，否則它會在兩種情況下都是綠的。

## 評估選項

| 選項 | 內容 | 為什麼不取 |
| --- | --- | --- |
| **(c) 逐版本、具名理由的放行**（取這個） | 自建 Skill 跑得起來，每一次放行是一個刻意的動作並留紀錄 | — |
| (a) 維持邊界，只把拒絕提前到 preflight | 誠實，但不解決「我想在 demo 上跑自己的東西」 | **不衝突，仍然該做**；見下方待決策 |
| (b) 放行「這個工作區自己帶進來的」內容 | 自建 Skill 跑得起來，不需要任何動作 | **不接受**：平台分不出自寫與轉貼（ADR-045），而 driver 沒有邊界。這會讓「上傳」等於「執行」 |
| (d) 給淨測試模式一個真的隔離邊界 | 什麼都能跑 | 那台機器**不能安裝軟體**——這正是 M6 存在的理由。結構上不可行 |

**機制上另外比過的一組**（(c) 內部）：**operator 端點 ＋ migration ＋ UI** 對上**部署設定檔**。前者在這個模式裡**買不到任何東西**（決策 2 的理由），而且要付 migration、契約、路由、稽核與前端；後者是 `02:SEC-011` 對同一形狀已經給過的答案。**環境變數**（而不是檔案）也比過：不可行——被放行的版本在啟動時**還不存在**，它是使用者上傳之後才生出來的 id，所以只在啟動時讀一次的值，只能放行上一輪的內容。

## 後果與已知邊界

- **`02:PORT-010` 第 5 條「該模式只跑 `PORT-007` 允許的策展素材」自本 ADR 起不再逐字為真。** 該條已改寫，原文保留（見 `02`）。
- **風險沒有被消除，只是換了持有人。** 從「預設不可以」變成「有一個具名的人說可以」，而那個人承擔的是他自己機器上的執行。這是一個**接受風險的決定**，不是一個實作選擇——本 ADR 存在就是為了讓它是一句寫下來的話。
- **放行不會過期，也不隨內容變化而失效。** 它綁死在一個 version id 上，而 version 是不可變的（鐵律 4），所以「放行的那一版」與「跑的那一版」永遠是同一批位元組。要收回就刪掉那一行，下一次派送就不再放行。
- **這個開關對 `04` 丙-114 記的另一半沒有幫助**：拒絕仍然發生在 `201 queued` 之後。R-37 的 (a) 仍然開著。

## 待決策

- **(a)：把 `requireCuratedContent()` 的判斷提前到 preflight 與 fork 出口**。它是純粹對 Skill 的判斷，preflight 完全問得起，而今天使用者是在投入四個步驟之後才被擋。承接見 `04` 丙-114。
- **要不要在放行被用到時，也在 Run 的畫面上說出來**。今天只有終端機知道這一版是被放行跑的；讀 Trace 的人看不出這次執行沒有經過策展。封測不會遇到（那裡沒有這個模式），但 demo 的觀眾會。
