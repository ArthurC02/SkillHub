# ADR-056：生成額度是自己的一個開關，而它現在是關的

- 狀態：Accepted
- 日期：2026-08-23
- 決策者：架構規劃（依 2026-08-23「額度先不限制」的既有裁示與「按最佳實務決定」的委任）
- 關係：落實 [ADR-047](./ADR-047-generation-path-rulings-retry-truncation-and-quota.md) 決策 5（生成與 Run 分開計額度）；沿用 [ADR-028](./ADR-028-beta-admission-and-quota-enforcement-points.md) 決策 2 的強制點形狀與決策 4 的「先建點、後追認數字」；與 [ADR-055](./ADR-055-the-run-allowance-is-turned-off-and-that-took-an-action.md) 同一個判斷但**不是同一個開關**

## 背景

ADR-047 決策 5 裁定「生成與 Run 分開計額度」，理由是共用一個池會讓一次生成安靜地吃掉試跑的餘額，而**試跑正是 MVP 漏斗在量的那件事**。該決策沒有給數字，也沒有說這個額度預設開還是關。

ADR-055 已把 Run 額度關掉（`RUN_QUOTA=off`），並在同一份裡訂正了一個相反的記載：`05` R-1a 曾寫「未設定＝不強制」，而 `quotaFromEnv` 說的是反面——**未設定＝以提案數字強制**。那個差別決定「一個什麼都沒設定的部署有沒有成本天花板」。

`GEN-004` 落地時必須同時回答兩件 ADR-047 沒回答的事：數字從哪裡來，以及預設開或關。

## 決策

### 1. 生成額度用**第二個環境變數** `GENERATE_QUOTA`，不與 `RUN_QUOTA` 共用

一個開關同時關掉兩個額度，就是 ADR-047 決策 5 裁掉的那個共用池換一套衣服穿。**兩個變數的語意刻意完全相同**（未設定＝強制、`off`＝不強制且不顯示），差別只在它們管的是哪一件事。

### 2. **未設定＝強制**，與 `RUN_QUOTA` 同一種不對稱

不對稱本身是決定：**關掉額度要有人寫下一個動作**。ADR-055 的訂正說明了為什麼——把「未設定」讀成「不強制」的那份文件，讓一個沒有設定過任何東西的部署看起來是安全的，而它不是。

### 3. 數字沿用 ADR-028 決策 4 的分工：**點先建、數字待追認**

`policy.DefaultGenerateQuotaLimits()` 給的是**每日 10／每窗 30／首窗 20／窗長 30 天**，四個數全部標 **待追認**，並在程式碼裡寫明它們是怎麼估的，讓 PDM 追認時是複審而不是重來：

- 一次生成實測 **$0.0055**（預設的 mini 級）、**$0.113**（flagship），見 [m5/report-generate-baseline.md](../plans/mvp/m5/report-generate-baseline.md)。（**2026-08-24 補記**：flagship 的 $0.113 是 spike 報告訂正前的數，baseline 報告記的是 **$0.1186**；mini 精確值 $0.00553。數字不影響本 ADR 的任何決策。）
- 一次 Run 的閘道實付中位數是 **$0.0382**（ADR-055 訂正後的數）。**生成比試跑便宜。**
- 使用者對生成結果不滿意時會改寫任務描述再跑一次，所以**每日的數字比 Run 的 5 高**；每窗的不高。

ADR-028 決策 4 允許這個分工，但它同時禁止一件事：**未追認的數字不得出現在畫面上**。這條寫進 `04` 乙-22，`GEN-008` 的生成前額度顯示受它管。

### 4. 依 2026-08-23 的既有裁示，`.env.example` 設為 `GENERATE_QUOTA=off`

「額度先不限制」是產品負責人當天對封測所下的裁示，而 ADR-055 已把它套用在 Run 上。生成沒有理由是例外——**同一個封測、同一批人**。

**但曝光的形狀要寫下來，因為它與 Run 的不同：**

| | Run | 生成 |
| --- | --- | --- |
| 每次的煞車 | 閘道 key `max_budget` $0.50、SBX-013 的 300K in／60K out | 16000 token 上限、~~閘道 key~~（**08-24 補記**：生成走的是共用靜態 `LITELLM_API_KEY`，它的 `max_budget` 是部署級累計餘額，不是每次的煞車——`.env.example` 已訂正；每次真正的煞車只有 token 上限與 4000 rune 的輸入界） |
| 沒有上限的是 | 次數 | 次數 |
| 一次的實測中位數 | $0.0382 | $0.0055（mini） |
| 一次失敗會不會收費 | 會（Run 走到 `preparing` 就計） | **不會**（沒有列就沒有計數） |

**生成這一側便宜一個量級，而且失敗天生不計費**——因為計數的方式是數 `skill_sources` 的列，不是維護一個餘額。**這不是省下來的實作，是省下來的一整類錯誤**：沒有東西可以扣，就沒有東西會扣錯。

**⚠️ 2026-08-23 稽核補記：上面那句話成立，但它靠的不是計數方式本身。** 稽核指出重複內容會讓 `persistVersion` 在 `CreateSkillSource` **之前**就返回——一次已經付過錢的生成因此不寫任何列，也就不計費。**那個洞已經被另一條守衛關掉**（`importZip` 拒絕生成物與既有 Skill 的同名碰撞，見 `03:GEN-003`）：生成現在永遠建立一列新的 Skill，新列沒有任何版本，`VersionByContent` 因此找不到重複。**成立的理由是間接的，寫在這裡，因為哪天那條守衛被拿掉，這一句會安靜地變成假的。**

## 後果

- **`GEN-004` 的強制點在呼叫模型之前**，符合 `02:GEN-001`「不得先花錢再說」。它**不在寫入結果的那個交易裡**，與 `EnforceQuota` 不同——模型呼叫夾在中間，跨著它持有一個連線的代價遠大於它擋掉的溢出。
- **溢出是無界的，這裡寫明而不是暗示**（**08-24 補記：同日稍晚 `skill/admission` 加了每工作區單一進行中的生成槽（`holdGenerateSlot`），溢出現在以 API 副本數為界，不再無界**）：同一個工作區的並行生成會讀到同一份用量，而 Run 有 `MaxConcurrentRunsPerWorkspace` 把溢出夾住，生成~~沒有對應的閘~~。今天的入口是一個瀏覽器分頁裡的一個按鈕；哪天不是了，就在計數外面加一個 per-workspace advisory lock（程式碼裡有 `ponytail:` 註記指到這裡）。
- **`ingest` → `policy` 是一條新的跨 context import**，同批已加入 [ADR-032](./ADR-032-ddd-bounded-context-governance-for-platform.md) 附錄 A 與 depguard；方向與既有的 `run` → `policy`、`packaging` → `policy` 相同——規則在 `policy`，**強制點在問問題的那個 context**。
- **一件沒有被這份 ADR 解決的事**：`GENERATE_QUOTA=off` 之下，`02:GEN-001` 要求的「生成前顯示預估成本與本次將消耗的額度」**顯示不出額度**（沒有額度可顯示），只剩成本。這是 04 乙-2 既有紀律的直接後果——**沒有被強制的數字不得顯示**——不是缺漏。

## 待決策

- **四個數字的追認**（`04` 乙-22，[`05` R-9](../plans/05-pending-rulings.md)）。在追認之前，`GEN-008` 不得把它們畫在任何畫面上；`off` 之下這一條自動成立，但**開關一旦打開，那個限制就要有人記得**。
