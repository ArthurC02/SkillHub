# ADR-015：ADR 管理

- 狀態：Accepted
- 相關：[ADR-013](./ADR-013-repository-layout-ci-and-verification-tiers.md)（Repo 結構、CI 與驗證層）、[ADR-014](./ADR-014-developer-automation-and-dependency-governance.md)（開發自動化與依賴治理）

## 背景

ADR 記錄架構決策的內容與理由。它同時是其他文件、程式與設定查詢現行規則的地方，所以別處常直接寫某一份 ADR 的編號或檔名。決策一變，這些引用就悄悄指向過時的內容。另一方面，「決策變了就新增一份、舊的標成取代」會讓檔案數跟著決策次數無限增加，讀者得走完整條取代鏈，才知道哪一條還成立。

## 決策

### 決策 1：一個主題一份 ADR，內容永遠是現行版本

- `docs/adr/` 只放現行的主題 ADR 與索引 `README.md`。
- 決策改變時，直接改寫該主題 ADR 裡的那一段，讓全文仍然只描述現行的決策。改變的理由與經過寫進 commit message；舊版本由 git 保存。不保留被取代的檔案，不加補記，不留刪除線。
- 出現新的主題才新增 ADR，編號＝索引最大號＋1，刪除過的編號不再使用。
- 主題拆分或合併時，新寫的 ADR 取代原來的，原檔刪除；同一個 commit 更新索引與所有連到它的連結。

理由：讀者要的是「現在的規則是什麼、為什麼」。歷史交給 git，檔案數就跟著主題數，而不是跟著決策次數成長。

### 決策 2：只有 ADR 與索引寫 ADR 編號或檔名

- 其他所有檔案——文件、程式、測試、設定、契約——寫規則本身。
- markdown 文件需要讓讀者看理由時，連到索引的主題段落：`docs/adr/README.md#<主題>`。索引裡每個主題的標題就是那份 ADR 的標題，所以錨點穩定；主題改名時，同一個 commit 改掉所有連到舊錨點的連結。
- 程式、設定與契約不連 ADR。

理由：編號和檔名會隨整併與改名變動；主題名稱穩定，而索引本來就是讀者的入口。

### 決策 3：記錄下來的輸出與第三方內容照原樣保存

里程碑的執行紀錄（transcript、probe、log 等非 markdown 證據）、量測結果、模型寫出的 Skill 本體、第三方 Skill 語料，保留寫下當時的樣子；裡面出現 ADR 編號也不改寫。改寫它們等於竄改證據。例外名單在檢查器裡，逐條寫出理由。

### 決策 4：ADR 不寫施工日誌

ADR 只寫背景、現行決策與理由、影響、仍待決定的問題。不寫日期、補記、實作註記、放行紀錄、工作項編號、過程敘述；數字只留作為決策理由的那幾個。這些內容寫進 commit message。

### 決策 5：由 `automation-check` 的 `adr-citations` 強制

1. `docs/adr/` 以外，除了決策 3 的例外，不得出現 ADR 編號。
2. `docs/adr/` 只有 `ADR-NNN-<slug>.md` 與 `README.md`；每份 ADR 都列在索引裡，而且列在與它標題相同的標題底下。
3. ADR 與索引裡引用的編號都要有對應的檔案。
4. 連到索引的錨點都要對得到索引裡的標題。

## 影響

### 正面

- 引用不會指向過時的決策：別處不寫編號，ADR 本身永遠是現行版。
- 檔案數受主題數約束。
- 讀者從索引一步就到現行規則。

### 成本與限制

- 決策的歷史只在 git：要知道某條規則以前的樣子與改動理由，看那份 ADR 的 git log 與 commit message。
- 整併前的 commit message 引用的是舊編號，與現行編號同號不同義。
- 改寫 ADR 時要自己維持「全文都是現行版」；機器檢查不出內容是否過時。
