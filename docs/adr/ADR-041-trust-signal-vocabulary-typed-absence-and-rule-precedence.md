# ADR-041：信任訊號的表達方式、缺席的型別，與規則優先序

- 狀態：Accepted
- 日期：2026-08-22
- 關聯：[ADR-039](ADR-039-frontend-design-system-and-ui-evaluation-criteria.md)（設計系統的存在理由）、[ADR-036](ADR-036-real-browser-verification-tier.md)（瀏覽器驗證層）、[ADR-025](ADR-025-run-terminal-state-and-evaluation-verdict-separation.md)、[ADR-027](ADR-027-download-artifact-shape-reproducibility-and-integrity.md)、[ADR-011](ADR-011-workspace-tenancy-policy-and-usage.md)
- 操作手冊：[docs/design/system.md](../design/system.md)

## 背景

ADR-039 建立了一把尺。這一份是**第一次拿它走完全部十八個畫面**之後的結果。

那次走查加上四份外部調查（第三方套件生態的信任訊號、公開設計系統的治理機制、設計規則的機器強制手段、漸進式揭露與缺失資料的呈現）產生三類發現，三類都不是 ADR-039 能涵蓋的：

1. **原則會互相牴觸，而且已經在正式畫面上牴觸過。** 首頁手機版：三個停用篩選各自帶一整段理由（原則 2.4 正確執行），加總把第一筆結果推到 1180px，違反義務 1.2。兩條規則都對。一份沒有優先序的原則清單不是系統。
2. **「未知不是空白」不夠細。** 這條規則只有一個詞可用，而畫面上實際存在六種不同的「沒有值」，其中兩種（`無權檢視`、`尚未定值`）是本產品特有而觀測工具沒有的。已經有兩處因此寫錯：Run 產出的保存期限因 PDM-006 未追認而不能印數字，於是印了空白；`RunPreflight` 的成本區明確避開了零值填補（對），落到了空白（錯）。
3. **這個產品即將面對一整類它沒有詞彙可談的東西。** `01` §7.3 列的 MVP 後續裡，評分與排行榜和 `01` §5 原則 2（證據優先，不只依賴 Star）正面衝突；Marketplace 會把商業誘因壓在徽章上；長時間工作需要一個這份系統完全沒有的時間軸。**一份設計系統如果第一次遇到新功能就啞了，它就沒有達成它宣稱的目的。**

## 決策

### 1. 規則優先序（新增，`system.md` §0）

牴觸時順位為：**安全與不誤導 → 永不折疊清單 → 可及性硬需求 → 速度與版面 → 一致性與美觀**。

配套的形狀規則：**順位低的規則讓步時，讓的是形式，不是內容。** 首頁那個例子的正解不是刪掉停用理由，也不是忍受 1180px，而是在窄螢幕把篩選收進 `<details>` 而把「3 個條件目前無法篩選」留在 `<summary>` 上——數量留在外面，段落收進去。

### 2. 缺席是資料層的列舉值（新增，`system.md` §2.9）

固定六詞：`0`／`不適用`／`未測量`／`測量失敗`／`無權檢視`／`尚未定值`。任何非表列的缺席呈現（空欄、`—`、`N/A`）即不通過，且 `0` 與 `未測量` 在同一張截圖上必須長得不一樣。

`尚未定值` 是與 §2.2（顯示與強制成對）咬合的那一格：平台自己還沒決定的值，既不准印一個沒被強制的數字，也不准留白。

### 3. 不做綜合信任分數（見下方「評估選項」）

不引入任何把多項證據壓成單一數字或等第的呈現；風險以**具名能力**表達；**人氣數字不得與信任主張相鄰，也不得作為預設排序**；每一個驗證徽章必須在同一個區塊、以文字說出它**不涵蓋**什麼。

### 4. 卡片判準改寫（`system.md` §4.3）

> 一列是卡片，若且唯若它帶著（a）自己的控制項或連結，或（b）自己的巢狀子清單。

舊判準「一則可以被單獨採信或拒絕的東西」不可證偽。曾經提過的收緊（「自己的動作**或**自己的識別」）更糟——每一列都有識別碼，該析取式對全部十二個清單都成立，其中七個答錯。新判準對十二個清單全部給出正確答案，並在採用當下就抓到一個未修缺陷（`.finding-list`）。

### 5. 文件即政策，CSS 即事實，測試比對兩者

`design-system.test.ts` 不再手抄尺度，改為 parse `system.md` §4.1／§4.2／§5.2 的粗體 `**NNpx**` 儲存格，與 `index.css` 抽出的實際值比對。同時把棘輪從「偏離清單的長度」改扣到**尺度的總階數**——ADR-039 自己承認的頭號代價是「文件會漂，而且它漂的時候沒有任何測試會 FAIL」，而 §5 明文的退場路徑（「改回尺度上」）過去正是唯一沒人看的那條路。

### 6. 新值的入場規則（`system.md` §5.1）

> **兩處才成階。** 新的字級／間距／表面／狀態樣式只有在 `apps/web/src` 有 ≥2 個 call site，**且既有的階涵蓋不了**時才進 §4。

這是 GOV.UK 貢獻準則（Useful ＋ Unique，要求證據）在單一 app 上最便宜的誠實版本：證據用 grep，不用使用者研究。它當場裁掉了兩個懸案——`6px` 有八處但 `8px` 蓋得住（收掉）、`2px` 只有三處且無推導（收掉），偏離清單由五條縮到兩條。

## 評估選項（決策 3：要不要做綜合信任分數）

這是本 ADR 唯一的選型決策，其餘五項是邊界定義。

| | A. 綜合分數（0–10 或健康分數） | B. 等級階梯（SLSA 式 L1–L3、Soundcheck tracks） | C. 具名能力＋逐項狀態（**採用**） |
| --- | --- | --- | --- |
| 十分鐘旅程 | **最好**：一個數字活得下來 | 好 | 較差：讀者要看數項 |
| 學習者可用性 | **最好** | 好 | 中等，靠白話措辭補 |
| 排序可解釋性 | **最好** | 中等 | 需要另外設計 |
| 「沒檢查」與「檢查過沒事」分得開嗎 | **分不開**——這是決定性的 | 分不開 | **分得開**（§2.9 的六詞） |
| 已記錄的實際失效 | OpenSSF 空 repo 在某些檢查上拿 10 分；Zahan et al.（ICSE-SEIP 2023）量到分數與回報漏洞的關聯方向不符預期 | 「L3 所以安全」的過度解讀 | Socket.dev 的能力告警是目前最接近的正面案例 |
| 與 `01` §5 原則 2 的相容性 | 衝突 | 衝突 | 一致 |
| 商業誘因下的耐受度 | 低（Snyk 的健康分數有四分之一是人氣） | 低（Docker／VS Code 的「Verified Publisher」實質是付費或網域年資） | 高：能力名稱不容易被稀釋 |

**選 C 的關鍵理由只有一個**：綜合分數**必然**把「沒檢查」映射到與「檢查過、沒事」同一條軸上。那正是義務 1.1 存在要防的失效，而且它是**把缺席轉換成看起來像核可**最有效率的機器。A 的三項優勢是真的，但全部輸給這一條。

**支持 A 最強的論證**（記在這裡，免得未來被當成沒想過）：十分鐘的閉環裡只有一個數字活得下來，而沒有分數就沒有可解釋的排序。回應是：排序可以用具名的召回理由（目前 `.match-reason` 已在做），而「一個數字活得下來」在這個產品上是缺點不是優點。

## 影響

- **`system.md` 從八條原則長到十一條、checklist 從九條長到十六條。** 成本落在每一批 UI 工作的人身上。但舊的九條只折了十一條規則裡的五條，`02:NFR-001`／§2.2／§2.5／§2.8 一條都沒有——而 §2.2 是全文件唯一有三次獨立事故紀錄的原則。
- **十六條裡有六條有機器守門，十條沒有。** §6 逐列寫出覆蓋範圍，包括三處舊版本文的過度宣稱（焦點環與 Tab 順序實際只跑 `/` 一條路由，合成像素對比只跑兩條）。
- **決策 3 是一條禁令，不是一個功能。** 它的價值在於未來的 PR 必須論證**反對一條規則**，而不是論證**支持一個功能**——後者永遠比較容易。
- **決策 5 讓文件與程式互相綁死。** 好處是文件漂掉會 FAIL；代價是 `system.md` 的三張表變成了程式的一部分，格式跑掉會壞測試。已加 sentinel 斷言，讓格式漂移表現為明確失敗而不是靜默地把尺度清空。
- **§7 列出的路線缺口不是全部都能現在填。** 它們是被命名的空格，不是承諾。命名本身有價值：下一個功能不會在無人注意的情況下把某條原則悄悄破壞掉。

## 待決策

1. **評分／排行榜要不要做，以及若做，怎麼與 `01` §5 原則 2 共存。** 決策 3 只禁止了「人氣與信任主張相鄰」與「人氣作為預設排序」，沒有規定評分自己怎麼呈現。**這是產品決策不是 UI 決策**，要在功能排程之前解決。 → [ADR-042](ADR-042-roadmap-product-rulings-evidence-aggregate-in-flight-axis-and-enforcer-attribution.md) 決策 1：評分與排行榜改為**永久不做**（不是延後），替代品是帶分母的試跑證據彙總。
2. **長時間工作與串流的時間軸語彙。** `RUN_STATUS_LABEL` 已有五個非終態，而 §4.4 的四種視覺全是終態判定。目前 app 裡十二處載入狀態都是 `<p>載入中…</p>`，那是慣例不是規則。 → [ADR-042](ADR-042-roadmap-product-rulings-evidence-aggregate-in-flight-axis-and-enforcer-attribution.md) 決策 2：進行中是第三軸，規則進 `system.md` §2.12。
3. **清單長到數百列時卡片怎麼辦。** §4.3 對卡片的整個論證是「每一則要能被單獨判斷」，那在 50 列以上會塌掉。目前已有四種並存的分頁策略。 → [ADR-042](ADR-042-roadmap-product-rulings-evidence-aggregate-in-flight-axis-and-enforcer-attribution.md) 決策 3：判準不是列數而是「這一頁在問什麼」；截斷一律要說出總數與理由；策略收斂為三種。
4. **當強制的一方不是平台時（Local Runner、遠端 MCP），§2.2 要怎麼寫。** 平台對使用者自己的機器強制不了任何東西，但那些限制是真的存在。初步方向：畫面必須說出**誰在強制**，而不是隱藏那個限制。 → [ADR-042](ADR-042-roadmap-product-rulings-evidence-aggregate-in-flight-axis-and-enforcer-attribution.md) 決策 4：§2.2 由雙向擴為三向，強制者具名，平台強制不了的事不得用完成式。
5. ~~**`01` §5 原則 7 的「一般模式／進階模式」措辭**與 §1.3 的漸進式揭露裁定衝突，要依三文件同步規則修 `01`。~~ **已撤回（2026-08-22，同日）：這一條是錯的，而且錯的是設計文件不是 `01`。** 查證後「一般模式／進階模式」是整套 MVP 文件一致使用的承重術語，而且**已經出貨**——`02` §DISC-003 與 §TRACE-001 各自定義兩種模式的內容，`03` `TRACE-006`／`TRACE-007` 都已勾選且 `?mode=advanced` 是 API 參數，`m0` 威脅模型把進階模式當成一個安全情境，`m2` 對帳驗過，而 `RunTrace.tsx` 有一個真的切換器。`system.md` §1.3 已改寫成三種機制（模式切換／另一個位址／`<details>`）與它們的選用判準，判準是**被藏起來的東西是什麼**，不是它有多技術；三者共同受 §2.10 約束。**`01` 不需要修。** 留下來的真缺口是：`RunTrace` 的模式在 component state 而不在 URL，所以進階視圖無法被連結（`system.md` §7.1 第 1 項）。
6. **持久化的「總是展開技術細節」偏好算不算模式。** 初步裁定：**單向、只展開不收起、不改變任何文字與版面**的偏好不算模式，可做；一旦它會**收起**任何東西（「精簡模式」），它就是模式，禁止。這一條是推論不是引用，等到真的要做時再確認。 → [ADR-042](ADR-042-roadmap-product-rulings-evidence-aggregate-in-flight-axis-and-enforcer-attribution.md) 決策 5：確認，並收緊為「偏好只能改變預設開合，不能改變有沒有這個東西」。
7. **位元組相同的複本，能不能繼承祖先的量測。** §2.9 的六詞在 2026-08-22 第一次遇到一個它分不了的情況：Fork 出來的 Skill 內容雜湊與來源完全相同，來源掃描過，複本沒有。目前一律是 `未測量`，並在契約與畫面上明說「那是來源的量測結果，不是這裡的」。三個選項——維持 `未測量`／以「來源已掃描」另立一詞／Fork 時把量測複製過去——各有代價，而**決定它需要的是產品判斷，不是 UI 判斷**。已經確定的只有一件：不得靜默繼承。 → [ADR-042](ADR-042-roadmap-product-rulings-evidence-aggregate-in-flight-axis-and-enforcer-attribution.md) 決策 6：**可以繼承，但只限於對位元組成立的量測**（靜態掃描、規格驗證、License），且需具名歸屬、當下比對雜湊、只從公開目錄祖先繼承、祖先 takedown 後失效。
