# ADR-057：把別人的內容標成可散布，要具名的證據，不是一個按鈕

- 狀態：Accepted
- 日期：2026-08-27
- 關聯：[ADR-021](./ADR-021-skill-license-provenance.md)（來源層級）、[ADR-045](./ADR-045-self-supplied-content-is-not-redistribution.md)（自送內容不是再散布）、[ADR-027](./ADR-027-download-artifact-shape-reproducibility-and-integrity.md)（待決策「`redistribution` 的寫入端」）、[ADR-012](./ADR-012-packaging-portability-and-agent-adapters.md)、`02:SEC-007`／`SEC-011`、[`05` R-3a／R-3b](../plans/05-pending-rulings.md)、[`04` 乙-17](../plans/04-backlog-and-handoffs.md)

## 背景

`skills.redistribution` 決定平台會不會把一份 Skill 的位元組交給人。它在 2026-08-23 之前是**全庫唯一一個沒有稽核就能改的閘門欄位**——旁邊管同一個下載的 `access_restriction` 有端點、有 operator 檢查、有 audit event，它只能直接跑 SQL。那個不對等由 [`05` R-3c](../plans/05-pending-rulings.md) 補上（`PUT /admin/skills/{id}/redistribution`），而 R-3c **刻意沒有回答**它旁邊的兩個問題：**誰能改**（R-3a）、**改成 `allowed` 要什麼證據**（R-3b）。那條路由因此帶著一個暫時的形狀跑了四天：operator-only 是因為那是兩個選項裡較窄的一個，理由不是它對，而是**之後放寬是加呼叫者，先放寬再收回是拿走東西**。

最痛的那一半在此之前已由 ADR-045 移走：使用者下載得了自己上傳的 Skill（匯入直接寫 `self_supplied`），所以本 ADR 面對的只剩**別人的內容**。

## 決策

### 1. 只有 operator 能改（R-3a 取 (a)）

理由不是保守，是 [ADR-021 §5.3](./ADR-021-skill-license-provenance.md) 記下的那個發現：**兩個 repo 的根目錄 `LICENSE` 是合法的 MIT 檔，而它涵蓋的內容並非該作者所有**（實為 `anthropics/skills` 的 source-available 衍生物）。「repo 根有 MIT ⇒ 子目錄是 MIT」是錯的，**而且錯在放行方向**。

**這個判斷連做過授權查核的人都會做錯，交給按下按鈕的人不會更準。**

**要付的代價寫在這裡，不藏在「較安全」三個字後面**：使用者匯入第三方內容而授權判定不足時，他看到的是「你的 Skill 不能下載」，而**沒有任何自助路徑**——以 `unknown` ＝ 擋為預設，這會是常態。這正是 `N-2` 預期的第一個需求訊號；它出現時重開的是本節，不是整份 ADR。

### 2. 改成 `allowed` 必須具名它依據的證據（R-3b）

沿用 ADR-021 已定義的**來源層級**，不新增概念：要把一個 Skill 標成 `allowed`，請求必須同時帶 **`license_expression`** 與 **`license_source`**，而且**兩者都要與該 Skill 最新版本凍結的快照相符**；不符就拒絕，並在拒絕訊息裡說出快照記的是什麼。

三種拒絕是三句不同的話，這是刻意的：

| 情況 | 說法 | 為什麼要分開 |
| --- | --- | --- |
| 沒填 | 少了兩個欄位 | 這是漏填 |
| **快照什麼都沒記** | 這個 Skill 的最新版本沒有任何授權紀錄，重新匯入才有 | **這一個不能靠再猜一次繞過** |
| 填了但不符 | 快照記的是 X from Y | 這是在描述另一個套件 |

把三者壓成「授權證據無效」一句，會讓中間那一個讀起來像表單錯誤，**而它是唯一一個不該被繞過的**。

**這道檢查買到的不是「證明」，是「可以被反駁」。** 一個確認框沒有任何人能說它填錯了；一組具名的運算式與層級可以被平台當場否定——而說不出匯入器讀到什麼的人，看的就不是下載會交出去的那份位元組。

比對**去空白且不分大小寫**：SPDX 識別字本身就是不分大小寫定義的，為了 `mit` 與 `MIT` 拒絕一次釋出，只會教出「複製貼上」而不是「讀過」，那和這條規則的目的相反。

### 3. 只有 `allowed` 要證據；`blocked` 與 `unknown` 不要

**要求為了「擋」而先做一次授權判定，等於對「拒絕做判定」這件事收費**，而 ADR-021 §5.3 說誤判必須錯在擋的方向。這兩個方向不收費。

### 4. 稽核記的是快照的值，不是操作者打的字

audit event 的 `license_expression`／`license_source` 取自版本列，不取自請求。兩者到達這裡時只差大小寫與空白，**而差的正好是查詢要對的那一格**：`「所有以 repo-license-file 為據放行的 Skill」` 是一句 SQL，它比不到寫著 `MANIFEST` 的那一列。

這一條是**測試先發現的**：第一次跑就以 `MANIFEST` 進了 audit（測試用 `mit`／`MANIFEST` 送出，斷言 trail 裡是 `manifest`）。這也正是層級要與運算式分開具名的理由——ADR-021 決策 1 的「永不壓成單一字串」在稽核這一端同樣成立。

`blocked`／`unknown` 的事件**不帶**這兩個鍵，而不是帶空字串：空的授權擺在一次封鎖旁邊，會被日後查表的人讀成「在沒有證據的情況下放行」。

## 不做什麼

- **不改成逐版本的判定。** 欄位在 Skill 上，判定就在 Skill 上。改成逐版本要動 migration 與整條下載路徑，而目前沒有任何訊號說需要它。
- **不啟用 ADR-021 的第 4 層 `curated-declared`。** 它是唯一一個證據**不隨套件走**的層級，拿到位元組的人無法重驗一次以它為據的放行——那與本 ADR 第 2 點的整個理由相反。
- **不做自助路徑**（見決策 1 的代價段）。

## 已知邊界

- **判定黏在 Skill 上，新版本不會使它失效。** 一份標成 `allowed` 的 Skill 匯入新版本之後，那個判定仍然有效，而新版本的授權可能不同。今天沒有機制會重新問一次。**證據檢查與寫入同交易**，擋掉的是「檢查期間有新版本落地」，**不是**「日後有新版本落地」。重開訊號：同一個 Skill 出現第二個來源層級，或封測出現第一次版本間授權變更。
- **`repo-license-file` 仍然可以作為放行依據**，而它正是 §5.3 誤判的形狀。本 ADR 沒有把它降為不足，因為那會擋掉今天合法的策展路徑；取而代之的是決策 4 那句 SQL——**先讓它查得出來，再決定要不要禁**。
