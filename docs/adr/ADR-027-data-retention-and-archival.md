# ADR-027：資料保存、到期與封存

- 狀態：Accepted
- 相關：[ADR-002｜資料所有權與核心基礎設施](./ADR-002-data-ownership-and-core-infrastructure.md)、[ADR-005｜模型閘道與可觀測性](./ADR-005-model-gateway-and-observability.md)、[ADR-009｜評估判定與 Judge 信任邊界](./ADR-009-evaluation-verdicts-and-judge-trust.md)、[ADR-010｜產品分析與稽核邊界](./ADR-010-product-analytics-and-audit-boundaries.md)、[ADR-017｜Query 與寫入所有權](./ADR-017-query-and-write-ownership.md)、[ADR-023｜帳號清除](./ADR-023-account-purge.md)、[ADR-025｜Credit 計量與扣款](./ADR-025-credit-metering-and-charging.md)、[ADR-028｜平台 Agent](./ADR-028-platform-agents.md)

## 背景

[ADR-002](./ADR-002-data-ownership-and-core-infrastructure.md) 要求每一類資料的保存與到期規則落成設定，不停在原則層級。目前有期限的資料都只有一種處置：到期刪除——Trace 與分析事件按月 `DROP` 分割，稽核事件、回報、Session、下載產物與 Run 產出各有排程清除。沒有任何資料會先搬到物件儲存再從資料庫刪除。

另一端是對使用者揭露為「永久」的資料：Run 紀錄、狀態轉換與評估結果。它們沒有期限、沒有清理，每一次試跑都會讓它們長大。在合成資料上以最難壓縮的文字量測，一次 Run 連同評估、產出清單與計費紀錄約佔 14 KB；每天一萬次 Run 約每年 50 GB。單一 PostgreSQL 的資料量直接決定從備份還原要多久，而容量與高可用的要求是故障後 15 分鐘內恢復——資料庫會先撞到還原時間，才撞到磁碟。

封存若處理不當，會在兩個方向上違反已經做出的承諾：把資料留得比揭露的期限更久，或讓仍需要原始資料的功能（評估重評讀 Trace）提早失去它。

## 決策

### 決策 1：每張表宣告一種處置，新表在同一個 commit 宣告

每張表屬於且只屬於下列一種處置：

| 處置 | 意思 | 例 |
| --- | --- | --- |
| 到期刪除 | 期限由部署設定給值，排程到期刪除 | Trace、分析事件、稽核事件、回報、Session |
| 隨擁有者刪除 | 沒有自己的期限，跟著上層資料或帳號清除一起刪 | 創作會話事件、Test Case |
| 永久保留 | 留在資料庫，不封存、不刪除 | Credit 帳戶、扣點分錄、成本事件 |
| 永久保留、可封存 | 永久保存，但冷資料可以搬到物件儲存 | Run 底下的快照與狀態轉換、評估一族 |
| 工作暫存 | 待處理工作、意圖與觀察紀錄，工作完成或狀況解除即刪 | 物件收集佇列、上傳意圖、孤兒觀察、限流計量桶 |

處置描述的是資料隨時間的命運；帳號清除與它正交——除了 Credit 紀錄，任何處置的資料都在帳號清除時刪除或去識別化。

處置宣告在 `db/query-owners.yaml` 的 `retention:`，與表的擁有者放在一起；`automation-check` 對帳每張有擁有者的表都有一個處置。新增資料表而沒有宣告處置就是紅的——保存義務不靠記得。

### 決策 2：封存不延長、也不縮短保存期

對使用者揭露的期限，是這筆資料在資料庫與封存兩處的總和。有期限的資料期滿時，封存物件與資料庫列一起刪；一筆資料不能因為被封存而比揭露的期限活得更久。反過來，一個仍需要讀原始資料的功能，不能因為資料被搬走而提早失去它。

### 決策 3：Trace 不封存，只到期刪除

Trace 的保存期限就是評估的可重評窗：重評讀的是原始事件，到期後評估改顯示當時保存的摘要（[ADR-009](./ADR-009-evaluation-verdicts-and-judge-trust.md)）。在這個前提下封存 Trace 只有兩條路，都不成立：延長總期限要重新揭露並取得同意；縮短資料庫內的期限會讓重評提早失去證據。因此 Trace 只有到期刪除。落在 default 分割、早於最舊保留月份的列同樣在輪替時刪除，期限對每一列都成立，不只對有名字的月份成立。

### 決策 4：封存的觸發是還原時間，不是日曆

封存不按固定週期啟動。維運報表以實測的還原速率換算資料庫大小，預測何時超過還原預算——**資料庫可在 10 分鐘內從備份還原**，留 5 分鐘給其餘恢復步驟。預測在 90 天內越線時告警，並啟動「永久保留、可封存」那一類的封存；沒有越線就不搬。理由是封存有成本：多一個儲存位置、多一條還原路徑、多一份帳號清除要涵蓋的範圍，只在它換到的還原時間有需要時才值得。

### 決策 5：先證明封存成功，才刪資料庫列

封存一個批次依序是：依月份與 Workspace 匯出成壓縮的 JSON Lines 物件；從物件儲存讀回、比對筆數與內容雜湊；在同一個交易裡寫入封存清單（表、期間、Workspace、物件鍵、筆數、雜湊、綱要版本）並刪除資料庫列。任何一步失敗，資料庫列原樣保留，下次重試並告警。封存物件依 Workspace 分開存放，帳號清除依 Workspace 刪除它們，受同一把清除 fence 管轄（[ADR-023](./ADR-023-account-purge.md)）。

### 決策 6：被封存的 Run 照常出現，識別永久有效

Run 列本身留在資料庫，不封存：它是永久識別（`run_id` 不得失效）、清單的排序鍵，也是成本與扣點紀錄指回的對象。被封存的是它底下的大列——快照、狀態轉換、評估結果與建議、Test Case 快照。Run 清單照常列出被封存的 Run；詳情標明「已封存」並只顯示留在資料庫的摘要，不假裝細節還在，也不顯示成空白。

### 決策 7：還原只給營運者、按需執行

產品的讀取路徑永遠不碰封存物件。要看封存內容時，營運者以 `maintenance` 子命令把一個封存批次還原到隔離的暫存表，供調查使用、用完即刪；還原與刪除都寫稽核。

### 決策 8：期限的現行值寫在設定與揭露端點，不寫在這裡

各類資料的期限天數由部署設定給值，對使用者揭露的頁面讀取資料保存政策端點，不寫死。本 ADR 只規定處置的種類與它們之間的約束；數字之間的下界（下載產物、Run 產出與分析事件的期限）由規格的保存期限約束條款管。

## 影響

### 正面

- 保存義務變成每張表都有、機器會對帳的宣告，不再有「在收、卻沒有期限也沒有清除」的資料類別。
- 資料庫大小有一條以還原時間定義的上限，容量與高可用的恢復目標不會被資料成長悄悄吃掉。
- 封存不會成為延長保存期的後門，也不會讓評估提早失去證據。

### 成本與限制

- 封存啟動之後多一條還原路徑與一份封存清單要維護；帳號清除的盤點範圍多了物件儲存裡的封存物件。
- 被封存的 Run 詳情只剩摘要，事後要看細節需要營運者還原，不是使用者自助。
- 還原速率要在真實節點上實測；在那之前，報表只能用保守的估計值換算，告警可能偏早。

## 待決策

- 回饋文字的保存期限仍待法務確認；確認前它維持「清除工作拒絕啟動」的現況。
- 上傳 Dataset 的期限仍是提案值，尚無對應的部署設定。
