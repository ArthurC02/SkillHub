# ADR-043：引用的成立條件是引文本身可回驗，來源標籤只是提示

- 狀態：Accepted
- 日期：2026-08-22
- 關聯：[ADR-026](ADR-026-evaluation-reassessment-evidence-lifetime-and-judge-trust-boundary.md)（本 ADR 修訂它的 defence 3 判準，其餘四條防線不變）、[ADR-025](ADR-025-run-terminal-state-and-evaluation-verdict-separation.md)、[ADR-041](ADR-041-trust-signal-vocabulary-typed-absence-and-rule-precedence.md) §2.11(c)
- 承接：`04` 乙-13（G7 與 G8，同一次拍板）

## 背景

M3 的 Judge 回歸實測（[m3/report-judge-regression.md](../plans/mvp/m3/report-judge-regression.md)）在**同一輪**量到兩個方向相反的失誤，而它們是同一個判準的兩端：

- **G7：該擋的沒擋。** `verify()` 對 `kind = artifact` 只檢查「路徑在 manifest 上」，**引文完全不比對**——因為請求裡本來就沒送 artifact 位元組（控制平面不解封存，evaluation-design §2.2 的硬線）。於是 `evidence_required: true` 的條目**可以用一段沒人驗過的引文通過**，而報告裡存的 `excerpt` 是平台自己的 manifest 行（檔名＋大小），不是那段引文。9 筆 `passed` 裡有 **6 筆只靠這種引用**。
- **G8：不該擋的擋了。** `agent_output` 型引用的引文本體逐字正確，但尾端多了 `}],`（模型把 JSON 分隔符寫進了字串值），`strings.Index` 比不到，**兩條正確的 `failed` 被降成 `undetermined`**。

逐筆追查的結論改變了這一題的形狀：**模型沒有捏造**。抽查的引文逐字存在於該 Run 的 `trace_events` payload 裡——模型看了 trace，卻把來源標成 `artifact`。所以真正的缺陷不是「模型不誠實」，是**平台分不出「歸錯類」與「編造」，而 `verify()` 對兩者一律放行**。

`04` 乙-13 把處置寫成二選一：(a) `artifact` 型引用不得滿足 `evidence_required`；(b) 保留但標示「此引文未經回驗」。**兩個都不夠好**，理由見下方「評估選項」——(a) 會把那 6 筆**證據其實是真的**的判定一起打掉，(b) 則把辨別的工作丟給讀者。

## 決策

### 1. 判準改成一句話，同時管住兩端

> **一個引用成立，若且唯若它的引文能在可回驗的來源裡（正規化後）逐字找到。`kind` 是模型給的提示，不是憑證。**

可回驗的來源目前有兩個，都已經在 `verify()` 的手上：Run 的 trace 摘要（`digest`）與 agent 的最終輸出（`m.summary.FinalOutput`）。artifact 位元組不在裡面，而且**刻意不會在裡面**——把它們讀進控制平面就是 evaluation-design §2.2 劃掉的那條線。

**這一條同時修好 G7 與 G8，而那正是它非得是一條不可的原因**：`04` 乙-13 自己寫著「分開改會把判準改成兩把尺」。

### 2. 歸錯類的引用要**改正**，不是打回

`verify()` 先照 `kind` 解析（快路徑，而且那條路徑才拿得到精確定位：trace event id、字元範圍）。當指名的來源交不出引文時：

1. 在可回驗的來源裡搜這段引文。
2. **找得到** ⇒ 這是歸錯類。以**實際找到的來源**成立這個引用，並在 `EvidenceRef` 上記下 `reattributed_from`，報告與 UI 要看得到。
3. **找不到** ⇒ 這段引文平台無法回驗，**不得滿足 `evidence_required`**。

第 2 步就是「平台分得出歸錯類與編造」的具體內容：**去可回驗的地方找一次**——找到就是標籤錯，找不到就是沒有東西支撐它。這件事此前沒做，不是因為做不到，是因為沒人問過那個問題。

**實測後果（估計，需 B 輪覆核）**：A 輪那 6 筆的引文既然逐字存在於 `trace_events`，它們會被改正並維持 `passed`，同時在報告上帶著改正紀錄。**選項 (a) 會把這 6 筆全部打掉，而它們的證據是真的。**

### 3. `artifact` 型引用保留，但它證明的是「存在」不是「內容」

路徑在 manifest 上是**模型編不出來的**，這一點沒有變，所以 artifact 引用仍然是合法的引用——只是它能支撐的主張只有「這個檔案存在、大小是多少」。因此：

- **單靠 artifact 引用不能滿足 `evidence_required`。**
- 它在報告與 UI 上必須說出自己的上限（[ADR-041](ADR-041-trust-signal-vocabulary-typed-absence-and-rule-precedence.md) §2.11(c)）：**「僅證明檔案存在，未回驗引文」**。目前存進 `excerpt` 的是平台的 manifest 行卻沒有任何字說明它不是引文——那正是 §2.11(c) 要擋的形狀。

### 4. 正規化是有界的，而且界線本身是判準的一部分

逐字比對前，兩邊都做且只做這些：

1. Unicode **NFC**；
2. 連續空白（含全形空格、換行、tab）折成一個半形空格；
3. 去除**首尾**的空白與結構性標點：`} ] ) , ; " ' 「 」 『 』` 與反引號。

**只去首尾，不去中間**——中間的標點是內容。並且：

> **正規化後長度不足 12 個字元的引文，不接受正規化比對**（只接受原樣逐字命中）。

理由是正規化天生放寬匹配，而短字串在放寬之後太容易命中；長度門檻是最便宜的補償。它是**推導不是量測**，B 輪要回頭校準，而校準方向只能往上。

比對結果要分三態存下來：`exact`／`normalized`／`not_found`。**`normalized` 是一個可稽核的事實**，不是靜默的成功——G8 那兩筆如果當時有這個欄位，看報告的人一眼就知道發生了什麼。

### 5. 這動的是 ADR-026 的 defence 3，其餘四條不變

ADR-026 的四條防線裡只有 defence 3（引用回驗）的**判準**改變，防線本身仍在，而且變嚴了：此前 `artifact` 是一條繞過整條防線的路。ADR-026 不標 `Superseded`，由本 ADR 回填引用。

## 評估選項

| | (a) `artifact` 不得滿足 `evidence_required` | (b) 保留並標示「未經回驗」 | (c) **內容回驗＋改正**（採用） |
| --- | --- | --- | --- |
| G7（該擋的沒擋） | 擋住 | **沒擋**——只是加了一句話 | 擋住 |
| G8（不該擋的擋了） | **沒處理**（不同一把尺） | 沒處理 | 同一條規則一起處理 |
| A 輪那 6 筆真證據 | **全部打掉** | 全部保留但變成「未回驗」 | **改正後保留，並留下改正紀錄** |
| 分得出「歸錯類」與「編造」嗎 | 分不出，一律當成後者 | 分不出，一律當成前者 | **分得出**——去可回驗的來源找一次 |
| 讀者要做的事 | 無 | **要自己判斷一段未回驗的引文可不可信** | 無 |
| 實作成本 | 最低（一個 if） | 最低 | 中：一次字串搜尋＋正規化＋三態欄位 |

**選 (c) 的關鍵理由**：(a) 與 (b) 都建立在「平台分不出來」這個前提上，一個選擇全部當假、一個選擇全部當真。**那個前提是可以被拿掉的**——引文在不在可回驗的來源裡，是一次字串搜尋就能回答的問題。當一個二選一的兩個選項都在猜，該做的是去查。

**支持 (a) 最強的論證**：它最小、最保守，而保守在安全題上通常對。回應是：這一題的失效模式不是「放行了壞的」，而是「平台不知道自己在放行什麼」；(c) 的擋止範圍嚴格大於 (a)（(a) 只擋 artifact，(c) 擋所有回驗不到的引文，包含 `trace_event` 與 `agent_output` 上編造的），保守的其實是 (c)。

## 影響

- **`verify()` 的回傳要多帶兩個事實**：`match`（`exact`／`normalized`）與 `reattributed_from`。兩者都要進報告的 `EvidenceRef`，也都要上 UI——不上 UI 的稽核欄位等於沒有。
- **報告的 `excerpt` 語意變乾淨**：它從此一律是**被回驗過的那段字**；artifact 引用不再把 manifest 行放進 `excerpt` 冒充引文，改為以獨立欄位呈現並附上「僅證明檔案存在」。
- **B 輪回歸（`04` 丙-8）現在有第二個目的**：除了原本要測的「證據完整時逐項引文的實判定」，還要覆核本 ADR 的兩個估計——那 6 筆會不會真的被改正保留，以及 12 字元門檻會不會誤放。**B 輪要發 5 次真實 Run，是會花錢的一批。**
- **這不擋 CONTENT-007**：它對任何帶 `evidence_required` 的 rubric 一視同仁，與 rubric 內容無關。

## 待決策

1. **12 個字元的門檻是推導不是量測。** B 輪要回頭校準，而方向只能往上。
2. **可回驗來源的第三個候選：Test Case 的輸入快照。** 目前不在 `verify()` 的手上，而有些條目的證據天生在輸入側（「它有沒有照著我給的欄位名」）。加進去之前要先確認它不會讓「引用輸入」變成一種繞過。
3. **改正紀錄要不要回饋給 Judge 的提示。** 一個模型如果反覆把 trace 標成 artifact，那是提示的缺陷不是判定的缺陷；但把統計餵回提示會讓判定與提示互相糾纏，先量再說。
