## 背景

負責人指出畫面文字量仍然很多，使用者容易失焦。**先量再裁**：九個子代理逐檔讀完 `apps/web/src` 的 17 個頁面與 20 個元件，把每一段可見文字抄下來、數字數（Unicode code point，與 `FeedbackEntry.tsx` 的 `runes()` 同一種算法）、逐段問「它在替讀者做什麼」；另外四個子代理實際打開 9 套公開設計系統規範、8 個套件市集、8 個開發者工具與 8 個 LLM 觀測產品的真實頁面。研究紀錄在該日的子代理報告；下面只留會改變決策的數字。

### 第一個發現：重的不是教學，是「同一句話印了 N 次」

| 畫面 | 可見字數 | 教學（D）佔比 | 真正的重量在哪 |
| --- | --- | --- | --- |
| `/`（目錄態，45 列） | 12,118 | **0.3%** | 但書（C）佔 **53%**：`tier.note`／`category.note`／`risk.note`／`compatibility.note` 四句**逐位元相同**地跟著每一列印 45 次，合計約 **6,000 字**；其中 `risk.note` 一句就是 1,665 字 |
| `/runs/$id`（評估區塊，8 筆證據） | 1,219 | 5% | 引文回驗的解釋句 `MATCH_NOTE` 每筆證據印一次：**232 字，佔全頁 19%** |
| `/lab/run` | 886 | 33% | 伺服器固定送六則 `notes[]`，其中四則（193 字，22%）是**平鋪文字的複述**；權限清單本身只佔 17% |
| `/skills/$id/package` | 2,163 | **42%**（全 app 最高） | 有 **381 字是詳情頁三個證據區塊的逐字複本**，使用者三十秒前才讀過 |
| `/lab/test-cases/$id` | 940 | 44% | 「Run 會把當下內容凍結成快照」這條規則在兩頁講了**四次，260 字** |
| 四個畫面（`WorkspaceSkills`／`Account`／`Policy`／footer） | — | — | 「東西要去哪裡刪」的地圖**四份、措辭各異、457 字** |
| `/workspace/import`、`/lab/datasets` | 288／306 | **10%／5%** | 字多但幾乎全是平台真的會擋人的上限（§2.2）——**不是瘦身目標** |

三件事從這張表直接推出來：

1. **`.note` 不是可行動的指標。** `system.md` §4.5 用「8 條路由有 65～83% 的字元屬於 `.note`」描述問題，但 `.note` 同時承載但書（順位 1）與教學（順位 5）——`SkillDetail` 上但書 316 字**比**教學 194 字還多。「把 `.note` 減下來」若被當成指令執行，第一個被砍的會是順位最高的那類文字。預算要綁在**文字的類別**上，不能綁在 class 上。
2. **最大的槓桿不需要任何新機制。** 逐列複述、跨頁複本與同頁同義句加起來，首頁一頁可少約 4,600 字（38%）、評估頁 232 字、試跑前頁 193 字、打包頁 381 字——**一個字都不用刪、不用折、不碰 §2.10 任何一項**，用的是 §3 第 14 條已經存在的規則，只是它今天只管「同一頁」、機器只看 `.note`。
3. **但書不能移進互動後才出現的容器，而且不需要。** 這是 §2.4 第 3 項已經裁過的事（`LabelledBadge` 把「收錄不等於精選。」放進 `title`，觸控裝置上不存在），也是市集研究的反面教材（npm 的綠勾、VS Code 的藍勾都把「這不保證沒有惡意程式碼」藏在另一份文件裡，VS Code 因此被使用者公開判定為誤導）。而量出來的結果是：把所有但書合併成「同一區塊一句、仍然平鋪」在詳情頁只省 6%——**力氣不該花在這裡**。

### 第二個發現：外部規範對「能藏什麼」高度一致

九套規範（WCAG 2.2 1.4.13／2.5.8／1.1.1、ARIA APG、Atlassian、Polaris、Carbon、GOV.UK、Material 3、Apple HIG、NN/g、Fluent 2）與 GitHub Primer、Vercel Geist 的結論可以壓成四句：

- **浮層只放補充；完成任務要用的東西必須有一份不互動就看得到的版本。** Polaris：「Never hide essential information, errors, or required instructions in tooltips」；Carbon：「do not include pertinent information for the user to complete their task」；Primer 更直接——tooltip 是「最後手段」，替代順序第一條是**乾脆平鋪**。**這正是 §2.4 與 §2.10 的外部背書。**
- **hover 不是一個管道。** Apple HIG：iPhone／iPad 沒有 tooltip 這個東西；WCAG 1.4.13 把原生 `title` 明文排除在作者可控範圍之外；NN/g：「Don't rely on hover to reveal text labels」。想放連結或要在觸控上存在，得是**點擊觸發**的 toggletip（Carbon）／info label（Fluent）／rich tooltip（M3）。
- **icon 不得單獨承載語義。** NN/g：「A text label must be present alongside an icon」；WCAG 1.1.1：icon-only 控制項要有描述用途的名字；2.5.8：命中區 ≥24×24。反面案例是 Sentry 用彩色方塊表嚴重度、hover 才知道是 warning 還是 fatal——觸控與色盲直接失去這個資訊。
- **「看過一次就不再顯示」沒有任何主流設計系統為說明性內容背書**；只有 onboarding 的 teaching popover／coachmark 是一次性的，而且必須 optional、**可以再叫回來**（Linear 的 `?`、Carbon 的「alternative routes」）。

Claude Code 的權限對話另外給了一條可以直接借的硬規則：**「看不完就不給永久允許」**——當對話框無法把它將要放行的東西全部攤出來時，它抽掉「以後別再問」的選項。這與 §2.2「會擋住人的東西必須在他撞上之前顯示」是同一個形狀。

## 評估選項

| | A. 總字數上限 | B. 把 `.note` 收進 tooltip／折疊 | C. **依文字類別分流：判斷不動、複述去重、說明移形（採用）** | D. 維持 §4.5 的裁定（只縮行長、不動字） |
| --- | --- | --- | --- | --- |
| 減得掉多少 | 看上限訂多嚴 | `.note` 的全部 | 首頁 38%、評估頁 19%、試跑前頁 22%、打包頁 18%（**去重那一半**）＋教學與推導移形（另一半） | 0（§4.5 自陳「一個字都沒有刪」） |
| 動到 §2.10 嗎 | **必然**：任何以字數為單位的上限，都會在某一頁要求刪掉封閉清單上的東西 | **必然**：`.note` 裡一半是 §2.11(c) 的但書 | **不動**：A／B／C 三類不入預算，只能因為合併同義句而變少 | 不動 |
| 需要新機制嗎 | 否 | 要 tooltip | 去重不要；移形要**一種**（Tip） | 否 |
| 已記錄的失效 | 「兩條規則都對，畫面壞了」（§0 的首頁例子） | §2.4 第 3 項、npm／VS Code 的徽章 | 無現成反例；**Tip 若做成 hover 會重蹈 §2.4 第 3 項** | 頁變高（`run-trace` 2913→3070px），§1.2 更依賴「操作在一處」 |

**選 C 的關鍵理由**：它是唯一一個把「負責人要的減量」與「§0 的順位表」同時滿足的做法，而且它的第一半（去重）**今天就有四個具名實例、不需要任何新元件**。A 與 B 的問題不是做不到，是做到之後 §2.10 會少東西——那是順位 1 對順位 4 的讓步，§0 禁止。

## 決策

規則與判準寫進 [`system.md` §2.13](../design/system.md)（新原則，第十三條）、§1.3（機制表加一列）、§4.7（語彙）；本節只記決策本身。

### 1. 文字先分類，預算只下在能動的類別上

畫面上每一段可見文字屬於且僅屬於一類：

| 類 | 是什麼 | 入不入預算 |
| --- | --- | --- |
| **A 判斷依據** | §2.10 十項；權限、額度、期限與判定 | **不入**。只能因為合併同義句而變少 |
| **B 原因** | 停用、缺席、被擋的原因（§2.4、§2.9）；`aria-describedby` 的目標 | **不入** |
| **C 但書** | 「這個徽章不涵蓋什麼」（§2.11(c)）、限制的強制者（§2.2 第三向） | **不入** |
| **H 限制** | 上限、白名單、保存天數——平台真的會擋的值 | **不入**（值與型別詞不動；推導可移形） |
| **G 進行中** | §2.12 的三件事、會變的量、多久沒動了 | **不入**（會變的量永遠平鋪；不會變的理由可移形） |
| **D 說明** | 讀過一次就懂的教學。判準：**同一個人第二次來看，這段文字不改變他這次要按什麼** | **入預算** |
| **F 識別符與推導** | 雜湊、UUID、digest、映像名、「為什麼是這個順序」 | **入預算**（§2.6 本來就要折） |
| E 操作回饋 | 按鈕字、status 一句話 | 不計 |

**預算**：一條路由在預設狀態下（已登入、讀取成功、清單一列、未展開任何確認、旗標關），**平鋪的 D＋F 不得超過同頁 A＋B＋C 的字數，且單一 D 區塊不超過 100 字**。門檻的值是本次量測給的（四頁實測 D≈A 的只有 `/lab/run`，剛好卡線），**先量再定值，不先定值**；`system.md` §6 誠實記它今天沒有機器。

### 2. 同一件事講一次——三條去重規則，兩條是 §3 第 14 條的延伸

- **逐列複述**：一段文字在同一份清單內**逐位元相同地渲染超過一次**，它就不是那一列的事實，是那份清單的事實；提到清單層級講一次。§2.10 的十項仍逐列可見，搬走的只是**與列無關**的那一句。為什麼與 §2.10 相容：§2.10 保護的是**能區分這一列與那一列的事實**；一句在 45 列上完全相同的話，讀者從第 2 列起就不可能因為它而作出不同判斷，後果不對稱性為零。樣板已在 repo：`Catalog` 的 `rankNoteInList={false}`、`RunVerdict.tsx` 的 `NOTE_SHOWN`（註解逐字：「On a page of fifty rows a sentence per row is noise」）、`CompatibilityStatus` 對區塊句已涵蓋的軸送空 `note`。**這一條可機器化**：每個清單容器下的 `.note` 文字做集合，任一字串出現次數 >1 即 FAIL。
- **同頁同義句**：`title=` 與可見 `.note` 同字算兩次（今天的機器只數 `.note` 節點，數不到 `title`）。**§2.4 補一句：原因搬出 `title` 之後，`title` 要拿掉**，否則每次修 §2.4 都留下一份重複。
- **跨頁複本**：§3 第 14 條今天只管同一頁。打包頁 381 字是詳情頁證據區塊的逐字複本，這一格**沒有人裁過**——記為 R-42 (c)，本 ADR 不代簽（它碰 §2.10 第 1、3 項在「決定散布」那一頁要不要再出現一次，順位 1）。

### 3. 第四種揭露機制：Tip（點擊觸發的 toggletip），六條入場條件缺一不可

§1.3 的三種機制（模式切換／另一個位址／`<details>`）加第四種。**它藏的是「為什麼」，不是「是什麼」**：`<details>` 藏的是屬於本頁某個事實的細節（版本 id、雜湊），Tip 藏的是**一個已經說完的句子的理由**。操作化：**把一頁上所有 Tip 刪掉之後，每一個判斷仍然做得出來**——做不出來的就不是 Tip 的內容，是 §2.10 的內容。

1. **只准裝 D 與 F。** A／B／C／G 的三件事一律不准進去；與 `<details>` 同一條約束（§1.3「三者共同的約束」自此是四者）。
2. **不得是 `title=`、不得是 hover-only。** 觸發是點擊／Enter／Space，內容在 DOM 裡、可鍵盤到達、`aria-expanded` 在觸發鈕上（ARIA APG Disclosure 的形狀，不是 Tooltip——APG 自己標 tooltip pattern 為「work in progress」且 tooltip 不得含可聚焦元素）；Esc 關閉；開合不改變其他內容的版面高度（會改就是 `<details>`，走那一列）。
3. **錨點必須自己成立。** 錨點是被限定的那個東西本身（徽章、數字、一句完整的話）或一個帶主詞／帶數量的短語——「為什麼可以關掉這一頁」合格、「淨測試模式：5 項在這個模式下不成立」合格；「詳情」「說明」「?」與**沒有文字的圖示不合格**。§0 已證過兩次：「一個停止描述底下清單的數量，比沒有數量更糟」。
4. **觸發鈕永遠帶可見文字**，命中區 ≥24×24（WCAG 2.5.8）、有描述用途的 accessible name（1.1.1）；aria-label 不能代替可見字（NN/g；本 app 的 axe 只抓「完全沒名字」，抓不到「有 aria-label 沒可見字」）。
5. **一頁至多三個 Tip。** 理由與 §4.6.3「一頁一個主要動作」同構：十個問號和沒有問號一樣沒有指向。
6. **需要很多 Tip 是設計訊號不是解法**（Polaris：「work on clarifying the design and the language」）：先去重、先改文案，Tip 是最後一步。

**會變的量永遠平鋪，不會變的理由才可以折。** 這一句同時解掉 §2.12 的分工（哪一步／已記錄幾件事／多久沒動＝平鋪；「憑什麼可以離開」＝Tip，但錨點要把強制者說完——「可以關掉這一頁（**平台**在跑，不是你的瀏覽器）」）、Run 產出的保存期限（`尚未定值` 平鋪、為什麼可折，§2.10 第 10 項本來就這樣寫）、試跑前頁的資源上限（值平鋪、換算可折——除非像 Token 輪數那樣被 `02` 的允收準則釘住）。

### 4. 標籤：一句話能變成一個帶字的名詞短語就變

負責人說的「標籤」在這套系統裡的合法對應是**帶字的徽章**（§4.4「badge 永遠帶文字」、§4.6.3「永遠描邊、不得填色」）與 `a.chip`（導覽）。判準：**一段文字的內容是一個狀態、一個分類或一個計數，就用標籤，不用句子**。本次盤點最值得標籤化的一格是評估頁的引文回驗結果——四種結果改成 `已逐字回驗`／`正規化後比對`／`找不到`／`未回驗引文`，解釋句進 Tip，省 232 字而 §2.11(c) 的第一訊號完整保留。首頁的分類 chip（「文件（20）」）是已經做對的樣板。

### 5. 圖示：回答 ADR-064 待決策 3——允許，但永遠是第三訊號

ADR-064 決策 7 寫「不做圖示集，等第一個『沒有它會誤讀』的實例」。本 ADR 把觸發條件換掉：**圖示不是為了避免誤讀，是為了讓人少讀**——它的工作是讓一列徽章在掃視時可被辨認，不是承載任何一個字承載不了的意思。所以：

- 圖示只出現在 §4.4 狀態語彙表的列上（不通過／未知或未檢查／降級／通過）與 Tip 的觸發鈕上，**一列一個**，全 app 至多六個形狀；inline SVG 寫在元件裡，`aria-hidden="true"`，**不加資產目錄、不加字型、不加套件**（ADR-064 待決策 3 的形狀照收）。
- **永遠伴隨可見文字**；拿掉圖示後畫面的每一個狀態仍然讀得懂（§2.3 的「詞在前面」不變；顏色第二、線型／圖示第三）。
- 圖示的顏色來自它所在徽章的 token（`--danger`／`--accent`／`--text`），**不新增語意色**——ADR-064 決策 6 保留給路線圖的四個頻道一個都不用。
- 「不做圖示**集**」仍然成立：六個以內、逐個有主張的形狀不是集。

### 6. 「看過一次就收起來」：對所有人**預設收合**，不記住誰看過

負責人的措辭是「看過一次之後就可以摺疊」。ADR-042 決策 5 寫「偏好只能改變預設開合，不能改變有沒有這個東西；**一旦它會收起任何東西，它就是模式，禁止**」，§0 的落地紀錄再說一次「只會展開的規則是預設值，會關上的規則才是精簡模式」。**本 ADR 維持 ADR-042 決策 5**，理由有三：規範研究裡沒有任何一家為說明性內容的一次性隱藏背書；記住「已讀」需要一份狀態（IA R4：偏好不進網址，那就是 localStorage——換瀏覽器就消失，於是同一個人會看到兩種畫面）；而**達到同一個目的不需要它**——一段 D 類文字對所有人預設就收在一個帶主詞的錨點後面（Tip 或 `<details>`），第一次來的人多按一下，第二次來的人不用按，兩者看到的畫面一樣。

「記住已讀並自動收起」的持久化變體**不採用**，但寫成 R-42 (a) 給負責人：那是他的原話，本 ADR 不替他把它讀窄。

### 7. 與 §4.5 同日裁定的關係，直說

§4.5 在同一天量出「整頁文字非常滿」並裁定「問題在文字的形狀，不在它的量……一個字都沒有刪、沒有折、沒有改寫」，修法是 40em 行長。**本 ADR 把那句話限縮到它量的東西上**：40em 修的是行長，它是對的、不撤；但它不是對「量」的裁定，只是那一批刻意不動字。本 ADR 對「量」的裁定是：**A／B／C／H／G 的量不動（§4.5 的立場延續），D／F 與複述的量要動**。兩份裁定管不同的軸，不並存為兩種說法。
