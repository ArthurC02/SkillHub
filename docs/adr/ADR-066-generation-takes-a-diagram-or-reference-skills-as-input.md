# ADR-066：生成的輸入多兩種——一張流程圖，或參考既有 Skill；輸出路徑不變

- 狀態：**Accepted**（2026-09-05，負責人指示「自建 Skill 必須有三種方式都徹底實現：只用白話描述、上傳流程圖、搜尋現有 Skill 再配合白話描述」）
- 日期：2026-09-05
- 決策者：產品負責人、架構規劃
- 相關：[ADR-046](./ADR-046-generating-a-skill-from-a-task-description.md)（生成物是工作區私有，不是目錄的第四層——本 ADR 縮限它的決策 3 與決策 5，見決策 5）、[ADR-047](./ADR-047-generation-path-rulings-retry-truncation-and-quota.md)（生成路徑的五個裁定——本 ADR 不動它們）、[ADR-045](./ADR-045-self-supplied-content-is-not-redistribution.md)（`redistribution` 判準的同一把尺）、[`02:GEN-005`／`GEN-006`](../plans/02-specifications-and-acceptance-criteria.md)、[`05` R-41](../plans/05-pending-rulings.md)（本 ADR 是它的裁定）

## 背景

[`05` R-41](../plans/05-pending-rulings.md) 問的是「參考既有 Skill 生成」要不要做，2026-09-03 的建議是 (a)：不做，理由是 [ADR-046](./ADR-046-generating-a-skill-from-a-task-description.md) 決策 3 逐字寫著「生成**不以任何既有 Skill 版本為輸入**」，而 `generated` 的定義（決策 5）是「沒有上游」——帶參考的生成物有上游，落在五個 `redistribution` 值之外；R-41 同時記著這條路要動四層：兩份契約、Go 的 scope／takedown／hold 檢查、Python 的 `untrusted.py` 威脅模型升級（別人寫的文字進 prompt）、以及 `GenerateSkill.tsx` 印的成本區間會失效。

ADR-046 決策 3 當初劃這條線，理由是**改善迴圈的防線整條不適用**：`suggest.go` 的 `suggestionEvidence` 要求提案的引文逐字出現在平台放進 digest 的 excerpt 裡（ADR-043），而從零沒有既有版本、沒有 Run、沒有 excerpt。那個理由問的是「能不能把生成當成改善」，答案仍然是不能——**但它沒有回答「生成能不能把既有 Skill 當成讀過的材料」**，那是一個不同的問題，本 ADR 把它分開回答。

負責人 2026-09-05 的指示是「自建產品是本系統關鍵功能」的延伸：三種輸入方式都要徹底實現，不是各挑一種意思意思。這是一次**凍結例外**（`01` §10 裁定 4 的新功能凍結仍在生效，本次是負責人本人放行的例外，登記於 `01` §10 第五批），把 R-41 從「建議 (a)，等封測訊號再議 (b)」改為 (b)：做參考生成，同一天再加一個第三輪（本 ADR 新談的）：流程圖輸入。

## 決策

### 1. 三種輸入模式，一條輸出路徑

`POST /skills/generate` 的請求體新增 `diagram`（流程圖）與 `reference_skill_ids`（既有 Skill 參考），與既有的 `task_description` 並列；至少要有 `task_description` 或 `diagram` 之一（422 否則），`reference_skill_ids` 可以在有描述或有圖時附帶，本身不構成請求的充分條件——**參考是材料不是題目**，模型仍然需要一個任務（文字或圖）才知道要做什麼。三種模式共用同一條輸出路徑：走 `apps/llm` 的 `POST /v1/generate-skill`（現在收三種可選欄位），Go 端走**與匯入完全相同的驗證路徑**（`skillpkg.Validate`），寫版本、`redistribution = generated`。**ADR-046 決策 6～7、ADR-047 決策 1～2 全部原樣適用**：語法門不是品質門、`possible-secret` 不重試、16000 token 上限、額度以一次生成計。

### 2. 參考是模型讀過的材料，不是套件裡的位元組——所以 `redistribution` 仍是 `generated`

ADR-045 決策 4 與 ADR-046 決策 4 的判準是同一個問題的同一個答案：**平台有沒有多加一個散布環節**。參考 Skill 的位元組**不進生成物的套件**——模型看到的是最新版本 SKILL.md 的文字（fenced 為不可信資料，≤`generateMaxReferenceChars`＝20000 runes，超過的部分明確標記截斷），生成物是模型依這份材料與任務描述**重新寫出來**的新內容，版本 1，沒有上游版本鏈。這與「以既有版本為起點的改寫」（`EVAL-002`／`suggest-improvements`）是两件不同的事：後者的輸出是同一個 Skill 的下一個版本、且引文必須逐字對上原文；生成的輸出永遠是新 Skill 的第一個版本，讀過參考不等於延續參考的版本鏈。

**為什麼這不與 ADR-045、ADR-047 決策 4 衝突**：ADR-045 決策 4 問的是「平台把使用者自己的位元組交還給他，算不算多加一個散布環節」；ADR-047 決策 4 問的是「生成物能不能當 Fork 的來源」——兩者都在管**位元組的流向**。本決策管的是**閱讀，不是位元組流向**：模型讀了三份別人的 SKILL.md，就像人類創作者讀了三份別人的 SKILL.md 再動筆一樣，讀過不會讓輸出物繼承來源的授權狀態。若讀者本身有能力逐字照抄，那是既有的 `possible-secret`／驗證路徑要擋的問題，不是 `redistribution` 語意要吸收的問題。

**推論**：ADR-046 決策 3「生成不以任何既有 Skill 版本為輸入」現在讀作「生成的**輸出**不以任何既有 Skill 版本為起點（不延續版本鏈）」——參考 Skill 進的是 prompt 的材料區，不是生成請求的起點版本。決策 3 原本否決的「放寬 `evaluate.py` 的 prompt 允許新增檔案」**維持否決**：改善迴圈與生成端點仍然是兩個端點、兩種語意，本 ADR 沒有把它們合併。

### 3. 哪些 Skill 可以被參考——讀不到、被下架、被限制存取、`redistribution=blocked` 一律拒絕

參考的 Skill 必須是呼叫者讀得到的（自己的工作區，或目錄——同 Fork 的既有 scope 規則），且不是下架（takedown）、不在 `access_restriction` 之下、`redistribution` 不是 `blocked`。三者任一命中即整批 422（單一錯誤形狀，同批列出哪一個 id 不合格與原因）。理由與 ADR-057「只有 `allowed` 要證據，為了『擋』而先做判定＝對拒絕做判定收費」同一條紀律的另一面：**一個平台已經判定不可信、不可散布、或已撤下的 Skill，沒有理由被當成「值得參考的既有實務」餵給模型**——那等於在生成物身上重複一次已經被否定的判斷。可讀性檢查與 Fork 用的是同一段既有 scope 邏輯，不新增第二套規則。

### 4. 流程圖是輸入不是物件——只留數位指紋，不留位元組

`diagram` 是請求體裡的一個欄位（`media_type` ∈ `image/png`／`image/jpeg`／`image/webp`，base64 `data`，解碼後 ≤ `generateMaxDiagramBytes`＝4,000,000 bytes），走 LiteLLM 閘道的多模態訊息交給模型，**平台不落地儲存這張圖片本身**——`skill_sources.generation_inputs` 只記 `sha256`／`media_type`／`bytes`，不記圖片內容。這不是效能考量，是刻意的範圍收斂：儲存使用者上傳的任意圖片會立刻繼承一整套物件儲存的保存期限、存取控制與刪除規則（同 `NFR-002` 對使用者主動提交內容的既有要求），而流程圖對生成結果沒有任何**事後**價值——它不像任務描述原文那樣是「生成物唯一的來源紀錄」的一部分（生成物的來源紀錄仍然是任務描述＋提示詞版本＋模型識別，圖片只是額外輸入），沒有它，來源紀錄依然完整、依然「重現得出工作區裡的那份套件」（ADR-047 決策 1 的字面只約束平台不得修改模型交出的位元組，不要求平台保存全部輸入）。**SVG 刻意不在允許清單裡**：SVG 是可以夾帶腳本與外部引用的標記語言，不是純位元圖——把它當「圖片」直接交給模型解析，等於在生成路徑上新開一個未經 `skillpkg.Validate` 審視的解析面，而流程圖輸入的價值只在於視覺結構，PNG／JPEG／WebP 三種點陣格式已經涵蓋。

### 5. 這對 ADR-046 決策 3 與決策 5 縮限了什麼，留下了什麼

**縮限的**：決策 3「生成不以任何既有 Skill 版本為輸入」現在只約束**輸出的版本鏈起點**，不再約束**模型的輸入材料**——見決策 2。決策 5「生成器不得寫 `license` 欄位」不受影響，但它的理由句「生成物沒有上游，所以 `SKILL-004` 的多層溯源在它身上沒有東西可以溯」現在要讀成「生成物**在授權意義上**沒有上游」——它讀過的參考材料不構成授權上游，模型寫出的任何授權字串依然一律丟棄（決策 5 原樣適用）。

**留下的**：決策 1（列 M5、MVP 範圍不動）、決策 2（不進目錄、不進搜尋索引）、決策 4（`generated` 與 `self_supplied` 兩個值不互相替代）、決策 6（`skillpkg.Validate` 是唯一的門，Script 不享寬待）、決策 7（首頁不放對等入口）**全部原樣成立**，本 ADR 一個字都不動它們。ADR-047 的五個裁定同樣全部原樣成立。

### 6. 曝光邊界不變

`01` §10 的三條 ⛔ 邊界（放行不含曝光、M5 不計入 MVP 完成度、閘門與封測不可並行）與 `03` §19 的「⛔ 放行沒有授權曝光」逐字適用於三種輸入模式：`diagram`／`reference_skill_ids` 與既有的 `task_description` 一樣，只掛在 `GENERATE_SKILL_EXPOSED` 之後、`GenerateSkill` 元件既有的兩個掛載點上——首頁不新增入口，不新增路由，不新增 `useGenerateEntryPoint` 呼叫端。**這是一次凍結例外，不是解除邊界**：凍結例外放行的是「可以動這段程式」，不是「可以讓封測使用者看到它」，兩件事分開判定，同 `01` §10 第三、四批放行的既有慣例。

## 後果

### 正面

- 學習者 persona 現在有第三條路：搜尋到「接近但不夠」的既有 Skill 時，不必二選一（Fork 微調 vs 從零生成），可以把它們當材料重新生成一份更貼近任務的新 Skill。
- 流程圖輸入涵蓋「任務用文字很難說清楚，畫一張圖比較快」的情境（`01` §2.1 的學習者 persona 隱含的另一種表達方式）。
- 三種模式共用同一條驗證與儲存路徑，`SKILL-002`／`SKILL-003`／`WS-001`／`WS-002`／`TEST-*`／`RUN-*`／`EVAL-*`／`PACK-*` 對新輸出物一體適用，沒有第二套規則要維護。

### 成本與限制

- **多一個外部輸入的攻擊面**：參考 Skill 的 SKILL.md 是「別人寫的文字」進入 prompt，`apps/llm` 的 untrusted 邊界（fenced、不可信）要覆蓋這條新路徑；圖片是二進位輸入，解碼與尺寸檢查在 Go 側先做（`generateMaxDiagramBytes`），閘道那一側的多模態訊息格式要跟供應商的實際支援對齊。
- **`GenerateSkill.tsx` 既有的成本區間估計值可能不再準確**：帶圖片與帶參考的請求 token 輪廓與純文字請求不同，估計值要重新量。
- **mini 級模型是否支援視覺輸入尚未對真實閘道驗證**——今天只由閘道的模型清單斷言，見待決策。<br>**2026-09-05 稍晚補記：驗證了。** 三種模式各對真實閘道跑一次（純文字、只有流程圖、描述＋一個參考 Skill），三次都第一次嘗試就通過驗證並建版；流程圖那一次產出的 SKILL.md 逐步對應圖上六個節點與 10000 的分岔，參考那一次只借了範例的段落骨架、本文沒有抄。合計 US$0.016。證據與逐字產出見 [m5/report-generate-modes.md](../plans/mvp/m5/report-generate-modes.md)；`04` 丙-160 同日結案。
- **provenance 只記數位指紋，不記內容**：稽核或使用者事後想知道「當時傳的到底是哪張圖」答不出來，這是決策 4 刻意付出的代價，換來的是不必新開一套物件儲存的保存期限規則。

## 待決策

1. **provenance 的顯示**：詳情頁的生成物來源區塊要不要顯示 `generation_inputs`（流程圖 sha256／媒體類型／位元組數，參考 Skill 的清單）——今天只寫入資料庫，讀取面沒有做（`04` 丙-159）。
2. **參考別人目錄裡的 Skill，要不要在生成物頁面上留一個「歸屬」的連結**——本 ADR 沒有要求，也沒有禁止；今天生成物的來源紀錄裡完全不提參考清單這件事對使用者可見。
3. **流程圖要不要曾經被保存**——本 ADR 的決策是不保存（決策 4），但若日後需要事後複現生成結果（例如支援診斷一次失敗的生成），現在的紀錄不足以支援；是否值得為此開一個有明確保存期限與存取控制的例外，留給下一次需要它的人判斷。
