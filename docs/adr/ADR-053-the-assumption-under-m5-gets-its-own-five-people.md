# ADR-053：M5 底下那個零證據的假設，脫離 D 日單獨問——並成為 M5 的投入上限

- 狀態：Accepted
- 日期：2026-08-23
- 回答：[`05` R-7](../plans/05-pending-rulings.md)
- 修訂：[ADR-052](./ADR-052-m5-starts-in-parallel-with-an-unfinished-mvp.md)（加一條投入上限；「M5 可開工」不變）
- 相關：[ADR-046](./ADR-046-generating-a-skill-from-a-task-description.md)（它的整個前提就是這個假設）、[m5/README.md](../plans/mvp/m5/README.md)、[gate-test/moderator-guide.md §3.D](../plans/mvp/gate-test/moderator-guide.md)、`04` 乙-10

## 背景：一個零證據的假設，它的解正在被寫成程式

ADR-046 的整個前提是**使用者搜不到會想要生成一個**。[m5/README.md](../plans/mvp/m5/README.md) 逐字寫著這個假設**至今零證據**——用來檢驗它的「前期驗證 2」掛在 M1 閘門的主持稿裡，成本零，**但同時繼承了 D 日的無限期，而 D 日至今未宣告**。

ADR-052 同日放行了 M5 開工。兩件事合起來的狀態是：

> **一個沒有人驗過的假設，它的解正在被寫成程式。**

曝光旗標（ADR-052）擋住了「使用者看得到」，**但它擋不住投入**。假設若不成立，那時 M5 已經有 `GEN-001`～`011` 的一批程式。

**這是路線圖上唯一一個「越晚知道越貴」的風險**——其餘各項晚一天的代價是晚一天，這一項晚一天的代價是**多寫一天會丟掉的程式**。

## 決策 1：脫離 D 日，單獨問 5 個人

「零成本但無限期」換成「低成本但這週有答案」。

材料是 [m5/ask-5.md](../plans/mvp/m5/ask-5.md)：**5 個人、每人 5～8 分鐘、三個問題、不需要產品**。

**它問的不是閘門那一題，這是刻意的。** 閘門版問的是「看到我們的無結果畫面之後你會怎樣」，需要產品、需要 D 日；這一版問的是**回溯的真實經驗**——「上次你想讓 AI 幫你做某件重複的事，找不到現成的，然後你做了什麼？」。

- **它更早拿得到**：不需要產品、不需要凍結、不需要 D 日。
- **對這個假設它其實是更乾淨的證據**：ADR-046 賭的是「這種人想要一個東西被做出來」，那是一個關於人的性質，不是關於我們某一版 UI 的反應。回溯版**完全不被我們的畫面定錨**。
- **它不能取代閘門版**：閘門版驗的是「在我們的畫面上、在那個當下」，那是 `GEN-004` 入口設計的證據。兩者互補，都保留。

**成本只有一項，寫清楚**：**被問過的人不能再當閘門受測者**（`m4/README §5.3` 理由②）。所以 5 個人從候補名單取，不動正式 9 人。

## 決策 2：這一題是 M5 的 kill switch——**在有訊號之前，投入限制在「丟得掉」的量**

> **⚠️ 2026-08-23 稍晚：本決策的投入上限已解除 → [ADR-054](./ADR-054-the-cap-was-lifted-by-authorisation-not-by-evidence.md)。** **解除它的是授權，不是本決策訂的那個條件**——`ask-5` 一次都沒被問過，ADR-046 底下那個假設今天的證據量仍然是零。單獨讀本份的人看到的上限**已不在效力中**。

ADR-052 說 M5 可開工。本 ADR 加一條上限，直到決策 1 有結果為止：

| M5 工作項 | 訊號前 | 理由 |
| --- | --- | --- |
| `GEN-001` 契約 schema | ✅ 可做 | 一份 YAML，假設不成立就刪掉 |
| `GEN-005` `redistribution` 值域 | ✅ 可做 | 一行 CHECK ＋ enum，且它獨立於生成好不好用 |
| `GEN-009` ③④ 量測 | ✅ 可做 | 它本身就是在買資訊 |
| **`GEN-002` `apps/llm` 端點** | ⛔ **暫停** | 一個端點、一份 prompt、一套版本化紀律 |
| **`GEN-003` 生成管線（Go）** | ⛔ **暫停** | **這是最大的一塊**：呼叫、打包、走 admission、重試、失敗處置 |
| **`GEN-004`／`006`～`008`／`010`／`011`** | ⛔ **暫停** | 配額、來源紀錄、UI、政策、Fork 繼承——全部只在生成真的要做時才有意義 |

**分界線是「假設不成立時，這段東西丟得掉嗎」。** 契約與值域丟得掉；一條打通 `apps/llm` → Go → admission 的管線丟不掉。

## 決策 3：三段門檻，寫在問之前

**n=5 是方向性的，不是統計的。** 門檻因此定成三段而不是一個百分比：

| 5 人中自發落入 `build_it_himself`／`ask_ai_to_build` | 處置 |
| --- | --- |
| **0** | **假設沒有支持。** M5 停在契約層，**重開 ADR-046**——那不是延期，是那份 ADR 的前提沒有成立 |
| **1～2** | **弱訊號。** 投入上限維持，等閘門的 in-context 版本（前期驗證 2 原版）再決 |
| **3 或以上** | **解除投入上限**，`GEN-002`～`011` 可做。**曝光旗標不解除**——它綁的是漏斗讀數，與這一題無關 |

**門檻寫在問之前，不在看到答案之後。** 這是本專案對 `PDM-009` 封測門檻的既有紀律，同一把尺。

## 影響

### 正面

- 那個假設**這週**會有答案，而不是等一個未宣告的日期。
- ADR-052 的並行放行仍然成立，只是投入被限制在丟得掉的部分——**兩者不衝突：放行的是准許，上限限制的是暴險**。
- 決策 3 的三段門檻讓「假設不成立」有一條寫好的路，而不是一個沒有人想過的分支。

### 成本與限制

- **5 個人不能再當閘門受測者。** 從候補名單取。
- **n=5 沒有統計效力。** 0/5 與 3/5 之間的區別是方向不是顯著性，決策 3 已按這個限制設計。
- **回溯訪談有回憶偏誤**，而且「你做了什麼」的答案會被受訪者事後合理化。緩解是只記逐字原話、只計**自發**提及，不追問、不給選項。
- **這一題問完，閘門那一題對這 5 個人就失效了**（同一個人問兩次不會得到第二次自發反應）。`moderator-guide §3.D` 已註明閘門當日不對他們重複問——但他們本來就不在正式 9 人裡。
