# ADR-042：路線圖上六個未決問題的產品裁定——以試跑證據取代評分、進行中的軸、強制者具名、量測的繼承

- 狀態：Accepted
- 日期：2026-08-22
- 關聯：[ADR-041](ADR-041-trust-signal-vocabulary-typed-absence-and-rule-precedence.md)（本 ADR 回答它的待決策 1／2／3／4／6／7）、[ADR-025](ADR-025-run-terminal-state-and-evaluation-verdict-separation.md)、[ADR-029](ADR-029-product-analytics-events-and-audit-trace-boundaries.md)、[ADR-034](ADR-034-cross-context-writes-close-by-inversion-not-by-events.md)、[ADR-011](ADR-011-workspace-tenancy-policy-and-usage.md)、[ADR-006](ADR-006-local-runner-for-local-resources.md)
- 操作手冊：[docs/design/system.md](../design/system.md)

## 背景

ADR-041 走完十八個畫面之後留下七個待決策，其中一個當天就被撤回，剩六個的共同特徵是**它們都不是 UI 問題**。「要不要做評分」是產品定位，「進行中長什麼樣」是承諾範圍，「誰在強制」是責任歸屬，「複本能不能繼承量測」是證據的定義。ADR-041 誠實地把它們標成產品決策就停住了，而**被命名的空格放久了會被下一個功能默默填掉**——這正是那份 ADR §7 存在的理由。

同一天的 `04` 丙-31 收尾又生出第七個問題：Fork 出來的 Skill 內容位元組與來源完全相同，來源掃描過，複本沒有。目前一律 `未測量`，而那個答案讓一份「你自己會拿去跑的程式碼」的清單對**最常見的那一類（Fork）**什麼證據都給不出來。

這六加一個問題現在一次裁定，理由是：它們**互相咬合**。評分的替代品是試跑證據，試跑證據需要進行中與部分資料的語彙，證據能不能跨工作區彙總與能不能跨 Fork 繼承是同一個「這個量測對什麼成立」的問題，而 Local Runner 的答案是「量測的強制者不是我們」。分開決定會得到六個各自合理、合起來互相矛盾的答案。

## 決策

### 1. 不做評分與排行榜；做「試跑證據彙總」（見下方「評估選項」）

**（a）永久禁止全域評分與排行榜。** 不是延後到 MVP 之後——`01` §7.3 把它列為「MVP 不包含」讀起來像時程，本 ADR 把其中的評分與排行榜改成**定位**：任何把 Skill 排成一條全域名次的呈現，與 `01` §5 原則 2（證據優先）在結構上不相容，因為名次必須可比較，而**本產品的證據天生不可比較**——A 的驗收條件不是 B 的驗收條件。

**（b）它的替代品不是「不給社會證明」，是給一種更好的。** 這個產品有幾乎所有 Registry 都沒有的東西：**每一個使用者都在自己的資料上真的跑過這個 Skill，而且留下了驗收判定**。那不是意見，是量測。所以 MVP 之後要做的是**試跑證據彙總**：

> 在 12 個工作區的 37 次試跑中，28 次符合**各自的**驗收條件。

**（c）四個入場條件，缺一不可**（違反任何一條即不得上線）：

1. **一定要有分母，而且分母要在同一句話裡。** 沒有分母的比例是分數的另一種寫法。
2. **永遠不是預設排序，也永遠不是唯一的數字。** 它與 §2.11(b) 的人氣禁令同級：可以顯示，不可以成為排序鍵。
3. **必須在同一個區塊說出它不涵蓋什麼**（§2.11(c)）：「這些是別人的驗收條件，不是你的」。
4. **k 門檻與自證排除**：少於 5 個**不同**工作區時顯示 `未測量` 而不是隱藏（§2.9）；Skill 擁有者自己的工作區不計入分母。

**（d）它跨工作區，所以它是同意書的事情，不是分析事件的事情。** ADR-029 管的是漏斗量測，本項是**由使用者資料推導出的產品內容**，兩者的邊界不能混。上線前置是[受測者同意書與資料保存政策](../plans/mvp/gate-test/consent-and-data-policy.md)（待法務確認）＋**每個工作區明確 opt-in**。未取得之前，這個欄位的正確呈現是 §2.9 的 `尚未定值`。

**（e）唯一允許的「排名」是逐次查詢的候選比較**，也就是現有的 Compare 畫面：它是**你這個任務上的**比較，有具名的比較維度，沒有跨查詢的全域順序。

### 2. 進行中有自己的軸（`system.md` 新增 §2.12）

ADR-041 §7 指出全文件沒有時間軸：`RUN_STATUS_LABEL` 已有五個非終態，而 §4.4 的四種視覺全是終態判定，十二處載入狀態都是 `<p>載入中…</p>`——那是慣例不是規則，而第一個串流畫面會把它取代掉。

**進行中是第三軸，不是判定的一個值。** ADR-025 已經把執行狀態與任務判定分成兩軸，本項再切一刀：

1. **進行中不得產生判定。** 一個還在跑的 Run，它的任務判定是 `未評估`（§2.9／§2.10 第 7 項），不是空白、不是樂觀猜測、不是一個較淺的顏色。ADR-041 §7 記載 `RunEvaluation` 已自行發明了進行中的呈現；它從此受本條約束。
2. **進行中的畫面必須說出三件事**：現在在哪一步、這一步**會不會自己結束**、以及**使用者能不能離開**。第三件是十分鐘承諾裡最重要而最常被忘記的一件——如果可以關掉分頁，就要說可以。
3. **必須有一個會變的量，以及一個「多久沒動了」的事實。** 一個永遠不動的轉圈分不出「在跑」與「卡住」；最後更新時間是最便宜的反卡死訊號，而 Trace 事件本來就帶時間戳。
4. **逾時、上限與配額在進行中畫面上同樣受 §2.2 約束**：指得出強制它的那一行，否則不顯示。
5. **部分資料必須標記為部分，而且分母要在**（與決策 3 共用同一條規則）。

### 3. 大清單：卡片的判準不變，改變的是「這一頁在問什麼」（`system.md` §4.3 擴充）

§4.3 對卡片的論證是「每一則要能被單獨判斷」，ADR-041 §7 說它在 50 列以上會塌掉。**查清楚之後，塌掉的原因不是視覺密度，是 §2.10**：一則卡片要放得下風險摘要、驗證狀態、可散布性與停用理由，那些**一項都不准折疊**；把卡片壓扁成表格列的唯一方法就是把它們擠掉。所以判準不能是列數。

**判準是這一頁在問什麼：**

- 問「**這一則行不行**」→ 卡片。逐則判斷，§2.10 的十項要放得下。
- 問「**哪一則最好**」→ 表格。跨則比較，欄位對齊比單則完整重要，而此時 §2.10 的項目改以**欄**存在（每一則仍然看得到，只是排成一欄）。
- 清單長到一個螢幕裝不下時，正解是**把它縮小到可判斷的數量**（篩選、搜尋、範圍），不是把每一則削薄。

**外加一條硬規則（本產品目前四種分頁策略並存，且只有一種做對）**：

> **任何被截斷的清單都必須說出總數與截斷理由。**「共 N 筆，這裡顯示 M 筆，因為 X」。

策略收斂為三種，各有適用面：**「載入更多」**用於使用者自己的、只增不減的時間序資料；**cursor 上一頁／下一頁**用於需要穩定位置的證據流（Trace）；**硬截斷**只有在同時給出總數與理由時才允許。**「完全不設限」不再是一個選項**——搜尋結果目前落在這一格，要補上限與總數。

### 4. 強制者必須具名（`system.md` §2.2 由雙向擴充為三向）

`01` §7.3 的 Local Runner 與遠端 MCP 會讓 §2.2 結構性失效：**平台對使用者自己的機器強制不了任何東西**，但那些限制是真的存在。

1. **每一條限制在畫面上都要帶一個強制者：`平台`／`你的機器`／`第三方服務`。** 三者措辭不同，而且**平台不得為它強制不了的事情背書**。
2. **平台強制不了的事情，不得使用完成式。** 不能寫「已阻擋」「不允許」，只能寫「這個 Skill 會做 X」＋「要不要讓它做，由你的機器決定」。
3. **預設拒絕，而且拒絕狀態必須是可用的。** VS Code 的 Restricted Mode 是對的形狀：未授權時內容仍可讀，只是不執行。
4. **授權是一次阻斷式的決定，不是被動通知。** 這一條有實測資料支撐：VS Code 團隊原本刻意設計成不打擾的被動提示，結果**授權率極低，而且使用者花時間以為自己弄壞了東西**，最後改回強制對話框。本產品在這裡沒有比他們更好的條件。
5. **執行前顯示命令**（`01` §9.2 已寫，本條只是把它接到 §2.2 上）。
6. **遠端 MCP 的名稱驗證要說出自己的上限**（§2.11(c)）：「這個名稱屬於 X」沒有說它做什麼。

### 5. 「總是展開技術細節」的偏好可以做（`system.md` §1.3 補一句）

確認 ADR-041 待決策 6 的初步裁定，並收緊成一句可判定的話：

> **偏好只能改變「預設開合」，不能改變「有沒有這個東西」。**

單向展開、不改變任何文字與版面、可在一處反轉 → 不是模式，可做。一旦它會**收起**任何東西（「精簡模式」），它就是模式，禁止。模式切換的合法用途仍然只有 `01` §5 原則 7 的一般／進階，判準見 `system.md` §1.3。

### 6. 位元組相同的複本可以繼承量測，但只限於「對位元組成立」的那一類，而且必須具名歸屬

這是 `04` 丙-31 收尾時生出的問題，也是本 ADR 唯一有現成外部答案的一題：**in-toto／SLSA 的 attestation 綁定的是 subject 的 digest，不是它的位置**——tag 可以改指，digest 不行，所以同一份位元組在哪裡都是同一份。靜態掃描是位元組上的確定性函式，`content_hash` 相同就是同一份輸入。

**所以量測分成兩類，這條線是本項的全部內容：**

| 類別 | 例子 | 可否繼承 | 為什麼 |
| --- | --- | --- | --- |
| **對位元組成立** | 靜態掃描、規格驗證、License 判定 | **可以** | 輸入相同、函式確定性，換個工作區不會換答案 |
| **對環境成立** | Runtime 相容性、試跑結果、評估判定 | **不可以** | 它們量的是「這份內容在**那個映像／那個 Test Case**上的行為」，條件跟著工作區走 |

**四個前提，缺一不可：**

1. **`content_hash` 必須在讀取當下比對相等，不得假設。** Fork 當下相同不代表之後仍然相同。
2. **只從公開目錄祖先繼承。** 祖先若在別人的私有工作區，答案是 `無權檢視`（§2.9），不是繼承——ADR-011 不因為溯源鏈存在而放寬。
3. **必須具名歸屬，且時間戳是祖先掃描的時間，不是 Fork 的時間。** 較舊的時間戳是誠實的，而且有用：它告訴讀者這次掃描有多舊。
4. **祖先被 takedown 之後不得繼續繼承那份量測。** 內容還是那份內容，但「我們仍然這樣說」已經不成立。

呈現上不新增 §2.9 的詞——繼承的量測**不是缺席**，它是有值且有歸屬。`SkillVerification` 的 `scanned` 狀態保留，由伺服器的 `label` 與 `note` 說出來源。

### 7. `04` 丙-32 走 ADR-034 反轉，不走第二個端點

`RunListItem` 缺判定欄位，兩條路是「eval 開讀取面由 composition root 注入」與「前端另外呼叫一個 eval 擁有的批次端點」。**選前者**，理由是 §2.5 而不是效能：那條規則要求判定與執行狀態**同一列、判定在前**，而第二個請求意味著整份清單會先以單軸渲染再補上第二軸——**讀者會在判定到達之前先讀完一整欄「執行完成」**，那正是這條規則存在要防的事。

形狀與 `04` 丙-31 剛落地的 `SkillRisks` 相同，且判定要送 `Labelled`（丙-29 裁定②的形狀），所以順帶收掉那份對照表的一半。

## 評估選項（決策 1：社會證明要用什麼形式）

這是本 ADR 唯一的選型決策，其餘六項是邊界定義或路徑選擇。

| | A. 五星評分＋排行榜 | B. 只做讚／不讚 | C. 什麼都不做 | D. 試跑證據彙總（**採用**） |
| --- | --- | --- | --- | --- |
| 回答「別人用得怎樣」 | 是 | 勉強 | **否** | 是 |
| 資料是意見還是量測 | 意見 | 意見 | — | **量測**（真的跑過，有驗收判定） |
| 已記錄的失效 | J 型分佈：五星與一星兩個峰、中間塌陷，**兩千則以上的樣本仍然如此**，所以「平均分」幾乎不帶訊息 | 同樣的自選擇偏差，只是少一個維度 | 使用者轉去看下載數與星數——也就是 §2.11(b) 剛禁掉的東西 | 分母小的時候不穩，**靠 k 門檻擋** |
| 可被灌嗎 | 可以，而且便宜 | 可以，而且更便宜 | — | **貴**：要真的跑一次 Run，而且工作區要不同 |
| 與 `01` §5 原則 2 的相容性 | 衝突（名次即 Star 的另一種寫法） | 衝突 | 相容但沒解決問題 | **一致**：它本身就是「試跑與驗收證據」 |
| 跨 Skill 可比較嗎 | 假裝可以 | 假裝可以 | — | **明說不可以**（各自的驗收條件），這是特性不是缺點 |
| 隱私成本 | 低 | 低 | 無 | **高**：跨工作區彙總，要同意書與 opt-in |

**選 D 的關鍵理由**：C 不是中立選項——不給社會證明，使用者就會去看下載數與星數，而那正是 §2.11(b) 剛剛禁掉的訊號。A 與 B 的資料是意見，而**這個產品唯一的結構性優勢就是它握有量測**。D 的代價（隱私前置、分母小的時候不穩）是真的，但它們是**可以用規則處理的代價**，而 A 的 J 型分佈是用規則處理不掉的。

**支持 A 最強的論證**（記在這裡免得未來被當成沒想過）：十分鐘旅程裡只有一個數字活得下來，而 D 要讀一整句話。回應與 ADR-041 決策 3 相同：在這個產品上，「一個數字活得下來」是缺點不是優點——那個數字活下來的方式，是把「沒人跑過」與「跑過而且不錯」壓進同一條軸。

## 影響

- **`01` §7.3 有一項語意改變，要同步。** 「社群留言、完整評分機制與排行榜」原本讀起來是時程（MVP 不包含），決策 1 把其中的**評分與排行榜**改成定位（永久不做）。留言不在本 ADR 範圍。依三文件同步規則，`01` 與 `02` 要補這一行。
- **`system.md` 只增加一條原則（§2.12）與一條 checklist（第 17 條）。** 其餘五項都改寫進既有章節（§2.2 擴為三向、§2.9 補一句、§2.11 補 (d)、§4.3 補尺度條款、§1.3 補一句）。這是刻意的：ADR-041 自己記載那份文件的成本落在每一批 UI 工作的人身上，**六個決策換六條新原則會讓它變成沒人讀的東西**。
- **決策 6 立刻有實作工作**，而且它會改動剛落地的 `SkillVerification`：要加祖先讀取（僅限公開目錄）、`content_hash` 當下比對、takedown 檢查與具名歸屬的措辭。列入 `04` 丙類。
- **決策 1 沒有立刻的實作工作，但有前置**：同意書（乙類，待法務確認）與 opt-in 的資料模型。在那之前這個欄位不存在，而不是存在且空白。
- **決策 3 讓「搜尋結果不設限」變成一個缺陷**，它現在有名字了。
- **決策 4 是本 ADR 裡唯一會在事故當下才被驗證的一條。** Local Runner 尚未實作，所以這條規則在寫下的當下沒有任何實例可以對帳——它的價值是**在第一個實例出現之前就存在**，因為那個畫面會是這個產品史上風險最高的一個。

## 待決策

1. **試跑證據彙總的 k 門檻定在 5 個工作區，是推導不是量測。** 它同時要擋自證灌水與保護隱私，兩者的合適值不一定相同；有真實流量之後要回頭校準，而校準的方向只能往上。
2. **留言要不要做。** 決策 1 只處理了評分與排行榜。留言是意見，但它是**帶理由的**意見，與星等不是同一件事，值得另外決定。
3. **決策 6 的「對環境成立」那一欄，在同一個 Runtime Image 上要不要放寬。** 若兩個工作區跑在同一個釘選 digest 的映像上（ADR-023），相容性量測的條件其實相同。目前一律不繼承是保守選擇，代價是重複量測。
4. ~~**進行中的「能不能離開」在 MVP 的答案是什麼。**~~ **已回答（2026-08-22 同日，`04` 乙-20）：可以離開，而且指得出強制它的那一行。** `run_execute` 是 Postgres 裡的 River job 由 `cmd/worker` 消費，Trace 由沙箱直接 POST 回 API——**兩條路徑瀏覽器都不在裡面**。留下的殘留是這是讀架構讀出來的，不是真的拔過網路線；實機斷線驗證屬於部署期（甲類）。
